# DX11 자동개발 — 30분 독립 실행 (2026-10-11 최신 우선)

목적: 새 코딩 작업을 실행한다. TASK_ID는 GitHub 커밋을 식별하기 위한 표식일 뿐, 과거 TASK_ID 완료·backlog·C6 승인 대기가 신규 개발을 막는 선행조건이 아니다. 30분마다 새 대화가 들어온다. 현재 지시에서도 계획·검토·기존 PASS 점검만 반복하지 말고 소스·테스트의 실제 변경을 수행한다.

1. GitHub 연결 도구로 thp32tt/OutRun2006Tweaks의 vr-dx11-native-r71 최신 HEAD와 AGENTS.md, docs/automation/DX11_AUTODEV_EXECUTION_POLICY.json, 최신 작업 로그를 확인한다.
2. 우선순위: 이미 소스/빌드까지 완료된 FIRST_GAME_DRAW_FRAME를 다시 검증만 하지 말고, **메뉴→차량 선택→레이스 화면 및 게임패드 입력**을 실제 네이티브 Draw/DrawIndexed 경로로 확장한다. 다음은 OpenXR 프레임 제출 및 안전한 DX9Ex fallback. 해당 변경이 이미 있으면 남은 미완료 연결을 찾아 구현한다.
3. 빈 문서·상태 업데이트·단독 readiness/guard/probe와 기존 통과한 테스트 반복은 작업 성과가 아니다. 실제 렌더링·입력 관련 C++ 또는 필수 연동 코드 수정과 해당 부분을 검증할 최소 테스트를 수행한다.
4. 현재 브랜치 HEAD와 작업자별 변경 경로를 확인하고 이미 진행 중인 동일 파일 수정을 피한다. 충돌하면 다른 미완료 구현 부분으로 이동한다. GitHub 업데이트는 비강제만 사용하고 CI-skip 없이 커밋한다.
5. C0 원인 파악→C1 구현 범위→C2 실제 코드 구현→C3 관련 테스트/빌드→C4 GitHub material commit→C5 패키지 필요시 생성→C6 결과 기록. 실기 HMD/게임 미실행이면 RUNTIME_VALIDATION=UNTESTED. CI 결과를 실제 화면 정상으로 과장하지 않는다.
6. TASK_ID가 새로운 개발 범위를 뜻할 수 있지만, 과거 TASK_ID 미종결이나 기능 목록 소진은 작업 중지 조건이 아니다. 매번 바로 실제 개발을 시작한다. DXVK 및 한글화 브랜치는 수정하지 않는다.

해당 턴이 30분 뒤 새 채팅으로 넘어가더라도 GitHub에 확보한 소스 변경이 재개 기준이다. 새 대화에서 재보고만 하지 말고 다음 구현을 지속한다.
