## Cycle 095 — 60 Hz simulation vs 72/80/90 Hz render cadence

- **Existing runtime evidence:** R73 HMD runs above simulation rate, so numUpdates=0 frames are expected.
- **Disassembly/source evidence:** hooks_framerate keeps simulation CalcNumUpdatesToRun(60) while render unlock follows XR cadence; SumoUISpriteReplay fills tick-drawn UI on zero-update frames.
- **Analysis:** This timing architecture makes semantic replay loss frequent, not rare, and could explain HUD elements that appear wrong only in VR/high-Hz path.
- **Falsification / next evidence:** Add counter: original tagged nodes vs replayed untagged nodes by payload hash.
- **Verdict:** `HIGH_CONFIDENCE_TIMING_RISK`

## Cycle 096 — Semantic registry cross-thread publication

- **Existing runtime evidence:** Prior source explicitly moved SpriteNode tag table from thread_local to shared mutex-protected storage because producer/render threads can differ.
- **Disassembly/source evidence:** Register/consume uses pointer+serial; publication count is atomic.
- **Analysis:** Original node tags can survive cross-thread handoff, so cross-thread loss is less likely than replay-created fresh-pointer loss.
- **Falsification / next evidence:** Compare registered/consumed/stale counts around bad element.
- **Verdict:** `FALSIFIES_OLD_THREADLOCAL_CAUSE`
