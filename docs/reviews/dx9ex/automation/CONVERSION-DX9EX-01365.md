## REVIEW_SCOPE

Independent **resource-lifetime/recovery** seam on a game Reset and a source-size-only change: the game temporary-resource release/create midhooks, the separate R7 device Reset vtable callback, the F11 font-atlas invalidation/recreation boundary, and the source-size-sensitive letterbox VB. This review is distinct from 01364's failed secondary D3D9 Get*/Set* state snapshots *during a successful letterbox Draw*, 01363's PMT frustum enclosure and 01362's optional R84 particle VB bind failure. Question: does the hook itself prove that the ImGui DX9 font texture was restored before the first F11 Draw after Reset, or does that conclusion require an independent backend/device-object result?

It does **not** prove precise device-reset callback ordering in a live game. External F11 ImGui is mod-generated at EndScene, not an original +TIME/GOAL SpriteNode or queue epoch.
2. **Original temporary-resource midhooks:** `src/overlay/hooks_overlay.cpp::D3DHooks::apply:549-568` installs separate executable-relative `0x17970` release and `0x17A20` create callbacks. `::D3DTemporariesRelease:512-527` invalidates ImGui DX9 device objects when initialized and releases/zeros the letterbox VB/device/size cache. `::D3DTemporariesCreate:530-536` invokes `ImGui_ImplDX9_CreateDeviceObjects()` when initialized and then `CreateLetterboxVertex()`. **The DX9 backend creation return/status is not inspected or propagated by this callback.** A hook installation success is not a font-atlas GPU allocation success.
3. **Different R7 Reset owner:** `src/vr/d3d9/stereo_renderer_r7.inc::ResetDest:1744` separately invalidates R7 state, calls `OutRunVRRenderer::NotifyGameReset()`, releases private eye targets, clears world/pose/transport frame metadata, delegates to D3D9/ResetEx compatibility, then primes state and attempts `EnsureStereoResources` on successful reset. This Reset path does not itself establish that EXE temporary callbacks ran before the next F11 render, nor does it check the ImGui DX9 backend result. It deliberately publishes stereo-disabled metadata while resetting; it does not assert a fresh XR frame.
4. **Source-size-only letterbox owner:** `src/overlay/hooks_overlay.cpp::CreateLetterboxVertex:47-108` allocates a source-sized DEFAULT-pool VB and caches it only after successful Create/Lock/Unlock; `::D3DEndScene:142-164` recreates when the live `Game::screen_resolution` or borrowed device pointer differs. This resize detection is intentionally independent of game temporary-resource Reset callbacks. A valid bar-on frame uses the cached current-sized buffer, native fixed-function `DrawPrimitive` and `ScreenOverlay2D` scope (`:175-314`), with per-state restore afterward (`:316-360`, separately reviewed in 01364). A failed letterbox VB allocation is retried without proving F11 font-texture readiness.
5. **F11 atlas and backend handoff:** `src/overlay/hooks_overlay.cpp::D3DInit:117-135` initializes ImGui/Win32/DX9 once. `::D3DEndScene:364-488` computes an F11-only VR font multiplier from latched visibility, valid paired XR extents and hysteresis; when `Overlay::FontsDirty`, it calls `Overlay::rebuild_fonts()` and `ImGui_ImplDX9_InvalidateDeviceObjects()`. `src/overlay/overlay.cpp::rebuild_fonts:375-461` clears/rebuilds CPU atlas and clears `FontsDirty`. `hooks_overlay.cpp:489-507` then calls backend `NewFrame`, `Overlay::render`, `ImGui::Render`, and `ImGui_ImplDX9_RenderDrawData`. There is **no local post-create readiness check** between the temporary create callback and this physical F11 draw. Whether Dear ImGui's linked DX9 backend internally recreates a missing font texture during `NewFrame` must be checked against its **exact bundled version**, not assumed failed.
6. **Semantic and two-eye conditional route:** external active-VR F11 DrawData is tagged `ScopedExternalOverlaySemantic(ScreenOverlay2D)` (`hooks_overlay.cpp:496-507`), so `src/vr/game/render_semantics.hpp::CapturePhysicalDrawCommand:1420-1431` cannot borrow original queued D3DX producer/node/epoch. Native F11 fixed-function indexed DIP is tried by `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawIndexedPrimitiveDestR30:5421-5505` via dedicated `R30TryExternalImGuiIndexed`, ahead of R62 original SpriteNode qualification; R30/R29/original fallbacks remain conditional. For qualifying GPU draws R7 `stereo_renderer_r7.inc::ExecuteStereoDraw:1525-1555` targets L/R with RT/depth/viewport and transform restoration; a semantic tag alone does not prove both physical draws.
7. **Final Present and host boundary:** `stereo_renderer_r7.inc::PresentDest:1625-1741` requires independently verified world+duplicated-eye eligibility, pose, resources and no incomplete/right-failure before publishing fresh stereo; source-only F11 draw or temporary callback success cannot seed world-stereo. Original Present HRESULT and any R32 DirectGPU EVENT/ACK versus SBS fallback must be correlated with the host R24/R32 selected OpenXR layer; no matched capture or Quest3/VDXR evidence was provided.
