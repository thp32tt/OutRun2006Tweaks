## EVIDENCE — independently pinned source-to-final-submission walk

1. **Native source and physical GPU ownership are prerequisites, not the eventual cache's proof of currency.** Historical original-EXE REA records the queue consumer `0x0042D710` (normal caller `0x449050`) and four distinct GPU endpoints: type-0 D3DX `0x42A0A0`, direct-UP `0x42C0F0`, animated quad `0x42A3A0`, mask/composite `0x42A800` (`docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-39`). SpriteNode semantic tagging and D3DX deferred Flush/End in `src/hooks_uiscaling.cpp:1277-1352,3504-3580,4228-4270` do not themselves certify GPU pixels. R26 `R30TryScreenSpaceFovDraw` demands canonical semantic corroboration (`src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:5033-5075`); R62/R29 remain separate conditional owners. R7 `ExecuteStereoDraw` preserves the left/right viewport, RT, depth, WVP/fixed-function and restore outcomes (`src/vr/d3d9/stereo_renderer_r7.inc:1540-1556`). This review does not assert that every result sprite is stereo or that all scene draws succeeded.
2. **The x86 Present/Frame.v2 handoff advertises completed stereo only after guarded publication.** In `stereo_renderer_r7.inc:1625-1741`, R7 checks completed world/duplicated/pose/target conditions, handles DirectGPU vs classic SBS, records `presentStart` QPC, marks classic `RenderFramePresentInFlight` before the real D3D9 `Present`, and publishes `StereoSbsActive` plus `sourcePoseSequence`/`frameId` only when the completion path allows it; otherwise it publishes fallback or explicitly holds previous valid DirectGPU data. `PublishRenderFrame:1491-1494` writes the Frame.v2 ring under slot/ring sequences. `src/vr/ipc/protocol.hpp:190-233` gives distinct run identity, source pose, flags, presentQpc and eye metadata. An existing valid prior Frame.v2 is not a new Present receipt.
3. **Host acceptance and two-eye projection are originally guarded.** `vrhost/src/main.cpp::RenderFrameReader:757-900` validates ring/slot sequences and current client PID/run generation. `vrhost/src/main_r23.cpp:2940-3289` selects latest eligible direct source or classic DXGI capture-correlated history, matches pose history, checks `R23FrameUnchanged`, commits and publishes a verified bundle only on the successful projection path. `R23RenderProjection:1440-1513` samples independent left/right SRVs or SBS halves, performs *both* D3D11 eye draws, unbinds on failure, releases the swapchain image, and assigns XR projection imageArrayIndex 0 and 1. These operations certify a previously assembled image, not perpetual producer freshness.
4. **R23 gameplay cache has no matching expiry in its final per-tick admission.** `main_r23.cpp:3292-3305` defines `cachedHold = cachedProjectionValid` independently of the 250ms `StereoGraceMs`, with an explicit comment to never age out a previously released stereo projection while Gameplay persists. When no new frame is committed, `:3316-3337` skips redundant dual-eye blits; `:3369-3409` submits `cachedProjectionViews` as `projection-cached` whenever `cachedProjectionValid && (grace || cachedHold)`. `cachedHold` makes the age-dependent grace check irrelevant to this branch. `:3562-3570` forwards the intended projection to `xrEndFrame` through the final guard, whose actual submitted kind is inspected at `:3574-3589`.
5. **The final R24 owner applies a distinct finite verified-bundle contract.** `vrhost/src/runtime/r23_verified_bundle.hpp:17-20,91-145` defines `MaxPresentationAgeMs=1000`; `ReadFresh` requires the committed bundle to remain within that age and in the current producer run. `vrhost/src/runtime/r24_black_screen_guard.hpp:35-43,577-705` routes XR final submission: intentional mono menu projection bypass and separately validated classic/direct projection are preserved; after exact/grace checks fail, a fresh classic fallback is tried before `SubmitVisibleFallback`. `ReadDisplayGraceSnapshot:154-169` uses `DisplayOnlyGraceMs`, which is also **1000ms**, not an indefinite R23 cache extension. Thus a still-set outer `cachedProjectionValid` does not by itself guarantee a final stereo projection after 1000ms without refresh.
6. **Fallback is deliberately visible but can change the layer type and binocular semantics.** `r24_black_screen_guard.hpp::SubmitVisibleFallback:479-574` tries already-released cached projection/theater, direct-flat, live theater, emergency fallback and only then no layer. `BuildCachedVisibleQuad:416-445` returns a `XrCompositionLayerQuad` in VIEW space using **array slice 0**, eyeVisibility BOTH (`:203-218`), when the committed projection cache and producer-run identity validate. This is a *flat both-eye visibility safety net*, not the source's two separate projection-eye views. It is incorrect to claim a guaranteed black screen: the final guard may successfully show an intentional flat fallback, and the exact path depends on runtime resource state.
7. **The pacing CSV has a separate blind spot for old cached display.** `main_r23.cpp:3590-3644` increments `pacingXrTick` but emits a `Pacing::Sample` only if `actualSubmittedLayer && actualSubmittedFrameId && OutRunVrR23VerifiedBundle::ReadFresh` and frame IDs match. R24's visible fallback records frameId=0 / kind None (`r24_black_screen_guard.hpp:571-574`), and after the age ceiling `ReadFresh` rejects old bundles. Consequently such XR ticks need not appear as CSV rows even though the R24 fallback emitted a layer; the outer `cadence.NoteFrame(frameCachedProjection, layerReady)` reflects intended R23 state, not necessarily final R24 projection class. This is **conditional observability loss**, not measured frame rate.
