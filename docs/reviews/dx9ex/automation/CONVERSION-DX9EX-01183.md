## REVIEW_SCOPE — original producer → semantic / queue → D3DX or native GPU → R30/R62/R26 L/R → restore → R9 Reset/Present → fresh DirectGPU/SafeEye → projection → xrEndFrame

1. **Original draw identity remains a prerequisite.** The checked-in *historical*, not newly executed, original-game REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:31-76` traces original `0x00449050` scheduler, `0x00429530→0x00428A10→0x00429460→0x00429350→0x00428BD0` sprite queue, original D3DXSprite Begin/Draw/**deferred Flush/End**, and native Draw/UP paths. The producer/semantic tag alone does not identify a physical draw or pixel. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawPrimitiveDestR30/DrawIndexedPrimitiveDestR30:5349-5415` conditionally consume the physical semantic and try XYZRHW/R62/native fallback; `::R30ExecuteXyzrhwStereo:3829-3922` attempts left native GPU draw, right RT/depth/viewport+GPU draw and restore. Neither eye success nor physical queue ownership was measured in this run.
2. **Same-run Reset can change the game backbuffer without changing the XR projection allocation.** `src/vr/d3d9/stereo_renderer.cpp::ResetDestR9:825-838` delegates to the underlying `src/vr/d3d9/stereo_renderer_r7.inc::ResetDest:1739-1741` when R9 callbacks are actually installed (`R9InstallCallbackPolicy:849-887`). The lower reset releases prior eye/backbuffer/direct-slot resources and on success re-primes them. Game-side `EnsureStereoResources:1454-1466` re-reads the newly returned backbuffer descriptor. Conversely `vrhost/src/main_r23.cpp:2585-2640` publishes a common XR eye extent at host startup, confirms the compositor allocation, while `vrhost/src/main.cpp::CreateProjectionSwapchain:1924-1944` constructs a 2-slice projection at the resolved extent. The inspected main loop does not recreate this projection swapchain in response to an ordinary game-only D3D9Ex Reset. A game's desktop/backbuffer dimension change is **not automatically** an XR swapchain dimension change.
3. **Shared-eye target size is explicitly host-authoritative on the producer.** `src/vr/ipc/xr_eye_extent.hpp::ResolveHost/ResolveGame:13-48` provides a shared common-eye allocation/validation policy; `src/vr/d3d9/stereo_renderer_r7.inc::DirectTransportTargetSize:1300-1347` seqlock-reads both published, equal eye sizes and rejects invalid/out-of-caps sizes. `::EnsureDirectTransportResources:1353-1357` rebuilds the 4-slot shared left/right textures at that resolved eye size, bumps `DirectTransportGeneration`, and can only return ready once all slot resource and event-query allocations succeed. A transient sequence read can reuse an already valid producer extent; no proof of a mid-session host XR resize follows from this.
4. **Game-source-to-shared-eye resampling is not inherited cached UV.** `::StretchDirectEye:1349-1352` attempts LINEAR `StretchRect` and only on failure NONE; `::ResolveDirectTransport:1358-1426` copies the *new* game left backbuffer and right-eye surface to the newly allocated shared pair and arms producer EVENT. If game resolution changes while XR stays fixed, this may produce a different whole-image sampling ratio (already established in 01177), but there is no old-image crop rectangle or first-frame inherited UV in this helper. Actual filter success/visual texture resolution is unmeasured.
5. **New frame resource identity is validated before SafeEye ownership changes.** `vrhost/src/main_r23.cpp:2940-3045` selects completed DirectGPU history by frame and transport generation under the same PID/run; it does not treat a Reset as new PID/run. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp::R32OpenSharedSlot:111-207` keys cache on slot, generation, run, PID, both handles, dimensions, format and host device, validates both texture descriptors. `::R32EnsureInactiveEyes:211-252` reuses the inactive copy pair only if its size/format/device match; `::CopySharedFrameToSafeEyesR32:253-319` copies both into inactive eyes, waits for GPU completion and swaps only after successful publication. If the game or host cannot satisfy the new extent/format or GPU fence, the new frame does **not** become a proven SafeEye; it may leave the *old released XR projection* available, which is the distinct predecessor 01182 concern.
6. **A fresh accepted projection has current full-eye UV, output rect and source-matched pose.** `vrhost/src/main_r23.cpp:3215-3290` validates the candidate's frame identity, commits the direct source and calls `R23CopyMatchedViews`. `::R23RenderProjection:1437-1515` uses `{0,0,1,1}` direct SafeEye UV independently for both eyes; the left/right D3D11 `RenderTo` dimensions are `projection_.width/height` rather than remembered producer backbuffer dimensions. The successful path builds each `XrCompositionLayerProjectionView` with the selected views' pose/FOV, `imageRect={0,0, projection.width, projection.height}`, and array slice 0 or 1. `::R42 projection refresh:3300-3390` replaces `cachedProjectionViews` only after this fresh projection returns success; final `xrEndFrame:3557-3580` is separate. No evidence was found of a first-*fresh*-frame branch that copies prior projection UV/rect/FOV or uses the old producer's width to address the new swapchain.
7. **Frame cursor survives Reset intentionally, not a reset-induced frame-ID wrap.** `src/vr/d3d9/stereo_renderer_r7.inc::StereoFrameCounter:201;::NextStereoFrameId:1473` increments an in-process monotonic counter; `::ResetDest:1739-1741` resets `PresentEpoch` but does not reinitialize that counter. The R41 `lastProcessedStereoFrame` predicate therefore does not imply permanent first-fresh-frame starvation just because same-run D3D9Ex Reset did not clear the host cursor. This is a source-conditional finding, not a measured recovery latency.
