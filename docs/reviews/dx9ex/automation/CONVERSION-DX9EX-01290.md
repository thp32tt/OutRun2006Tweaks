## REVIEW_SCOPE

Independently follow **R26+HUD dynamic indexed XYZRHW CPU-shadow initialization**, instead of repeating 01289's +TIME mask pixel-to-XR extent and ScreenOverlay2D/R51 comment finding, 01288's masked D3DX deferred-batch speculation, 01287's Present-to-XR freshness or 01286's opt-in R84 WorldParticle first-eye DynamicVB bind failure. The exact question: can the game's first IB Lock/Unlock precede R30's global shadow-capture arm, so an otherwise eligible first DrawIndexedPrimitive cannot use its newly allocated index shadow, whereas a later draw after a new IB write can? Trace producer -> semantic/queue -> physical DIP/D3DX separation -> R62 priority / R30 admission -> dual eye -> stream/depth/RT restore -> R9 Present -> host projection/xrEndFrame. This is conditional static branch reasoning; no original object-to-physical-DIP identity or visual defect is asserted.

## EVIDENCE — pinned static execution simulation

1. **Original producer and GPU ownership are not interchangeable.** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:1-39` (original EXE SHA256 `68ceb386829066f8455b9d027320af962584321f3e2e8a79c72841495a6134c3`) identifies four original SpriteNode consumer routes: type-0 D3DX `0x42A0A0`, type-0 direct UP `0x42C0F0`, type-1 direct quad `0x42A3A0`, type-1 masked/composite `0x42A800`. There are 36 unresolved indirect consumer calls. This **does not prove** any of those four paths or a sand/particle producer uses an R30 captured indexed VB; do not relabel D3DX Draw as actual DIP without matching physical GPU evidence.
2. **Semantic/queue cutoffs and physical API are separate.** `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1837` establishes lazy queue cutoff, node epoch and exact producer tags; unknown sprites remain `ScreenOverlay2D`. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawIndexedPrimitiveDestR30:5379-5458` consumes draw semantic and first tries external F11 ImGui and R62 fixed-function D3DXSprite indexed quads, then `R30TryXyzrhwIndexedPrimitiveVB`, then `R30GuardScreenSpace`/original R29/native dispatch when the XYZRHW candidate returns `E_NOTIMPL`. R62 rejection by itself is *not* final HUD rejection; the shadow scenario applies only if the DIP reaches the R30 indexed-VB candidate.
3. **First-index-write ordering (new bounded finding).** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30CreateIndexBufferDest:827-843` installs the IB Lock/Unlock hooks on buffer creation but calls `R30EnsureIndexShadow` only when `R30BufferShadowCaptureArmed` is already true. `::R30IndexBufferLockDest:696-710` similarly starts an observed IB Lock **only if the same global arm is true**. `::R30IndexBufferUnlockDest:712-733` snapshots only an observed lock. By contrast, `::R30CreateVertexBufferDest:790-823` can register an exact XYZRHW-FVF **vertex** buffer before the first Draw; no equivalent positive pre-Draw FVF identity exists for an IB. Consequently, **IF** an IB was filled before the first R30 arm and has not been written under an observed lock afterward, its bytes are not in the valid shadow range even though its physical D3D9 buffer is valid.
4. **Arm happens after an indexed physical candidate starts.** `::R30TryXyzrhwIndexedPrimitiveVB:4236-4297` checks R30 prepare, reads stream 0 / GetIndices, ensures hooks, then `R30BufferShadowCaptureArmed.exchange(true)` and ensures VB/IB shadow entries. `::R30CopyIndexShadow:604-634` requires registered bytes plus a covering valid interval; an entry created now has no historic game index bytes. `::R30TryXyzrhwIndexedPrimitiveVB:4297-4320` fails `E_NOTIMPL` when `R30CopyIndexShadow` fails, before either transformed eye draw. No GPU Lock readback or implicit recovery of historic IB contents occurs. R30's existing native/R29 dispatch must handle this candidate rejection conservatively.
5. **Later writes can change eligibility; this is *not* proof of a regression.** `::R30BeginObservedLock:503-526`, `::R30FinishObservedLock:529-565` capture valid game Lock/Unlock bytes. `src/vr/d3d9/r30_shadow_ranges.hpp:1-66` coalesces observed ranges and demands full requested coverage, including after partial writes. `D3DLOCK_DISCARD` invalidates previous coverage; Release removes registry/budget at `::R30IndexBufferReleaseDest:734-751`. Thus after a subsequent full required-window write an otherwise eligible DIP may reach R30's L/R transformation. If there is **no later write**, or the first write occurs after arm, or the draw is R62/VS/unknown non-XYZRHW, this conditional transition is absent.
6. **Failure branch and overhead guard.** `::R30CopyIndexShadow:604-634` returns false without attempting to draw either eye when coverage is missing. `::R30TryXyzrhwIndexedPrimitiveVB:4236-4350` rejects malformed index format, out-of-bounds regions and read misses; `src/vr/d3d9/r30_shadow_bytes.hpp:1-48` and `r30_shadow_scratch.hpp:1-56` avoid redundant zero fills but do not assert that uncaptured bytes are authoritative. `R30ShadowReadMisses`, `R30ShadowReadHits`, `R30ShadowWrites`, `R30ShadowDiscardInvalidations` and `R30BufferShadowCaptureArmed` are reported by `::R30MaybeLogTelemetry:1438-1460`. No draw-count-per-particle, memory bandwidth, VRAM churn, p95 or p99 samples were gathered.
7. **Dual-eye/restore boundary only after successful candidate admission.** `::R30ExecuteXyzrhwStereo:3829-3944` submits left from transformed source, switches right RT/depth and original viewport, restores via `RestoreRightPassState`, flags right/restore errors and records authoritative world-stereo pose only if corresponding gate passes. The indexed-VB path also restores the original VB+IB stream/index bindings at `::R30TryXyzrhwIndexedPrimitiveVB:4410-4500` after eye attempts. A pre-draw `E_NOTIMPL` from missing IB shadow does **not** demonstrate failed right-eye restoration; R30's later R29/native dispatch must be analyzed separately. Do not count attempted candidate admission as a real GPU draw.
8. **Frame boundary stays independent.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-823` publishes valid stereo only when frame world/duplicated-draw/pose/resource conditions pass, preserves mono/fallback and advances Present epoch after normalized Present. `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` selects verified DirectGPU per-eye hold versus SBS source and independently draws the two OpenXR projection images; `::xrEndFrame:3562-3635` checks actual final submission. A native indexed Draw is *not* automatically a missing XR layer, and a later successfully shadowed Draw is *not* proof of binocular HMD correctness.

## NEW_FINDING — confirmed conditional control-flow ordering, not runtime bug

- **NEW_FINDING=R26_INDEXED_XYZRHW_IB_FIRST_WRITE_PRE_ARM_CAN_CAUSE_FIRST_CANDIDATE_SHADOW_MISS**.

- **FACT:** IB creation/Lock captures game index bytes only after global arm, whereas the first candidate DIP turns on that arm **after** earlier game writes may have happened; a newly ensured shadow cannot retroactively acquire those bytes, so `R30CopyIndexShadow` may veto the first stereo candidate without any per-eye GPU submission.
- **HYPOTHESIS:** a game indexed-XYZRHW path could switch from native/R29 handling on its first physical draw to R30 stereo handling after a later fully observed IB update, potentially changing screen placement or frame time. This path, producer provenance and visual effect are NOT observed.
- **FALSIFIERS / NEGATIVE CONTROLS:** a pinned actual DIP whose IB Lock is always after the global arm; a prior accepted XYZRHW VB draw arming capture; full valid IB shadow coverage before the DIP; R62 or other earlier handler consuming the draw; non-XYZRHW/VS geometry; no subsequent IB rewrite; actual Quest 3/VDXR captures demonstrating identical per-eye output and stable p95/p99. Verify exact DLL config/SHA, queue producer/epoch, stream FVF/VS, IB pointer generation, lock/flags/write bytes, expected `startIndex * indexSize` interval, shadow miss/hit and final Draw API before promoting from conditional analysis to reproduced defect.
