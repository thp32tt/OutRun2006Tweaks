## Original producer -> semantic -> native physical draw -> L/R -> restore -> Present/OpenXR

1. **Original/producer provenance (previously checked in, not newly disassembled).** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:3-39` pins original EXE SHA-256 `68ceb386829066f8455b9d027320af962584321f3e2e8a79c72841495a6134c3`; `0x449050 -> 0x42D710` dispatches type0 D3DX `0x42A0A0`, type0 direct UP `0x42C0F0`, type1 animation `0x42A3A0` and masked type1 `0x42A800` conditional routes. +TIME has six independently checked original E8 calls. Not all indirect targets are resolved, and no particular sprite/UI glyph's final physical API is proven by this map.
2. **Game logical menu transform is its own coordinate contract.** `src/hooks_uiscaling.cpp:652-714` calls original `D3DXMatrixTransformation2D`, then under `frontEndPivot` and finite verified inputs reads `Game::screen_scale`, `Game::screen_resolution`, `Game::original_resolution`, computes `BuildFrontEndAffineContain`, and publishes a corrected transform only if affine/matrix shape checks succeed. Partial front-end menu matrices are fingerprinted for later already-contained detection. These game-side logical dimensions and an already-contained D3DX matrix are **not** a measured per-eye XR framebuffer size. A source-resolution update must not silently double-apply containment.
3. **Queue/D3DX admission does not prove the physical raster source.** `src/hooks_textures.cpp::put_sprite_ex2_dest:1117-1160` calls the original producer while scoped texture-parent and mask UV changes are restored before `TagDirectVrSpriteNodes`. `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1837` consumes exact producer/scope under queue registration cutoff, else conservatively chooses `ScreenOverlay2D`. `EndSpriteQueueRender/Frame:1839-1905` preserves unvisited tags through partial passes until Present/Reset. D3DX `src/hooks_uiscaling.cpp::VRProjectedD3DXSpriteIsolationR64::BeforeQueueNode:3661-3690` distinguishes proven outgoing deferred native batch ownership before incoming queue identity. A D3DX `Draw` can be deferred until native `Flush/End`; it is not synonymous with one submitted D3D9 Draw. For any sample, capture the *actual* final Draw API, not a guessed D3DX ownership inferred from logical UI scaling.
4. **Default R26 physical route and viewport are independently sampled.** `AGENTS.md:1-11` selects protected option-free R26+HUD; R84 is opt-in A/B only. In `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30PrepareXyzrhwState:2493-2543`, fixed-function XYZRHW eligibility requires a live VS==null, XYZRHW FVF, `EnsureStereoResources`, successful `device->GetViewport(&state.viewport)`, nonzero viewport and valid Z range, plus a latched same-pose stereo affine. `R30TransformXyzrhwVertices:3427-3516` computes screen->NDC from **that captured viewport's X/Y/Width/Height** for eligible reprojection, not automatically from desktop client, `Game::original_resolution` or host `sourceWidth_`. In `DrawIndexedPrimitiveDestR30:5377-5461`, external F11 ImGui -> R62 exact fixed-function indexed Sprite -> R30 XYZRHW VB -> guarded R29/original are distinct alternatives. `DrawPrimitiveDestR30:5349-5375` and UP entrypoints `:5464-5525` have different eligibility. R62 result-HUD rejection is R62-only; it cannot resolve final actual API. No evidence here that a specific UI sample reaches the XYZRHW conversion.
5. **Right-eye and raster-state restoration remain separate gates.** An eligible R30 XYZRHW draw uses `R30ExecuteXyzrhwStereo:3829-3945`: left physical submit, right RT/depth switch, `SetViewport(&state.viewport)`, right submit, and `RestoreRightPassState` with saved RT/depth/viewport. A success return from left can coexist with a recorded right or restoration failure and frame poison. R23 raster state capture `stereo_renderer_r23.cpp:67-139` live-samples viewport/scissor on render-target changes, including implicit RT viewport reset. Thus use pre-draw **live viewport and RT generation**, not cached desktop dimensions or a stale previous-pass scissor rectangle.
6. **The host has two different extent consumers, neither synonymous with (2)-(4).** `src/vr/ipc/xr_eye_extent.hpp:10-52` resolves common per-eye XR allocation from both eyes' recommended/maximum sizes and render scale; `ResolveGame` rejects a host extent larger than game caps instead of silently clamping to desktop dimensions. `vrhost/src/main_r23.cpp:2597-2636` prepublishes startup XR extent and explicitly checks real compositor allocation equality. However `vrhost/src/main_r23.cpp:1530-1562,1601-1685` separately constructs the LOCAL-fixed **menu** from captured desktop/game-window client and UV: intersects both eyes' tangent FOV, uses physically sampled `c.sourceWidth_ * whole.w` and `sourceHeight_ * whole.h`, keeps wide selector uncropped, and changes title/main-menu crop UV and optical aspect together. The source's `imageMatteVerified=false` is a policy constant, not pixel proof. `main_r23.cpp:1686-1736` centers menu on the asymmetric optical ray, conditionally stabilizes uncropped selector height, and emits per-state `VR MENU ASPECT` diagnostic values. None of those host menu UV decisions is a guarantee that a game-side native XYZRHW HUD physical Draw used the same source rectangle.
7. **Final frame identity is yet another boundary.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-815` requires valid world evidence, duplicated draws, same pose and no right/restore failure before composed stereo and successful native `Present`; otherwise emits fallback/mono as appropriate. `vrhost/src/main_r23.cpp:2927-3004` selects only eligible producer generations and may use latest-frame-wins DirectGPU. `main_r23.cpp:3562-3618` distinguishes the intended projection layer from **intercepted actual** `xrEndFrame` submitted frame ID/layer; cached menu projection and gameplay stereo cannot be conflated. A correct game screen-space transform alone does not certify binocular Quest3 pixels.
