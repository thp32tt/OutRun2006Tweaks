2. **The bounded asymmetric tangent affine is a candidate gate, not an optical assertion.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30BuildEyeAffine:2414-2449` computes left/right tan FOV, average tangent interval and individual scale/offset; it rejects invalid/too-large ratios. `R30PrepareXyzrhwState:2492-2543` additionally requires live fixed-function/XYZRHW FVF, nonempty finite D3D9 viewport, latched pose and a matching world-frame pose sequence. The input viewport need not start at (0,0): `R30TransformXyzrhwVertices:3427-3490,3690-3780` transforms physical XYZRHW pixels with `(x - viewport.X) / viewport.Width` and similarly Y; no global raw desktop-to-XR equality is assumed.

4. **R62 has another physical format and its own state boundary.** `R62TryFixedFunctionSpriteIndexed:5126-5310` admits only semantic-proven HUD/projected marker, backbuffer, live VS=null, indexed TRIANGLELIST FVF=0x142 and valid pose/viewport. For exact screen HUD it builds the same `hudClipX/Y/W` into a clip matrix, postmultiplies the original D3DX fixed-function projection per eye, executes left and right indexed DIP and restores original projection. Projected rank/rival takes separate anchor delta; do not conflate them with result HUD. `R30ExecuteXyzrhwStereo:3830-3945` separately restores RT/depth/viewport after the right draw, marks a bad right eye or restore incomplete, but returns left HRESULT: left S_OK alone is **not** bilateral proof. `R30TryScreenSpaceFovDraw:4887-5110` owns the shader/c64 alternative and aborts unsafe WVP/right-state paths. A failed route may revert to original/R29/R26 conservative dispatch and must not be assumed repaired.
