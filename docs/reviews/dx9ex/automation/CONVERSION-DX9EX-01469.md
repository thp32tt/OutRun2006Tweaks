## EVIDENCE — confirmed code distinctions, prior REA, known negative experiment

1. **Original producer and eventual actual Draw must not be conflated.** Archived `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:5-39` records +TIME six original x86 CALLs and four distinct 0x42D710 SpriteNode branches: type0 D3DX Draw (possibly deferred to Flush/End), type0 direct UP, type1 animation primitive and type1 masked/composite; this is *historical REA*, not a new disassembly. `src/vr/game/render_semantics.hpp:1420-1431` carries exact effective semantic and queue node+epoch when queued. F11's external ImGui indexing is not proved to pass through the original SpriteNode queue; separately require the physical DIP and F11 producer scope, not an invented D3DX queue owner.
2. **R30 general shader/c64 HUD deliberately leaves the game's scissor unchanged, with prior negative evidence.** `src/vr/d3d9/stereo_renderer_r30.cpp:8131-8147` obtains the saved viewport from R29 tracked state/live getter, then explicitly says a *prior runtime test at 7081b389 ruled out per-eye scissor remapping* for that path; no per-draw GetScissorRect or SetScissorRect is performed. `:8150-8185,8265-8343` uploads separate L/R c64, performs actual left/right native draws, switches right RT/depth, restores viewport/original c64 and publishes completion only with successful second draw+restore. Thus R33/R22 restoring scissor is not equivalent to *spatially transforming* a scissor; in this route the unchanged original scissor is the intended boundary, not a newly proven bug. The older negative experiment is not independently replayed in this task.
3. **A dormant generic helper is not an active per-eye clipping transformation.** `src/vr/d3d9/stereo_renderer_r30.cpp:2606-2651` defines `R30TransformHudScissor`, mapping a stock RECT about the current viewport centre by scaleX/scaleY and offsetX, clamping to current viewport bounds. A full-file symbol/use inspection of this pinned `stereo_renderer_r30.cpp` found only this definition, not a call. It cannot be cited as evidence that the shader HUD route now transforms scissors. Nor is there evidence that activating this helper would improve the compiled R26+HUD baseline.
4. **Exact F11 has an independent screen-pixel/scissor policy and conservative admission.** `src/vr/d3d9/stereo_renderer_r30.cpp:3655-3744,3756-3823` is explicitly marked as the R84 split-chain F11 owner. It requires the external ScreenOverlay2D semantic, live-null VS, XYZ|DIFFUSE|TEX1, orthographic world/view/projection, disabled depth, scissor enabled, a valid viewport, and a coherent latched stereo pose. It projects **four stock ImGui per-command scissor corners** through each eye's projected matrix, perspective-divides and converts via `viewport.X/Y/Width/Height` to actual D3D9 pixel rectangles, then clamps and rejects empty/invalid rectangles. That is distinct from R30's general shader-HUD stock-scissor policy, and from using the portrait OpenXR eye-image extent as the game's viewport.
5. **F11 draw and restore order includes physical failure guards.** `src/vr/d3d9/stereo_renderer_r30.cpp:3826-3962` makes an exact indexed physical draw for left, switches RT/depth and restores current game viewport for right, uploads per-eye projection and per-eye scissor before the right draw, then restores the original projection and scissor plus RT/depth/viewport. Pre-left admission returns E_NOTIMPL if projection/scissor cannot be safely computed; right-eye failure or restore failure arms safety rather than inventing a successful two-eye result. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:2873-3189` has a related R26-safe F11 branch with separate entry conditions. Do NOT assume source comments about an R84 split-chain route prove that the immutable 0cff83cf compiled package currently uses it.
6. **R33 and R22 state ownership protects restoration, not arbitrary offscreen/game-pixel equivalence.** `src/vr/d3d9/stereo_renderer_r33.cpp:250-291` consumes the current physical draw semantic once and delegates the eligible game-backbuffer path through R32/R22 raster replay guard after pending StateBlock resync. `src/vr/state/d3d9_raster_state.hpp:11-45` tracks viewport, scissor enable and scissor rect as independently valid members. That is a guarantee sought for returning the game state after stereo/internal passes, not proof that the transformed rectangle is correct for every font atlas draw or F11 optical size.
7. **Pixel and optical evidence remain downstream.** `src/vr/d3d9/hud_1080p_reference.hpp:1-45` defines 1920x1080 *HUD reference* with scale-to-contained game canvas; it does NOT allocate a 1920x1080 GPU RT or authorize substituting eye XR extent for desktop game pixels. `src/vr/d3d9/stereo_renderer_r7.inc:1519-1559,1685-1744` gates actual final L/R and game Present; `vrhost/src/main_r23.cpp:1440-1513,3559-3593` independently chooses DirectGPU/SBS, renders D3D11 eye-array slices and submits XR. `docs/automation/reviews/DX9EX_HMD_REFERENCE_20261020_0CFF83CF.md:1-31` is a prior exact compiled Quest3 baseline with residual F11 sizing and +TIME head-lock reports, NOT a runtime observation of this HEAD or proof of a scissor cause.
