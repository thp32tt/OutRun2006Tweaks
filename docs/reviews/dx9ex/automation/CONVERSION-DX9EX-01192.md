2. **GOAL/result source geometry stays separate from front-end containment.** `src/hooks_uiscaling.cpp:89-128` explicitly keeps gameplay HUD/GOAL/+TIME out of front-end affine containment; the helper's 640x480 and widescreen math is not an automatic GOAL coordinate fix. `::ResultProgressEnter/Leave:1536-1615` and `::GoalTime_TagHelper:1858-1907` label exact GOAL/result synchronous sources and appended queue siblings. The two GOAL helpers (`0xBE020`/`0xBE150`) and original result-progress parent must remain separate. Previous 01191 source-admission asymmetry is **not** independently reproduced as a new finding.
3. **A tag is neither geometry nor a final D3DX draw.** `src/vr/game/render_semantics.hpp::CanReprojectFiniteResultHudPlane:202-221` admits only exact result/+TIME producers, while `::SelectSpriteQueueNode:1789-1837` binds queued node/consumer epoch and `::EndSpriteQueueFrame:1866-1901` bounds retirement. `src/vr/game/hud_command_batch.hpp::Ledger:12-47,74-141` retains D3DX Begin/Draw/Flush/End generation plus homogeneous owner and queued node/epoch. A source queue tag cannot establish exact original vertex-pixel space or deferred physical DrawSerial. Unknown/mixed batches use native fallback; B9200 post-CALL/+5 sites remain forbidden.
4. **Confirmed backbuffer-based gameplay HUD fitting.** In the R26+HUD source, `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30HudContainScale:1773-1796` computes uniform `userScale * OutRunVRHud1080p::ContainedScale(BackBufferDesc.Width, BackBufferDesc.Height)` when the 1080p reference option is on, intentionally avoiding an earlier double/asymmetric HUD aspect correction. `::R30BuildHudPlaneCoefficients:2731-2777` uses that scale, game base-projection terms and current per-eye HUD view-projection to produce `hudClipX/Y/W`; `::R30ConfigureXyzrhwWorldEffect:3215-3291` explicitly checks latched head/eye pose sequence and, for exact result producers, calls `BuildStageEyePoses` to include per-eye orientation/cant. No direct original `Game::screen_resolution` or `D3DVIEWPORT9` dimensions are validated as equal to `BackBufferDesc` inside `R30HudContainScale`.
5. **Confirmed live-viewport pixel conversion is a distinct basis.** `::R30PrepareXyzrhwState:2493-2543` accepts only no-VS, XYZRHW-position FVF with valid live `GetViewport`, stereo pose and FOV; `::R30TransformXyzrhwVertices:3428-3460,3705-3789` derives NDC from `(vertexXY - viewport.XY)/viewport.WidthHeight` and maps per-eye projected coordinates back through the **same live viewport**. For valid `ScreenHud` it applies the `hudClipX/Y/W` plane map. These are distinct inputs from the backbuffer dimensions used for optional HUD 1080p fitting. The code intentionally supports different source/game/viewport/XR sizes; a mismatch is not automatically a defect.
6. **R62 fixed-function XYZ is not XYZRHW and must not be globally merged.** `::R30IsExactResultHudDraw:3073-3083` requires exact physical command owner, plus valid queue node/epoch if queued. `::R62TryFixedFunctionSpriteIndexed:5135-5310` accepts only `D3DPT_TRIANGLELIST`, live null VS and exact `FVF 0x142`, live viewport/pose and valid finite HUD state; it forms a projection-space `clipMap` and post-multiplies D3DXSprite's **original projection** for two physical indexed-eye draws. It does **not** reinterpret the original XYZ mesh as a raw XYZRHW pixel quad. `::DrawIndexedPrimitiveDestR30:5377-5461` tries external ImGui first, R62 next, XYZRHW then R29/original; `::DrawPrimitiveUPDestR30:5464-5488` has its own physically distinct UP route. The logged `RESULT_HUD_REJECT` is `R62_ONLY finalRoute=UNDETERMINED`, not proof of optical failure.
7. **Binocular commit, restore and host extent are independent checks.** `::R30ExecuteXyzrhwStereo:3829-3945` draws left then sets right RT/depth/live viewport, detects right-eye and restore failure and keeps world-stereo authority distinct from HUD duplicate counts. `::R62TryFixedFunctionSpriteIndexed:5290-5307` restores the original projection and arms fail-closed fallback on failure. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-818` only accepts the **frame** when world-stereo, duplicate draw, right-eye, pose and transport criteria are satisfied; otherwise it uses mono/SBS/DirectGPU fallbacks and checks real Present HRESULT. In the x64 host `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513`, a direct shared eye uses full UV per eye whereas SBS halves the source UV, then renders each XR projection slice using `projection_.width/height`, which need not match game/backbuffer logical pixels; `::xrEndFrame:3562-3599` is final submission. An OpenXR submitted frame is not a sampled proof that one GOAL glyph was correct in both eyes.
