## Producer → semantic → queue → terminal D3D9 → R30/R62 → L/R → restore → Present/OpenXR (static simulation only)

1. **Original producer / visibility decision, before physical draw.** `pmt_node_culling_contract.hpp:7-21` maps original EXE+0x5015 CALL `render_node_visible_404b00` and EXE+0x501D `TEST EAX,EAX` to an original scene PMT visibility gate; offset names and compatible stock bytes are explicit, but this review did not fresh-disassemble the EXE. `hooks_graphics.cpp:1661-1672,1856-1903` installs the matching before-CALL and after-CALL hooks with signature validation and after-hook first; no B9200 post-CALL/+5 hook is involved. The original game may discard a PMT node **before** any drawable primitive exists. This stage is CPU culling, not a semantic proof that a particular visible draw used DIP, DP, UP or D3DX.
2. **Scoped CPU matrix and restore.** `hooks_graphics.cpp::BeforeVisible():1767-1805` validates gameplay, mode 1, projection address and finite perspective `_11/_22/_34/_44`; it copies original `0x0095D8A0` projection, lowers the positive perspective `_11/_22` via `min(original,1/tan(wideFov))`, sets `_31/_32=0`, and marks TLS `saved.active`. `AfterVisible():1807-1834` restores saved CPU bytes before reading the original EAX; mode 2 forces visible; mode 1 fail-opens EAX if no safe scope. There is no broad draw-time/render-WVP matrix mutation by this code. The `saved` slot is one-deep; whether this exact native callsite reenters was **not established** and is not separately claimed as a new defect.
3. **New precise FOV-envelope limitation.** `GetWideFov():1722-1755` requires a valid latched frame/pose sequence, checks each eye FOV finite and ordered, then computes `max(abs(left),abs(right))` and `max(abs(down),abs(up))` across two `frame->eyeFov` entries. It adds 0..15 degree user margin and caps to 1.48 rad, without reading any left/right eye orientation, world camera relation or origin/parallax. When `saved.active=true`, `AfterVisible` trusts original EAX (not the later native stereo geometry). **Illustrative mathematical counterexample, not a measured Quest 3 setting:** each eye has +-45 degree horizontal FOV, one eye is rotated 10 degrees outward relative to cull camera, margin=0 and original half-FOV=40 degrees. The code expands CPU half-FOV to 45 degrees, whereas the rotated outer ray is 55 degrees. A PMT object on that outer ray can be culled at CPU level despite being visible to that eye, conditional on the game's original node test and pose geometry. Separate accepted-angle boundary: eyeFov 1.50 rad passes the <1.56 validation but is capped to 1.48, so this function alone does not guarantee a mathematical enclosure even without cant. **Real HMD angles, stage visibility, pose transforms and default margins were not observed.**
4. **Other edge-culling path is not this source.** `hooks_graphics.cpp::ScreenEdgeCullFix::destination():1614-1651` invokes original `CalcBall3D2D` then may rescale X/Y based on `Game::screen_resolution`; `stage_edge_cull_projection.hpp::CorrectBallProjection():16-41` validates finite, nonzero source aspect and preserves the original sphere on invalid Reset/minimized source. It affects spherical source-screen edge coordinates rather than PMT node visibility EAX. Game source/backbuffer (historically 3440x1440) is not XR eye texture (historically 2496x2688). Neither may be silently substituted for PMT eye pose; historical extents are not proof for this SHA.
5. **Only survived producer can enter queue/physical draw.** REA `OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-51` maps original scene dispatch, priority queue `0x0042D710`, deferred D3DXSprite Draw `0x0042A0A0` to End `0x00429F60` for sprite sources and separate immediate native DP/DIP/DPUP/DIPUP for other sources. On a terminal draw the source semantic/queue node and exact API must independently be measured. ## Facts, falsification and negative regression boundaries

- **FACT (static):** a mode-1 successful CPU PMT scope uses original per-eye local FOV angles but no eye orientation/origin in its union computation; cap and mode-1 EAX behavior above follow directly from code. **NOT PROVEN:** real Quest3 FOV, eye cant, headset optics, any clipped stage object, a net performance gain or observed stall. The FOV-rotated example shows insufficiency of a general guarantee, not a repro.
- **H1 (UNPROVEN visual):** fast cornering or head movement can cause a world PMT mesh visible in one eye to be preculled by original CPU source before R30. **Falsify on same installed DLL and same-frame original PMT call** if eye-pose-transformed full frustum plus PMT sphere bounds remain entirely within the scoped conservative cull envelope, or if original EAX returns visible for the suspicious objects under the recorded pose and mode. Track original PMT node ID/center/radius, EAX, actual cull matrix, both eye rays, absolute pose/camera basis and native L/R GPU survivor IDs; no unsafe live hook without separately authorized source change.
- **H2 (UNPROVEN performance):** a requested mode-2/full fail-open or large margin may increase drawn/processed world nodes and push CPU/GPU tail latency in dense stages. **Falsify** with same-resolution, same-SHA controlled mode 0/1/2 A/B, identical quality/eye texture/motion, native surviving node count, D3D9 draw calls, R13 D3D9Ex copy, host D3D11 fence/wait, actual xrEndFrame and p95/p99. Static `scoped_calls` and `fail_open_calls` are not frame-level GPU cost.
- **H3 (UNPROVEN control):** a nested same-callsite visibility traversal could exercise the single TLS `saved` slot and early `RestoreScopedProjection`; not evidence that recursion occurs. **Falsifier:** original x86/REA call graph plus runtime bounded call-depth demonstrates no in-flight repeated 0x5015 invocation until 0x501D restoration.
