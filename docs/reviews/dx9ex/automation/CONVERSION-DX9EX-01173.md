## REVIEW_SCOPE — source producer → semantic/queue → actual GPU API → R30 or lower R26/R23 → left/right → restore → Present/OpenXR

1. **Original producer ambiguity, distinct from lens.** Checked-in historical REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-45,74-92,103-123` identifies main frame dispatcher `0x00449050`, queued sprite consumer `0x0042D710`, deferred kind-0 `ID3DXSprite::Draw→Flush/End` versus native kind-1 `DrawPrimitiveUP`, and explicitly says some original scene callbacks are indirect with unresolved GPU-owner attribution. This is checked-in secondary disassembly analysis, NOT freshly decoded original EXE evidence. **Neither an assumed D3DX batch nor SceneEffect label may be assigned to the base sky absent actual physical draw provenance**. A scene callback may be direct and not queue-owned.
2. **Separate lens sources confirmed in code.** `src/hooks_graphics.cpp::VRLensFlareProjected2D:548-565,628-650,660-745,754-783` marks the exact C993 centre object `0x570002` conditionally `WorldBillboard`, while the separate CABE producer uses `ProjectedScreenEffect2D`. These scope guards do **not** identify a base-sky shader draw. The original `SceneEffect` scope referenced by R30 is separate from the plugin-owned `R30DrawSkyGlowPass`. `src/vr/game/render_semantics.hpp:906-916,998-1027,1083-1101` gives queued exact ownership precedence and excludes `SceneEffect` and projected screen effects from the first HUD cutoff. An untagged stage-sky draw must not inherit C993/CABE ownership or a queued sprite node/epoch by similarity of glow, alpha or shader.
3. **R30 classification and c64 provenance.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30ExactSceneEffectScope:1916-1921` admits exact `SceneEffect` or `ProjectedScreenEffect2D`; `R30GetExtendedRawWvpForExactSceneEffect:1923-1947` requires an original game c64 write with the **same shader identity and shader serial** and bounded top-level draw age. `R30ClassifyScreenSpacePass:2133-2148,2227-2285` refuses unknown alpha/untagged draws, and for an admitted exact scene effect first requires perspective projection and game-owned raw WVP, then splits `SpatialBillboard→WorldBillboard`, `FlatHud→PerspectiveHud`, otherwise `None`. These are source-defined admission rules, **not proof a stage-one sky shader physically reached the branch**. A reused shader signature or bright texture alone cannot establish it.
4. **Different possible GPU paths and refusal boundary.** Four physical GPU entrypoints `DrawPrimitiveDestR30`, `DrawIndexedPrimitiveDestR30`, `DrawPrimitiveUPDestR30`, `DrawIndexedPrimitiveUPDestR30` in `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:5339-5518` call `ConsumeForDraw` and dispatch F11/R62 (DIP only), XYZRHW (when eligible), then `R30GuardScreenSpace`. `R30TryScreenSpaceFovDraw:4876-4957` requires an exact recognized semantic, source matrix, live stereo/pose/depth gates and buildable eye constants. `R30GuardScreenSpace:5103-5113` sends `E_NOTIMPL` down the installed **R26 lower hook**. It is incorrect to infer mono, source failure, or the R84-only R29 route from an R30 refusal alone.
5. **Lower R26 world path.** In `src/vr/d3d9/stereo_renderer_r26.cpp::R28CanRebindVerifiedWorld:435-524` a shader epoch-rebind candidate needs a verified original perspective game matrix, matching projection and latched pose, and refuses unsafe RT/occlusion conditions; `R27GuardWorldEffect:637-711` tries that gate or captures original effect state before a conservative R13/R23 fallback. The exact C993 centre has its own rejection rule, but this does not authorize projecting an indirect base sky as C993, CABE or fixed-function SkyRotationOnly. `R30BuildScreenSpaceEyeConstants:4490-4768` constructs two WVPs only after the route is proved; a `WorldBillboard` transforms stock WorldView with head inverse, eye orientation/offset and per-eye projection, whereas a `PerspectiveHud` uses a distinct finite-HUD correction. An incorrect family could produce optical divergence even if both draws succeed, but **the current base-sky family is unobserved**.
6. **Physical eye/transport end.** When R30 accepts a shader draw, `R30TryScreenSpaceFovDraw:4971-5055` uploads left WVP, executes left physical draw, switches right RT/depth/viewport, uploads right WVP, draws right, and restores RT/depth/viewport and original c64; failures poison the frame. A lower R26/R23/R9 route has its own world/fragile rules, not a guaranteed identical R30 result. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-822` requires frame world/duplicate/pose and successful original Present for stereo publication. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:267-319` validates two-eye copy/fence and SafeFrameId, while `vrhost/src/main_r23.cpp:3555-3615` separately records actual `xrEndFrame` submission. None provides pixel-level attribution for the base sky without matching physical draw and HMD capture.
7. **Negative field control, not proof of source.** `docs/automation/reviews/DX9EX_R26_QUEST3_FIELD_3RUN_SUN_HUD_F11_20261021.md:8-13,38-55` reports two stage-one suns even in a capture where exact C993 object `0x570002` was suppressed. This falsifies **C993 centre alone being a sufficient universal explanation** for that observed run. It does NOT positively identify base sky, CABE, SkyGlow, a different original light, parallax/cant, a duplicate draw, or an old lens image. Those runs differ in SkyGlow factor/MSAA and are not a same-condition optical route experiment.
