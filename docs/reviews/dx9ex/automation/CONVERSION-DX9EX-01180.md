4. **Producer ring allocates an independently selected physical slot.** `src/vr/d3d9/stereo_renderer_r7.inc::ResolveDirectTransport:1358-1426` chooses a free one of four slots, copies L/R with `StretchDirectEye`, issues an `IDirect3DQuery9` EVENT, sets `producerPending=true`, `pendingFrameId=frameId`, `frameId=frameId`, and **`published=false`**. On the next scan, a completed pending slot with `!published` is explicitly reclaimed **without host ACK**; the host-consumed-frame check protects only `slot.published && slot.frameId` slots (`:1368-1409`). That branch presumes an unpublished completed image was never offered to the host.
5. **R7's explicit post-Present producer fence transition.** `src/vr/d3d9/stereo_renderer_r7.inc::DirectTransportFrameReadyAfterPresent:1428-1453` polls with a maximum one-millisecond, non-FLUSH EVENT wait; success clears `producerPending/pendingFrameId` and sets **`slot.published=true`**. Its old `PresentDest:1694-1727` invokes the helper before final `StereoSbsActive` direct publication; failure retains the quarantined slot and does not advertise it as successful direct stereo. The 1 ms window is a *coded limit*, not an observed delay or a guaranteed GPU completion time.
6. **Different R9 post-Present path, the distinct finding.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:703-812` invokes `ResolveDirectTransport`, publishes an in-flight descriptor, calls original `Present`, normalizes HRESULT, and on `composedStereo && SUCCEEDED(hr) && !FrameStereoIncomplete` publishes `StereoSbsActive` with `directTransport=true`. In the inspected complete R9 function there is **no `DirectTransportFrameReadyAfterPresent` or equivalent transition to `slot.published=true`** between `ResolveDirectTransport` and active publication. `PublishRenderFrame` in the included R7 source `:1491-1494` serializes active shared handles/generation/slot from the selected transport but does not itself mutate the producer slot's `published` flag. The R9 source's post-Present HRESULT alone is therefore not a source-level proof of that producer-fence and ACK-ownership transition. This contrast is not a claim that a Quest3 frame visibly tore or even exercised DirectGPU.
7. **Host/eye delivery is a separate stage.** `vrhost/src/main_r23.cpp:2940-3070` has R41 latest-complete-frame selection and selective skip-ACK of older unsampled frames within the same run/generation; host ignores in-flight descriptors. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp::R32OpenSharedSlot:100-203;::CopySharedFrameToSafeEyesR32:252-315` validates shared resources, submits D3D11 `CopyResource` for both eyes, waits for a *host-side* copy fence, acknowledges, then swaps the inactive pair and advances SafeFrameId. The host-side fence cannot by itself demonstrate that R9 marked the **producer-side** D3D9Ex slot published or protected it from next-frame reuse. A later verified pair is projected and submitted through `vrhost/src/main_r23.cpp:3555-3615` `xrEndFrame` independently; no actual host overlap/tearing was sampled.
