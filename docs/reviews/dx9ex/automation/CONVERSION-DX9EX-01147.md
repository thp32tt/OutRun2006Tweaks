1. **Three separate coordinate authorities (confirmed):** `src/vr/ui/vr_logical_coordinate_space.hpp:1-43` defines the original 640x480 logical grid with a contain transform whose inputs are *game render* dimensions and explicitly not XR extent. `src/hooks_graphics.cpp:2245-2300` uses `Game::screen_resolution` for the game source and separately fits only the borderless Win32 mirror window to the monitor; mirror dimensions need not equal game source or XR eye pixels. `src/vr/ipc/xr_eye_extent.hpp:12-86` bounds the host's **shared per-slice** OpenXR extent and refuses invalid/mismatched startup/published game targets rather than substituting desktop width.
2. **Producer -> queue -> actual API, not semantic-only promotion:** checked-in original REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:29-89` identifies original stage/priority queue `0x00449050/0x0042D710`, kind-0 ID3DXSprite `0x00429C60/0x0042A0A0`, and deferred `Flush/End` at `0x00429F60`; kind-1/flagged glyphs may instead use native UP. Different +TIME glyph, result/GOAL and vehicle-rank parents must not be collapsed. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:3063-3072,5370-5455` consumes draw semantics and tries external F11 ImGui first (exclusive), then R62 kind-0, then XYZRHW and native/R29 fallback. The exact result predicate checks original batch admission or live queue node+epoch. This establishes possible **code route**, not a confirmed post-resize physical Draw.
3. **Narrow R62 admission condition:** `stereo_renderer_r30_r26_safe.cpp::R62TryFixedFunctionSpriteIndexed:5116-5180` requires triangle-list, `TargetIsBackBuffer()`, `R30SafeStereoBase`, a positively corroborated projected-world-marker or HUD scope, a live null vertex shader, exact FVF `0x142`, `EnsureStereoResources`, successful `GetViewport` and nonzero `viewport.Width/Height`, current latched stereo pose and valid per-eye FOV affine. It does **not directly compare** `viewport.X/Y/Width/Height` to `BackBufferDesc`, the current game logical-contain viewport, host allocated XR extent or a resize generation **inside this routine**. The absence of a local comparison is confirmed; it is **not** evidence that D3D9 accepted an invalid viewport or that upstream `R30SafeStereoBase/EnsureStereoResources` lacks equivalent protections.
4. **Scale/projection ownership is not one shared dimension:** `stereo_renderer_r30_r26_safe.cpp:1763-1785` feeds `BackBufferDesc.Width/Height` (not `state.viewport`) into `OutRunVRHud1080p::ContainedScale` when enabled; `src/vr/d3d9/hud_1080p_reference.hpp:1-40` says this is a *uniform game-backbuffer reference* and not an XR allocation. `R30BuildHudPlaneCoefficients:2718-2775` applies common uniform scaling to the finite world-locked plane, and `R62TryFixedFunctionSpriteIndexed:5180-5288` post-multiplies original D3DX projection with an independent projected-marker clip shift or the `hudClip*` per-eye matrix. Each path can be appropriate with nonzero eye cant; a mere source-pixel or FVF identity cannot establish placement correctness after resize.
5. **Eye viewport/restore and bounds of this finding:** `R30ExecuteXyzrhwStereo:3820-3935` draws left, temporarily switches right RT/depth, restores `state.viewport` on right, then calls `RestoreRightPassState`. `R62TryFixedFunctionSpriteIndexed:5263-5321` separately restores **original projection** and on failure records a restore failure and arms safe fallback. Its result HUD telemetry records the original viewport and L/R HRESULT, but not the game-source/logical-viewport/XR allocated-generation tuple. In contrast, `stereo_renderer_r22.cpp::R22GameClearCoversBackbuffer:473-501` positively checks a full-buffer viewport for a **different clear/depth-seed contract**; its stricter check must not be blindly imposed on every sprite draw, since valid viewport-limited draws can exist.
6. **Actual downstream frame identity is gated, not presumed:** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-805` requires world stereo, duplicated draw, no right-eye/frame failure, valid frame pose and resources, otherwise restores mono if possible; it publishes successful stereo only after physical Present. `vrhost/src/main_r23.cpp:2585-2636` resolves common startup allocated eye extent from both runtime view recommendations/maxima, publishes it, and fails if compositor allocation differs. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:253-322` validates paired shared-eye descriptors and promotes `SafeFrameId` only after completed fence/copied eyes; `vrhost/src/main_r23.cpp:3559-3605` checks actual `xrEndFrame`/submitted layer identity. These checks can reject a failed or stale frame, but **do not prove** every successfully submitted sprite had the intended optical size/placement.
