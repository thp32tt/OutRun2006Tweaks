## Producer -> semantic -> queue -> D3DX / native final draw -> R30/R62 -> L/R -> restore -> Present/OpenXR

1. **Game and REA source family.** The checked-in original disassembly report maps `0xCF4E -> Calc3D2D`, `0xD3A0` object `0x570002`, `0xD3A5 -> C980 -> C993 -> DrawObjectAlpha_Internal`; separate outer `0xD5F5..D796 -> C9A0 -> CABE`. That report does not establish one-to-one correspondence between a visible sun pixel and either native GPU draw. REA original sprite-priority consumer `0x0042D710` can defer D3DX physical execution from Draw `0x0042A0A0` until End `0x00429F60`, whereas other sprites/alpha/effects can use direct D3D9 DP/DIP/DPUP; a SceneEffect scope is **not proof** that its draw is a deferred queue node.
2. **Camera/semantic lifetime.** `hooks_graphics.cpp::FixZBufferPrecision::CalcCameraMatrix_dest():1985-2060` differentiates short near plane from cockpit/world view. `Clr_SceneEffect_dest():2063-2110` saves the previous near plane and suppression flag, scopes the original callback under `RenderScope::SceneEffect`, requests 0.05 near plane, then reconstructs previous world view after the nested effect returns. `driver_seat_render_pass.hpp::RunSceneEffectThenRestoreView()` uses a TLS depth guard to keep driver-seat offset out of nested effects. This is a CPU camera *scope transaction*, not itself final c64 upload or per-eye GPU ownership proof; its nested restoration must be kept intact.
3. **Queue/provenance boundaries.** `render_semantics.hpp` uses TLS effective scopes and separately tagged queue nodes; queued D3DX scope/epoch and direct SceneEffect scope differ. `scene_effect_wvp_provenance.hpp::OwnsOriginalWorldWvp():20-43` explicitly requires same SceneEffect written/current scope, identical producer, same nonzero pose epoch, identical shader+epoch, bounded forward draw serial <=12, and either identical nonzero queue node/epoch or both queue node pointers null in direct mode. This is an existing defensive *contract*, not proof that it is enforced at every current Draw site.
4. **CONFIRMED active-gate gap.** `stereo_renderer_r30_r26_safe.cpp::R30ExactSceneEffectScope():1917-1921` admits SceneEffect **or** ProjectedScreenEffect2D; `R30GetExtendedRawWvpForExactSceneEffect():1923-1948` checks source game raw write and same current shader/epoch then merely `0 < currentDraw - writeDrawSerial <= R30ExactHudRawWvpDrawWindow`. The shared window is **128** (`:1801`), not the helper's 12. It does not query `GetLastGameWvpSemanticProvenance`, producer, queue identity/epoch, or latched pose (contrast `R30GetExactLensCentreRawWvp():1992-2029` and strict helper). The inspected R30 file has no `OwnsOriginalWorldWvp` invocation.
5. **Physical classification and actual owner still conditional.** `R30ClassifyScreenSpacePass():2250-2284` first tries `R44GetOwnedRawOverlayWvp()` with a separate 12-draw shader-age test, then the weaker 128-draw SceneEffect gate. A successful raw WVP may classify as `SpatialBillboard` or `FlatHud`; `R30BuildScreenSpaceEyeConstants():4554-4600` also calls the SceneEffect gate for per-eye original c64 restoration. A class label is not a final native API, texture, scene object, or actual L/R submission. R62 fixed-function FVF0x142/null-VS indexed Draw is an independent *possible* queued sprite route; direct C993/SceneEffect must not be silently described as R62 DIP.
6. **Depth / viewport / state / eye gates.** `R30TryScreenSpaceFovDraw():4877-5114` requires live per-eye resources, depth/stencil right-eye synchronization, pose and finite WVP; handles left/right native API calls and restores RT/depth/viewport/original c64.
