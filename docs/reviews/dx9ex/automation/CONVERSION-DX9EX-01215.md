## Source/REA/semantics and timing-boundary walk

1. **Producer-to-physical distinction remains a prerequisite, not this task's new optical finding.** The checked-in original-executable REA audit `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:6-43` records six +TIME E8 sites (RVA 0x9898E/0x989AD/0x98A10/0x98A36/0x98A89/0x98AC6), original `0x449050 -> 0x42D710` queue and four original GPU consumer families `0x42A0A0` (D3DX), `0x42C0F0` (direct UP), `0x42A3A0` (animation quad) and `0x42A800` (masked/composite). `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1837` binds node/producer/epoch and `EndSpriteQueueRender:1840-1865` does not prematurely retire partial priority pass tags. `src/hooks_uiscaling.cpp::BeginDest,FlushDest:3397-3465` preserves native deferred D3DX batch ownership, including mixed/unproven vetoes. The selected physical DIP/UP and DrawSerial of any particular +TIME/GOAL glyph remains **unobserved** here: counting producer calls is not counting GPU draws or GPU time.
2. **Physical stereo is a gate before copy, not latency proof.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30ExecuteXyzrhwStereo:3829-3945` draws left, binds the right RT/depth/viewport, draws right, restores previous state and poisons a frame on failed right draw/restore despite the left HRESULT return. `R62TryFixedFunctionSpriteIndexed:5126-5190` instead admits only live no-VS FVF=0x142 indexed sprite with positive HUD/projected owner and valid stereo context; an unproven draw retains its original/conservative path. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-811` requires completed world stereo, duplicated draw, valid pose, success of native Present and transport/fallback policy for a completed Frame.v2. This does not assert Quest3 stereo quality, selected consumer identity or identical L/R GPU duration.
3. **D3D9 producer copy/event and finite wait have separate semantics.** In `src/vr/d3d9/stereo_renderer_r7.inc::EnsureDirectTransportResources:1353-1355,::ResolveDirectTransport:1357-1427`, each free 4-slot shared-eye target receives two `StretchRect` copies then a producer D3D9 EVENT; slots with pending fences or un-ACKed published frames cannot be blindly overwritten. The base `PresentDest:1645-1740` only marks a DirectGPU frame complete after successful native Present **and** `DirectTransportFrameReadyAfterPresent:1428-1455` (no-FLUSH `GetData`, bounded 1 ms). A timeout quarantines that frame pending a future ring scan; the call does **not** spend an unbounded 4 ms waiting, guarantee the next GPU free slot, or measure a full graphics pipeline duration. In the R13 overlay `ResolveDirectTransportR13:220-373`, per-slot host GPU-complete ACK is checked **before** reuse, and outstanding producer EVENT must separately pass; query/copy hard failures reject rather than silently recycle. Preserve both independent ownership proofs. The alternate R9 hook path and base hook must be identified by installed build/profile before attributing runtime timing to either code route.
4. **Host selection is latest-eligible, not FIFO.** `vrhost/src/main_r23.cpp:2930-3095` in DirectGPU-only mode scans Frame.v2 history and uses `OutRunVrDirectRingLatest::Pick` to choose the newest completed transport-generation frame; older, unsampled frames of the **same** run can receive skip ACK without D3D11 sampling, while a selected frame is protected by later GPU completion. Invalid/in-flight/stale-run generations do not become a new source merely because their frameId or slot index is present. Dropped source frames and 'projection-cached' XR ticks can therefore be an intentional *freshness/latency* tradeoff, not automatically an FPS decrease or incorrectly owned eyes.
5. **Host copy and eye submit are ordered but asynchronous.** `vrhost/src/main_r23.cpp::R23StageDirectHold:550-638` allocates host-owned L/R D3D11 hold textures as necessary; each newly identified immutable producer frame issues exactly two `CopyResource` calls, and same complete source identity can reuse the hold without a second pair. Host `main_r23.cpp:3170-3366` commits the candidate only after validation, defers lastProcessedStereoFrame/display-bundle authority until both projection eyes render successfully, and explicitly defers consumed ACK until R32 GPU EVENT completion after the copy+projection GPU commands. `R23RenderProjection:1440-1513` draws distinct left/right XR array-slice RTVs; only a successful pair yields a new projection. The cached-release projection path resubmits prior safe stereo when a new game source is not committed; do **not** mistake its repeat XR ticks for new D3D9 Present throughput.
6. **Clock domains and true submitted layer are separate.** `vrhost/src/main_r23.cpp:2740-2825` brackets `xrWaitFrame`, records QPC wait and wait-return interval, then performs `xrBeginFrame/xrLocateViews`; `main_r23.cpp:3562-3720` compares R24/R32 actual final-layer counters around `xrEndFrame` and records `gameRenderMs/gamePresentMs/presentToConsumeMs/hostCaptureMs/hostCopyMs/hostRenderMs/xrWaitMs/xrEndMs` together with `cached`, run generation, frameId, candidate reject reason and actual submitted frame ID. Those are **CPU/QPC/pipeline proxy intervals**; without timestamp queries and exact source-to-host-to-XR identity they are not per-effect GPU execution time, compositor scanout latency, or measured p95/p99. GPU frame content, sandbox logs and exact Quest3/VDXR frames were not provided to this task.
