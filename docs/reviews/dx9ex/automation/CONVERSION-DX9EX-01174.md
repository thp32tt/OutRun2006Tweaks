This task cannot label a particular sky sun/lens draw as R28-owned without physical evidence.
2. **Actual GPU shader tracking setter.** In `src/vr/d3d9/stereo_renderer_r7.inc:1618,1879`, `SetVertexShaderDest` calls the original `SetVertexShader` first and, only after success on the game device outside internal passes, updates `CurrentVertexShaderIdentity` and increments `VertexShaderSerial` when the pointer differs. `GetCurrentShaderEpoch` reads the serial around the identity. The two atomics are **software tracking fields**; the D3D9 device's actual shader binding is a separate hardware/API state. Internal passes are specifically excluded from tracking.
3. **R28 admission after shader change.** `src/vr/d3d9/stereo_renderer_r26.cpp::R28CanRebindVerifiedWorld:435-524` requires active game backbuffer stereo/seed, no auxiliary target/forced-mono/unsafe occlusion, nonzero tracked shader, perspective-world semantic, verified source WVP and pose generation/sequence, valid current projection and live c64..c67 numerically matching the verified WVP. Crucially it returns false when current tracked `(shader identity, serial)` already equals the verified pair; the path explicitly handles a **different** tracked epoch. These guards prove a bounded matrix/pose agreement, not that an entirely different physical vertex shader interprets c64 identically.
4. **Distinct NEW state boundary: tracked epoch is substituted without rebinding the live D3D9 shader.** `R28RunWithVerifiedWorldEpoch:527-584` calls `CurrentVertexShaderIdentity.exchange(verifiedIdentity)` and `VertexShaderSerial.exchange(verifiedSerial)`, invokes `r9Draw()`, then independently attempts CAS restoration of the two tracked values. No `device->SetVertexShader(verifiedShader)` occurs in this function. A comparison build may intentionally permit continuation across a shader switch, but the verified *software epoch* at `r9Draw` does not establish what vertex shader the GPU currently executes. This is a source-proven state/identity separation, **not proof of shader incompatibility or visual failure**.
5. **Why eye acceptance can differ from physical shader provenance.** `src/vr/d3d9/stereo_renderer_r7.inc:929-960` (world eye-constant build) requires the current tracked identity/serial to equal the last verified WVP owner and live c64 to equal the verified values, then derives per-eye WVP from projection and latched left/right eye orientation/translation. By substituting the verified tracked pair, R28 can satisfy this *software identity* check even though the real device binding remains the newer shader. The original physical draw still executes through its actual DrawPrimitive/DrawIndexedPrimitive/UP API and whichever shader is bound. If both shaders share the same c64..c67 WVP convention this may be correct; if not, per-eye constants could target a different shader register interpretation. Neither outcome is observed here.
6. **Lower route and restoration.** `R27GuardWorldEffect:637-711` tries the R28 verified epoch continuation first when GPL shader tracing is off; otherwise captures one draw-time effect snapshot, uses existing R13 fallback or a separate guarded perspective-effect path. It never authorizes a generic queue HUD or all alpha effects. In the compiled R26+HUD stack, `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:5349-5523` consumes the physical semantic and may own qualified XYZRHW/R62 or shader HUD passes before declining to its lower installed hook. R28's independent CAS pair is intended to restore tracking; it is not a D3D9 shader, c64, RT, depth or viewport restore. Those physical left/right and restore operations are separately guarded downstream by R7/R9. A nested setter changing one tracked field during the synthetic epoch would require a separate same-thread/serial trace before asserting any torn-epoch consequence.
7. **Frame delivery remains an independent gate.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-822` requires seeded stereo, world + duplicated draw, valid right-eye/pose/resource conditions and successful actual Present for publication. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:267-319` waits for both GPU eye copies before advancing SafeFrameId. `vrhost/src/main_r23.cpp:3555-3615` separately distinguishes actual `xrEndFrame` submission. Passing these gates does not prove a specific original sky shader generated visually correct left/right pixels or that current Quest3 optics accept the draw.
