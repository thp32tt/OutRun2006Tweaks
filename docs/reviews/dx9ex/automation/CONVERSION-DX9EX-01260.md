Registered R14 translated MANAGED textures may be `Shadow` (SYSTEMMEM CPU peer + DEFAULT GPU) or `DirectOnly`. `TextureAddDirtyRectDestR14` first calls `R14Find`; if mode is `Shadow` and `retirePending=false`, it **returns D3D_OK without invoking the original AddDirtyRect and without inspecting `rect`**. On no registry entry, DirectOnly or retirePending, it forwards the original texture-method HRESULT. This is a confirmed *return-contract split*, not proof of an illegal rectangle supplied by the game or of incorrect pixels: R14 intentionally uploads writable shadow Unlocks explicitly instead of using native dirty propagation.
4. R14 `TextureGenerateMipSubLevelsDestR14` calls the original void method then, outside `R14InternalUploadDepth`, marks an external GPU write and may retire the *whole* CPU shadow. But R15 installs an inline overlay on that R14 destination: `TextureGenerateMipSubLevelsDestR15` calls the original method trampoline and, at depth zero, `R15InvalidateGeneratedMipShadows`. For Shadow mode R15 retains level-0 validity (`validMask &= 1u`), discards lower-mip validity/dirty bits and lower-mip lock rectangles; it does **not** immediately retire an unlocked shadow. DirectOnly or unregistered textures bypass that bookkeeping. Because the underlying method is void, neither path provides a generation HRESULT.
5. R15's `lockedMask != 0` test is **texture-wide**, not only lower-mip locks: a generated-mip call overlapping a CPU Lock of *any* level sets `externalWriteDuringLock` and `retirePending`. At subsequent R15 Unlock, an overlapping Lock produces `D3DERR_INVALIDCALL`, and final Lock drain retires the shadow. Without overlap, a new CPU Lock for a generated lower mip sees its cleared `validMask` in R14 `TextureLockRectR14`, retires the unlocked shadow and delegates to original R13/direct-lock path; a level-0 Lock can still use the coherent CPU shadow. This identifies the boundary where previously retained CPU shadow stops being eligible, not proof of a runtime fallback success or performance cost.
6. For a legal Shadow writable Lock that remains valid, R15 `TextureUnlockRectR15` uploads the exact mip via `R15UploadLevel`: an UpdateSurface partial-RECT failure is fail-closed (no destructive whole-mip copy), whereas whole-mip locks may use `R14CopyWholeLevelByLock` fallback; the CPU peer is retired on upload failure. R14 `R14InternalUploadScope` protects its own exact-mip UpdateSurface from falsely appearing as an external write. Synthetic AddDirtyRect D3D_OK **does not** imply a later upload succeeded; distinguish native HRESULT, shadow Unlock HRESULT and actual sampling.
