## REVIEW_SCOPE — bounded logical simulation, not physical GPU capture

Original get_texture(mask ID) / get_texture(parent ID) before a put_sprite_ex2 CALL -> `TextureLookupWindow<void>::Observe` moves previous sprite lookup into the mask slot; a third lookup or failure can replace/clear it -> `put_sprite_ex2_dest` consumes the one-shot lookup and independently compares original parent's COM texture pointer and child_B4 mask COM pointer -> optional `ScopedSprArgs2Scale` on each argument's 8 UV values -> original native `put_sprite_ex2` (the only call seeing the temporary values) -> explicit child/parent UV restore -> exact source/producer classification and verified append-only SpriteNode tagging -> priority queue (REA 0x0042D710; partial 0x004C50A0 not yet full REA PASS) -> original type-1 masked 0x0042A800 / type-1 ordinary 0x0042A3A0 direct `DrawPrimitiveUP` or type-0 direct 0x0042C0F0, versus separate type-0 0x0042A0A0 deferred D3DX negative control -> current R26+HUD `DrawPrimitiveUPDestR30` semantic + live FVF/VS/viewport/pose gates -> accepted R30 XYZRHW finite HUD/world transform into L/R UP vertex buffers or fail-closed R29/original -> left actual draw, switch to right RT/depth/viewport, right actual draw, restore -> R7 qualified Present DirectGPU/SBS/hold -> host R23 two SRV/UV/eye pose/FOV/imageRects -> xrEndFrame.

The CPU UV transaction is upstream of both eyes. Independent per-eye reprojection changes XYZRHW positional coordinates of scratch copies; it is not evidence that parent/mask original DDS UVs were correctly paired, and two successful draw HRESULTs are not a texture-alignment verification. The original 0x0042A800 direct-UP mapping comes from archived REA; no newly captured raw opcodes or exact per-eye GPU commands were available.

## NEW_FINDING — source-confirmed narrow ownership window, conditional defect only

- NEW_FINDING=PUT_SPRITE_EX2_MASK_UV_PROVENANCE_SUPPORTS_ONLY_TWO_CONSECUTIVE_GET_TEXTURE_LOOKUPS_AND_ONE_NATIVE_SUBMISSION; THIRD_SUCCESSFUL_LOOKUP_CAN_EVICT_PRIOR_MASK_SLOT_BEFORE_CONSUME.
- CLASSIFICATION=CONFIRMED_STATIC_WINDOW_SEMANTICS; ACTUAL_THIRD_LOOKUP_IN_ORIGINAL_MASK_PATH=UNPROVEN; UV_MISMATCH=UNPROVEN; WHITE_SELECTOR_MASK_ARTIFACT=UNPROVEN; FPS_COST=UNMEASURED.
- Concrete sequence: `Observe(mask,maskId,true)` then `Observe(other,otherId,false)` then `Observe(parent,parentId,true)` results in `sprite=parent`, `mask=null`. `put_sprite_ex2_dest` then can scale the parent but cannot scale the child mask even if its texture pointer still equals the first `mask`. With a scaled `other`, the mask candidate becomes `other`; pointer equality guards reject different actual mask COM pointers. With exactly two expected lookups, both mask and parent can be recognized and the compile-time positive test covers it.
- Conditional visual hypothesis: if a selector uses a replaced/scale-adjusted parent + child mask and a third intervening native `get_texture` occurs before ex2, a parent-only UV adjustment might change mask/parent coverage, yielding wrong mask/white/edge pixels without an R30 stereo-state failure. This is not evidence that the original game actually issues that third lookup, that 0x42A800 uses this particular argument pair, or that the reported screen artifact currently reproduces.
- Falsifiers: original call trace shows exactly mask->parent->ex2 without intervening lookup/failure/pack switch; target mask does not have a replacement scale; the child mask mode flag is disabled; COM pointer guard intentionally rejects a foreign pack; native unmodified/modified same-SHA raster output proves equivalent source mask coverage; the relevant physical draw is not the tagged type-1 mask, or an observed mismatch originates only after optical projection. Inspect exact IDs/pointers instead of attributing a white pixel to stereo depth/stencil.
- Performance: extra UV saves/restores and a copied L/R UP payload are bounded design costs; no attributable CPU/GPU p95/p99, draw-count, memory alloc, or 72 Hz comparison measured. Do not optimize by retaining potentially stale pointers across xstset generations.
