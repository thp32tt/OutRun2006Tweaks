## EVIDENCE — source-confirmed execution / conditional boundaries

1. **Original physical API is not identical to SpriteNode type.** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:26-50` names REA-confirmed `0x42D710` queue split: type-0 normal D3DX `0x42A0A0`, type-0 flagged UP `0x42C0F0`, type-1 animation UP `0x42A3A0`, type-1 mask/composition UP `0x42A800`. `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:7-43,59-71,115-130`: original `0x417B20 -> 0x449050 -> 0x42D710`; D3DXSprite `Begin/Draw/Flush/End` can issue *later* physical GPU draws. This identifies static candidate call paths, not whether any selector mask actually sets D3D9 scissor.
2. **Selector identity and CPU-queue semantic do not confer raster-state ownership.** `src/hooks_textures.cpp::TagDirectVrSpriteNodes:980-1114` associates verified new native SpriteNodes with callsite/source semantics; `src/vr/game/render_semantics.hpp::BeginSpriteQueueRender/SelectSpriteQueueNode:1760-1836` snapshots serial cutoff, sets `SpriteQueueNodeEpoch`, and defaults unproven sprites to `ScreenOverlay2D`. `src/hooks_textures.cpp::put_sprite_ex2_dest:1118-1164` consumes parent/mask UV transaction then restores original SPRARGS before deferred physical submission (already reviewed in #01375). Neither a selector texture nor a queued node alone is an observed GPU scissor/blend state.
3. **Native UP eye geometry is transformed, but this helper does not transform native scissor.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawPrimitiveUPDestR30/DrawIndexedPrimitiveUPDestR30:5508-5571` consume semantic and first try `R30TryXyzrhwPrimitiveUP` or indexed variant, otherwise `R30GuardScreenSpace` into R29 guarded path. `::R30TryXyzrhwPrimitiveUP:3990-4031` copies transformed L/R scratch vertices and invokes the original physical `DrawPrimitiveUP` separately for each eye; `::R30TransformXyzrhwVertices:3471-3523,3740-3838` subtracts actual source viewport X/Y and maps via eye-specific NDC/projective HUD plane. Eligibility (valid XYZRHW, semantic, resource, pose) can fail and delegate elsewhere; `0x42A800` reaching this specific helper is NOT proven.
4. **The actual L/R native helper changes RT/depth/viewport, not scissor in this function.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30ExecuteXyzrhwStereo:3870-3982` calls left draw, switches `RightEyeSurface`, right depth, `SetViewport(state.viewport)`, calls right draw, and `RestoreRightPassState` for RT/depth/viewport; it neither reads `D3DRS_SCISSORTESTENABLE` nor calls `GetScissorRect/SetScissorRect`. A tightly clipped source UI rectangle *if enabled at this exact physical draw* may therefore remain in original raster coordinates while geometry moves differently per eye. This is a **source-confirmed local state-ownership split** with a **conditional effect**, not proof that scissor is enabled or that the shader/device cannot preserve a correct rectangle elsewhere.
5. **Fixed-function D3DX kind-0 has a separate admission route.** `::R62TryFixedFunctionSpriteIndexed:5171-5363` requires exact `ScreenHud` or projected-marker semantic, backbuffer, FVF `0x142`, NULL live VS and latched eyes, then changes per-eye projection for the two physical `DrawIndexedPrimitive` calls via `R30ExecuteXyzrhwStereo` and restores stock projection. Unknown selector `ScreenOverlay2D` does not automatically enter R62; an R62 rejection is **not** evidence of no right-eye GPU draw because `::DrawIndexedPrimitiveDestR30:5425-5512` retains XYZRHW and R29 fallback. As in native UP, exact physical scissor/alpha under D3DX Flush/End must be sampled separately; D3DX StateBlock or game `SetRenderState` ownership is not established by semantic alone.
6. **F11 is an explicit counterexample, not an owner of original selector sprites.** `::R30PrepareExternalImGuiProjection:2841-2992` checks the *live* scissor-enable state and rectangle, reconstructs each eye's scissor using all four corners, transformed ortho/FOV matrix and actual viewport offsets, and rejects empty rectangles. `::R30TryExternalImGuiIndexed:2994-3119` calls `SetScissorRect` per-eye and restores stock scissor and projection. F11 is external ImGui `DrawIndexedPrimitive` (exact `ScreenOverlay2D` plus world-ready gate), **not** the original kind-1 selector mask source. Its existing solution does not imply native sprite scissor needs the same transformation, nor that this F11 path is active in the default package.
7. **Frame publication cannot diagnose per-sprite clipping.** `src/vr/d3d9/stereo_renderer_r7.inc::PresentDest:1625-1734` requires world and duplicated eye evidence/pose/restore, successful original `Present` and, for DirectGPU, post-Present fence; otherwise hold/SBS/fallback. `vrhost/src/main.cpp:2700-2719` matches source frame/pose/flags and renders matched `XrView` or bounded last-safe-frame grace. Neither an eligible Present nor successful `xrEndFrame` proves both selector mask pixels survived original scissor/alpha in the intended location.
