3. **Creation-time early VB path is deliberately narrow.** `src/vr/d3d9/r30_early_rhw_shadow.hpp:5-24` accepts only positive explicit creation-time `fvf != 0 && (fvf & POSITION_MASK)==XYZRHW`; failed/external-overlay Locks are excluded. `stereo_renderer_r30_r26_safe.cpp::R30CreateVertexBufferDest:789-823` installs VB Lock/Unlock/Release hooks and, only when hooks ready, game-owned, VR enabled and explicitly XYZ/RHW FVF, registers a VB shadow and sets `createdWithXyzrhwFvf` before the caller's first Lock. `R30VertexBufferLockDest:633-657` may then observe that one VB's pre-arm Lock; Unlock snapshots bytes *before* forwarding and a failed Unlock invalidates its range (`660-675`). FVF=0/declaration-backed or nonproven world VB does **not** get this early privilege. Missing budget/hook registration is also a conservative miss, not proof of bad rendered bytes.
4. **Distinct confirmed pre-arm IB limitation.** `R30CreateIndexBufferDest:826-842` installs IB Lock hooks, but registers the new IB shadow only when `R30BufferShadowCaptureArmed` is already true. Crucially, `R30IndexBufferLockDest:696-708` tests *global capture armed* and nonexternal scope; unlike early XYZ/RHW VB there is **no creation-FVF analogue permitting a first IB Lock before the arm**. Consequently, for the bounded hypothetical sequence `CreateVB(explicit XYZRHW)→VB Lock/Unlock→CreateIB→IB Lock/Unlock→first eligible R30 DIP`, with no earlier capture arm, VB bytes can be observed while first IB bytes cannot. `R30TryXyzrhwIndexedPrimitiveVB:4261-4266` arms global capture and registers the IB shadow **after** that prior IB Lock; `4305-4314` demands a fully observed index interval and returns `E_NOTIMPL` before the stereo physical draw on an IB shadow miss. The first such DIP therefore takes guarded original/R29 rather than the R30 VB/IB stereo conversion unless independently valid earlier IB evidence exists. An IB write Lock/Unlock *after* arm can make a subsequent eligible draw convertible. This is a **static cold-start coverage asymmetry**, not a measured missing eye, GPU corruption or proof the game issues this call chronology.
5. **Second related, specific arm-placement boundary.** `R30TryXyzrhwPrimitiveVB:4153-4161` and `R30TryXyzrhwIndexedPrimitiveVB:4261-4273` both call `R30BufferShadowCaptureArmed.exchange(true)` once preparatory state/stream admission succeeds **before** desc/byte range checks (`4164-4175`, `4274-4295`), before observed shadow read (`4185-4191`, `4305-4314`), and before a successful bilateral physical GPU submission. After arm, `R30VertexBufferLockDest:639-656` and `R30IndexBufferLockDest:700-708` may snapshot nonexternal subsequent game Lock writes, not only proven HUD buffers. `R30MaxShadowBytes=16 MiB`, total reserved budget 64 MiB (`331-333`) and coverage/budget rejection (`449-503,567-631`) constrain growth, but the arm point itself does **not** certify a converted draw. The existing log wording “after a real XYZRHW ... draw” denotes an admission attempt, not necessarily completed physical stereo. This is a potential CPU Lock/Unlock churn source, with **zero quantified incidence/cost in this review**.
6. **Reset/Release and shadow freshness are independent.** `ResetDestR30:1511-1521` disarms global capture and tears down SkyGlow resources, but does not itself wipe the VB/IB registries or establish that all buffers died; Release hooks erase entries only on final reference count zero (`678-693,727-743`). `R30RollbackBufferShadowHooks:862-885` does clear registry and early flag at hook teardown. `R30BeginObservedLock/R30FinishObservedLock:506-565` preserve exactly observed valid intervals, DISCARD invalidates old intervals, and unsuccessful Unlock invalidates entries. `R30Copy*Shadow:567-631` refuses unobserved regions. 7. **L/R plus host gate.** If IB/VB validity permits R30 conversion, `R30ExecuteXyzrhwStereo:3829-3945` submits left then right with RT/depth/viewport restore; right failure/restoration poisons incomplete stereo even when left HRESULT is returned.
