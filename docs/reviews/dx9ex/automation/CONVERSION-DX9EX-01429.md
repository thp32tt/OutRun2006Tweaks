## EVIDENCE (pinned source, REA and previous reviews; static facts)

1. **Compiled owner:** root `AGENTS.md:1-5` and `CMakeLists.txt:102-108,135-148,230-246,269-303` establish the new option-free R26+HUD owner `stereo_renderer_r30_r26_safe.cpp`, while R33 is HEADER_FILE_ONLY for this build. Explicit preconfigured comparison caches require independent verification; the source tree is not a runtime binary attestation. R84 is an optional comparator only.
2. **Original physical method is unresolved for any selected sprite.** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:17-41` confirms original 0x42D710 type-0 D3DX/UP and type-1 animation/masked branches, with indirect calls unresolved. `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:7-44` identifies D3D9 vtable index 84 as DIPUP, but the identified +TIME/6C animation paths predominantly describe direct DPUP or deferred D3DX, **not a proven indexed-UP draw**. Do not relabel +TIME, mask, dust, rank or lens as an indexed-UP physical producer from alpha, FVF or queue tag alone.
3. **R26 live physical DIPUP dispatch is separate from semantics.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:5642-5699` consumes the semantic only at a game-device physical DrawIndexedPrimitiveUP hook, attempts `R30TryXyzrhwIndexedPrimitiveUP`, and on `E_NOTIMPL` invokes the guarded R29/original API. A tagged queue epoch is not proof this specific method was called or that either eye succeeded.
4. **Index admission is fail-closed for the declared window.** `stereo_renderer_r30_r26_safe.cpp::R30TryXyzrhwIndexedPrimitiveUP:4120-4187` rejects zero/oversized primitive index count (MaxIndices 524288), absent pointers, stride under 16 bytes, formats other than INDEX16/INDEX32, and invalid `[minVertexIndex,minVertexIndex+numVertices)` windows. `r30_indexed_up_bounds.hpp:1-36` caps declared vertices to 262144, uses 64-bit addition, and rejects index values outside the declared window; `vrhost/tests/r30_indexed_up_bounds_smoke.cpp` contains static assertions/negative bounds examples. These are *existing* guards, not fixes made in this task. No CPU-pointer readability proof is obtained from an API argument alone.
5. **Newly isolated performance-relevant byte-ownership fact:** `stereo_renderer_r30_r26_safe.cpp:4161-4196` initializes `scratch.used` over the **whole declared `numVertices`** and marks only referenced local indices. But `R30TransformXyzrhwVertices:3555-3601` unconditionally resizes and `memcpy`-clones `vertexCount*stride` original bytes *before* checking `usedMask` for per-vertex transformation; `R30TransformXyzrhwStereo:3923-3954` invokes this once per eye (and can invoke both a second time for bilateral affine fallback). Therefore an admitted DIPUP with a small referenced set and large valid declared vertex window can still pay **two full-window CPU copies** plus full mask initialization, not a used-vertex-only clone. The scratch reuse helper `r30_shadow_scratch.hpp:1-58` amortizes allocations, **not the current memcpy per eye**; whole-buffer overwrite is deliberate for deterministic data provenance. This is a static cost contract, not a measured regression or permission to remove initialization.
6. **Optional rebase is conditional, not an index corruption finding.** `stereo_renderer_r30_r26_safe.cpp:4198-4254` reuses original indexData if minimum vertex index is zero; otherwise it produces a 16/32-bit local index buffer and uses shared rebased indices for both left/right `DrawIndexedPrimitiveUP` calls. The index window was checked first; no overflow, aliasing defect or real input distribution was demonstrated. `tools/verify_vr_r30_index_rebase_fastpath.py` describes a different full-chain R84 indexed *VB* decode cache and must not be counted as a passing measurement or existing optimization for this R26 DIPUP path.
7. **A GPU draw is not the end-to-end success criterion.** `stereo_renderer_r30_r26_safe.cpp:3957-4073` submits left then swaps right RT/depth/viewport, draws right, restores tracked state, and poisons/arms safe fallback on right draw or restoration failure; its API HRESULT return is the left result, so callers cannot infer right-eye success from SUCCEEDED alone. This failure-result contract was discussed in older reviews; it is cited only as the downstream boundary, **not claimed here as a new defect**. `stereo_renderer_r7.inc:1625-1741` guards composed frame publication with world/pose/right-eye/restore/Present and verified DirectGPU event or SBS; `vrhost/src/main_r23.cpp:3540-3570` finally selects a layer and calls `xrEndFrame`. None proves a specific indexed-UP scene appears correctly in Quest 3.
8. **Runtime evidence limitation:** Issue #13 is an append-only regression ledger, not same-SHA DIPUP CPU timing or a synchronized Quest3/VDXR L/R GPU capture. No new GPU profile, original queue-to-DIPUP correlation, HMD session or exact deployment SHA was generated by this review.

- **Confirmed** on this pinned owner: `usedMask` saves some *per-vertex reprojection work*, not the two complete source-payload memcpy copies for a valid indexed-UP window; bilateral retry can add another pair of full copies. Allocation reuse does not remove the copying.
- **Hypothesis only:** a real scene repeatedly using large declared indexed-UP windows with very few referenced vertices could amplify CPU p95/p99 and resource/cache bandwidth in dense scenes. No producer-to-DIPUP or true FPS/VR regression evidence exists, and small/dense windows or rare draws can make impact negligible.
- **Falsifiers / negative controls:** (a) exact R26 binaries show no qualifying DIPUP in slow frames; (b) DIPUP declared windows are tightly packed and referenced almost completely; (c) measured p95/p99 per-call dual memcpy overhead is negligible versus game/world GPU work; (d) inspected compiled variant differs from fresh R26; (e) an independent optimized memcpy implementation is proved in the *actual* shipped DIPUP path. The existence of an R84 indexed-VB cache is not (e).
