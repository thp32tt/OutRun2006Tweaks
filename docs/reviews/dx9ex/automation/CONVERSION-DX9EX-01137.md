## NEW_FINDING — exact code ownership confirmed; occurrence remains conditional

NEW_FINDING=CONFIRMED_STATIC_TWO_INDEPENDENT_POST_RESET_IMGUI_DEVICE_OBJECT_CREATION_PATHS_WITH_NO_SHARED_FONT_GENERATION_GATE.

At `src/overlay/hooks_overlay.cpp::D3DTemporariesCreate():529-535`, the original game's temporary-resource-create hook eagerly invokes `ImGui_ImplDX9_CreateDeviceObjects()` when `overlayInited`; it does **not** inspect `Overlay::FontsDirty`, `VrFontMultiplier`, current VR-vs-front-end mode or the next frame's `GlobalFontScale`. Separately `D3DEndScene():383-490` computes current visibility, VR/gameplay state and available published eye extents, may change `VrFontMultiplier` and mark `FontsDirty`, then calls `Overlay::rebuild_fonts()`, `ImGui_ImplDX9_InvalidateDeviceObjects()` and `ImGui_ImplDX9_NewFrame()` on the next frame. In ordinary Dear ImGui DX9 backend operation, NewFrame recreates missing device objects. These are **two independently scheduled opportunities for GPU font resources to be created**; there is no source-visible shared atlas-generation/Reset-generation coalescing guard between them in this hook class.

**Conditional consequence, not a measured defect:** if a successful temporary-resource Create produces ImGui device objects based on the old atlas, *and* the following EndScene changes the font atlas (for example returning from 1.25x VR F11 to 1.0x desktop, or a pending GlobalFontScale edit), the Create work can immediately be invalidated and reconstructed by the first following NewFrame. If font density/scale stays unchanged, the second rebuild is absent. No trace here proves the game actually calls those two callbacks in that order for a specific Reset, that both resource allocations succeed, or that the double-work produces a dropped frame, lost F11, mono overlay or measurable slowdown.

The separate F11 font-only branch now caps visible gameplay multiplier to 1.25 (`hooks_overlay.cpp:466-487`); the prior 01135 work already reviews the shell's remaining `GlobalFontScale` multiplication. Neither detail alone is a fresh UI-size bug finding here. The new review focus is **resource-generation/lifetime order**, not atlas density or HMD optical geometry.
