## REVIEW_SCOPE — original producer → semantic / queue → D3DX/native Draw → R46 versus R30/R26 → L/R → restore → Present / OpenXR

1. **Producer and physical draw remain separate.** Checked-in historical REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-45,74-92` identifies original scheduler `0x00449050`, priority queue consumer `0x0042D710`, deferred type-0 D3DXSprite `Draw→Flush/End`, and direct/native type-1 `DrawPrimitiveUP`. The checked-in REA is secondary analysis, not fresh proprietary EXE disassembly. A producer CPU call/token, bright texture, alpha state or D3DX `Draw` does not prove which final GPU primitive generated a sky/lens/+TIME/rank pixel. Queue ownership must be joined to the actual native draw, including possible N:1 D3DX batching.
2. **R30 first-owner / R26 lower path.** In the **current compiled default** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:5349-5525`, four Draw* entrypoints consider XYZRHW; indexed calls also consider external F11 and R62 fixed-function sprites, before `R30GuardScreenSpace`/lower hook fallback. `R30TryScreenSpaceFovDraw:4886-5110` requires exact semantic, pose, depth/stencil and original WVP before uploading c64..c67 and executing left and right native draws; it restores the original WVP, RT, depth and viewport and poisons/backs off on right/restore failure. It does **not** universally run the later R46 fingerprint logger before every R30-owned early return. A log entry from R46 alone is not a physical draw ID, final route, complete VS+PS state timeline or eye-proof.
3. **The distinct bytecode fingerprint path.** `src/vr/d3d9/stereo_renderer_r26.cpp:312-334` has `R46TraceShaderFingerprint` guarded by opt-in `TraceEnabled()`, calling `CaptureCurrent(device)` then `RememberPair(pair)`; `R27GuardWorldEffect:637-711` invokes this while choosing R28 or legacy R13 behavior. In `src/vr/d3d9/shader_fingerprint_gpl.hpp:141-181`, `CaptureCurrent` obtains **live** `GetVertexShader` and `GetPixelShader` COM objects, but then hashes each via separate 256-slot static caches. This is a useful *diagnostic*, not evidence that a particular original D3DX producer is physically associated with the sample, nor that its full pixel shader constants and textures were captured.
4. **NEW exact cache/lifetime boundary.** `shader_fingerprint_gpl.hpp:118-138` makes `HashBytecodeCached` return a previously stored hash whenever the current COM pointer address matches `entry.first`. The key contains **no device ID, lifetime/recreation generation, or shader bytecode verification on a cache hit**. `CaptureCurrent:161-175` uses function-static VS/PS caches and releases the newly queried COM references after the lookup. No invalidation/reset operation appears in this helper. If a distinct shader object later occupies the same numeric address before cache eviction, the cached fingerprint can be attributed to the wrong *currently bound* shader even though `GetVertexShader/GetPixelShader` correctly returned it. This is source-proven **conditional diagnostic identity risk**, not evidence that allocator pointer reuse occurred in a real session.
5. **Why this is not a screen defect or a reimplementation request.** `RememberPair:184-216` intentionally deduplicates bytecode **hash pairs**, not COM identities. That deduplication is reasonable for identical bytecode; however, a stale pointer→hash lookup can cause a genuinely different shader pair to look previously seen, suppressing a meaningful first occurrence in the R46 log. It does not itself rebind shaders, change native GPU constants, alter R28's two atomic tracking fields, or change rendered pixels. Do not infer a sun/sky/marker error or FPS loss from this diagnostic-only failure mode. Normal renderer and headset outcomes remain unproven.
6. **Per-eye/transport is a separate evidentiary chain.** Lower D3D9 world shader path `src/vr/d3d9/stereo_renderer_r7.inc:929-960,1052-1080` checks verified WVP/shader epoch, writes per-eye constants and restores state; `src/vr/d3d9/stereo_renderer.cpp:569-673` selects R9 stereo/mono-shadow or lower draw and `:692-822` gates final Present. The x64 host waits for both copied SafeEye GPU images before publishing `SafeFrameId` (`vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:267-319`) and independently records `xrEndFrame` (`vrhost/src/main_r23.cpp:3562-3610`). Neither an R46 hash pair nor a successful D3D9 Present proves a matching Quest3/VDXR eye image or that a producer's final physical draw was R46-captured.
