## REVIEW_SCOPE

An independent **game-side DX9Ex mono-shadow restore / failed stereo Present boundary**, not 01332's menu bootstrap or 01333's *host* partial-eye cached projection. Follow original producer -> deferred sprite queue -> R26+HUD R30/R62/native GPU draw -> R9 mono shadow/eye duplications -> failed stereo eligibility or SBS compose -> mono `StretchRect` restore -> actual D3D9 Present and Frame.v2 -> host source candidate/left-right XR layer -> actual `xrEndFrame`. Question: does failure of the last mono restore prevent physical Present or become part of a verified fallback diagnostic?

## EVIDENCE — pinned static call/path simulation (not physical GPU proof)

1. **Original producer and deferred queue.** `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-41,67-96` documents original 0x00449050 frame scheduler, +TIME producer 0x00498670 with multiple sprite/numeric calls, static 0x004B9D80 rank and priority consumer 0x0042D710. Queue type-0 D3DX `Draw` may physically execute on `Flush/End`; type-1 can emit `DrawPrimitiveUP`. This is existing REA/disassembly-derived **static mapping**, not this task's new binary evidence or an exact failed primitive identity.
2. **Semantic -> physical game draw.** `src/vr/game/render_semantics.hpp:1303-1444` captures producer, queue node/epoch and scope only at the physical primitive; unknown/non-proven screen traffic must not borrow last world WVP. In the active R26+HUD path, `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawPrimitiveDestR30:5395-5420`, `::DrawIndexedPrimitiveDestR30:5422-5502`, and `::DrawPrimitiveUPDestR30 / DrawIndexedPrimitiveUPDestR30:5505-5573` consume semantic and try R30 XYZRHW / R62 fixed function / original R29/native fallback as applicable. An R62 candidate rejection is **not** a final draw rejection. Actual left/right draw, restore, eye cant, pose and RT/viewport state need frame-fingerprint confirmation.
3. **Mono backup creation and failure isolation.** `src/vr/d3d9/stereo_renderer.cpp::ClearDestR9:519-574` only seeds `R9StereoSeeded` and `R9MonoSeeded` after successful full main-target color clear and replayed mono clear; a failed replay poisons the frame/sets a backup gap. `::R9ExecuteDraw:577-642` replays eligible draws to the mono shadow, sets `R9MonoBackupGap` and poisons on replay failure, and stops new stereo after `FrameStereoIncomplete`. These are deliberate fail-closed guards: an arbitrary D3D9 error does **not** imply a valid mono copy exists.
4. **Concrete last restore result.** `src/vr/d3d9/stereo_renderer.cpp::R9RestoreMonoBeforePresent:383-398` rejects absent device/seed, backup gap, mono surface or backbuffer. If resources are present, it issues `device->StretchRect(R9MonoSurface, ..., BackBuffer, ...)`; on failed HRESULT it increments `R9MonoFallbackRestoreFailures`, logs reason/HRESULT and returns `false`; on success increments `R9MonoFallbackRestores` and returns `true`. This is a *checked helper*, not unconditional success.
5. **NEW seam — the caller discards that check.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:687-810` independently computes `frameEligible` using both-eye/pose/resource guards, attempts DirectGPU or SBS, and sets `composedStereo`. At **:758-766**, when `!composedStereo || FrameStereoIncomplete`, it calls `R9RestoreMonoBeforePresent(...)` **without inspecting its returned boolean**, and skips even that attempt if `!R9MonoSeeded || R9MonoBackupGap`. At **:770-805** it publishes an in-flight fallback state, calls the actual D3D9 `Present`, normalizes its result, and then reports stereo active only on composed/succeeded/incomplete=false; otherwise publishes mono fallback/disabled state. No distinct last-restore-success latch, additional poison or Present suppression is visible between restore and real Present. This is source-confirmed control flow, **not proof that a StretchRect failed in the field**.
6. **Display/output distinction.** If the restore succeeds, the intended independently rendered mono buffer replaces the stereo backbuffer before Present. If it fails *after a stereo partial render*, the original backbuffer can be left without this final verified overwrite; exactly what pixels remain depends on prior GPU writes and driver error behavior. A `R9MonoBackupGap` can skip restore entirely by design, but such a gap already has explicit poison and should not be mislabeled a new StretchRect failure. Game-side PC mirror correctness is distinct from any actual OpenXR stereo projection; successful D3D9 `Present` alone cannot certify repaired pixels.
7. **Host candidate counterweight / final XR.** `vrhost/src/main_r23.cpp:3089-3140` requires a non-in-flight `StereoSbsActive` Frame.v2, valid frame/pose, completed draw flags and unchanged source. `::R23Capture` plus selected frame history is needed for classic SBS; DirectGPU uses a separately verified resource/run. Therefore the fallback state above is **not** by itself eligible as a fresh stereo source; depending on host settings it can retain a prior projection, use distinct menu/Desktop Duplication handling or not submit a new layer. `vrhost/src/main_r23.cpp:3562-3616` calls actual `xrEndFrame` and joins confirmed submitted frame ID, but there is no joined `R9MonoFallbackRestoreFailures` / backbuffer-surface content record to assert final HMD appearance. This review does **not** reassert the host cache-pixel issue from 01333.
8. **Limits of evidence.** Inspected live GitHub HEAD code, AGENTS.md 2026-10-20 newest R26+HUD override, optical route policy, original REA map, prior 01333 report and existing Issue #119 UI tracker. No exact-HRESULT failed `StretchRect` trace, game GPU readback, matched R30 physical draw, Quest3/VDXR capture, differential p95 frame pacing or new original EXE disassembly was executed.
