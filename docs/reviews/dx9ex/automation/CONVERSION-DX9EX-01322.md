## REVIEW_SCOPE — new boundary, distinct from 01321

01321 reviewed R9 depth-bind attempt counters and the R23 passive-clear generation fence. This pass reviews the *vehicle environment-reflection cubemap update budget*: original Envmap_FaceCount hook producer -> clock/cadence semantics -> per-frame cubemap face allowance -> auxiliary GPU render and later sampled vehicle-world draw -> R30/R62 or conservative native draw -> left/right and restore -> R9 Present/Frame.v2 -> x64 OpenXR. The important separation is **time between invocations of an EXE envmap hook** versus **time between actual game Present or XR frames**. These are not automatically identical clock domains.

1. **Original producer and provenance:** The mod hooks original game's face-count computation at module-relative EXE offset 0x1447E via ReflectionUpdateRate::apply and returns the selected number of cube faces in ctx.eax. Source comment says the original envmap renders a subset of six cubemap faces and rolls remaining work across frames. This identifies a hook site but **does not prove its original CALL graph, number of invocations per outer game Present, GPU texture/RT identity, or HMD symptom**. Historical REA places frame orchestration at 0x00449050 and documents the separate 0x0042D710 SpriteNode/D3DX priority queue; it provides no traced envmap-to-car sample fingerprint for this review.
2. **Semantic / queue / D3DX ownership:** This reflection face-count control is not itself a SpriteNode or D3DXSprite Flush/End. A future car/material world draw may sample the resulting cubemap, but that dependent original producer/VS/PS/texture ID, native DP/DIP/UP identity and node/epoch are UNKNOWN at this pinned SHA. Do not count a face allowance, semantic scope, queue tag, or CPU hook return as a completed GPU draw. D3DX deferred HUD batches remain a different original source-to-physical-draw route.
3. **Clock origin is source-confirmed:** In src/hooks_graphics.cpp::ReflectionUpdateRate::FaceCount_dest, static lastCounter is sampled by QueryPerformanceCounter **only within the face-count midhook** when VR and VRNormalizeReflectionRate are enabled. The delta (now-lastCounter) feeds AdaptiveFrameCadence::Observe and frameScale60; there is no read of PresentEpoch, actual R9 Present timestamp, host XR predictedDisplayTime, or original envmap call frequency check at this site. When normalization is disabled, lastCounter and cadence are reset, not tied to an XR frame ID.
4. **Actual admission and bounded work:** AdaptiveFrameCadence::Observe uses a learned healthy 55–150 Hz period, an absolute >18ms late cutoff, a learned reference delta >20%+0.5ms after four healthy samples, and 24 consecutive matched slower nominal samples for refresh-mode re-lock. Advance applies requested ReflectionUpdateRate to 6 faces, time-scales the normalized budget and caps admitted faces at 3 normally or 2 on a classified late interval. Retained face debt is bounded; zero rate cancels debt. This guards workload but says nothing about why the preceding hook-to-hook interval lengthened.
5. **Conditional counterexample, NOT observed:** If the original envmap face-count hook is skipped on one render Present because of car selection/menu/scene effects while game Present continues normally, the next hook delta can exceed 18ms and be classified late although XR refresh did not miss a deadline. Conversely multiple envmap hook invocations within one Present (not established for OutRun) would sample an intra-frame interval and under-weight normalized face allowance. Both scenarios follow the clock design *if the premise occurs*; neither is evidence that the game actually takes either path.
6. **Cubemap to native L/R boundary:** If an envmap update actually binds an auxiliary cubemap render target, R26's fragile-effect stereo promotion rejects AnyAuxRenderTargetActive; R23/R22 capture/restore tracked game RT/depth/viewport and mono/eye baseline separately. A later physical vehicle reflection sample requires independent texture/VS/PS, original producer/call RVA, queue/batch if any, and actual L/R draw HRESULT/RT/depth/viewport+restore. Default R26+HUD R30/R62 exact screen-space fast paths do not automatically own a perspective vehicle draw; unproven work stays on conservative R29/R26/R23/R22/R13/R9/native logic.
7. **Present/OpenXR conclusion:** R9 stereo Frame.v2 needs a seeded and completed world+duplicated L/R frame, valid pose/metadata, no failure, and normalized native Present before active publish; otherwise fallback/mono. The host independently checks final xrEndFrame and actual submitted layer/frame ID. Neither R9 Present eligibility nor XR submission proves that a particular reflection face actually drew or that hook-to-hook pacing equals eye refresh. There is no captured Quest 3 reflection stability or p95/p99 measurement here.
