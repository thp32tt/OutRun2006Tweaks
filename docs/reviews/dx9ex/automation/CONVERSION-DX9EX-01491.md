## REVIEW_SCOPE — original producer → semantic → queue → native API → R30/R62 → L/R → restore → Present/OpenXR

1. An original game world-particle producer may reach a D3D9 DrawPrimitiveUP after its scene and queue semantic has been selected. The game's archived sprite REA separately resolves scheduler 0x00449050/consumer 0x0042D710 and four sprite branches (0x0042A0A0, 0x0042C0F0, 0x0042A3A0, 0x0042A800); this **does not establish** which original branch, if any, produced the particular particle DrawPrimitiveUP considered here. No fresh REA/native-call mapping is claimed.
2. `src/vr/game/render_semantics.hpp:979-1027` provides current scope/one-shot draw semantics. `src/vr/d3d9/stereo_renderer_r33.cpp:249-300,1985-2044` consumes the semantic, guards game/RT/StateBlock and dispatches a physical DrawPrimitiveUP to fixed-sprite, R30 XYZRHW or original/lower R29 fallback. Exact `WorldParticle` (not arbitrary alpha, water, cockpit glass, lens, HUD or result text) and world optical validity are required for the optional GPU-upload fast path.
3. `src/vr/d3d9/stereo_renderer_r30.cpp:6480-6539` transforms XYZRHW scratch independently for LEFT and RIGHT before physical submission; with `OUTRUN_VR_R30_PARTICLE_VB=1`, reliable effect telemetry, alpha blend on, z write off, nonindexed UP, valid size/stride and no StateBlock recording, it may acquire the GPU ring. `r30_particle_dual_eye_ring.hpp:15-79` allocates DEFAULT-pool 4 MiB DynamicVB, locks once for both eye-specific arrays, and binds stream zero separately for each eye.
4. `stereo_renderer_r30.cpp:6540-6589` binds eye 0, performs a raw D3D9 DrawPrimitive only *after successful bind*, then repeats for eye 1 using `R30ExecuteXyzrhwStereo`; completion/eye RT/depth/viewport restore goes through R30/R62, and `finishUp` restores stream 0 to the null state a native DrawPrimitiveUP leaves. On proved pre-physical-draw failure the helper permits returning E_NOTIMPL to the R33 dispatcher, whose lower/original DrawPrimitiveUP fallback is independent of the attempted VB optimization.
5. `src/vr/d3d9/stereo_renderer_r7.inc:1624-1741` gates valid stereo Present on `!FrameRightDrawFailed && !FrameStereoIncomplete`, transports eligible SBS/DirectGPU eye frames through Frame.v2 and the x64 R23 host to R24/OpenXR xrEndFrame. Failure fallback is not a proven Quest3 outcome; HMD, actual GPU draw calls, host XR submissions and frame hashes were not captured.

## EVIDENCE — exact static ordering

1. `src/vr/d3d9/stereo_renderer_r30.cpp:168-175`: the opt-in is only enabled by environment `OUTRUN_VR_R30_PARTICLE_VB=1`; no assertion that the user's test configuration enables it.
2. `src/vr/d3d9/r30_particle_upload_policy.hpp:10-45`: `Eligible` rejects unreliable effects, depth-writing, indexed/StateBlock and small/oversized draws. `MayUseNativeUpAfterGpuAttempt(false,true,true)` is explicitly TRUE; with any actual GPU attempt or failed stream restoration it is FALSE. The fallback policy distinguishes no-draw errors from partial-raster errors.
3. `src/vr/d3d9/r30_particle_dual_eye_ring.hpp:55-69`: `bindEye(0)` returns failure when SetStreamSource fails, without issuing DrawPrimitive. `finishUp` issues SetStreamSource(0,nullptr,0,0). The mutex covers both eyes to avoid DISCARD overwriting right-eye bytes; Reset invalidates the ring under that mutex (`stereo_renderer_r30.cpp:1839-1851`). These are existing safeguards.
4. `src/vr/d3d9/stereo_renderer_r30.cpp:6540-6582`: `physicalEye(0)` checks bind HRESULT and returns before setting `physicalDrawAttempted=true` or calling `R29OwnerCallRawDrawPrimitive`. After `R30ExecuteXyzrhwStereo` it restores UP stream semantics; if `gpuHr` failed and no physical Draw was attempted and stream restoration succeeded, it returns `E_NOTIMPL` for caller fallback.
5. `src/vr/d3d9/stereo_renderer_r30.cpp:6228-6267`: **before calling** the supplied LEFT lambda, `R30ExecuteXyzrhwStereo` unconditionally executes `R29OwnerNoteStereoDrawWithoutMonoBackup()` and optional depth-content accounting. Any FAILED(leftHr), including a pre-draw `SetStreamSource` failure, executes `R29OwnerMarkRightDrawFailed()`, `R29OwnerInvalidateRightDepthStencilIfLeftMayWrite`, `R29OwnerReportStereoFailure(StereoFailureLeftDrawFailed,...)`, and `R29OwnerArmMonoSafety()`; there is no argument conveying `physicalDrawAttempted=false` into this generic failure branch.
6. `src/vr/d3d9/stereo_renderer_r29.cpp:1284-1292,1325-1335`: these accounting helpers reach `R9NoteStereoDrawWithoutMonoBackup`, `R9Poison` and `FrameRightDrawFailed=true`. `src/vr/d3d9/stereo_renderer_r7.inc:718-726,1632-1636,1718-1733` shows poison sets FrameStereoIncomplete, and Present refuses new stereo publication when that or FrameRightDrawFailed is set.
7. `src/vr/d3d9/stereo_renderer_r33.cpp:1988-2044,1561-1618`: E_NOTIMPL from R30 returns to the original/lower fallback path via R33Dispatch. That fallback is not shown undoing the previously recorded R30 frame failure. Lower R29 may apply additional fail-closed logic; this review does NOT claim a successful physical fallback was observed or that a full stereo image would otherwise be guaranteed.
8. Negative controls: GPU ring allocation/Lock/Unlock failure before `R30ExecuteXyzrhwStereo` enters the normal UP path without this particular premature poison. Successful bind and successful L/R Draw, or right/left failure *after* a physical GPU Draw was attempted, correctly retain fail-closed behavior. Ordinary default-disabled GPU upload and unrelated original D3DX/type-1 sprite branches do not enter this path.
