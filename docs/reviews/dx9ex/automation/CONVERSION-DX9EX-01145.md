The native R22 hook `src/vr/d3d9/stereo_renderer_r22.cpp:562-578,805` closes common stereo eligibility, resets its depth/scissor/viewport baseline and state-shadow before R13, and re-primes the shadow only upon successful Reset.
2. **R13 local control-flow difference.** `src/vr/d3d9/stereo_renderer_r13.cpp:425-449` closes the original sprite queue epoch in R26+HUD comparison builds via `EndSpriteQueueFrame(true)` for game devices, **then immediately delegates to** `R13ResetR9Hook` when R13 overlay is not ready, or when the device is not both game-owned and recognized as a compatible D3D9Ex device. Neither early branch calls `R13ResetCommonPre` locally. The fully eligible compat path disarms competing legacy Reset, calls `R13ResetCommonPre`, and invokes `ResetCompatDevice`; a declined ResetEx owner returns INVALIDCALL after pre-cleanup. This is a conditional source branch property, not evidence that a real launch hits it.
3. **Cleanup that the early branch omits locally.** `stereo_renderer_r13.cpp:381-423` shows `R13ResetCommonPre` invokes `OutRunVRRenderer::NotifyGameReset()`, releases transport ACK and stereo resources, clears various ring/frame/pose-admission counters and publishes disabled stereo. `src/vr/game/outrun_renderer.cpp:2274-2287` shows `NotifyGameReset` explicitly clears `PresentPoseLocked`, restores the saved CPU game camera, drops partial HUD/lens WVP, invalidates game WVP, resets pose/frame state and disarms cadence. In contrast `src/vr/d3d9/stereo_renderer.cpp:825-840` R9 Reset callback releases mono/depth resources, resets R9 stereo seeding and conditionally captures a new depth identity; it does **not itself** call `NotifyGameReset`. Another external reset owner or a later callback could still clear the state: **global non-cleanup is not established**.
4. **First-scene consequence requires a specific sequence.** `src/vr/game/outrun_renderer.cpp:1761-1789` on a successful non-internal game `BeginScene` calls `LatchFramePose()` only when `PresentPoseLocked == false`; if it is true, it calls `ReusePresentPoseForScene()`. `ReusePresentPoseForScene:1526-1541` resets scene-local WVP classification and camera sync, but retains the previously latched pose. `NotifyGamePresent:2262-2272` normally clears `PresentPoseLocked`, while `ResetFrameState:1280-1300` invalidates old c64/pose. Therefore **IF** a prior successful scene leaves `PresentPoseLocked` true, **AND IF** R13 takes an early Reset branch, **AND IF** no other callback/Present clears this lease before the next successful scene, the new scene could reuse a pre-Reset pose. A failed BeginScene explicitly drops its frame state and pose lock; this is an important negative path. R23 additionally gates injection on host-fresh/common eligibility (`outrun_renderer_r23.cpp:218-241,260-284`), so retained CPU pose does not automatically imply physical wrong-eye submission.
5. **Only physical GPU evidence could turn this into a screen defect.** Original `0x00417B20` frame/Reset context -> `0x00449050` stage scheduling + *indirect* world callbacks -> native D3D9 physical DP/DIP/UP under R26 verified-world guard; unrelated original `0x0042D710` sprite priority queue has kind-0 `0x0042A0A0` D3DXSprite `Draw` whose GPU submission can defer to `0x00429F60` `End`, and kind-1/flagged native `0x0042A3A0/0x0042C0F0` UP. These are **different** semantic families. R30 first requires exact queued node/epoch/producer and live FVF/shader or R62 result-HUD proof before qualifying an eye draw (`stereo_renderer_r30_r26_safe.cpp:3065-3113,5339-5395`); R26 world checks are independently conservative. An R13 Reset omission is not permission to globally reclassify any sprite, lens, sky, HUD or scene draw.
6. **L/R -> restore -> transport gate is separate.** For each attributable post-Reset physical draw, the evidence needed is new source generation + pose sequence, raw c64/WVP, VS/PS/FVF/texture/RT/viewport/depth, exact API and left/right HRESULT, raster/depth/WVP restore status. `src/vr/d3d9/stereo_renderer.cpp:692-819` requires fully eligible world-stereo + duplicated draw + nonfailed right eye + resources; it mono-restores on incomplete output, calls actual Present and resets per-Present flags. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:253-325` advances `SafeFrameId` only after completed host copy/fence and state publication, while `vrhost/src/main_r23.cpp:3559-3605` observes actual XR layer/frame-ID and `xrEndFrame`. Source-only predicate mismatch cannot prove a stale image, duplicated F11, binocular alignment failure, frame drop or VR PASS.
