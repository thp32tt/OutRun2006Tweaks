4. **Producer to transport:** `src/vr/d3d9/stereo_renderer_r7.inc::PresentDest:1625-1741` requires stereo world/duplicate/pose/resources/restore eligibility, invokes original Present, and publishes stereo frame metadata only after successful gated paths. DirectGPU additionally uses R32 ring slot ownership, producer EVENT and host GPU ACK (`stereo_renderer_r32.cpp:494-575` and R7 post-Present completion). Failed/nonready direct-only frames can retain older frame metadata. Thus *producer frame ID* and *host XR tick* are not synonymous.
5. **Host pre-submit selection:** `vrhost/src/main_r23.cpp:2911-2928,3316-3345` initializes `frameFreshProjection=false` per XR tick, sets true when R23 refreshes/releases projection, and publishes a `R23VerifiedBundle` after successful resource rendering. If R23 reuses an already released projection, it sets `frameCachedProjection=true` at `:3369-3379`. These booleans label R23 **pre-`xrEndFrame`** work. They do not themselves prove the final interceptor-selected layer.
6. **Outer authoritative final gate:** `vrhost/src/runtime/r32_direct_submit.hpp:544-613` attempts a fast DirectGPU submission only after exact frame/ACK criteria; if rejected it delegates to R26/R24. `vrhost/src/runtime/r24_black_screen_guard.hpp:577-706` chooses exact/classic/direct-safe/grace or `SubmitVisibleFallback`; that fallback can replace the requested projection by cached/direct-flat/live-theater/emergency quad (`:479-574`) or submit zero layers. `r23_runtime_hardening.hpp:36-77` reports actual **successful-submission intent** as frame ID, source kind, has-layer; it is not pixel readback. A visible R24 fallback records `frameId=0, kind=None, layer=true` (`r24_black_screen_guard.hpp:571-574`).
7. **Post-intercept metrics split:** In `main_r23.cpp:3562-3597`, R23 snapshots R24/R32 counters, calls `xrEndFrame`, reads final kind and `LastSubmittedFrameId/Kind/Layer`, then feeds `pipelineWindow.Note` the computed **actualFinalLayerKind**. But `cadence.NoteFrame(frameFreshProjection, frameCachedProjection, layerReady,...)` uses *pre-intercept* booleans. `NoteFrame` counts `fresh/cached/noLayer/other` purely from these flags (`main_r23.cpp:2219-2238`); consequently a layer provided solely by R24 after R23 requested no layer can still count as `noLayer`. That counter is not an actual headset-black metric.
8. **CSV frame join and diagnostic filtering:** `main_r23.cpp:2638-2656,3598-3644` opens opt-in `outrun-vr-frame-pacing.csv`; the row joins only if `actualSubmittedLayer && actualSubmittedFrameId && ReadFresh(bundle) && bundle.frameId == actualSubmittedFrameId && bundle.frame.frameId == actualSubmittedFrameId`. This correctly rejects an uncorrelated stale newest frame. But `sample.cached = !frameFreshProjection` does not inspect post-intercept `actualFinalLayerKind`, `actualSubmittedSourceKind`, or a final-rendered-image cache flag. Its `hostCaptureMs/hostCopyMs` only populate for not-cached and matching `candidateGameFrameId`. The CSV schema contains no actual-final-source-kind or last-submitted-layer category. `src/vr/ipc/frame_pacing_diagnostics.hpp:74-120` then uses `cached` as an identity rule: same-run noncached IDs must advance, cached IDs must equal the last accepted ID; false classification can conditionally suppress a row. Crucially R24 visible fallback with recorded `frameId=0` produces **no CSV row by design even when layer=true**. CSV row count is NOT total XR submitted-layer count.
9. **Present/OpenXR result boundary:** Requested `end.layerCount` (`main_r23.cpp:3562`) and post-intercept actual layer-intent marker are separate from compositor-recognized XR images, GPU/HMD pixels and Quest3 display. No frame-based pacing/FPS improvement, display defect, or HMD success is established without correlated runtime logs and left/right measurement.
