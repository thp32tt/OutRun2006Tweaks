## REVIEW_SCOPE

Different from #01412's sand/spray producer and optimizer attribution: test the new CORRECTNESS policy assertion `-DirectGpuOnly=false` against *two distinct fallback timing boundaries* of the **default** R26+HUD renderer:
(A) DirectGPU not ready/ResolveDirectTransport=false **before** game Present, so `ComposeSbs` is eligible; (B) ResolveDirectTransport=true and the shared-eye copy/Event is issued, but EVENT completion is not proven in the 1 ms **after** Present, so no SBS was composed for that frame and a safe last projection can be held. Follow source provenance -> semantic -> queue -> D3DX/native -> R30/R62 L/R -> restored eye pair -> R7 ring/Present -> active R23 OpenXR. This is a distinction of frame-transport failure *phase*, not an assertion that a specific screen item is now fixed or broken.

## NEW_FINDING

- NEW_FINDING=FALLBACK_ENABLED_DIRECTGPU_POST_PRESENT_EVENT_MISS_HOLDS_FRAME_NOT_SAME_FRAME_SBS.
- CLASSIFICATION=SOURCE_CONFIRMED_CONTROL_FLOW_AND_TELEMETRY_LABEL_AMBIGUITY; OBSERVED_OPTICAL_DEFECT=UNPROVEN; PERFORMANCE_IMPACT=UNMEASURED.
- **FACT:** `DirectGpuOnly=false` permits pre-Present SBS when DirectGPU was not chosen. It does **not** guarantee same-frame SBS recovery after DirectGPU has been chosen and its *post-Present* EVENT misses the bounded grace interval. An unconditional `markDirectOnlyHold` calls a “DIRECT-ONLY” warning and increments fallback statistics in the latter case, so telemetry interpretation requires separately distinguishing `prePresentSbs`, `postPresentDirectHold`, and `directGpuPublished` on the same game frame.
- **LIMIT:** Deliberate reuse of a previously safe XR layer is preferable to publishing an incomplete shared eye; static analysis does **not** establish a present-day visual freeze, dropped 72Hz frame, or a new bug. A false “fallback unavailable” reading from that warning would be a **diagnostic error** if the session had `DirectGpuOnly=false`.
- **FALSIFICATION:** A same-SHA instrumented trace proving CORRECTNESS uses `DirectGpuOnly=true`, a different compiled `PresentDest` owner, or an independent successful same-frame SBS composition+complete packet after `DirectTransportFrameReadyAfterPresent` fails would refute the configuration-specific inference. A frame with `ResolveDirectTransport=false` is *not* a counterexample; it follows the distinct pre-Present branch. Any alleged visible stall requires matching EVENT, host cached/fresh choice and optical capture.
