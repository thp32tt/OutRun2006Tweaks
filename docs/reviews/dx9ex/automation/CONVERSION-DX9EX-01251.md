## REVIEW_SCOPE — different from 01250

Follow 01250 NEXT_REVIEW: check the lifetime of `OcclusionQueryTrackingUnavailable`, `ActiveOcclusionQueries` and the `QueryIssueHook` on R7 Reset, R9 Reset and R13-owned ResetEx, then check whether the first subsequent `CreateQuery(D3DQUERYTYPE_OCCLUSION)` re-arms query tracking. This is NOT 01250's R9 backup + R7 real Draw duplication hypothesis. Here the distinct question is whether a failed Issue-hook attempt can remain fail-closed across successful Reset even after the active-query counter was cleared, in the absence of later game occlusion-query creation.

Static path simulation (a route diagram, not observed native ownership): original +TIME six x86 E8 sites / GOAL-result and unrelated game draw -> 0x449050 / 0x42D710 SpriteNode consumer -> type-0 D3DX 0x42A0A0, type-0 direct UP 0x42C0F0, type-1 quad 0x42A3A0, or type-1 mask 0x42A800 -> optional delayed D3DX Begin/Draw/Flush/End, exact producer/semantic/queueNode/queueEpoch -> physical final GPU DP/DIP/UP -> R30 external F11 exclusion, R62 admitted fixed-function sprite or XYZRHW/R29/native fallback -> when selected, R13 guard and R9 mono backup/R7 L/R native submission -> RT0/depth/viewport/StateBlock restore -> Present R9/R13 stereo-SBS or mono fallback -> x64 host actual xrEndFrame/fresh-or-cached layer. Reset/ResetEx drops frame/eye/shadow/queue state before a later seeded Present. No specific producer has been tied to a live occlusion-query interval by the checked-in REA.

## NEW_FINDING — source invariant, practical impact conditional

- NEW_FINDING=CONFIRMED_STATIC_RESET_CLEARS_ACTIVE_QUERY_COUNT_BUT_PRESERVES_TRACKING_UNAVAILABLE_AND_NO_RESET_REPROBE; PERMANENT_STEREO_DEGRADATION=HYPOTHESIS_ONLY; HMD_DEFECT=NOT_ESTABLISHED.
- FACT: If Issue-hook installation failed before Reset, both R7 Reset and the R13-owned ResetEx can clear `ActiveOcclusionQueries` to zero while leaving `OcclusionQueryTrackingUnavailable=true`. Successful Reset/ResetEx does not itself clear this fail-closed state. The directly observed recovery write to false exists in `CreateQueryDest` after a later successful occlusion-query Issue-hook creation, not in Reset or Present.
- HYPOTHESIS: If a session has an unavailable tracking hook, resets successfully, then creates no further game occlusion query (or all subsequent attempts fail), later eligible main-target physical draws may repeatedly take R7/R13 unsafe-single-execution and mono fallback even when no active game occlusion query exists. This could suppress L/R stereo or waste reseeding/fallback work; runtime existence, extent, +TIME/result symptom and performance impact are unverified.
- CONTRARY: A failed hook may never occur on Quest3; the game may immediately create a new occlusion query after Reset, successfully rearming the hook; R13/R30 may keep correct routes, the renderer may not request stereo until after a new query, or no main-target eligible physical Draw may occur. Keeping the fail-closed flag on Reset may be intentionally safer than clearing it without a verified Issue hook. Do not call the flag a bug in isolation.
- FALSIFY: In an explicitly authorized same-executable-SHA diagnostic session, bound logs to event transitions (no per-draw GPU stall): `CreateQuery` query type, HRESULT, Issue hook creation result and existing hook identity; Issue BEGIN/END HRESULT, query GetDevice, active counter, flag; Reset/R13-owned ResetEx entry/exit and HRESULT, device identity and rebind, RenderFrameRunGeneration, query creation immediately after Reset, R9InstallReady/R13OverlayReady, frame seed/main RT/depth/viewport, exact producer/node/epoch at D3DX Flush/End, actual R30 F11/R62/XYZRHW/R29/R13/R9/R7 physical native calls and L/R/HRESULT, restoration, game Present mono/stereo decision, host actual xrEndFrame frameId/layer/fresh/cached. Compare A=tracking initially OK+Reset, B=failed Issue hook+Reset+new successful occlusion CreateQuery, C=failed hook+Reset+no new occlusion query, D=failed hook+Reset+failed CreateQuery, E=already-active tracked query+Reset, F=Reset failure, G=R13 ready vs not ready, H=offscreen/sprite native fallback. Refute the runtime hypothesis if C cannot occur before a seeded eligible game frame, if flag does not stay true, or stereo eligibility/HMD frames are unaffected; preserve the source-level state invariant regardless.
