## NEW_FINDING — conditional static distinction, NOT a live bug claim

- NEW_FINDING=FINITE_RESULT_PLANE_ADMISSION_DOES_NOT_IMPLY_VALID_ORIGINAL_GAME_PIXEL_EXTENT.
- CLASS=SOURCE_CONFIRMED_CONDITIONAL_GUARD_SEPARATION; NEW_RUNTIME_DEFECT=UNPROVEN; VISUAL_MISALIGNMENT=HYPOTHESIS_ONLY; PERFORMANCE_CHANGE=UNMEASURED.
- FACT: `R30BuildStageExtensionXyzrhwEyePlane` returns success independently of whether `stageSource2DWidth/Height` are populated. The downstream `R30TransformXyzrhwStereo` selects original-game-pixel to current-viewport conversion only when those values are valid and dimensions differ. A source-proven finite HUD plane thus does **not** itself prove correct *source pixel-domain attribution* under an unavailable/invalid original game resolution.
- HYPOTHESIS_ONLY: if a real +TIME/GOAL/ordinary ScreenHud draw has source pixels authored for a different game canvas from the active eye RT and the game dimensions were unavailable or invalid at that physical draw, both eye transforms could be spatially scaled/offset despite valid eye pose/draw HRESULTs. No exact-SHA HMD frame or log establishes that this precondition occurs.
- CONTRARY / FALSIFY: prove the installed original game resolution is always finite, valid and correct for all physically selected source HUD draws; or show original game and actual eye target extents are equal; or capture paired LEFT/RIGHT vertices showing correct normalized mapping even when `stageSource2DWidth=0`. In any such case reject the proposed source-domain mismatch. Distinguish source-pixel attribution from a RIGHT/state restore failure or host grace reuse.
- Not a license to change runtime code, default R84, game HUD scaling, root projection, sprite scissor or VR eye extent without baseline-controlled HMD proof.
