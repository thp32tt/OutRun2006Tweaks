The per-eye upload cache is keyed correctly to the **value it receives**, so making cache invalidation alone more aggressive would not refresh the source of truth.
- **Conditional simulation:** an HDR output remains on the same `HMONITOR`, `IDXGIOutputDuplication` stays valid, the user changes Windows SDR content brightness (query would now return S2 rather than S1), and a fresh classic SBS frame arrives. R23 passes the old member S1 to each eye; HLSL normalizes scRGB by S1, not S2, until some later `BindCaptureOutput` updates the member. E.g. S1=1.0 and S2=1.5 would imply a 1.5x normalization difference **for unsaturated scRGB samples under those assumptions**, not a measured image. BGRA8 does not use that scale. No claim this transition actually bypasses DXGI reinitialization on the user's system.
