## EVIDENCE — pinned GitHub static source, REA and independent issue context

1. **Original producer has multiple physical API paths**: checked-in `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:5-51` attributes original `0x449050 -> 0x42D710` queue and four sprite branches: type-0 D3DX `0x42A0A0` (possible Begin/Flush/End-deferred physical DIP), type-0 flagged direct UP `0x42C0F0`, type-1 animation UP `0x42A3A0`, type-1 masked UP `0x42A800`. This is checked-in REA evidence, not new binary instrumentation. `src/vr/game/render_semantics.hpp::BeginSpriteQueueRender/SelectSpriteQueueNode:1760-1837` establishes queue serial cutoff, node epoch, exact producer only on tagged nodes, generic unproven `ScreenOverlay2D`. `src/vr/game/goal_progress_physical_source.hpp::Source:10-25` stores scope/producer/node/epoch/pose/draw serial/shader/original game WVP generation, not actual depth-surface COM identity.
2. **R23's depthless first-seed predicate is attachment-dependent, not ZENABLE-dependent.** `src/vr/d3d9/stereo_renderer_r23.cpp::R23ObservePassiveDepthClear:167-199` tracks depth/stencil clear epoch, top-level draw serial and depth generation when the original game clear succeeds, full raster covers the game backbuffer and depth is mirrorable. `::R23DepthBaselineSafe:201-227` initializes `stencilSafe=true` and **returns true immediately if `TrackedDepthStencil == nullptr`**, whereas attached depth requires same PresentEpoch, game draw serial and generation, plus stencil proof if test active. This means a legitimately depthless GOAL pass may be seeded by a full-color clear without an impossible depth clear. It does *not* show an incorrect seed.
3. **A later live depth read is distinct from the tracked-depth predicate.** `src/vr/d3d9/stereo_renderer_r23.cpp::R23InitializeStereoFromAuthoritativeBaseline:286-306` obtains live `device->GetRenderTarget(0,...)` and `device->GetDepthStencilSurface(&savedDepth)`, accepting `D3DERR_NOTFOUND`; `::...:312-381` replays full-color clears to private right/mono, conditionally clears private depth **only when `TrackedDepthStencil` is non-null**, restores saved live RT/depth/viewport/scissor, and sets depth/stencil synchronization flags true in the tracked-null case. No explicit equality comparison between `savedDepth` (live COM surface pointer) and `TrackedDepthStencil` appears in this function. The normal tracker may already be perfectly synchronized; **a stale-tracker mismatch is hypothetical, not observed**. `::ClearDestR23:416-525` executes the original game clear once, then requires full color, no MRT, depth predicate, pose warmup/host freshness/current-frame pose before stereo initialization; `::R23BeforeTopLevelDraw/Draw*DestR23:528-584` increments the draw serial.
4. **R62's kind-0 result admission probes a *render-state bit*, not depth attachment.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30SafeStereoBase:75-93` rejects unseeded/recovery/deferred/unmirrorable depth/incomplete frames. `::R62TryFixedFunctionSpriteIndexed:5171-5242` requires exact HUD/projected semantic, physical DIP TRIANGLELIST, live VS-null, FVF `0x142`, nonzero viewport, latched stereo pose; `ReadTrackedRenderState(D3DRS_ZENABLE)` sets `state.depthTestEnabled`. ZENABLE is not `GetDepthStencilSurface` and is not proof of a live attached depth. `::R62TryFixedFunctionSpriteIndexed:5243-5380` builds per-eye finite projection, uses `R30ExecuteXyzrhwStereo` and restores *original* projection, recording both eye HRESULTs and restoration on bounded exact-result telemetry. Its rejection is not a global no-draw: `::DrawIndexedPrimitiveDestR30:5425-5512` may continue via XYZRHW/R29 fallback.
5. **The right-eye depthless shortcut has its *own* stricter provenance.** `src/vr/d3d9/stereo_renderer_r30.cpp::R30ExecuteXyzrhwStereo:6157-6335` captures exact GOAL physical producer before native left, rejects changed producer/node/epoch/pose/shader source after it, and never replays a left draw. `::...:6336-6417` gets R29's *post-left* `frame.trackedDepthStencil`; it selects `depthlessPass` only for **null tracked attachment AND `StateBlockTracker::Reliable()`**. That path skips redundant null-depth setter on right and in `::R30RestoreDepthlessRightPassState:6007-6025`, while uncertain or attached-depth cases take original full right-depth attach/restore. Exact GOAL ownership is checked again immediately before right. `::...:6419-6469` publishes a two-eye draw only after left/right HRESULT and restore success, and poisons incomplete state on right/restore failure. These safeguards are not evidence that an application-level `GetDepthStencilSurface` or pixel compare happened for every GOAL draw.
6. **R62 outer projection restoration is separate from R30 right-eye RT/depth/viewport restoration.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R62TryFixedFunctionSpriteIndexed:5310-5380` restores `D3DTS_PROJECTION` after the stereo transaction, even if the inner call rejects; restore failure arms fallback/returns failure for exact result if stereo otherwise succeeded. The capture, before-right source checks, inner depth restore and outer projection restore must be correlated as **distinct gates** before labeling a GOAL as successfully stereo-projected.
7. **Final frame transport is not a glyph/depth proof.** `src/vr/d3d9/stereo_renderer_r7.inc::PresentDest:1625-1745` checks frame completion and waits for real Present plus post-Present DirectGPU completion before publication; `vrhost/src/main.cpp:2700-2719` checks frame/pose consistency, DirectGPU or capture availability, then reuses a bounded last-safe projection when necessary. Therefore successful Present/OpenXR projection cannot distinguish source depthless, depth-attached, failed R62 candidate plus R29 fallback, or a genuine missing first result glyph.
8. **Issue context and duplicate guard:** GitHub Issue #6 `[N100] Continuous Review Inbox` is an append-only finding inbox, not runtime evidence. #01378 found first-only early GOAL eligibility telemetry can conceal later seeded draw; this review instead isolates **tracked-vs-live depth attachment / Z bit predicate separation**. No captured original game GPU state, device-loss log or Quest 3 image was available for this task.
