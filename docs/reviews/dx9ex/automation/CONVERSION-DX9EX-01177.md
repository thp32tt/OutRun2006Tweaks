2. **Physical HUD draw, eye transforms, restore.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:2400-2550,3417-3715,3820-3934,4886-5110,5116-5321,5349-5525` conditionally consumes exact queued semantics at actual DP/DIP/UP, distinguishes shader HUD from fixed-function XYZRHW/R62, writes left/right native GPU draws and restores state; rejection routes to lower R26/stock. Thus a HUD texture can already be filtered at an original D3DX/native physical Draw before the *independent frame-scale* discussed here. No current actual Draw ID, texture sampler or eye pixel was captured in this task.
3. **Game source size separated from desktop mirror and XR allocation.** `src/hooks_graphics.cpp:2243-2306` uses `Game::screen_resolution` to size the game source while optionally fitting the desktop mirror HWND without changing the HMD source. `src/vr/ui/vr_logical_coordinate_space.hpp:1-43` contains the original 640x480 grid within *game* pixels, not XR pixels. `OutRun2006Tweaks.ini:433-445` selects `UnifiedEyeMenuSource=false`, `FollowGameResolution=true`, `Hud1080pReference=true`, `HudScale=0.55`. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30HudContainScale:1773-1796` applies uniform `HudScale * ContainedScale(BackBufferDesc.Width, BackBufferDesc.Height)`; it does not allocate the eye texture.
4. **Separate host-authoritative XR eye size.** `vrhost/src/main_r23.cpp:2585-2645` resolves and publishes the common allocated per-eye OpenXR extent before the game window; `src/vr/ipc/xr_eye_extent.hpp:15-87` rejects mismatched or out-of-caps extents, rather than silently replacing dimensions with desktop width. `src/vr/d3d9/stereo_renderer_r7.inc::DirectTransportTargetSize:1300-1347` reads the two same-sized published eyes under seqlock, and `EnsureDirectTransportResources:1353-1357` creates one left and one right shared render texture at that **XR allocated size**, independently of `BackBufferDesc`.
5. **NEW distinct pixel-sampling boundary.** `src/vr/d3d9/stereo_renderer_r7.inc::StretchDirectEye:1349-1352` calls `IDirect3DDevice9::StretchRect(source,nullptr,target,nullptr,D3DTEXF_LINEAR)` and retries `D3DTEXF_NONE` on HRESULT failure. `ResolveDirectTransport:1358-1420` applies that same whole-surface operation separately from game `BackBuffer` and `RightEyeSurface` into the XR-sized left/right shared textures, then issues a GPU event fence. **There is no equal-source/target-size or same-aspect fast path in this helper**. Thus if source and XR extent differ and DirectGPU transport is actually selected, a full-frame resize/filter step necessarily sits *after* original D3DX/native HUD rasterization and binocular game render, even when native L/R Draw HRESULT and c64/RT restore all succeed. Whether the driver uses LINEAR or fallback NONE and whether the image is perceptibly worse are runtime questions.
6. **SafeEye and final submission are independent quality gates.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-822` gates eligible stereo, real Present and fallback. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp::CopySharedFrameToSafeEyesR32:252-319` `CopyResource`-copies validated same-size D3D11 shared-eye textures into inactive safe eyes, waits on the fence and advances `SafeFrameId`; it is not another size-correction contract. `vrhost/src/main_r23.cpp::R23RenderProjection:1437-1505` sends the full `{0,0,1,1}` UV rects of direct SafeEye SRVs through `RenderTo` per eye, and `main_r23.cpp:3562-3610` records actual `xrEndFrame`. Valid queue owner, two GPU draws, valid ring descriptor, SafeFrameId and xrEndFrame do **not** verify resulting glyph edge quality in Quest3.
