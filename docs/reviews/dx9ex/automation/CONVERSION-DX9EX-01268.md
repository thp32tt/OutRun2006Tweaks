## Static producer → semantic → queue → D3DX/native → R30/R62 → L/R → restore → Present/OpenXR

1. **Original producer (checked-in REA evidence, NOT rerun):** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md` records original OR2006C2C.exe SHA256 `68ceb386829066f8455b9d027320af962584321f3e2e8a79c72841495a6134c3`; six original +TIME E8 rel32 CALL RVAs `0x9898E/0x989AD/0x98A10/0x98A36/0x98A89/0x98AC6`; consumer `0x449050→0x42D710`; four physical exits: type0 D3DX `0x42A0A0`, type0 UP `0x42C0F0`, type1 quad `0x42A3A0`, type1 mask `0x42A800`. 36 indirect CALLs remain unresolved. These anchors do not alone establish which original physical draw enters R62.
2. **Provenance/queue:** `src/vr/game/render_semantics.hpp::PhysicalDrawCommand` captures scope/producer/queueNode/queueEpoch at physical draw. `src/hooks_uiscaling.cpp::FlushDest/EndDest` restores a deferred +TIME/GOAL producer only for an exact, homogeneous active D3DX owner at native submission, with a native Flush/End HRESULT and generation-safe cleanup; mixed/foreign/unknown queues cannot borrow ownership. A source-side CPU sprite token alone is not binocular GPU evidence.
3. **R30 routing:** `DrawIndexedPrimitiveDestR30` consumes semantic scope, first attempts F11 external ImGui, then R62 fixed-function `DIP`, then XYZRHW, then guarded R29/native when the preceding candidate returns `E_NOTIMPL`. R62 accepts corroborated `ScreenHud` or `ProjectedWorldMarker2D` with game backbuffer, TRIANGLELIST, real null VS, FVF `0x142`, valid viewport/pose, finite projections and valid HUD plane/marker anchor. For a *claimed* R62 draw, `E_FAIL` is terminal to R30: it does not imply a second fallback DIP.
4. **Left projection and native call are separate:** R62 `drawEye(0)` first writes `eyeHr[0]=SetTransform(D3DTS_PROJECTION, eyeProjection[0])`. If that upload fails, it returns **`E_FAIL`** immediately; `DrawIndexedPrimitiveHook` is **not called**. If successful, `eyeHr[0]` is overwritten with the native DIP result. `R30ExecuteXyzrhwStereo` calls `leftDraw`, treats either failure as `StereoFailureLeftDrawFailed` and arms safe fallback without proceeding to right RT/state. R62 still subsequently attempts restoration of the original projection. The helper's label is thus a *left-pass failure*, not proof of an executed failing native draw.
5. **Right RT/state and projection are separate:** Only after a successful left callback, R30 switches RT0, depth and viewport. It sets `rightFailure=StereoFailureRightDrawFailed` immediately **before** `rightDraw()`. If `SetTransform(eyeProjection[1])` fails inside `drawEye(1)`, that callback returns `E_FAIL` without calling native right DIP; `R30ExecuteXyzrhwStereo` marks `FrameRightDrawFailed`, poisons with `StereoFailureRightDrawFailed` and arms fallback. The original underlying projection-upload HRESULT remains in R62's local `eyeHr[1]`, but the helper receives synthetic `E_FAIL`, not that exact failure code. A genuine native right DIP failure can reach the **same high-level reason**. This is a CONFIRMED_STATIC **diagnostic conflation**, not confirmed headset corruption.
6. **Right-state failure versus rightDraw failure:** RT0/depth/viewport setup failure remains classified as `StereoFailureRightStateFailed` (the default before `rightDraw`), so that reason is distinguishable. However, the helper sets `FrameHadDuplicatedDraw=true`, increments `DuplicatedDraws` and `R30SafeTwoEyeDraws` **after the right-pass attempt regardless of right native DIP issuance or its HRESULT**, as long as leftDraw succeeded. These are attempt/route counters, not conclusive successful two-eye GPU-call counts. On failed right projection upload, the right DIP was not invoked despite those increments.
7. **Restoration and caller HRESULT:** `RestoreRightPassState` runs after right setup/callback and can independently note restore failure/fallback. `R30ExecuteXyzrhwStereo` returns **leftHr** even on right failure, while flags/poison reject stereo. R62 additionally attempts `SetTransform(originalProjection)` and handles restore failure; 01267 already covers exactResult-specific final restore return asymmetry. The `R26 RESULT_HUD_EYES` log records local `eyeHr[0/1]`, projectionRestored and frameIncomplete, but **does not separately log** per-eye `SetTransform` vs native DIP stage nor guarantee that the recorded right HRESULT is from DIP. A right failing upload may be distinguishable only by new stage-aware bounded trace, not by the current generic right-draw-failed reason alone.
8. **Present/OpenXR evidence boundary:** `src/vr/d3d9/stereo_renderer.cpp::PresentDest` gates `frameEligible` on `FrameHadWorldStereo && FrameHadDuplicatedDraw && !FrameRightDrawFailed && !FrameStereoIncomplete` and valid pose/resources. A successful left original return cannot override right failure gate. Incomplete stereo can restore mono when a valid mono backup exists; real normalized Present HRESULT is authoritative for publishing active stereo. x64 `vrhost/src/main_r23.cpp` uses actual `xrEndFrame`, final layer kind and submitted frameId/sourceKind to join the physical frame. No such runtime frame join was performed in this review.
