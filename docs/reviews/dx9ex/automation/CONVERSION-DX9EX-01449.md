## REVIEW_SCOPE — pinned static execution simulation (not a GPU capture)

1. **Original producer and semantic.** Original-EXE REA evidence in `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:1-42` separates 0x0042D710 type-0 D3DX Draw (0x0042A0A0), type-0 direct-UP (0x0042C0F0), type-1 animation (0x0042A3A0), and mask composite (0x0042A800). The external **F11 ImGui** source is *not* an original SpriteNode/RESULT producer and must remain `ScreenOverlay2D` with external overlay semantic depth. `src/hooks_uiscaling.cpp::VRProjectedD3DXSpriteIsolationR64::EndDest:3475-3508` shows that original ID3DXSprite End may submit a previously deferred native GPU Draw only inside its verified batch ownership; no CPU Draw or queued node alone proves a F11 physical DIP.
2. **State ownership predecessor.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1378-1417` restores optional R30 SkyGlow game state via `stateBlock->Apply()` followed by explicit RT0/depth/viewport restoration, and does **not visibly resynchronize `CurrentVertexShaderIdentity` at that local return**. `src/vr/d3d9/stereo_renderer_r7.inc:178-179,1618,1744` makes `CurrentVertexShaderIdentity` an atomic shadow updated on intercepted successful `SetVertexShaderDest` and cleared on Reset; `Apply` can restore D3D9 state without an observed call through that intercepted setter. This is a conditional cache-coherency window, NOT proof that any actual Apply changed VS or that the game lacked other resynchronization.
3. **Compare R31/R33 authority, do not migrate it.** `src/vr/d3d9/stereo_renderer_r31.cpp::R31OnStateBlockApply:580-589` records Apply and dirties recovery caches; `src/vr/state/state_block_recovery.hpp::FlushPendingResync:43-79` provides lazy callback-driven shader epoch/raster re-prime, and `src/vr/d3d9/stereo_renderer_r33.cpp:266-278,1569-1577` calls it on R33 dispatch. This is the separate R84/R31/R33 control/comparison path, **not** evidence that the R26+HUD `R30PrepareExternalImGuiProjection` automatically benefits from that lazy callback or that R84 should become default.
4. **Physical F11 candidate veto.** At `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawIndexedPrimitiveDestR30:5555-5581`, `ConsumeForDraw()` supplies the effective producer semantic and F11 gets first candidate chance. `R30TryExternalImGuiIndexed:3070-3080` calls `R30PrepareExternalImGuiProjection`; at **2873-2890**, this latter rejects when `CurrentVertexShaderIdentity != 0` **before it reaches** `GetVertexShader(&shader)`. Thus a hypothetical state `cachedVS != 0, live GetVertexShader == S_OK/null` with otherwise valid external F11 semantic/world stereo directly returns E_NOTIMPL **without querying live VS**, although the real physical device is in null-VS fixed-function mode. Unlike exact result-HUD, this F11 candidate has no cached-hint bypass.
5. **Later physical dispatch, per-eye restore and presenter.** After F11 `E_NOTIMPL`, `DrawIndexedPrimitiveDestR30:5580-5635` tries distinct R62 fixed function, XYZRHW and R29/native fallback. These are **not proof** that F11 gained independent stereo: R62 requires corroborated Game HUD/ProjectedWorldMarker and FVF 0x142 (`:5304-5350`), while `R30PrepareXyzrhwState:2560-2594` requires XYZRHW-position FVF, unlike the documented F11 XYZ/Diffuse/Tex1 format (`:2870-2900`). A later R29/native owner may still render; physical outcome is unknown. For *accepted* F11, `R30TryExternalImGuiIndexed:3080-3193` performs left native Draw, right RT/depth/viewport/projection/scissor, right Draw and explicit raster restore; the early stale-hint veto **precedes** that entire L/R transaction. `src/vr/d3d9/stereo_renderer_r7.inc::PresentDest:1625-1740` separately gates `FrameHadWorldStereo`, `FrameHadDuplicatedDraw`, right/restore failures and transport; `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` requires two `RenderTo` successes and valid eye poses/FOV/XR rectangles. Neither `E_NOTIMPL` nor a previous stereo frame proves Quest3 display pixels.
6. **Reset negative control.** `stereo_renderer_r7.inc::ResetDest:1744` clears the shader shadow and releases/stages the stereo state on D3D9 Reset/ResetEx. That is a *different* lifecycle from an in-frame or prior-frame StateBlock Apply, and clearing the shadow during Reset is not evidence that a stale nonzero cache was reconciled between normal HUD/F11 draws.
