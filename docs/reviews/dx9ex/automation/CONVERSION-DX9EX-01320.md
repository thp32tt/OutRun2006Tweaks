## REVIEW_SCOPE — independent from 01319

01319 reviewed single-execution write-free occlusion queries versus bilateral visibility. This pass instead audits **R26/R27 flat, depth-tested effect raster synchronization telemetry** against R23's trusted StateBlock shadow fast path, the separate RT0 implicit viewport/scissor live resync, and the first R23 stereo seed. The question is whether a counter labelled a resynchronization can certify a *physical live GetViewport/GetScissorRect acquisition*; it cannot in every admitted execution path. No specific sand/skid/original draw, disappearing right-eye pixel or measurable runtime stall has been captured.

### Static simulated source → final-eye path

1. **Original producer → semantic / queue epoch:** Historical original static REA distinguishes native world/effect Draw operations from 0x0042D710 SpriteNode priority walks, type0 D3DXSprite Draw/Flush/End and type1 UP. For the candidate flat depth-tested R26 effect, original CALL RVA/texture/shader/FVF and queue ownership are UNKNOWN; do not tag it as a specific sand particle or queued HUD. If queued, require 0x2D762 node+epoch and confirmed D3DX Flush/End physical draw; if direct, retain DIRECT_ORIGIN_UNKNOWN until native fingerprint. `render_semantics.hpp::CapturePhysicalDrawCommand` can record current scope and verified provenance but does not by itself prove GPU output.
2. **R30/R62 or lower native draw:** Default R26+HUD `Draw*DestR30` admits exact R30/R62 screen-UI/XYZRHW owner only on eligibility; otherwise it continues into R29/R26/R23/R22/R13/R9 conservative native DP/DIP/UP/DIP-UP handling. Do not infer R62 from `SceneEffect`, alpha, fixed-function hints or a queue tag. A flat/z-known/z-enabled effect may reach `R27ShouldBypassLegacyZeroDisparity`, but only if game device, stereo seeded, backbuffer, no auxiliary RT/occlusion uncertainty or forced mono.
3. **R26 periodic “effect state resync” scheduling:** `R27ShouldBypassLegacyZeroDisparity` requests `R23CaptureActualGameState(device, actual, "R28EffectDraw", true)` on a new Present epoch or after >=256 top-level draws, then increments `R27EffectResyncs` and advances sample epoch/serial. The wrapper comment describes live viewport/scissor resynchronization, but it does not inspect whether the callee actually performed D3D9 getters.
4. **R23 shadow-fast-path branch — confirmed:** In `R23CaptureActualGameState`, `effectForce = force && site=="R28EffectDraw"`. When `GetTrackedRasterShadow().Valid()` and `IsTrackedStateBlockReliable()`, the condition `(!force || effectForce)` is true: the routine copies cached state into `out` and **returns without GetViewport/GetScissorRect/GetRenderState**. Therefore `R27EffectResyncs` may increment on a successful trusted-shadow read, **not** necessarily on a physical live state acquisition. When shadow/reliability is absent, this forced effect call instead falls to `CaptureTrackedRasterState` and live getters; on failure the bypass returns false. This is diagnostic attribution, not evidence that the cache was incorrect.
5. **RT0 and StateBlock counterexample / fail-closed safety:** A successful game `SetRenderTarget(0,...)` enters `SetRenderTargetDestR23` and calls the same capture with site "SetRenderTarget", force=true. It does **not** take the `effectForce` fast path: it samples *live* viewport+scissor, retains the tracked `SCISSORTESTENABLE` bit only when Apply/setter shadow is valid+reliable (RT0 cannot toggle the bit), otherwise fully live-captures; `SetTrackedRasterShadow(actual)` writes the **same R22ShadowState** used by R22 replay. If live capture fails it invalidates and calls `FailClosedTrackedRasterReplay`. Independently `R22StateBlockApplyDest` re-primes live viewport/scissor/enable and marks tracker unreliable after failed/alternate interception. Thus no unsupported claim is made that RT0 resync leaves R22 stale.
6. **First seed / eye submission / restore:** Before first/recovery stereo seed, `ClearDestR23` live-captures full game raster and submits original Clear once, rejects partial viewport/scissor/rect, MRT, unsynchronized depth/stencil, stale frame pose/host, then seeds right/mono color/depth with controlled internal clears, restoring original RT/depth/viewport/scissor enable. R22 replay retains an outer captured raster and restores viewport/scissor after L/R draw; failure cancels stereo and poisons/marks mono gap. R30/R62/other exact owners still need actual L/R RT, depth, viewport, draw HRESULT and restore fingerprints — a successful logical R27 sync is not such a fingerprint.
7. **Present → OpenXR:** R9 only publishes active stereo Frame.v2 on seeded, duplicated+world L/R completion with current pose, no right-draw/incomplete failure, valid resources and successful normalized Present; otherwise mono/fallback is selected. The x64 host independently selects its final source/projection and records `xrEndFrame`/submitted layer and frame IDs. These gates cannot retrospectively prove which R23 raster read originated from device getters versus a reliable shadow, nor HMD pixels.
