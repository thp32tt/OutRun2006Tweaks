## REVIEW_SCOPE — checked-in original producer → matrix/semantic → D3DX native GPU batch → eyes/restore → Present/XR

Neither original x86/REA nor physical GPU draw was newly observed in this review.
2. **Distinct matrix input-gating confirmed.** `src/hooks_uiscaling.cpp::D3DXMatrixTransformation2D_dest:445-516` takes a VR-enabled early return for `KeepCentered` or `OnlineArcade`. For **both** non-null scale and translation and valid `Game::screen_scale/screen_resolution`, it computes a logical 640x480-style contain factor, rebinds *local* derived vectors and calls the original D3DX matrix routine; it does **not** test `Game::current_mode` or exact HUD producer here. This is an explicitly documented known-good compatibility rollback, not proof of accidental HUD displacement. The **separate**, non-early-return `originalFrontEndProducer` title/menu/selector gate only appears at `:528-543`, with front-end full/partial/pivot containment at `:555-699`. It cannot be assumed to gate the earlier VR full-vector call. The early branch leaves original caller input pointers untouched and passes nullable/partial vectors through unchanged.
3. **Logical source differs from actual physical raster state.** `src/vr/ui/vr_logical_coordinate_space.hpp:1-46` defines contain geometry from game-source width/height against original logical width/height (not XR extent), returning a validity flag for nonfinite/zero inputs. The early VR mapping samples `Game::screen_scale`, `Game::screen_resolution` and `Game::original_resolution` at *CPU D3DX matrix-construction time* (`hooks_uiscaling.cpp:461-505`). The audited branch does not attach a source-resolution/matrix generation, menu-mode tag, native viewport ID, or XR image extent to that D3DX output. This is a local code observation, not proof any two actual generations differ.
4. **Semantic and delayed batch have other, stronger identities.** `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1837` consumes queue node and epoch with exact producer tags. `src/vr/game/hud_command_batch.hpp::Ledger:74-141,177-282` stores native Begin/mutation, homogeneous producer, queue node/epoch and flush success; it does **not** store the original `D3DXMATRIX` transform or `Game::screen_resolution` generation. `src/hooks_uiscaling.cpp::VRProjectedD3DXSpriteIsolationR64::BeginDest/FlushDest/EndDest:3407-3508` keeps original native HRESULT and restores only proven homogeneous exact source at physical Flush/End; unknown/mixed or changed source fails closed. A positive queue token therefore cannot certify which logical-to-physical matrix was active when D3DX actually rasterized the triangles.
5. **Native draw to R22 and R62/R30, with guarded fallbacks.** A type-0 fixed-function physical indexed Draw reaches `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R62TryFixedFunctionSpriteIndexed:5126-5352` only under valid exact ownership, triangle-list, null VS, FVF `0x142`, live `GetViewport`, finite original D3DX projection and valid latched pose. For exact ScreenHud it post-multiplies that *original projection* with separate per-eye finite-HUD clip maps; it does not resample earlier D3DX matrix inputs. `::R30ExecuteXyzrhwStereo:3829-3945` draws L/R, switches/restores RT/depth/viewport and marks failed right/restore states; R62 independently restores original projection. `::DrawIndexedPrimitiveDestR30:5377-5461` falls through after R62-only `E_NOTIMPL` to XYZRHW/R29/original; type-1 native UP follows `::DrawPrimitiveUPDestR30:5464-5490`, **not** D3DX indexed provenance. If installed and eligible, `src/vr/d3d9/stereo_renderer_r22.cpp::R22ReplayScope:341-395,::DrawIndexedPrimitiveDestR22/DrawPrimitiveUPDestR22:639-714` snapshots and restores game viewport/scissor around the outer draw. A restored physical viewport does not prove an earlier authored 640x480 D3DX matrix used its intended pixel basis; absent proof of R22 activation one must not grant its guarantees.
6. **Terminal output is a separate frame/extent contract.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-818` requires world-stereo, duplicated draws, valid pose, right-eye/restore and successful native Present, with mono/SBS/DirectGPU fallback. `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` separately samples DirectGPU full-eye UV or SBS half-UV, draws per-eye XR projection images at `projection_.width/height`; `::xrEndFrame:3562-3599` submits a frame.
