## Static producer → semantic → queue → D3DX/native physical draw → R30/R62 → eyes → Present/XR simulation

1. **Grounded input paths, not a GPU attribution.** Checked-in original-game REA `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:3-46` establishes +TIME's six verified direct E8 callsites and the original sprite queue's type0 D3DX/UP and type1 quad/mask outgoing functions. These verify possible producers, **not** that +TIME/GOAL uses an R30 VB/IB DIP. `render_semantics.hpp::SelectSpriteQueueNode/EndSpriteQueueRender:1789-1868` owns node/producer/epoch and partial queue lifetime; `hooks_uiscaling.cpp::BeginDest/FlushDest:3407-3469` preserves proven deferred D3DX batch ownership. Semantic or early D3DX Draw alone is insufficient evidence of the **terminal** native GPU API.
2. **R26 active owner.** `AGENTS.md:1-17` and `CMakeLists.txt:95-153` make R26+HUD default in a fresh option-free configure, with R84 explicitly non-default. Physical `DrawIndexedPrimitiveDestR30:5377-5461` tries F11 external ImGui, R62 exact fixed-function indexed sprite ownership, then `R30TryXyzrhwIndexedPrimitiveVB:4233-4496`, with original R29/native guarded fallback only for `E_NOTIMPL`. The issue under review can only affect actual buffer-object-backed VB/IB draws; D3DX flushing to UP, nonindexed UP, and R62-owned draws require independent handling.
3. **Creation hook and object method placement.** `stereo_renderer_r30_r26_safe.cpp:327-348` allocates one process-global `SafetyHookInline` slot for each device CreateVertexBuffer/CreateIndexBuffer and VB/IB Lock, Unlock, Release. `R30InstallBufferCreationHooks:844-861` reads the incoming device vtable but creates detours only if the global slot is empty. `R30CreateVertexBufferDest:789-823` invokes `R30EnsureVertexBufferHooks` and uses its boolean to gate early explicit-FVF XYZ/RHW VB registration; `R30CreateIndexBufferDest:826-842` calls `R30EnsureIndexBufferHooks` without using its result for registration. For later *different* D3D9(Ex)/wrapper device method addresses, the install routine contains **no per-address equality check**.
4. **NEW distinct source-confirmed check gap.** `R30EnsureVertexBufferHooks:744-768` and `R30EnsureIndexBufferHooks:770-787` extract each buffer object's vtable and hold `R30ShadowHookMutex`, but skip creating the Lock/Unlock/Release hook when their **single global** hook object is already non-null; return truthiness of those global hooks without verifying that the new buffer's `vtable[11/12/2]` points at the hooked target. This is a demonstrable **absence of per-implementation method-address validation**, **not** proof that a second distinct vtable exists, that its methods execute unhooked, or that a use-after-free occurred. If all actual objects share the same implementation addresses, the current design is sufficient. Mutex protects installation concurrency; it does not establish cross-vtable equivalence.
5. **Partial installation / raw-address lifetime are bounded hypotheses.** `R30CreateIndexBufferDest` ignores `R30EnsureIndexBufferHooks`'s false result; `R30CreateVertexBufferDest` excludes failed early XYZ/RHW registration and can still lazily allocate a global-armed shadow. `R30TryXyzrhwIndexedPrimitiveVB:4250-4314` calls both `R30Ensure...Hooks` but does not test their return values, then arms capture and rejects an IB whose observed valid range is absent **before physical stereo submission** via `R30CopyIndexShadow`. `R30VertexBufferReleaseDest:682-695` and `R30IndexBufferReleaseDest:726-739` remove registry entries at final Release if detoured; entries are keyed by raw COM pointer (`:379-503`). If a *different unhooked Release method* and eventual same-pointer reuse are ever demonstrated, shadow lifetime/size/generation would need separate examination. Existing `GetDesc`, 16-MiB per-entry, 64-MiB total shadow budget, observed Lock coverage and copy bounds are real protections; no actual stale pointer reuse has been observed. Reset (`ResetDestR30:1511-1521`) disarms global capture but does not certify COM Release/recreation.
6. **Negative test-scope distinction.** `tools/verify_vr_r30_buffer_hook_install_fastpath.py:1-100` explicitly reads `src/vr/d3d9/stereo_renderer_r30.cpp` (R84 owner) and checks ready-flag fastpaths plus 13 mutations. Its PASS cannot alone validate `stereo_renderer_r30_r26_safe.cpp` **R26 default** hook-address identity or lifetime across distinct COM implementations. This is a test-coverage observation, not a claim that the test is broken or that CI has failed. No test was executed or modified in this task.
7. **Stereo/host gate.** When source buffers and owner/projection tests permit, `R30ExecuteXyzrhwStereo:3829-3945` performs physical L/R draws with RT/depth/viewport restore, while VB/IB conversion restores original game stream/index in `:4483-4496`; an observed shadow is not proof of both eye pixels.
