5. **Install-time coverage reset is not the same as reset-time raster re-prime**: `src/vr/d3d9/stereo_renderer_r31.cpp::R31InstallThread:595-660` explicitly calls `ResetCoverageLoss` when installing the event consumer, configures recovery callbacks and event fan-out, checks R22 lifecycle readiness, then publishes EventConsumerReady. In contrast, `src/vr/state/state_block_recovery.hpp::StateBlockRecovery::FlushPendingResync:42-82` optionally resamples shader/raster when callbacks are configured and a resync was queued; it does not clear CoverageLost when a prime succeeds. These audited paths do **not** establish that successful D3D9 Reset automatically requalifies previously lost Apply coverage. Another non-audited recovery owner could still change the global flag; no assertion is made about all source paths.
6. **Result physical Draw on a recovered frame can be safe yet follow a slower conservative route**: `src/vr/d3d9/stereo_renderer_r29.cpp::R29EffectCacheCurrent:125-149` rejects effect-state cache reuse if recording, `!StateBlockTracker::Reliable()`, generation/epoch mismatch or stale draw serial; it instead requires the conservative live-state path. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30SafeStereoBase:75-94` independently rejects recovery, warmup, unseeded, deferred-depth, incomplete-frame and other hazards. `::R62TryFixedFunctionSpriteIndexed:5171-5380` admits only exact FVF 0x142 fixed-function indexed candidates and restores projection; `::DrawIndexedPrimitiveDestR30:5425-5512` can fall through to XYZRHW/R29. `src/vr/d3d9/stereo_renderer_r30.cpp::R30ExecuteXyzrhwStereo:6158-6469` validates original exact GOAL source before/after native-left and before right, uses the tracked-null right-depth shortcut only if StateBlock tracking is Reliable (`6336-6417`), otherwise retains full depth/RT/viewport restore and publishes a stereo draw only on actual left/right/restore success. Thus even a fully recovered R23 seed does not imply a particular R29 cache hit or depthless shortcut.
7. **Frame transport cannot certify which recovery gate was active**: `src/vr/d3d9/stereo_renderer_r7.inc::PresentDest:1625-1745` requires completed left/right/world stereo and successful real Present; DirectGPU adds the post-Present completion event. `vrhost/src/main.cpp:2700-2719` checks matched game frame/pose and can reuse last-safe projection during bounded grace. A host OpenXR projection (or a nonblank GOAL image) does not prove the R22/R31 coverage flag recovered, cache fast paths were used, or a specific first GOAL physical draw got both eye pixels. Issue #6 is review context only, not device evidence.
