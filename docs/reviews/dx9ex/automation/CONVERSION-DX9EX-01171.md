## REVIEW_SCOPE — original rank/rival producer → queued semantics / D3DX Flush → native GPU API → R62 vs XYZRHW / R29 → L/R restore → Present / OpenXR

1. **Original producer and source limits.** Checked-in REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-42,69-74` maps frame scheduler `0x00449050`, 6th/6 *fixed HUD* `0x004B9D80`, car-attached rank `0x004BAD20` and `Calc3D2D 0x00449940`, plus priority consumer `0x0042D710`. Queue type-0 `ID3DXSprite::Draw` can remain CPU-pending until physical Flush/End; type-1/flagged draws can use native `DrawPrimitiveUP`. Rival and each ordinal are **not presumed** to share a physical GPU API. REA is repository historical static reconstruction, not a new x86 decode.
2. **Semantic / batch ownership.** `src/vr/game/render_semantics.hpp:998-1027,1042-1045,1076-1080` prioritizes an exact queued scope over an unrelated one-shot during the outer physical Draw. `src/vr/game/hud_command_batch.hpp:177-260` requires homogeneous producer, queue-node and epoch before treating delayed D3DX submissions as one exact batch; a CPU sprite label is not the physical Flush's final GPU owner. The independent 2026-10-21 historical rank review documents older R62 and R64 omission/restoration, and NaviPub-classification uncertainty; these are **not claimed as fresh defects** (`docs/automation/reviews/DX9EX_R26_RANK_RIVAL_HISTORICAL_FIRST_REGRESSION_AUDIT_20261021.md:13-35`).
3. **Default/physical dispatch.** `AGENTS.md:1-11` and `CMakeLists.txt:99-150` make option-free R26+HUD the current default, not R84. In `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawIndexedPrimitiveDestR30:5367-5451`, one physical DIP consumes scope, tries F11 external DIP (exclusive), **R62 fixed-function SpriteIndexed**, XYZRHW indexed VB, then R30 screen-space/R29/original fallback. Separate UP/DP APIs are not automatically R62; `E_NOTIMPL` indicates candidate refusal rather than a finished binocular result.
4. **R62 exact draw eligibility and optical route.** `R62TryFixedFunctionSpriteIndexed:5116-5188` requires triangle-list, backbuffer, stereo base, positively corroborated `ProjectedWorldMarker2D` or `ScreenHud`, null live VS, FVF `0x142`, pose sequence, viewport, resources, affine and finite stock projection. The projected branch `:5190-5214` builds a per-eye clip shift based on recovered projected anchor delta/base/scale; the HUD branch `:5215-5263` uses a finite recentered HUD plane. `R30ConfigureXyzrhwWorldEffect:3075-3168` makes projected ownership require `CurrentProjectedMarker()->valid`, finite renderer base projection and successful `R57BuildProjectedMarkerDelta`. A verified screen-HUD label does **not** mean a verified car anchor; conversely, a projected scope with missing marker data refuses the R62 owner.
5. **Physical two-eye / restore.** `R62TryFixedFunctionSpriteIndexed:5265-5337` sets eye-specific projection and calls the actual `DrawIndexedPrimitiveHook` through `R30ExecuteXyzrhwStereo:3820-3934`. The latter renders left, switches right RT/depth/viewport, attempts right Draw, restores tracked RT/depth/viewport and fail-closes the frame if right or restore fails; R62 also restores the stock projection. This is source control flow, **not** proof any particular ordinal or rival reached both eyes. 01168 already investigated the helper's left-HRESULT/right-failure semantics; this review does not claim it anew.
6. **NEW static diagnostic visibility difference.** R62 `FIXEDFN KIND0` logging `:5299-5313` for non-result projected/HUD traffic records **owner label, producer token, FVF, primitive count, marker-present bit, aggregate hit count**. It does **not** print this draw's queue node/epoch, actual captured marker car identity/depth, pose, left/right `eyeHr`, projection-restore outcome or final path/Present ID. The richer `RESULT_HUD_EYES` sample `:5314-5335` *is conditionally enabled only for `exactResult && Settings::VRTelemetry`* and includes node/epoch/pose/left-right HRESULT and restore; `RESULT_HUD_REJECT` `:5402-5429` is likewise result-only and explicitly says `finalRoute=UNDETERMINED`. **Therefore a positive non-result R62 hit plus maker=1 cannot by itself establish that ordinal 1–5 or rival used a unique valid car anchor and reached two successful physical eye draws.** The log difference is confirmed; the assertion that it causes the user's current screen symptom is unproven.
7. **Last-frame boundary.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-822` requires world-stereo, duplicated draw, valid metadata and no incomplete/right failure before final stereo state. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:267-319` publishes a safe copied pair after the GPU copy fence; `vrhost/src/main_r23.cpp:3555-3615` distinguishes actual `xrEndFrame` submission ID. Neither the R62 hit counter, successful API result, successful Present nor host SafeFrameId proves that a **specific rank/rival source node's** pixels reached Quest3 in both eyes.
