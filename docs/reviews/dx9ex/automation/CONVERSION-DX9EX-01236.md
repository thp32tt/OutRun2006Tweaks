1. **Default owner and original four branches.** `AGENTS.md:1-12` and `CMakeLists.txt:95-153` declare option-free R26+HUD (R84 explicit comparison only). Original REA `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:3-43` records original EXE SHA-256 `68ceb386829066f8455b9d027320af962584321f3e2e8a79c72841495a6134c3`, original 0x449050 -> 0x42D710 queue, type-0 D3DX 0x42A0A0 (later Flush/End possible), type-0 flagged UP 0x42C0F0, type-1 UP 0x42A3A0 and masked 0x42A800. This checked-in disassembly is not a new live original EXE capture. Exact +TIME and GOAL producer calls may be multiple nodes/native Draws.
2. **Reset can expire tags before device Reset succeeds.** `src/vr/d3d9/stereo_renderer_r13.cpp::ResetDestR13:425-461` conditionally compiles `GameSemantic::EndSpriteQueueFrame(true)` in `OUTRUN_VR_R26_HUD_COMPARE` and invokes it for the game device *before* testing `R13OverlayReady`/compatibility and *before* `ResetCompatDevice` returns an HRESULT. Therefore even failed/unsupported Reset attempts have already performed the semantic tag-expiry call (subject to the expiration function's cutoff). This is an observable ordering in source, not a demonstrated visual fault.
3. **Tag expiry is not a full active-scope invalidation.** `src/vr/game/render_semantics.hpp::EndSpriteQueueFrame:1870-1909`: the deviceReset branch bypasses the active-depth deletion veto, removes tags with serial <= current publication cutoff, resets `SpriteNodeSemanticFrameExpireCutoff` and `SpriteNodeSemanticActiveQueueCutoff` unless the early `cutoff == 0` return fires. It does **not** clear `SpriteQueueDepth`, `CurrentSpriteQueueNode`, `CurrentQueueExactScope`, `CurrentQueueProducer`, `CurrentScope` or `NextDrawScope`. The early-return case also does not clear the active cutoff. By contrast, `EndSpriteQueueRender:1840-1868` unwinds scope only when the queue depth actually reaches zero. A normal completed queue will unwind; Reset alone need not.
4. **A retained exact scope can influence the next physical draw, but only under a specific interleaving.** `render_semantics.hpp::EffectiveScope/ConsumeForDraw:977-1027` first accepts exact selected queue scope while `SpriteQueueDepth != 0`, before a pending one-shot token and unrelated generic scope. `BeginSpriteQueueRender:1751-1787` only establishes a fresh queue snapshot at depth 0; `SelectSpriteQueueNode:1789-1838` replaces the selected scope when a *new node* arrives. `src/hooks_uiscaling.cpp::VRHudQueueSemanticBridge::QueueNode/QueueEnd:4152-4175` connects actual original queue-node/epilogue hooks. Thus the narrow hypothesis requires a Reset while a queue node is selected, followed by a native Draw before a new node selection or a complete queue epilogue; ordinary non-reentrant game-loop Reset with depth=0 is contrary evidence. No such sequence was observed.
5. **Reset and StateBlock/draw safeguards are distinct.** `src/vr/d3d9/stereo_renderer_r22.cpp::ResetDestR22:562-580` fail-closes stereo eligibility, clears depth baseline and raster shadow before R13 Reset; successful Reset re-primes raster. `::CreateStateBlockDestR22/EndStateBlockDestR22:233-277` arms Apply interception for *newly returned* blocks; `::R22StateBlockApplyDest:155-179` invalidates and re-primes shadow after intercepted successful Apply. This does not explicitly cancel a retained `GameSemantic` queue scope. `::Draw*DestR22:625-717` gates native callbacks behind eligibility and replay raster capture. Guarded first seed/full-clear and depth-generation conditions `::R22GameClearCoversBackbuffer/R22InitialDepthBaselineSafe:473-536` reduce exposure; absent fresh post-reset eligibility no stereo is attempted. This is not a repeat assertion of 01235's coverage-loss path.
6. **Physical draw routing is conditional.** At the first native game DP/DIP/DPUP/DIPUP, `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::Draw*DestR30:5349-5526` consumes the selected semantic, may try R62 fixed-function or R30 XYZRHW, else returns through guarded original/R26/R29 route. A retained exact semantic could only matter *if* a physical Draw is actually reached while that scope persists; a queued producer or ID3DXSprite::Draw label alone does not identify GPU API, RT, VS/PS/FVF or L/R pixel ownership. `::R30ExecuteXyzrhwStereo:3829-3945` explicitly records L/R HRESULT, right RT/depth/viewport restoration and fail-closed state on right/restore failure. A successful code path is not HMD evidence.
7. **Present to actual XR boundary.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:680-823` requires a seeded, world-eligible, duplicated, pose-matched frame and successful device Present before publishing active stereo; otherwise fallback/reset counters apply. `vrhost/src/main_r23.cpp:3562-3615` records the actual intercepted `xrEndFrame` submitted frame/layer identity, not guaranteed by a game's queue node or successful draw. Neither automatically attests to clearing active queue semantic context at Reset. GitHub Issue #6 is an existing continuous-review inbox and contains no task-specific post-Reset physical draw proof.
