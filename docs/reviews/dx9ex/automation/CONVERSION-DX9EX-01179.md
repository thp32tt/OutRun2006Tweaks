## REVIEW_SCOPE — producer → semantic / queue epoch → D3DX/native GPU draw → R30/R62 or lower R26 → L/R restore → source pixels → Present/OpenXR

1. **Original game producer, not a physical draw.** The checked-in *historical* REA map `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-43,62-71` identifies `0x00498670` original +TIME, `0x004973C0/0x004974E0` numeric glyph paths, and `0x0042D710` priority SpriteNode consumer. Kind-0 `0x0042A0A0` can defer `ID3DXSprite::Draw` until `Flush/End`; kind-1 or flagged kind-0 can end at native `DrawPrimitiveUP`. A CPU producer or a single glyph's source UV is therefore not a physical draw's sampler/texture guarantee. These are prior REA notes, **not** new disassembly or an observed GPU event.
2. **Texture/UV producer boundary.** `src/hooks_textures.cpp::put_sprite_ex2_dest:1119-1163` snapshots queue/source evidence, conditionally matches an enabled UI replacement texture (and separately a child mask), temporarily changes original `SPRARGS2` UVs, invokes the native producer, then restores parent/mask UVs. `::put_sprite_ex_dest:1165-1190` separately conditionally changes `SPRARGS` UV/pixel scaling and restores after native return. Exact transforms and restore are in `src/vr/game/sprite_uv_transaction.hpp::ScopedSprArgs2Scale:13-62; ::ScopedSprArgsScale:65-105`. This is a *producer-side*, replacement-dependent transaction; it does not demonstrate whether the exact +TIME glyph uses either wrapper or which UV rectangle reaches a deferred D3DX native Draw.
3. **DDS mip-source boundary.** `src/hooks_textures.cpp:395-422` constrains fast-loader mip requests to available DDS levels (with the `MipLevels==0` UI path reduced to one in that fast path); `:1293-1330` validates replacement DDS headers, dimensions and entire mip payload before publishing replacement scaling. This proves possible content/mip **input** differences; no present evidence binds one of these DDS files/mip levels, filter modes, atlas coordinates or texture objects to the observed +TIME/GOAL/result glyph at the final GPU draw. Do not infer a global sampler setting from a loader.
4. **Semantic → physical GPU API.** `src/vr/game/render_semantics.hpp:246-300,340-390,979-1027,1374-1383` makes exact producer/queue-batch ownership conditional and warns of deferred `Flush/End`. `src/vr/game/hud_command_batch.hpp:8-42,67-122` documents sprite/generation/queue epoch and internal texture-switch Flush; it is not proof that any sampled glyph was homogeneous at runtime. On the compiled R26+HUD owner, `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30IsExactResultHudDraw:3073-3082` requires an exact finite result and valid queued node/epoch. Physical DP/DIP/UP enter `::DrawPrimitiveDestR30/::DrawIndexedPrimitiveDestR30/::DrawPrimitiveUPDestR30/::DrawIndexedPrimitiveUPDestR30:5349-5530`: R62 fixed-function candidate `::R62TryFixedFunctionSpriteIndexed:5116-5348`, XYZRHW early owners, shader `::R30GuardScreenSpace:5114-5138`, and lower R26/native fallback must be distinguished by **actual** accepted draw, not by producer identity. Right/left HRESULT and original projection/RT/depth/viewport restoration still gate acceptance.
5. **Physical texture/sampler boundary (newly audited).** The compiled R26+HUD `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1117-1155` expressly sets stage-0 `MINFILTER=LINEAR`, `MAGFILTER=LINEAR`, `MIPFILTER=NONE` and clamp while drawing the **SkyGlow postprocess** native fullscreen quad. The reviewed R30 gameplay HUD draw dispatcher `:5114-5530` does **not** establish that those SkyGlow settings are the sampler state of an original +TIME/GOAL D3DX texture draw, nor does the producer UV transaction capture that final state. D3DX internal flushes/StateBlocks may create additional boundaries. Consequently a final HUD screenshot cannot separate shader/geometry scalar differences, DDS/UV sampling, source pixel density and post-copy StretchRect solely from these static code snippets.
6. **Eye and host delivery after rasterization.** The accepted per-eye game draw and state restoration write into game-side eye surfaces before `src/vr/d3d9/stereo_renderer_r7.inc::StretchDirectEye:1349-1352` copies source into the DirectGPU eye ring with `D3DTEXF_LINEAR` (fallback `NONE`); `::EnsureDirectTransportResources/ResolveDirectTransport:1353-1398` owns the ring/ack boundary. `vrhost/src/main.cpp::PrepareDirectStereoSource/CommitDirectStereoSource:1342-1395` opens/copies the exact frame; `::RenderProjection:1435-1468` uses paired eye sources; `:2004-2007,2694-2717` acquires/waits XR textures and ultimately calls `xrEndFrame`. Thus source-RT jaggies before the ring must be distinguished from whole-eye scaling or OpenXR presentation. No Quest3/VDXR or screenshot comparison was performed.
