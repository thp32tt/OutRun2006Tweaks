## EVIDENCE — pinned current GitHub source and checked-in original REA

1. **Original +TIME parents are not all one sprite kind.** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:4-39` establishes SHA-pinned original six E8 calls: 0x9898E/0x98A36/0x98AC6 animation and 0x989AD/0x98A10/0x98A89 text/number. `src/hooks_uiscaling.cpp:373-400` intentionally tags only five exact +TIME parents: two B4/B5 sprani + three number calls; 0x98AC6 is the distinct mode-2 6C animation, not a proven +TIME HUD. In the same REA, original 0x42D710 queue dispatch can go through type-0 D3DX (0x42A0A0), type-0 direct-UP (0x42C0F0), type-1 animation quad (0x42A3A0) and masked quad (0x42A800). This original-static evidence cannot itself identify a contemporary physical GPU callback.
2. **Direct-versus-queued identity survives original E8 only conditionally.** `src/hooks_uiscaling.cpp:1690-1789` checks VR/queue admission and queue epoch before source-time direct ScreenHud ownership, tags only new tail nodes after a matching source exit, and attempts a proven direct D3DX flush before restoring old scope. `src/vr/game/stage_extension_source_admission.hpp:6-50` explicitly fails closed on VR toggles and changed queue epoch; `src/vr/game/render_semantics.hpp:1410-1519` separates physical draw command, queue epoch and temporarily suppressed unproven native D3DX Flush/End. Missing proof therefore means **one native/original draw** is an allowed outcome, not established disappearance.
3. **Native D3DX CPU Draw is not physical draw.** `src/hooks_uiscaling.cpp:3196-3266,3367-3507,3837-3965` tracks a *homogeneous* batch against the actual game ID3DXSprite pointer, handles reentrant Begin/Flush, isolates an old exact producer when a foreign texture Draw might implicitly flush it, and clears/suppresses mixed or unproven submission semantics. `src/vr/game/hud_command_batch.hpp:15-157` preserves per-node/queue/generation identity and reentrant mutation serials. GOAL B9200 parent-stack proof is constrained by `src/vr/game/goal_result_parent_provenance.hpp:9-57`; unsafe EXE +5 midhooks remain uninstalled. An R62 DIP at this boundary is not established merely by the earlier original E8 hook or a CPU-side ID3DXSprite::Draw result.
4. **Actual R62 admission has a separate physical signature.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:3196-3205` calls `CapturePhysicalDrawCommand` for an exact result family, with a live queue node+epoch required for queued identity. `:5315-5380` rejects R62 except actual backbuffer + safe stereo + exact ScreenHud/projected semantic + triangle list, absent *live* VS and actual FVF `0x142`. It explicitly distinguishes a possibly stale cached VS hint from `GetVertexShader`. Subsequent `:5380-5517` computes two eye projections, performs physical indexed draws via `R30ExecuteXyzrhwStereo`, restores original fixed-function projection, and logs `RESULT_HUD_EYES` when exact result telemetry is enabled. R62's E_NOTIMPL means only **this candidate** did not acquire the draw.
5. **Decisive diagnostic limit: `RESULT_HUD_REJECT` is deliberately stage-only.** `stereo_renderer_r30_r26_safe.cpp:5555-5638` calls external F11, R62, then XYZRHW VB, then `R30GuardScreenSpace`; it logs `VR R26 RESULT_HUD_REJECT: stage=R62_ONLY finalRoute=UNDETERMINED` immediately when R62 returns E_NOTIMPL. This is **before** XYZRHW, shader-c64 and delegated R29/original processing of the same DIP, so the logged rejection cannot prove final single-eye rendering, missing glyph, or successful two-eye output. No final route or GPU outcome is joined to that log line in this inspected path.
6. **Remaining original/shader route is independently gated.** `stereo_renderer_r30_r26_safe.cpp:4938-5147` attempts source-corroborated screen shader c64 and head-local/canted eye math, rejects missing pose/resources/depth/stencil and returns E_NOTIMPL as needed. `:5148-5297` executes L/R actual primitive calls, saves/restores original c64, RT/depth/viewport, and on right failure poisons stereo frame. `:5292-5303` delegates to R29 on E_NOTIMPL. `:3958-4074` likewise performs the R30 XYZRHW two-eye draw/restore and failure poisoning. These paths explain why stage-R62 reject is not final-path evidence; they do *not* prove which one an original +TIME/GOAL glyph uses at runtime.

None turns an R62-only rejection log into final HUD pixel truth. The 2026-10-22 direct R26 SkyGlow parity integration is recorded separately in `docs/reviews/dx9ex/FOCUS_REVIEW_INTEGRATION_20261022.md`; do not re-report it as an unpatched 01421 bug.
