## NEW_FINDING — SOURCE_CONFIRMED cross-process gate, runtime impact conditional

- NEW_FINDING=HOST_DIRECTGPU_PRIVATE_SNAPSHOT_FENCE_FAILURE_CAN_WITHHOLD_ACK_AND_INVALIDATE_GRACE_SOURCE.
- CLASS=SOURCE_CONFIRMED_CONTROL_FLOW; DEFECT_ON_QUEST3=NOT_ESTABLISHED; PERFORMANCE_BOTTLENECK=NOT_MEASURED.
- FACT: Game-side bounded wait (1 ms) is **not** the end of the producer-to-headset critical path. The host introduces two further CopyResource calls, per-call D3D11 EVENT CreateQuery+Flush+up-to-8-ms GetData wait before it ACKs a frame. On host snapshot failure it clears direct-frame validity, and game may retain unACKed published resource slots. The default summary logs fenceTimeout but omits maintained ringBackpressure. The host's 250-ms grace requires an actually valid cached source, not merely a previously matching frameId.
- HYPOTHESIS_ONLY: under transient host copy/query latency, fresh stereo admission may fall while game ring backpressure grows; when no SBS source remains valid, a prior match might not produce an OpenXR projection layer despite nominal grace. There is NO proof that this path caused the user's dense-buildings/sand FPS drops, missing HUD, or headset blanking. The original game, GPU driver, DX11/DXVK conversions, host timing and OpenXR compositor may dominate instead.
- FALSIFY: correlate an affected interval where every D3D11 copy fence completes well within budget, host ACK advances at expected cadence, ringBackpressure remains zero, `directFrameValid_` stays true and `xrEndFrame` submits a projection; then this mechanism is not the cause. Also disprove the missing-layer hypothesis by showing an independently valid SBS backup or persistent direct source on every failed snapshot. Under true latency spikes, require exact game/host frameId + QPC + GPU EVENT and eye-image correlation. Aggregate FPS alone cannot establish causality.
