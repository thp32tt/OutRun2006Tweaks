## REVIEW_SCOPE — independent from 01320

01320 resolved the static meaning of R27 effect *raster* sync. This pass instead examines **game SetDepthStencilSurface success/failure/no-op and Reset/device-loss transitions**, the R9 depth call counter, R23 passive depth/stencil Clear epoch+draw-serial+generation fences, R22 replay/restore, and the final physical L/R -> Present -> OpenXR route. This is a logical source simulation, **not an observed actual game depth-bind failure**.

1. **Producer / semantic / queue:** Existing original-game REA documents independent world/effects, partial priority 0x0042D710 SpriteNode traversal, +TIME/result type0 D3DXSprite deferred Draw/Flush/End and type1 direct UP. It does not identify an original depth-bind failure CALL RVA, a particular failed GPU draw, or the native D3D9 effect for this scenario. A queued draw requires 0x2D762 queue-node/epoch and eventual D3DX Flush/End physical identity; direct depth operations retain UNKNOWN producer until the original CALL and actual bound surfaces are captured. `CapturePhysicalDrawCommand` reports effective scope/producer/queue identity only; it is not GPU completion.
2. **R9 native depth-bind boundary:** In `SetDepthStencilSurfaceDestR9`, non-game/internal calls pass through. For game calls `R9DepthCalls` increments **before** invoking the actual `SetDepthStencilSurfaceHook`. If HRESULT fails, R9 returns immediately without replacing `TrackedDepthStencil` or applying the changed/auxiliary/main-depth branches. If HRESULT succeeds but the surface pointer is unchanged, the counter still increments and the function returns at `if (!changed)`. A changed success can bind null, recapture eligible main depth, restore exact main depth from a deferred auxiliary bind, or defer a foreign non-null identity. `R9MainDepthGeneration` advances at successful `R9CaptureMainDepth`, not on every SetDepthStencilSurface attempt.
3. **Passive Clear and first-seed authority:** Before first seed and during recovery, R23 captures live game raster and executes a game Clear **once**. Only a successful full-backbuffer clear with mirror-eligible depth records independent Z/stencil `PresentEpoch`, `R23GameDrawSerial`, `R9MainDepthGenerationValue()` and values. A later full color candidate requires a matching current depth generation and unchanged draw serial; stencil also must match if stencil testing is active. Failed/auxiliary binding cannot be assumed to record a valid main-depth clear. There is no proof that the R9 *call* count itself governs this admission.
4. **Failed Reset and generation fencing:** R22 `ResetDestR22` closes eligibility, clears older R20/R22 seed stamps and invalidates raster shadow before forwarding Reset. R9 releases mono/main-depth identity, clears stereo seed and sets `R9ExpectMainDepthAfterReset` before native Reset; only successful post-reset main depth capture advances generation. R23's passive depth/stencil stamp variables are not explicitly reset in the examined R22 reset helper; this is **not by itself stale-seed admission**: R9 mirror eligibility fails without known exact main identity, and a newly recaptured main surface advances generation, while R23 also requires a matching Present/draw-serial fence, real full game Clear and fresh current-frame pose. Failed Reset retains fail-closed eligibility; no desktop/HMD runtime assertion follows.
5. **R30/R62 physical draws and restore:** After an actual producer/semantic/queue-specific native DP/DIP/UP choice, default R26+HUD R30 tries exact XYZRHW or R62 fixed-function sprite ownership where eligible, otherwise R29/R26/R23/R22/R13/R9 conservative paths. One R9 `depth` call or R23 passive-clear counter cannot establish that a particular D3DX deferred batch physically drew L/R. R23 first seed replays verified color into right/mono, clears private depth (and stencil only if safe), restores actual RT/depth/viewport/scissor/enable, then R22 L/R replay must preserve native draw HRESULT/RT/depth/viewport and restore; failures close stereo or poison/invalidate its frame. A passive Clear alone is not an eye draw.
6. **Present/OpenXR:** R9 needs world+duplicated L/R completion, pose and successful frame composition/direct transport to publish active Frame.v2 after normalized Present; otherwise it attempts the mono backup/fallback. x64 host independently selects its source/layer, records actual `xrEndFrame`, submitted frame and timing. None validates the identity/outcome of an earlier D3D9 failed/no-op depth bind from R9DepthCalls alone.

- **Fact:** `R9DepthCalls` is an *attempt/call* metric, and is correctly labelled `calls[depth]` in the R9 summary. It cannot, on its own, quantify successful COM depth-identity changes, depth-generation advances, GPU work, or Reset recovery events. It includes failed HRESULTs and successful binds of the same surface.
- **Important contrary evidence:** This is not proof of defective rendering. Early return on failure leaves tracked depth unchanged; same-pointer success is legitimately a no-op; R9 maintains additional `transient/restores/reacquire/current/main/deferred` data, and R23 does **not** use `R9DepthCalls` to validate a new stereo baseline. Reset closes the common gate; there is no source evidence a failed SetDepthStencilSurface automatically produces stale right-eye stencil or a real performance regression.
- **Conditional hypothesis:** An external investigation that attributes depth resource churn or frame stalls to the number printed as `calls[depth]` alone could overcount actual state transitions, especially during repeated failed or same-pointer binds. If measured CPU/GPU frame pacing already correlates successful depth transitions and actual native draw/restore independently, reject this attribution concern.
