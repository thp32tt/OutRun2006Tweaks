## EVIDENCE — original producer -> semantic/queue -> native draw -> R30/R62 -> eyes/restore -> Present/OpenXR

1. **Original queue scope is orthogonal to query lifetime.** Existing checked-in REA `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-32` maps original `0x449050 -> 0x42D710` to D3DX `0x42A0A0` (deferred Begin/End submission possible), direct primitive UP `0x42C0F0`, animation `0x42A3A0`, and mask/composite `0x42A800`; 36 indirect calls are unresolved. `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1836` assigns the selected node/epoch and an unproven overlay scope. Neither a producer token nor D3DX Draw proves when a physical query-scoped Draw* executes. No new REA/disassembly/runtime trace was produced.
2. **Query counter lacks object/generation identity in the inspected handler.** `src/vr/d3d9/stereo_renderer_r7.inc::QueryIssueDest:1616` calls native Issue first and checks successful occlusion type plus game-device identity; on successful BEGIN it increments one global `ActiveOcclusionQueries`, and on successful END it decrements the global value if positive. The handler does **not** compare query pointer, per-query begin state or reset generation. `::CreateQueryDest:1617` hooks Issue once when absent and toggles `OcclusionQueryTrackingUnavailable` based on install success. `::InstallStereoHooks:1790-1843` installs CreateQuery and optionally probes the query hook. This is source-static accounting, not proof that any game uses a query across ResetEx.
3. **R13 is the ResetEx owner when ready and compatible.** `src/vr/d3d9/stereo_renderer_r13.cpp::ResetDestR13:425-463` first retires SpriteNode queue tags in comparison builds (lines 428-435), delegates when overlay/device/compatibility is not eligible (436-441), otherwise disarms the legacy Reset hook and calls `R13ResetCommonPre`, then `ResetCompatDevice` (443-463). `::R13ResetCommonPre:380-423` clears R9 seed/mono resources, host ACK state and eye resources, resets global `ActiveOcclusionQueries` to **zero** at 401, shader identity and PresentEpoch, and publishes disabled stereo. The common pre does not tag/retire individual query objects or disarm/reinstall `QueryIssueHook`. The delegated lower R7 `stereo_renderer_r7.inc::ResetDest:1744` also zeros the global counter. R9's delegated reset `stereo_renderer.cpp::ResetDestR9:825-840` releases mono/depth identities and reacquires depth on success.
4. **Conditional cross-generation counterexample (logical state trace, NOT an observed frame):** old query A successful BEGIN -> `active=1`; game ResetEx handled by R13 -> `active=0`; new query B successful BEGIN -> `active=1`; old query A successful END *after* reset -> global counter becomes `0` although B may still be active. This follows the handler only **if** both old/new `Issue` calls can succeed on that real device and in that order. No query object lifetime, post-reset successful old END, simultaneous B BEGIN, or query `GetData` has been observed. The opposite order (old END before new B BEGIN), failed old END, or old object release prevents this counterexample. Zeroing the counter alone is not evidence of a rendering defect.
5. **Downstream two-eye gate is state-derived.** With R13 armed and main/backbuffer/stereo seeded, `stereo_renderer_r13.cpp::R13GuardedDraw:595-650` computes `unsafeOcclusion` from global `active>0` **or** tracking-unavailable. If stale END made `active=0` while tracking remains available, this particular safety veto need not fire and the draw can take the legacy path; `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30SafeStereoBase:75-92` and `::R62TryFixedFunctionSpriteIndexed:5126-5155` use the same safety predicate before their HUD/XYZRHW and precise fixed-function DIP cases. The R7 `stereo_renderer_r7.inc::PrepareDuplicatedDraw:1519-1522` also checks active/unavailable; four physical DP/DIP/DPUP/DIPUP hooks and actual left/right state/viewport/depth/WVP restore are in `::ExecuteStereoDraw:1524-1560`. Other independent gates (pose, offscreen RT, MRT, depth/stencil sync, FrameStereoIncomplete, semantic match) may still reject a right-eye replay; this static condition does **not** prove double execution.
6. **Present/OpenXR are separate outcome gates.** `stereo_renderer.cpp::R9RestoreMonoBeforePresent:383-398` and `::PresentDestR9:759-823` restore mono when eligible, normalize actual native Present, publish SBS active/fallback, and clear frame seeds. `stereo_renderer_r13.cpp::PresentDestR13:718-748` ends queued sprite frame and clears forced-mono state on game Present. `vrhost/src/main_r23.cpp:3562-3609` records actual `xrEndFrame` result/source/layer and joins only confirmed submissions; the later fresh/cached timing join is at 3611-3630. No live GPU draw HRESULT, query identity/generation, right-eye fingerprint, restored RT/depth/viewport, actual native Present output or Quest 3/VDXR frames are attached.

## NEW_FINDING — confirmed static property vs conditional defect

- NEW_FINDING=RESETEX_OCCLUSION_COUNTER_HAS_NO_QUERY_GENERATION_KEY; CONFIDENCE=CONFIRMED_STATIC_STATE_ACCOUNTING_PROPERTY; RUNTIME_IMPACT=HYPOTHESIS_UNTESTED.
- **Confirmed:** ResetEx clears one global counter; successful Issue END can decrement it by game device/type alone. Inspected source has no per-query generation check at that decrement. Existing overlay readiness is an install-time atomic, not evidence of the survival/validity of a particular query object after ResetEx. This is distinct from 01277 clear-generation replay, 01278 right-stencil invalidation, 01279 unavailable-hook local R9 replay, and 01280 R13-ready effective owner.
- **Conditional hypothesis:** If a pre-reset query can still legally return successful `Issue(END)` after a post-reset query has begun, the global counter may under-report new query activity; a qualifying later seeded main-RT draw could then pass a veto designed to prevent replay of query side effects. This is neither proof that Windows D3D9Ex permits that sequence in this title nor proof that any observed HMD artifact follows.
- **Refutation:** An exact game trace showing all old query objects released/invalid after ResetEx, all old END before any new BEGIN, or old END HRESULT failure refutes the proposed cross-generation path. An independent stereo veto (tracking unavailable, MRT, fallback, no seed, offscreen, pose/depth invalid) also refutes a claimed dual-eye manifestation for that fingerprint. Successful Begin/End totals without object/generation IDs cannot resolve the issue.
