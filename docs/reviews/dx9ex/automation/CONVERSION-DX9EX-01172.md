## REVIEW_SCOPE — original sun/scene producer → GPU screen queue → clean pre-HUD L/R capture → R30 SkyGlow native-UP → restore → R9 Present → host OpenXR

1. **Producer and identity limits.** Checked-in original REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-44,75-81` locates scheduler 0x00449050, sprite priority queue 0x0042D710, type-0 deferred ID3DXSprite Draw/Flush/End and type-1/flagged native DrawPrimitiveUP. C980/C993 central 3D sun, C9A0/CABE surrounding circles, indirect base-sky/SceneEffect GPU callbacks and R30 plugin bloom are different objects. The REA is historical repository evidence, **not** a new x86 disassembly or proof of actual sky VS/PS/c64 physical Draw ownership. `src/hooks_graphics.cpp::RestoreSkyGlow::SkyGlowAllowed:930-935` disables the stock mono glow chain under VR stereo while R30 may execute its independent two-eye effect.
2. **Semantic → queue → actual original GPU draw.** `src/vr/game/render_semantics.hpp::ConsumeForDraw:998-1027` keeps queued exact ownership separate from temporary/direct scopes; `::IsSkyGlowPreHudBoundary:1083-1101` permits only ScreenHud/ScreenOverlay2D, rejecting SceneEffect, WorldBillboard, SkyGlow and particles. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawPrimitiveDestR30/DrawIndexedPrimitiveDestR30/DrawPrimitiveUPDestR30/DrawIndexedPrimitiveUPDestR30:5339-5517` call R30BeforeScreenDrawForSkyGlow on the *physical* API path before R62/XYZRHW/guarded R29/original. A queue label alone cannot identify the native draw or its scissor; the pre-HUD capture depends on physical scope and stereo-frame state.
3. **Clean scene extraction.** `R30CaptureSkyGlowSceneBeforeHud:1156-1192` checks true world stereo and duplicated draw, healthy right eye, valid BackBuffer/RightEyeSurface and one capture per PresentEpoch, then StretchRect-copies **each eye** to reduced render-target texture. `R30BeforeScreenDrawForSkyGlow:1196-1211` stamps the first eligible screen draw before attempting capture; failed capture is not retried behind a possibly HUD-contaminated screen. This is distinct from the previously documented mid-frame SkyGlow OFF->ON fence issue (01150).
4. **NEW DIFFERENT STATE BOUNDARY: the fullscreen SkyGlow geometry inherits caller scissor.** `R30DrawSkyGlowPass:1082-1154` directly sets target RT, null depth, new target-size viewport, fixed-function XYZRHW|TEX1 quad coordinates `[-0.5,width-0.5] × [-0.5,height-0.5]`, null VS, plugin PS, source texture, sampler, Z/stencil/alpha/blend and color masks, and submits `device->DrawPrimitiveUP(D3DPT_TRIANGLESTRIP,2,...)`. In this function there is **no call to SetRenderState(D3DRS_SCISSORTESTENABLE,FALSE), GetScissorRect, or SetScissorRect**. Its caller `R30ApplyStereoSkyGlow:1258-1403` saves D3DSBT_ALL/RT/depth/viewport and restores them afterwards but does not independently reset scissor *before* each plugin-owned pass. Therefore the actual scissor carried into Present can govern plugin bright extraction, blur and final additive full-resolution composite. A StateBlock's eventual restore prevents permanent state leakage but does not retroactively undo clipping inside an earlier pass.
5. **Per-eye postprocess and conditional consequence.** `R30ApplyStereoSkyGlow:1213-1403` selects two-eye eligible/scene-state gates, obtains source eye textures, performs bright/horizontal (+ optional vertical) blur and additive composite for left and right, then applies StateBlock and explicitly restores RT/depth/viewport. The reduced textures use `glowWidth=max(160,backbufferWidth/factor)`, `glowHeight=max(120,backbufferHeight/factor)` (`R30EnsureSkyGlowResources:973-1076`). Since a retained scissor uses pixel-space bounds while the plugin switches between reduced and full-size targets, a restrictive live scissor may affect intermediate and final quads differently. Conditional example only: a source full-buffer scissor X=[100,500) carried into a 3440-wide additive composite would clip that full-width quad outside X=[100,500), even with D3D_OK. The numeric values are **not** an observed device state. This differs from 01170: that review covers per-eye *transformed original XYZRHW HUD triangles*, whereas this one covers *untransformed fullscreen plugin bloom quads at Present*.
6. **Final screen/pipeline boundary.** `PresentDestR30:1491-1507` runs optional bloom under InternalPassScope before forwarding to the lower Present owner. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-822` checks world/duplicate draw, pose, right-eye incomplete flags and real D3D9 Present. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:267-319` copies both eyes, fences and only then publishes SafeFrameId; `vrhost/src/main_r23.cpp:3555-3615` separately observes actual xrEndFrame-submitted frame. Scissor-discarded bloom pixels can still return success from GPU Draw and survive otherwise healthy R9/host gates; none of these APIs prove a particular SkyGlow pixel reaches the Quest3 lens. Prior field log `docs/automation/reviews/DX9EX_R26_QUEST3_FIELD_3RUN_SUN_HUD_F11_20261021.md:8-13,38-55` compares different MSAA profiles (not same-condition SkyGlow A/B), and cannot confirm this clipping cause or the stage-one duplicate-sun cause.
