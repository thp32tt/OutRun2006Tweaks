It does not assign an exact per-object ProducerToken or a lens-centre call epoch. The game's internal renderer can issue *one or multiple* physical primitives; objectId count is not a GPU draw count.
2. **Semantic and queue:** The CABE wrapper's `ScopedRenderSemantic` is distinct from the centre's `ScopedExactProducerSemantic`/`ScopedExactLensCentreGpuDraw` (`hooks_graphics.cpp:693-779`). `render_semantics.hpp:1246-1282,1296-1332,1420-1431` shows `CapturePhysicalDrawCommand` samples effective scope/producer, current queue node/epoch at the physical boundary. No D3DX Draw/Flush/End batch can be attributed to CABE without live actual-API evidence. Unlike GOAL/+TIME kind-0 deferred texture batches, CABE is not statically identified as a D3DXSprite producer.
3. **R30 classification / exact matrix source:** On the *default R26+HUD file*, `R30ClassifyScreenSpacePass` requires exact `ProjectedScreenEffect2D` / `SceneEffect`, perspective base projection, and a recovered raw original-game WVP (`stereo_renderer_r30_r26_safe.cpp:2292-2339`). It tries `R44GetOwnedRawOverlayWvp` first and `R30GetExtendedRawWvpForExactSceneEffect` second; each binds shader pointer+shader-serial and bounded TopLevelDrawSerial age (`:1926-1999`). Neither helper here compares the c64 write's captured producer, queue node, CABE objectId, exact original CALL epoch, or *original write pose epoch*. `R44ClassifyOwnedOverlayMatrix` then returns `SpatialBillboard -> WorldBillboard`, `FlatHud -> PerspectiveHud`, otherwise native fallback. This source fact is a **proof-granularity difference**, not by itself evidence of a stale matrix.
4. **Contrast to stricter centre:** `R30GetExactLensCentreRawWvp` (`:2002-2083`) instead checks `IsDirectWorldLensCentre`, matching current versus captured lens CALL epoch, source scope/producer/null queue, shader serial and original-write versus current latched pose epoch. CABE has a precise *scope* but no corresponding precise *per-object c64* check in the reviewed R30 classification helpers. A previous same-shader neighbouring effect c64 inside the age window is conditionally eligible **only if** original CABE does not upload a newer compatible matrix; whether that event occurs is unobserved.
5. **Actual physical API route not assumed:** At `stereo_renderer_r30_r26_safe.cpp:5394-5569`, DP/DIP/DPUP/DIPUP hooks consume scope, process bounded XYZRHW or R62 fixed-function candidates and otherwise call `R30GuardScreenSpace`. Only a real original Draw primitive entering this hook with owned semantic and the correct vertex-shader/c64 configuration can reach `R30TryScreenSpaceFovDraw` (`:4931-4977`); else it delegates to the guarded R29/original path. Static CABE E8 tagging **does not identify** which physical Draw API, VS, FVF, texture, or RT the game uses.
6. **L/R and state recovery:** If the R30 candidate survives resource/depth/stencil/latched pose gates (`:4978-5012`), it generates original-and-L/R c64 via `R30BuildScreenSpaceEyeConstants` (`:4587-4695,4769-4823`). Under `InternalPassScope`, R30 emits original left Draw, sets right RT/depth/viewport/c64, emits right Draw, restores RT/depth/viewport/original c64 (`:5014-5104`). Right Draw or restore failure poisons/fails-safe, even though attempted duplication counters can increment (`:5106-5155`).
7. **Present and host:** `stereo_renderer_r7.inc::PresentDest:1625-1741` requires complete actual stereo frame admission, pose and resources before DirectGPU/SBS.
