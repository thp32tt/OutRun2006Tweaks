## REVIEW_SCOPE — producer → semantic/queue → D3DX/native physical GPU API → R30 or lower R26 → L/R → restore → Present/OpenXR

1. **Original producer is not GPU ownership.** Checked-in historical REA, `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:29-79`, maps original scheduler `0x00449050`, SpriteNode consumer `0x0042D710`, D3DXSprite Begin/Draw/Flush/End, native direct UP submission, and the independent +TIME `0x00498670` / result `0x004B9200` families. The game producer may generate many queued primitives; deferred D3DX Flush/End can change the physical draw batch. The REA is a *checked-in historical mapping*, not new binary analysis or proof of current physical draw identity.
2. **Semantic admission before changing any eye.** `src/vr/game/render_semantics.hpp:979-990,1052-1081,1103-1119,1279-1317` separates exact `ScreenHud` from untagged `ScreenOverlay2D`; `CorroboratesHud` is true **only** for `ScreenHud` while `CorroboratesScreenOverlay2D` is true only for `ScreenOverlay2D`. A generic queue node is not a +TIME/GOAL exact result producer. The original D3DX queue can include shader-backed GPU calls and pretransformed XYZRHW calls; a semantic tag alone does not demonstrate which native Draw executed.
3. **Source-pixel containment is a geometry scalar, not a 1080p texture allocation.** `src/vr/d3d9/hud_1080p_reference.hpp:1-46::ContainedScale` returns clamp((1920/1080)/(gameWidth/gameHeight),0.50,1.0). `OutRun2006Tweaks.ini:433-451` has `UnifiedEyeMenuSource=false`, `FollowGameResolution=true`, `Hud1080pReference=true`, `HudScale=0.55`. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1526-1529,1773-1796::R30HudContainScale` applies `HudScale*ContainedScale(BackBufferDesc.Width,BackBufferDesc.Height)` *uniformly* to X/Y, never uses the host OpenXR eye texture as the reference. At a **hypothetical** 3440x1440 game source: containment = 0.744186; effective scale = 0.409302. This arithmetic is not a measured raster footprint.
4. **Shader/c64 generic overlay branch uses a *different* scale.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:2143-2157,2235-2248,4499-4635,4711-4714,4777-4830,4887-4966`: if scope is `ScreenOverlay2D`, `R30ClassifyScreenSpacePass` admits that distinct kind; `R30TryScreenSpaceFovDraw` still requires its live stereo/semantic/pose and original c64 proof. In `R30BuildScreenSpaceEyeConstants`, `ScreenOverlay2D` assigns `hudScaleX=R30HudScaleValue()` and `hudScaleY=hudScaleX`, explicitly **bypassing** `R30HudContainScale`. With settings above the shader geometry factor is 0.55, not 0.409302. Its comment says no 1080p containment for ESC/overlay; the application is conditional on this exact shader/c64 route being admitted.
5. **XYZRHW queue overlay can enter the *contained* plane.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:3085-3123,3179-3219,3220-3291::R30ConfigureXyzrhwWorldEffect` accepts `semanticOverlay2D` into `!worldEffect`, calls `R30BuildHudPlaneCoefficients(state,true)`, and sets `hudWorldLockValid`. `R30BuildHudPlaneCoefficients:2714-2774` unconditionally starts with `R30HudContainScale`; the `gameplayHudOwner=true` argument preserves that `0.55*0.744186` factor even for generic `ScreenOverlay2D`. `R30TransformXyzrhwVertices:3749-3791` uses `hudClipX/Y/W` to place those pretransformed vertices into each eye; `R30TryXyzrhwPrimitiveUP:3935-3990` and indexed UP/other XYZRHW entries then issue the actual two native draws when their normal guards succeed. Thus there is a **source-confirmed conditional policy split** between physical routes *before* any full-frame XR resample.
6. **Avoid the false fixed-function-D3DX equivalence.** `R30TryFixedFunctionD3DXSpriteIndexed:5133-5167` (function vicinity) requires `projected` or exact `CorroboratesHud`, plus null VS and FVF `0x142`. A generic `ScreenOverlay2D` is not `CorroboratesHud`; do **not** claim its kind-0 D3DX Draw must use the same owner as the generic XYZRHW path. The relevant contrast is accepted *shader/c64 overlay versus actual XYZRHW native overlay*. For exact `ScreenHud`, shader and XYZRHW both use `R30HudContainScale`; do not extend the finding to every +TIME/GOAL/6th glyph or to externally rendered F11 ImGui.
7. **L/R and final publication remain separate.** For the shader owner `R30TryScreenSpaceFovDraw:4981-5109` submits native L/R calls with distinct c64, RT/depth/viewport and restore/failure guards. For XYZRHW `R30TransformXyzrhwStereo:3795-3827` computes both eyes before `R30ExecuteXyzrhwStereo:3829-3934` draws/restores. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-822` independently requires world stereo, duplicated draw, right-eye/pose/Present success; D3D9Ex direct `src/vr/d3d9/stereo_renderer_r7.inc::ResolveDirectTransport:1358-1420` may add the separate filter boundary from 01177. Host `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp::CopySharedFrameToSafeEyesR32:252-319` and `vrhost/src/main_r23.cpp::R23RenderProjection:1437-1505` copy/submit both eyes. Successful submission does not certify equal glyph pixel density or Quest3 image quality.
8. **Sampler/mip uncertainty is kept explicit.** The only located `D3DSAMP_MINFILTER/MAGFILTER/MIPFILTER` writes in `stereo_renderer_r30_r26_safe.cpp:1121-1125` belong to the **separate SkyGlow postprocess quad**, not a proven original HUD glyph sampler. This review cannot assign a native sprite glyph's texture, mip level, filter, original DDS pixel footprint or anisotropy without a same-Draw GPU state capture. The `HudScale` scalar changes projected geometric footprint; calling it a demonstrated source-texture downsample or aliasing root cause would be incorrect.
