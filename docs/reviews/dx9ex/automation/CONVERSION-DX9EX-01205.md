## REVIEW_SCOPE — producer → semantic/queue → physical GPU API → both eyes/restore → R9/R13 Present → Classic capture → OpenXR

1. **Producer/semantic are upstream provenance, not captured pixels.** Existing original-game REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-42,62-80` describes game loop `0x00417B20`, scheduler `0x00449050`, normal queue `0x0042D710`, conditional priority queue `0x004C50A0`, +TIME `0x00498670`, GOAL `0x004979E0`, type-0 D3DXSprite::Draw -> deferred Flush/End and type-1 `0x0042A3A0/0x0042A800` native DrawPrimitiveUP. Neither queue node nor logical draw tag alone proves final GPU output, exact eye pixels or captured output ownership. The present task adds **no original EXE draw ID**; existing 01202's +TIME/GOAL physical DIP ambiguity remains.
2. **Protected game-side L/R/restore and D3D9 Present.** `cmake.toml:84-90,117-129` chooses R26+HUD for option-free configurations, not R84. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30ExecuteXyzrhwStereo:3829-3945` selects left/right RT, depth, viewport, issues separate eye callbacks and restores the original state with failure veto. `::R62TryFixedFunctionSpriteIndexed:5126-5352` is an independent fixed-function HUD physical-draw gate; no heuristic +TIME marker proves binocular success. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-822` requires world/duplicated-eye/pose/restore success, publishes an in-flight Frame.v2 packet just before lower D3D9 Present and a completed `StereoSbsActive` packet after success; `stereo_renderer_r13.cpp::PresentDestR13:718-749` retires queue tags after lower Present. A completed producer Present still is not proof that DWM's later *output-global* sampled desktop image shows the same frame.
3. **Classic host capture transaction.** `vrhost/src/main_r23.cpp::R23Capture:1018-1205` obtains one Desktop Duplication frame, optionally reuses a pointer-only image *without* marking it fresh (1096-1115), queues D3D11 CopyResource after validated texture descriptors (1124-1171), releases duplication ownership and only then sets `status.fresh=fi.AccumulatedFrames>0` / stores `fi.LastPresentTime` (1172-1204). `vrhost/src/main.cpp::GetGameClientOutputRect:2120-2147` requires the **entire** game client within one capture output; this protects SBS seam placement, not per-frame pixel ↔ game-Frame.v2 equivalence. Dirty/move metadata was intentionally demoted from an admission requirement because of false negatives.
4. **Frame.v2 history is stable but selection is not monotonic.** `vrhost/src/main.cpp::RenderFrameReader::Read:757-779` returns the ring's latest slot, while `ReadHistory:820-864`, `ReadFrame:782-818`, `ReadSlot:877-903` apply ring sequence/run identity/stable-slot checks. `vrhost/src/main_r23.cpp::R23SelectClassicFrameForCapture:1257-1320` rejects in-flight/direct/incomplete or future-to-output frames, exact equality `frame.frameId == lastProcessedFrame`, and capture skew above 100ms; it picks the **highest admissible presentQpc** among remaining candidates. It does **not** explicitly reject a completed frame whose ID is *older than* `lastProcessedFrame` in the same run. `R23FrameUnchanged:1237-1254` verifies selected metadata stability, not monotonic presentation or captured-image identity.
5. **Latest-frame outer gate does not eliminate the conditional older-candidate path.** `main_r23.cpp:3092-3125` first requires a latest `before.frameId != lastProcessedStereoFrame`. For a new completed latest frame still **later** than output LastPresentTime, that gate can pass while the QPC matcher later excludes the latest and the already-processed immediately preceding frame, leaving a still-ring-resident *older* eligible frame. Host `R23Capture(compositor,2)`, full-client check and 100ms skew are applied at `3142-3170`. A recorded old pose may still pass `viewHistory.Find` at `3213-3223`; `R23FrameUnchanged` then permits Classic CommitStereoSource at `3228-3252`.
6. **Conditional example, not a real trace.** Assume same valid producer run, ring contains F40 (game Present t=100ms), F41 (t=116ms) and new completed F42 (t=132ms). The preceding *successfully rendered* XR bundle already committed F41 so `lastProcessedStereoFrame=41`. A fresh Desktop Duplication output frame has `LastPresentTime=124ms`, with complete OutRun client visible (output refresh can originate outside OutRun; the timestamp is output-global). The outer latest F42 permits entering Classic selection. F42 is excluded because t=132 > 124; F41 because ID==41; F40 passes 24ms<100ms and may be chosen, assuming its exact Frame.v2 slot and view history are still available. This counterexample proves **the static predicate admits an older ID**, *not* that an HMD actually displayed F40 or that these timestamps occurred. It also does not prove that the output image represented F40: it may be F41 or another composition.
7. **Publish/actual OpenXR are further gated.** `main_r23.cpp:3255-3289` only stages new bundle metadata after a successful commit, `::R23RenderProjection:1440-1513` must render both OpenXR eye array slices and release the acquired projection swapchain, and `main_r23.cpp:3316-3366` updates `lastProcessedStereoFrame=pendingBundleFrame.frameId` **after** successful projection rendering. Thus under all these guards the cursor itself can conditionally move backwards; otherwise cached projection or safe fallback remains. R32/R24 final `xrEndFrame` authority can reject/replace a requested projection, so `requestedLayer=projection-fresh` alone is not an optical PASS. `main_r23.cpp:3562-3695` reports `committedFrameId`, `candidateGameFrameId`, captureQpc, requested and actual final layers. OpenXR reprojection/72Hz pacing and Quest3 left/right pixels have **not** been checked.
