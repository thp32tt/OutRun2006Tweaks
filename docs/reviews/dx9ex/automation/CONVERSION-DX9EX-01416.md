## ORDERED STATIC SIMULATION (hypothetical, not a live observation)

1. **CABE**: original `EXE+0xCF4E` projected anchor -> exact outer `EXE+0xCABE` call -> `ProjectedScreenEffect2D` scope. If D3DX defers actual physical draw, require the same producer/node/epoch to reach the physical hook; otherwise classify it as `UNKNOWN` and do not grant R69. Keep C993/other halo and +TIME unrelated.
2. **Screen ownership:** VS/c64 proof + stereo pose + resources + affine/base-projection gates succeed. For the owned exact CABE shader draw, R30 uploads `original c64` identically into L/R and performs two hardware Draw calls. Right RT/depth/viewport and saved original WVP are restored. If any gate fails, the previous-renderer fallthrough or fail-closed frame takes precedence; **do not** label it the positive case.
3. **Transport:** R7 either resolves the L/R images directly or composes a complete SBS and invokes the original Present; successful Frame.v2 permits host copy. R23 separately maps each source eye into a full projection-layer slice and emits its *own* `views[eye].pose/fov` on that slice.
4. **Ray test:** for a common normalized horizontal image coordinate `u` (left edge 0, right edge 1), define each eye's local tangent-plane horizontal value `t_eye(u)=(1-u)tan(angleLeft_eye)+u tan(angleRight_eye)`. On the same `u`, if the eye's FOV edge tangents differ, `t_left(u)` need not equal `t_right(u)`. Rotate the associated local rays by **each view pose orientation** before comparing in a common reference frame; eye pose, asymmetric frusta, and angular-cant may cancel or augment differences. The R69 identical-WVP condition guarantees equal *pre-XR normalized position* under equal viewport/shader/state; it does **not by itself** prove equal common-frame projected ray direction. Physical per-eye compositing differences from depth test or alpha blending may provide an additional independent discrepancy even at the same geometric pixel.
5. **Controls:** symmetric frusta, identical view orientations, identical viewport and shader/texture/alpha/depth yield a null angular-delta control for equal `u`; an asymmetric but admissible synthetic FOV with same view orientations produces a nonzero tangent/ray delta even though the R69 pre-XR pixels remain aligned. Real `xrLocateViews` eye poses/FOVs may cancel the synthetic difference; do not map the toy example to Quest3 symptoms. Verify both `DirectGPU` and classic SBS under the same pose/frame identity.
