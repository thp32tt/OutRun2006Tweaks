## EVIDENCE — connected GitHub exact SOURCE_HEAD

1. **Producer/semantic is not automatic physical GPU identity.** `src/hooks_graphics.cpp:591-605,670-745` tags exact CABE/projected effects separately from centre C993. `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-39` records 0x42D710 type0 D3DX(0x42A0A0; deferred Begin/End possible), direct-UP(0x42C0F0), type1 quad(0x42A3A0), masked(0x42A800); unresolved indirect calls remain. `src/vr/game/render_semantics.hpp:1083-1111,1213-1432` separates the actual ScreenHud/ScreenOverlay2D pre-bloom boundary from ProjectedScreenEffect2D/world. None of these prove a particular EXE producer submitted a physical native Draw in this review; do not infer a C993/CABE or +TIME GPU frame from semantics alone.
2. **Where clean capture becomes an epoch stamp.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1157-1192` checks stereo/world/eyes, short-circuits if `R30SkyGlowSceneCaptureEpoch == PresentEpoch`, then copies both current eye surfaces into `R30SkyGlow.reduced[eye]`; only after both copies succeed does it stamp the epoch at line 1190. `:1194-1212` stamps first qualified screen-draw epoch *before* capture, even if it fails, to prevent a later HUD-contaminated fallback. `:1244-1255` skips glow when a screen boundary occurred without clean capture; that fail-closed case is **not** the issue analyzed here.
3. **Resources have mutable identity, but capture stamp has no generation field.** `stereo_renderer_r30_r26_safe.cpp:900-939` owns two `reduced[]` and two `temp[]` D3DPOOL_DEFAULT render textures and separately stores `R30SkyGlowSceneCaptureEpoch` / `R30SkyGlowScreenDrawEpoch`. `:974-1015` returns cached resources only if eye size, glow size, factor, shaders and textures all match; otherwise it calls `R30ReleaseSkyGlowResources()` and creates **new** reduced/temp GPU textures. `:1069-1074` records updated factor/sizes; neither `R30ReleaseSkyGlowResources` nor this reallocation updates the two capture-epoch variables in the inspected code.
4. **The source is rechecked at Present without re-capture on matching epoch.** `:1214-1258` admits a stereo SkyGlow operation during Present, separately blocks WARP/RESTART/GOAL/TIMEUP/LINK_TIMEUP/GIVEUP, then calls `R30EnsureSkyGlowResources(device)` at line 1258. `:1287-1323` loops L/R: if `R30SkyGlowSceneCaptureEpoch != PresentEpoch`, it fills each `reduced[eye]` by live eye `StretchRect`; if epoch matches, it *skips* that copy and immediately samples `reduced[eye]` into bright-pass `temp[eye]`. `:1326-1379` blur/composites, `:1385-1404` restores StateBlock plus RT/depth/viewport. The newly created GPU texture content was not initialized by `R30EnsureSkyGlowResources` itself.
5. **The two different gates create a conditional sequence.** If a clean pre-HUD capture succeeds with factor/dimensions A in epoch E, then `Settings::SkyGlowFactor` (or compatible resource dimensions) changes to B **before the same Present**; the subsequent `R30EnsureSkyGlowResources` can release and recreate `reduced[0/1]`. The stamped `R30SkyGlowSceneCaptureEpoch == E` still passes; the Present-time `StretchRect` is skipped, so the bright pass can sample newly allocated, not-in-this-epoch-filled GPU contents. This source sequence is reproducible as a **static counterexample**; a real mid-epoch factor/extent change was NOT observed. Output can be absent, inconsistent or implementation-dependent; do not claim a real headset artifact or GPU fault.
6. **Multiple BeginScene question is independent and lower confidence.** `src/vr/d3d9/stereo_renderer_r7.inc:194-226,1625-1634,1741-1744` counts multiple successful BeginScene calls per Present for telemetry, advances `PresentEpoch` only at Present, and resets epoch to 1 on Reset. `R30CaptureSkyGlowSceneBeforeHud` only checks PresentEpoch, not BeginScene count or later eye redraw. Thus an additional world pass after a successful early screen-boundary capture **could** leave a valid-but-earlier scene snapshot, but the real call order/projection is unknown; this is a secondary review hypothesis, not the main verified generation mismatch.
7. **Reset and final transport limits.** `stereo_renderer_r30_r26_safe.cpp:1492-1520` releases SkyGlow resources *and* invalidates capture epochs before delegating Reset; do **not** misreport an ordinary Reset as the same missing invalidation. `R30PresentDestR30:1492-1508` calls SkyGlow before original Present; `src/vr/d3d9/stereo_renderer_r7.inc:1494-1522,1625-1744` resolves DirectGPU or SBS, calls Present, publishes only eligible completed frames. `vrhost/src/main_r23.cpp:1440-1515,3510-3575` copies independent L/R images into OpenXR projection arrays and submits `xrEndFrame`; no host validation of bloom source texture *generation* is established. Positive host transport is not proof of correct bloom pixels.
8. **Context is bounded.** `docs/automation/reviews/DX9EX_HMD_REFERENCE_20261020_0CFF83CF.md:1-35` describes a user-tested *different exact compiled binary* baseline, not current-source SkyGlow activation. GitHub Issue #13 remains an open runtime regression ledger, not a reproduction of a factor-change-between-capture-and-Present. No per-frame factor-change trace, creation serial, scene capture epoch, physical draw log, eye surface dump or Quest3 capture was acquired.
