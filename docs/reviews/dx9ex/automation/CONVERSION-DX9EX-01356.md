A bounded stack-unwind probe accepts *only* the 19 verified return RVAs during GOAL with VR active. Unknown/FPO/unwind-failed stacks stay on their previous/native glyph path.
2. **Different source families remain different.** `GoalTime_TagHelper` redirects two separately verified E8 parents into their original `void(__cdecl*)()` helpers, carries `GoalTime020` or `GoalTime150` for synchronous Draw and tags only newly appended stable-root queue siblings. `ResultProgressEnter/Leave` carries its separate progress token around two 0x2D200 parents; the full progress-graph parents are also separate verified 0x979E0 wrappers. Three 0x975EE/0x97727/0x977FB Sumo_Printf parents are independently bracketed. It would be incorrect to claim a single GOAL or generic B9200 pixel owner from these names alone.
3. **Direct B9200 glyph proof and fallback.** The existing 0x2C808/0x2C9DB `TextGlyph_putSprite` entry checks the original GOAL call stack, captures queue roots/tails plus serial, optionally brackets a direct, non-queue `ResultTextB9200` source, then tags verified appended siblings; a rebuilt root cannot be credited solely by reused pointer. A distinct unowned `ID3DXSprite::Draw` path admits this producer only when VR+GOAL, no active queue/competing producer and exact B9200 return-on-stack all hold. Owned Draw still rechecks original stack before marking the deferred ledger as `provenDirectB9200`. Failure to prove the call is **conservative native behavior**, not evidence of an actual missing HMD glyph.
4. **Deferred texture-batch lifetime.** Native D3DXSprite::Draw may internally Flush on a texture change, or defer physical GPU submission until Flush/End after the producer unwinds. The `HudCommandBatch::Ledger` tracks sprite instance, generation, mutation, queue node+epoch, producer and exact-parent proof; unsuccessful Draw, foreign/reentrant Begin/Flush, mixed scope or unproven direct B9200 revoke homogeneous ownership. A same-generation successful internal Flush may intentionally start a clean next batch. The source-side wrappers call pre-owner flush and owner-exit flush **only for proven homogeneous direct work**. This cannot certify any physical GPU API or pixel by itself.
5. **Queue boundary, not caller tail.** `BeforeQueueNode` drains a proven direct B9200 batch **before** changing current node/epoch, then isolates GOAL token changes and also **same-token different-node** transitions. `BeforeQueueEnd` drains only a current, homogeneous, exact queued batch. `QueueNode` then selects the new semantic identity; `QueueEnd` retires the queue scope. The original D3DX mixed/unknown batch remains on native End/Flush, and optional earlier original partial-consumption does not imply two GPU submissions.
6. **Actual native draw versus R30/R62.** Only a real D3D9 primitive submission at the native D3DX Flush/End (or a separate direct original UP path) reaches the R26+HUD physical router. `CapturePhysicalDrawCommand` samples current semantic/producer/node/epoch at that GPU boundary. **If** the native GPU submission is an R30-eligible DrawPrimitiveUP with live XYZRHW/VS-null, pose/viewport/resource and proven HUD semantic, `DrawPrimitiveUPDestR30` may submit left original and right on the right RT/depth/viewport, then restore state. A non-eligible or unknown physical draw takes `R30GuardScreenSpace`/original-native fallback. A genuinely eligible fixed-function FVF 0x142 `DrawIndexedPrimitive` can instead follow R62; D3DXSprite::Draw alone is insufficient to assert either physical route. The opt-in R84 comparison is not a default.
7. **Present and OpenXR are stricter than semantic tags.** `PresentDest` requires world-stereo evidence, duplicated draw, valid pose/metadata/resources and no right-eye/restore failure before presenting source-stereo metadata; GOAL HUD alone cannot make `FrameHadWorldStereo`. Optional post-Present DirectGPU completion or SBS fallback/hold has a separate gate. Host R23 submits a fresh/cached layer via `xrEndFrame`, subject to its own actual-layer bookkeeping. There is **no supplied** same-frame physical GOAL glyph -> paired eye HRESULT -> published frame ID -> Quest3/VDXR pixel acceptance chain.
