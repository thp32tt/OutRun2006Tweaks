## EVIDENCE — GitHub-pinned static facts (not a reproduced visual defect)

1. `src/hooks_graphics.cpp:169-239` implements `VRDriverSeatCameraPose` using thread-local `hasLastValidPose`, `lastPosition`, `lastLook`, and `lastPlayer`. It resets only when `!VRDriverSeatGameplayActive() || player != lastPlayer`; a successful `ComputeStableSeatPose` refreshes the cache; otherwise any `hasLastValidPose` reuses the full old absolute position/look pair. There is no pose age, frame serial, timer, distance delta, native mode or gameplay generation in this fallback.
2. `src/hooks_graphics.cpp:241-275` defines active gameplay as GAME, GOAL, or START/progress 65; `VRDriverSeatCameraEligible` returns **before** calling `VRDriverSeatCameraPose` when no camera/car, incorrect SceneEffect scope, disabled DriverSeatView/VR, or inactive gameplay. The ordinary caller cannot reach the pose function's `!VRDriverSeatGameplayActive()` cache-clear arm during an inactive session. It *can* clear on a changed non-null player pointer at the next eligible call; do not misstate that protection as missing.
3. `src/hooks_graphics.cpp:2019-2037,2069-2076,2119-2140`: `CalcCameraMatrix_dest` samples `driverSeatFrame` through the eligibility wrapper, then `ApplyDriverSeatCameraOffset` calls `VRDriverSeatCameraPose` again, changes native camera position/look for the original matrix calculation and restores both after `CalcCameraMatrix.call`. A stale fallback can therefore be installed into an otherwise successful native view-matrix build even if the native camera was not deliberately modified before that call.
4. `src/vr/game/driver_seat_car_space.hpp:153-199`: `ComputeStableSeatPose` first optionally tries validated car-space offsets, then validated native `ComputeTranslatedCamera`, and returns false if neither can be constructed. `src/vr/game/driver_seat_camera_math.hpp:15-91` validates finite native vectors/offset and nondegenerate axes. A failure is an explicitly anticipated path, not proof of an observed failure frequency; default `DriverSeatCarSpaceBasis=false` avoids one source of car/native pose switching.
5. `src/hooks_graphics.cpp:278-384,2010-2018,2141-2167` routes full-car and driver-robot decisions through eligibility and temporarily guards/restores SceneEffect camera reconstruction. `src/vr/game/driver_seat_render_pass.hpp:8-13,42-64` keeps scene-effect camera reconstruction distinct. The seat pose issue must be diagnosed without replacing these independent scoped/atomic protections or changing the game's physics camera.
6. `src/vr/settings.cpp:146-163` and `OutRun2006Tweaks.ini:499-521` both keep `DriverSeatView=false`, `DriverSeatCarSpaceBasis=false`. Hence the identified live behavior is opt-in and **not exercised by default**. The settings describe the native camera relative offset rather than a guaranteed Quest APK absolute seat anchor.
7. Archived original mapping `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:7-33` and `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:3-32` distinguish actual four-way queue-to-GPU paths; they are archival x86/REA evidence, not new REA. `src/vr/d3d9/stereo_renderer_r7.inc:1518-1555,1625-1740` shows fail-closed physical LEFT/RIGHT admission, GPU restore, Present and Frame.v2 state. `vrhost/src/main_r23.cpp:3562-3590` calls xrEndFrame and inspects final submission; none certifies correctness of the PC-side seat cache.
