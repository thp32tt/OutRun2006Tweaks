## REVIEW_SCOPE — new state-provenance boundary, independent of 01322

01322 examined reflection cubemap face hook-to-hook clock versus Present/XR frame cadence. This pass examines **+TIME/GOAL/result HUD texture, pixel-shader, sampler and color-transfer provenance at the physical native D3D9 Draw**, as distinct from (a) original producer and queue identity, (b) R62's eye-projection/Draw-HRESULT log and (c) host xrEndFrame. The objective is to determine **what the current diagnostic proves**, not to assert a color defect.

1. **Original producer:** Historical original-game REA maps +TIME caller 0x00498670 to three animation and three number callsites, with numerals through 0x004973C0/0x004974E0 and glyph queue via 0x004B9200; progress has a separate 0x004979E0 producer. The original D3DXSprite Begin/Draw/Flush/End method interpretation is static and requires live verification when objects are rebound. A CPU producer CALL or single D3DX Draw does not imply an individual GPU Draw, texture or exact source pixel output.
2. **Semantic and deferred-queue ownership:** src/hooks_uiscaling.cpp braces exact +TIME, GOAL Sumo_Printf, progress and B9200 callers; it tags new SpriteNodes and isolates only eligible homogeneous D3DX batches. The D3DXSprite lifetime FlushDest/EndDest rebinds only proven native deferred direct-result ownership and explicitly leaves unknown, mixed, foreign and live-queue batches on native behavior. PhysicalDrawCommand carries semantic/producer/node/queueEpoch, but no GPU texture/sampler/color snapshot or native HRESULT. R30IsExactResultHudDraw checks exact result producer plus live node/epoch when queued; semantic proof must not be read as pixel-state proof.
3. **Actual R62 GPU gate:** In the R26+HUD default path, DrawIndexedPrimitiveDestR30 tries external F11 ImGui, then R62 fixed-function Sprite, then XYZRHW, then conservative R29/native. R62 requires game backbuffer, safe stereo seed, corroborated ScreenHud or projected marker, live GetVertexShader()==null and GetFVF()==0x142. The code calculates eye-specific projection, calls the original DrawIndexedPrimitive trampoline once per eye through R30ExecuteXyzrhwStereo, and attempts original projection restore; failed eye/restore invokes safety fallback. R30 RESULT_HUD_REJECT explicitly reports `stage=R62_ONLY finalRoute=UNDETERMINED`, not final rejection.
4. **Specific provenance gap:** The R62TryFixedFunctionSpriteIndexed admission/eye path (5171-5394) does **not sample live GetPixelShader, GetTexture, GetSamplerState or sRGB-related D3D9 state** and does not independently compare per-eye texture bindings before physical DIP. Its `VR R26 RESULT_HUD_EYES` message records route, producer, queued node/epoch, pose, viewport, FVF, `VS=0`, left/right HRESULT, projectionRestored, frameIncomplete. That provides valuable projected geometry/submit evidence, **not** evidence of original HUD DDS identity, sampler filters/addressing, texture-stage ops, pixel shader identity, D3DSAMP_SRGBTEXTURE, D3DRS_SRGBWRITEENABLE or final XR color transfer. A null vertex shader does not by itself prove a null pixel shader.
5. **R30 and R22 state boundaries:** R62 does not substitute a new texture/sampler; it sends the native sprite Draw with the extant game/D3DX GPU bindings and restores projection. Separately, R22 StateBlock::Apply success invalidates and re-primes tracked raster/render/shader epochs, but its raster reliability is not a per-result-HUD texture/sampler proof. The R30 sampler setters around 1119-1125 belong to a separate SkyGlow pass and must **not** be attributed to R62 HUD DIP. There is therefore **no confirmed source-level color mutation** in this route.
6. **L/R -> Present -> OpenXR:** R30ExecuteXyzrhwStereo calls left, switches right RT/depth/viewport, calls right, restores RT/depth/viewport and records failures. R62 independently restores original projection. R9 Present needs completed world + duplicated L/R, valid pose/metadata, no poisoned/incomplete state, successful native Present, then publishes active Frame.v2 or mono fallback. The x64 host observes xrEndFrame and submitted frame/layer ID. Neither present/host gate validates **which D3D9 texture/sample/color-transfer state** generated a given result glyph in both eyes.
7. **Conditional optical counterexample — NOT reproduced:** If a GOAL result D3DX batch crosses a producer/StateBlock/texture binding boundary and its physical DIP is admitted to R62 while sampling unexpectedly different state, existing `RESULT_HUD_EYES` success can coexist with an incorrectly colored/masked sprite. However source alone cannot establish that this happens: D3DX may preserve correct state, R62 does not itself change the sampler/texture, and actual HDR/SDR conversion or XR color parity was not captured.
