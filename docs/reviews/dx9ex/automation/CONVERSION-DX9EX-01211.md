## Source-pinned original-to-final-draw static simulation

1. **Original producer / final API are not synonymous.** Checked-in original-exe REA study `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:17-43` anchors scheduler 0x00449050 -> queue 0x0042D710, type-0 D3DX 0x0042A0A0, flagged type-0 native UP 0x0042C0F0, type-1 animation 0x0042A3A0 and masked type-1 0x0042A800. The mask branch still has unresolved indirect calls. A masked sprite, +TIME animation or GOAL glyph is **not proven** to use a particular `DrawPrimitiveUP` / `DrawIndexedPrimitiveUP`, nor to be duplicated physically. This task does not claim new original EXE analysis or source images.
2. **Semantic and queue remain bounded.** `src/hooks_textures.cpp:928-1161` separately owns source/mask texture lookup, native producer invocation and queue-tail proof; `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1838` sets node/epoch and defaults unproven content to `ScreenOverlay2D`, while `EndSpriteQueueRender/Frame:1840-1915` keep unvisited partial queue tags until a Present fence. No generic alpha/mask-bit promotion to `ScreenHud` or evidence of a unique physical UP draw arises here.
3. **The exact physical UP rejection ladder is two-step.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawPrimitiveUPDestR30:5464-5490` and `::DrawIndexedPrimitiveUPDestR30:5493-5525` consume a physical-draw semantic once, call `R30TryXyzrhwPrimitiveUP:3947-3990` or `R30TryXyzrhwIndexedPrimitiveUP:3992-4095+`. Rejection of invalid viewport/stereo/vertex bounds, indexed range, scratch or stereo reprojection returns `E_NOTIMPL` **before** `R30ExecuteXyzrhwStereo` submission for those shown branches. The next `R30GuardScreenSpace:5113-5124` calls `R30TryScreenSpaceFovDraw:4886-5110`. A second `E_NOTIMPL` delegates to the captured `R30Draw*R29Hook`; it does **not** call both the r29 lambda and original lambda. Fixed-function `R62TryFixedFunctionSpriteIndexed:5126-5210` belongs to non-UP indexed DIP; it is not consulted by either physical UP destination. All of this is a *code-path inference*, not a measured GPU draw count.
4. **Pre-draw state rejection and post-submission failure are different.** `R30TryScreenSpaceFovDraw:4891-4967` requires a live stereo/backbuffer context, source-owned canonical semantic, synchronized right depth/stencil if testing them, a latched matching pose and valid per-eye constants. Missing proof falls back conservatively. At `:4988-5010`, a partially failed **left WVP upload** explicitly attempts restoration of original c64 constants; only successful rollback returns `E_NOTIMPL` and undoes the pre-draw stereo count. Failed rollback instead poisons the frame, arms safe fallback and returns `E_FAIL` (no r29 retry). Once the left actual Draw has run, failures at `:5012-5025` also poison and return the error, not `E_NOTIMPL`. Thus an `E_NOTIMPL` from the observed WVP rollback gate does not prove that an original physical left eye was drawn.
5. **Right-eye and StateBlock/raster restore are independently fenced.** On admitted R30 screen-space replay, `:5028-5059` saves tracked RT/depth/viewport, binds right RT/depth, uploads right eye c64, calls the actual right Draw and invokes `RestoreRightPassState(..., original, true)`. `:5097-5110` poisons/arms fallback and invalidates right depth/stencil when right or restore fails even though the function returns `leftHr`. The alternative XYZRH-W UP owner `R30ExecuteXyzrhwStereo:3829-3945` similarly restores RT/depth/viewport, records right failure, and does not itself issue a second lower-route draw after actual submission. `RightDepthSynchronized`/`RightStencilSynchronized` are eligibility checks, **not evidence of HMD optical parity**, and the static path alone cannot guarantee restoration succeeds during Reset/device loss.
6. **Lower fallback still enforces negative controls; not “automatically mono” and not “automatically correct stereo.”** In the R26+HUD compiled overlay (`AGENTS.md:1-5`; `stereo_renderer_r30_r26_safe.cpp:14-16`), `stereo_renderer_r26.cpp::R27GuardWorldEffect:638-709` routes unproven world/fragile/unknown state through the conservative R13 chain instead of a newly forced WorldStereo. The R13 UP wrapper `stereo_renderer_r13.cpp:685-715` uses `R13GuardedDraw`, and `stereo_renderer_r23.cpp:578-595` retains before-top-level-draw state checking in its lower chain. No physical GPU capture shows which lower node consumed a **particular** masked element. A delegated R29/R26/R13/R9 outcome cannot be classified as correct left/right visual pixels from a wrapper call or `R30ScreenSpaceFallbacks` counter alone.
7. **End-to-end frame acceptance is stricter than draw HRESULT.** `stereo_renderer.cpp::PresentDestR9:692-805` requires verified world stereo, a duplicated draw, matching pose and no right-eye/incomplete-frame errors before transport/presentation; otherwise only eligible mono restoration/fallback is attempted. `vrhost/src/main_r23.cpp:3200-3366` separately validates/commits a host source and projection; actual `xrEndFrame`, submitted source frame/layer and any cached projection are distinguished at `:3562-3615`. Neither R30 leftHr nor R9 `StereoSbsActive` proves the specific mask/+TIME glyph was submitted binocularly on Quest3/VDXR.
