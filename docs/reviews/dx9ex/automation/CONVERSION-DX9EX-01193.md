2. **Semantic and native D3DX ownership are proof gates.** `src/vr/game/hud_command_batch.hpp:70-141,142-230` binds a homogeneous native Begin/Draw/Flush/End generation, producer, optional queued node/epoch and mutation serial; failed/mixed/reentrant ownership is rejected. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30IsExactResultHudDraw:3073-3083` requires an exact physical result command and a live node+epoch for queued draws. This ownership says *which source* a draw belongs to, not whether both GPU eye submissions succeeded.
3. **Physical routing selects R62 narrowly.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R62TryFixedFunctionSpriteIndexed:5135-5310` requires triangle-list indexed Draw, target backbuffer, live null vertex shader, FVF `0x142`, valid viewport and latched stereo pose, then forms per-eye fixed-function projection matrices. `::DrawIndexedPrimitiveDestR30:5377-5461` checks external F11 ImGui first, then R62, then XYZRHW, then R29/original fallback. `RESULT_HUD_REJECT` explicitly labels `R62_ONLY finalRoute=UNDETERMINED`; reject count cannot identify the final physical path. Native UP is independent in `::DrawPrimitiveUPDestR30:5464-5488`.
4. **Left success can coexist with right failure while an attempted-duplication counter increments.** `::R30ExecuteXyzrhwStereo:3829-3945` executes `leftDraw()`; on left failure returns immediately and poisons the frame. After left success it tries right RT, depth, viewport, `rightDraw()` and `RestoreRightPassState`. It sets `FrameHadDuplicatedDraw=true` and increments `DuplicatedDraws`/`R30SafeTwoEyeDraws` **before** testing `FAILED(rightHr)` and `!restoreOk`. It then sets `FrameRightDrawFailed`, poisons/arms fallback on right failure and notes restore failure; its return value remains `leftHr`. Thus these aggregate counters describe an attempted/entered stereo path, not an invariant of two successful eye API calls.
5. **R62 has stronger diagnostics than its aggregate 'hits' counter.** `::R62TryFixedFunctionSpriteIndexed:5213-5352` calls the helper and always tries to restore the original D3D9 projection. It separately increments route `projectedDraws/hudDraws`; for exact results with telemetry enabled it emits `RESULT_HUD_EYES` with physical left/right HRESULT, `projectionRestored`, `frameIncomplete`, producer, queued node/epoch, viewport and pose. For an exact result, failed projection restore converts a successful `hr` to `E_FAIL` at return; **right-eye failure alone does not necessarily convert the helper's returned left-success HRESULT**, although right failure is marked in frame state. This is a deliberate cross-layer error-reporting distinction; the code does not prove an optical defect.
6. **Present owns frame acceptance, not the R62 hit counter.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-826` sets `frameEligible` only with world stereo + duplicated draw + no `FrameRightDrawFailed` + no `FrameStereoIncomplete` + pose/metadata/resources. It then negotiates direct or SBS transport and checks real Present HRESULT before announcing `StereoSbsActive`; failed/incomplete composition can restore mono and report fallback. A single R62 `hits` event or `RESULT_HUD_EYES` pair cannot prove a complete eligible frame or a specific GOAL glyph reaching both eye swapchain views.
7. **XR is another asynchronous observable boundary.** In `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513`, direct-transport eye SRVs and SBS UV halves are rendered separately to XR array-eye layers; failure to render either eye fails that projection; `xrEndFrame` at `:3562-3599` submits the frame. This source check does not provide a correlated producer/physical DrawSerial → accepted Present transport/published packet → consumed host frame → submitted XR frame tuple. `docs/automation/reviews/DX9EX_HMD_REFERENCE_20261020_0CFF83CF.md:1-31` reports *older exact baseline HMD* bilateral GOAL/+TIME with outstanding headlock, not a new result for this HEAD. Issue #6 is a review inbox, not a runtime assertion.
