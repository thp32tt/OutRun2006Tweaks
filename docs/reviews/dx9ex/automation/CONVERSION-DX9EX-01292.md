Unresolved indirect calls prevent assigning a particular game HUD/sand draw to the indexed-VB R30 hook. Never infer an actual DIP from a producer name.
2. **Semantic and queue epoch are eligibility context only.** `src/hooks_uiscaling.cpp::VRHudQueueSemanticBridge:4154-4200` calls outgoing R64 D3DX batch boundary before selecting a new queued SpriteNode; `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1837` uses lazy canonical 0x2D762 node scope, producer identity and queue epoch, falling back to `ScreenOverlay2D` for unknown source. Neither queue tag nor D3DX Draw establishes final physical GPU API. Forbidden old 0x2D734/B9200 risky hook is not reintroduced.
3. **R62 takes precedence.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawIndexedPrimitiveDestR30:5379-5460` first routes external F11 ImGui, then `R62TryFixedFunctionSpriteIndexed:5126-5347` for qualified fixed-function D3DXSprite/exact HUD, then `R30TryXyzrhwIndexedPrimitiveVB`, otherwise `R30GuardScreenSpace`/R29/original native DIP. A qualifying R62 earlier return, non-RHW physical state, absent shadows or `E_NOTIMPL` excludes this particular conversion. An R62-only rejection is NOT final failure or a missing draw.
4. **Original declared vertex range is not compared with referenced indices.** `::R30TryXyzrhwIndexedPrimitiveVB:4236-4262` receives `minVertexIndex` and `numVertices`, but only rejects zero `numVertices`/zero index count and oversized index count. `::R30TryXyzrhwIndexedPrimitiveVB:4263-4350` retrieves stream/IB, validates IB byte range, reads complete shadow and builds every `physical=baseVertexIndex+rawIndex`. It guards signed/unsigned physical range and later `vertexCount=maxPhysical-minPhysical+1 <= 262144`, but there is **no guard proving each raw index lies within `[minVertexIndex,minVertexIndex+numVertices)`**. Local shadow/VB bounds (4350-4428) are different from the caller's declared D3D9 index range. Overflow-safe end calculation would be needed for any later candidate.
5. **Microsoft D3D9 original API range contract.** Official Microsoft Learn `IDirect3DDevice9::DrawIndexedPrimitive` specifies `MinVertexIndex` as zero-based relative to `BaseVertexIndex` and says using an index outside the declared `MinVertexIndex/NumVertices` range is invalid: https://learn.microsoft.com/en-us/windows/win32/api/d3d9helper/nf-d3d9helper-idirect3ddevice9-drawindexedprimitive . Its `DrawIndexedPrimitiveUP` reference uses a *different* `MinVertexIndex/NumVertices` for the user-memory data: https://learn.microsoft.com/en-us/windows/win32/api/d3d9helper/nf-d3d9helper-idirect3ddevice9-drawindexedprimitiveup .
6. **Replacement may broaden an invalid original range (new conditional mismatch).** `::R30TryXyzrhwIndexedPrimitiveVB:4400-4500` builds a new `scratch.used` mask from physical min/max, transforms separate eye vertices, rebases every index (INDEX16 or INDEX32), then calls original `DrawIndexedPrimitiveUPHook` with `minVertexIndex=0` and `numVertices=vertexCount`, not the original declared range. Synthetic illustrative TRIANGLELIST, BASE=0, original `minVertexIndex=8,numVertices=3`, valid INDEX16 entries `{8,9,12}`, sufficiently large and completely captured VB/IB: index 12 violates the original declared range [8,10], but transformed span [8,12], vertexCount=5, rebase `{0,1,4}` is within replacement [0,4]. If all R30 eligibility/transform gates pass and R62 declines, R30 can issue valid-form UP eye calls instead of exposing a would-be invalid original DIP. This is source/API arithmetic, **not** proof that OutRun emits this tuple or that any D3D9 runtime/driver actually accepts/rejects it.
7. **INDEX16 negative boundary control.** Under the already-checked physical-index guards, `maxPhysical-minPhysical = maxRaw-minRaw <= 65535` for INDEX16, irrespective of a constant baseVertexIndex. Thus a valid INDEX16 set cannot hit the 262144-span cap and cannot trigger `v>0xFFFF` in the INDEX16 local-rebase guard at ~4435-4452; INDEX32 can encounter the large-span cap. This is a mathematical control case, not a new 01291 sparse-copy defect, and says nothing about an observed source draw. The reported mismatch concerns the caller's declared `minVertexIndex/numVertices`, even for a tiny INDEX16 span.
8. **L/R, restore and Present do not validate the original input contract.** `::R30ExecuteXyzrhwStereo:3829-3944` draws left, sets right RT/depth/viewport, draws right, restores right-pass state and poisons on failed right/restore; `::R30TryXyzrhwIndexedPrimitiveVB:4471-4500` restores original stream 0 and index buffer after UP, needed because D3D9 UP unbinds them. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:685-823` checks world authority, duplicated draw, right-eye integrity, pose/resources and actual normalized Present before active stereo, otherwise mono/fallback. `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` chooses DirectGPU full-eye UV or SBS half UV, copies to L/R OpenXR projection images; `::xrEndFrame:3562-3635` inspects actual XR submission. Good Present/XR transport would not retrospectively prove the original call used valid index hints.
