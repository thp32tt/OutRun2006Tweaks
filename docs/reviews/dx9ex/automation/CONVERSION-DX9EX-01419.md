## REVIEW_SCOPE

Check whether a valid **clean pre-HUD SkyGlow snapshot** can outlive the scene pixels it represents even when its reduced textures are never reallocated: producer -> semantic -> original queued D3DX/direct-up/quad/mask -> actual physical Draw -> R30/R62 and L/R RT/depth/WVP -> pre-HUD L/R StretchRect -> **later original game D3DCLEAR_TARGET / new BeginScene / world redraw** in the *same* Present -> R30 bright/blur/composite -> StateBlock/RT/depth/viewport restore -> R7 DirectGPU/SBS Present/Frame.v2 -> R23 OpenXR projection -> xrEndFrame. Isolate the difference between a BeginScene counter, an actual two-eye TARGET clear, and a changed scene generation. No gameplay order or HMD output has been captured.

## EVIDENCE — exact GitHub source and checked-in REA

1. **Producer vs semantic vs physical draw:** `src/hooks_graphics.cpp:591-605,670-745` distinguishes exact projected CABE, C993 and screen HUD scopes. `src/vr/game/render_semantics.hpp:1083-1111,1213-1432` treats ScreenHud/ScreenOverlay2D as a SkyGlow cutoff, not world billboard/SceneEffect. `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-39` traces original 0x42D710 to type0 D3DX 0x42A0A0, direct-UP 0x42C0F0, type1 quad 0x42A3A0 and masked type1 0x42A800, with unresolved calls and possible D3DX deferral. This does **not** prove a specific runtime producer, physical API, queue/flush epoch or the relative order of later scene passes. Exact node + semantic + Draw identity is a prerequisite before associating a visual artifact with a named effect.
2. **Successful clean capture is only Present-stamped:** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1157-1192` requires already-complete stereo world/duplicated draw and working eye surfaces, returns early if `R30SkyGlowSceneCaptureEpoch == PresentEpoch`, otherwise StretchRects L and R into stable `reduced[]` and stamps the epoch after both succeed. `:1194-1212` stamps `R30SkyGlowScreenDrawEpoch` once, *before* attempting first qualifying screen draw capture; later screen boundaries in the epoch do not attempt a second capture. `:5123-5133,5520-5524,5550-5554,5636-5640,5667-5671` confirm owned/native GPU and delegated draw routes are not a generic proof of a second post-capture clean snapshot.
3. **R7 can clear both game eyes without touching the R30 snapshot flags:** `src/vr/d3d9/stereo_renderer_r7.inc:1562-1565` `ClearDest` issues the original LEFT Clear and, for an eligible backbuffer, binds the RIGHT eye RT/depth/viewport and issues the original RIGHT Clear before restoring state. The D3DCLEAR_TARGET flag may replace previously captured color in both eyes; success/failure, depth/stencil synchronization and restore have their own gates. That function does not reference `R30SkyGlowSceneCaptureEpoch`, `R30SkyGlowScreenDrawEpoch`, or invalidate the reduced texture snapshot. A successful full-color two-eye Clear is stronger evidence of a changed source image than a raw BeginScene-count increase.
4. **Additional world drawing does not refresh the old bloom source:** R7 `ExecuteStereoDraw` `src/vr/d3d9/stereo_renderer_r7.inc:1524-1555` executes actual LEFT and RIGHT primitive draw calls, guards pose/depth/stencil and restores original state, and can mark `FrameHadWorldStereo` / `FrameHadDuplicatedDraw` valid. It does not advance a SkyGlow content generation. Multiple valid later draws can change the L/R scene image after capture without changing the R30 capture epoch; *which* draws actually run after HUD is not established by source alone.
5. **BeginScene counter is merely coarse telemetry:** `src/vr/d3d9/stereo_renderer_r7.inc:206,224-226,1625-1629` tracks `GetBeginSceneCallCount()` changes since last Present and increments `MultiBeginScenePresents` for >1; `:1739-1744` advances `PresentEpoch` only after Present, resets per-frame stereo flags, and handles Reset separately. There is no demonstrated equality between multiBeginPresent, a later game full-color clear, and a changed L/R world; internal SBS composing may itself use BeginScene (`:1504-1511`). **Do not** treat the counter alone as a reproduced late-world-pass bug or as grounds to invalidate capture.
6. **Present-time lookup trusts successful epoch equality:** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1214-1258` excludes WARP/RESTART/GOAL/TIMEUP/LINK_TIMEUP/GIVEUP and skips bloom when first HUD drew but capture failed. After successful capture, `:1287-1323` skips live L/R `StretchRect` if `SceneCaptureEpoch == PresentEpoch` and instead bright-samples the old `reduced[eye]`; `:1326-1379` blurs and additive-composites to *current* L/R eye surfaces, `:1385-1404` applies StateBlock and restores RT/depth/viewport. This check does not compare source backbuffer color-generation, clear serial, or scene-pass serial. This is not #01418's resource generation mismatch: reduced targets remain identical and populated; their **content is stale relative to the newly cleared/redrawn source**.
7. **Frame delivery does not inspect bloom freshness:** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1492-1520` calls bloom before the delegated R29/R7 Present; Reset explicitly releases the resources and invalidates both epochs. `src/vr/d3d9/stereo_renderer_r7.inc:1625-1744` gates DirectGPU post-Present completion or SBS compose, Present HRESULT, and frame metadata; `vrhost/src/main_r23.cpp:1440-1515,3510-3575` builds separate L/R projection textures/views and submits with `xrEndFrame`. Those eligibility and transport gates cannot certify that an earlier bloom snapshot matches the final world color in either eye.
8. **Evidence limits:** `docs/automation/reviews/DX9EX_HMD_REFERENCE_20261020_0CFF83CF.md:1-35` is a *different exact tested baseline binary*, not a current-sha SkyGlow+late-clear repro. GitHub Issue #13 is an open runtime regression ledger; it does not supply a same-Present color-clear/capture serial trace. No new Quest3/VDXR eye dump, readback of depth/color, physical Draw/Flush trace, post-HUD game full-color Clear, source-SHA HMD A/B or GPU timing exists in this task.

- **Verified from code:** R7's eligible physical Clear writes both eye targets and never invalidates R30's already successful scene-capture stamp. R30's Present bright pass tests only the Present epoch and can reuse old reduced contents even if newer scene pixels are in the game eye surfaces. The mismatch is **content generation**, not resource creation generation (previous #01418).
- **Not established:** that OutRun's normal gameplay ever performs a full stereo game backbuffer TARGET clear and new world drawing after the first qualifying HUD in the same Present; that this occurs in an allowed SkyGlow game mode; that a delayed D3DX queue reorders an actual Draw across the candidate boundary; that any Quest3 luminance doubling, ghost halo or performance regression was caused by this path.
- **Falsifiers and alternatives:** exact same-SHA GPU/API timeline proves all game backbuffer target Clears and changed L/R world draws precede the first physical HUD cutoff; later clears are offscreen/depth-only or in excluded modes; bloom is already disabled; or an additional hidden game/renderer callback demonstrably invalidates and recaptures after late clear. Other causes include CABE/C993 optical overlap, SkyGlow stale resource generation (#01418), and double additive composite on failure (#01417).
