## REVIEW_SCOPE — source→semantic/queue→D3DX/native→R30/R62 or R26→L/R+restore→R9 Present→R41 host cache→OpenXR

1. **Original producer and deferred GPU ownership.** Existing checked-in historical REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:35-93` maps the original frame scheduler `0x00449050`, SpriteNode queue consumer `0x0042D710`, original kind-0 D3DXSprite `Begin/Draw/Flush/End` and direct native UP submits. `src/vr/game/hud_command_batch.hpp:8-118` tracks sprite generation, queue node/epoch and native internal Flush; it cannot prove a particular scene element drew in the current process. An admitted producer semantic alone is not a completed L/R image.
2. **Physical render and restore.** On the R26+HUD review baseline, `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawPrimitiveDestR30/DrawIndexedPrimitiveDestR30:5349-5440` consume physical-draw scope, try XYZRHW and guarded native paths; `::R62TryFixedFunctionSpriteIndexed:5123-5175` is restricted to corroborated HUD or projected markers with a live fixed-function FVF check; failures retain R26/native fallback. `::R30ExecuteXyzrhwStereo:3829-3910` calls the left GPU draw, switches RT/depth/viewport for right, then restores. Right-draw or restore failures block complete stereo; no physical draw or eye HRESULT was collected in this review.
3. **D3D9Ex copy/Present condition.** After positive `FrameHadWorldStereo`, `FrameHadDuplicatedDraw`, pose/metadata and resource checks, `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-812` computes `directOnly`, increments `pendingFrameId`, and tries `ResolveDirectTransport`. The included `src/vr/d3d9/stereo_renderer_r7.inc::ResolveDirectTransport:1358-1426` scans the four-slot producer ring with fence and host ACK constraints, copies L/R using `StretchDirectEye`, and can return false (not-ready, backpressure, resource/copy failure). Any one cause must be discriminated from telemetry, not presumed.
4. **New R9 transient-miss split.** For an eligible R9 DirectGPU-only frame with `ResolveDirectTransport=false`, R9 sets `composedStereo=false`, restores mono if a backup is available, and calls original `Present`. On its non-active branch `PresentDestR9:796-807`, R9 **unconditionally** calls `PublishStereoState(StereoSbsFallbackMono,false,0,0)` when stereo was requested. But its immediate `PublishRenderFrame(fallback,0,...)` is **skipped** specifically when `directOnly && stereoRequested && !directTransport` to avoid overwriting an earlier direct-eye ring entry. `src/vr/d3d9/stereo_renderer_r7.inc::PublishStereoState:1477-1481` clears shared `ClientStereoFrameIndex`, stereo-active/draw flags and source pose sequence in the fallback case. Therefore the sideband `ClientStereo*` reports fallback while Frame.v2 can still contain the prior completed direct stereo entry; R9's regular successful next frame can restore the sideband.
5. **The older included R7 callback is different.** `src/vr/d3d9/stereo_renderer_r7.inc::PresentDest:1632-1740` sets `directOnlyHold` for an eligible DirectGPU miss. Its fallback branch is suppressed under `directOnlyHold && stereoFrameEligible && SUCCEEDED(hr)`, explicitly retaining prior stereo metadata/projection. This is a **conditional source-level state-policy divergence**, not proof that R7 rather than R9 was installed at runtime. `src/vr/d3d9/stereo_renderer.cpp::R9InstallCallbackPolicy:849-887` must actually succeed before R9 semantics apply.
6. **R41 no-frame handling and prior projection are independent.** In `vrhost/src/main_r23.cpp:2940-3120`, the DirectGPU-only host reads Frame.v2 history, resets its `lastProcessedStereoFrame` cursor on a new PID/run epoch, uses `OutRunVrDirectRingLatest::Pick` for a *new* eligible `StereoSbsActive` frame, and explicitly sets `have=false` rather than reusing a previously displayed history slot as new. `vrhost/src/main_r23.cpp:3140-3290` commits only validated frame+pose and waits for successful projected rendering before updating verified bundle/processed frame identity. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp::CopySharedFrameToSafeEyesR32:252-315` uses host D3D11 `CopyResource`, bounded EVENT completion, per-slot ACK and SafeEye identity. This path does not make the cleared R9 sideband equal to the held image.
7. **XR output of the miss.** `vrhost/src/main_r23.cpp:3290-3460` keeps `cachedProjectionValid` across producer stalls while Gameplay remains active, reuses last released projection when no new match exists, and explicitly suppresses classic theater fallback in `directTransportOnly`. A bootstrap case may show the last LOCAL menu projection until first valid gameplay stereo. The final `xrEndFrame` at `vrhost/src/main_r23.cpp:3560-3630` submits a cached/fresh projection or a no-layer frame according to `layerReady`; **neither source-level `PublishStereoState` nor an XR submit API success demonstrates what was visible in Quest3.** Current review has no matching PID/frame/eye/source-pixel observation.
