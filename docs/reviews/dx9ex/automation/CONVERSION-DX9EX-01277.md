## NEW_FINDING — fact / conditional hypothesis / refutation

- **NEW_FINDING=RIGHT_STENCIL_BOOTSTRAP_SAME_PRESENT_REPLAY_LACKS_POST_CLEAR_WRITE_PROVENANCE**; CONFIDENCE=CONFIRMED_STATIC_ACCEPTANCE_BOUNDARY; RUNTIME_DEFECT=UNPROVEN. A same-Present full-clear epoch plus compatible surface descriptors is enough to replay a clear and mark the right-eye stencil synchronized, even though the bootstrap does not check whether left-only stencil writes occurred **after** the recorded clear. Unlike 01276 (R30 HUD early return), this review isolates the **meaning and freshness of the synchronization bit itself**.
- **HYPOTHESIS_ONLY / minimal counterexample sequence:** (A) full stencil clear, initially aligned eyes; (B) a native **left-only** write with stencil test/write-mask/op actually active changes left stencil and invalidates right sync; (C) a later eligible draw in the same `PresentEpoch` sees a stale recorded clear and bootstraps the right by replaying **only** the earlier clear; (D) `RightStencilSynchronized=true` admits a later stencil-reading two-eye primitive though left retains step B's write. This might yield divergent mask/cutout pixels even when both draws and Present succeed. It requires proof that B and C truly coexist on a non-poisoned eligible frame; the code inspection does not establish that.
- **REFUTATION:** No original `0x42A800` stencil-active draw; no left-only stencil writer before the bootstrap; all relevant writes mirrored to both eyes; a later full paired stencil clear after B; every candidate transition poisoned/mono-rejected before draw or publish; paired stencil buffers demonstrably equal after bootstrap; or the composite uses alpha-only state. Any of these defeats a claimed runtime mask defect. Do not label this fixed, reproduced, or confirmed in Quest3 without actual evidence.
