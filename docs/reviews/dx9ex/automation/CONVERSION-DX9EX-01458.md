## EVIDENCE — anchored six-to-five producer and submission boundary

1. **Original producer inventory is six calls, not six identical HUD owners.** The archived SHA-pinned original EXE REA document (`docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:3-17`) verifies E8 parent RVAs `0x9898E -> 0x429530` (B4 animated), `0x989AD -> 0x4973C0` (B4 text), `0x98A10 -> 0x4974E0` (B4 number), `0x98A36 -> 0x429530` (B5 animated), `0x98A89 -> 0x4973C0` (B5 text), and `0x98AC6 -> 0x429530` (6C animation). That REA notes the 6C call was absent from its reconstructed outgoing-function inventory despite original E8 bytes: it is a real original call, not an invalid address. This is **archived reverse-analysis evidence**, not a new binary analysis today.
2. **The active source deliberately permits only 2+3.** `src/hooks_uiscaling.cpp:379-395` explicitly distinguishes original mode 1/9 B4, mode 0/7/8 B5 from mode=2 6C. `StageExtensionSpraniCalls={0x9898E,0x98A36}`; `StageExtensionPrintCalls={0x989AD,0x98A10,0x98A89}`. The comment says `0x98AC6` must **not** inherit +TIME ScreenHud semantics. `src/hooks_uiscaling.cpp:3032-3075` installs enter/leave hooks as one five-parent unit, rolls back all five when incomplete, and logs exactly `2 extension sprani + 3 print`. This is a **positive/negative semantic ownership boundary**; 6 total REA calls must not be reported as 6 successfully hooked/eyed +TIME sources. No replacement or additional hook is proposed.
3. **Five eligible parents have separate CPU and deferred GPU lifetimes.** `src/hooks_uiscaling.cpp:1719-1846` runs `StageExtensionEnter/Leave` with a depth guard and captures VR/queue-epoch admission and sprite-priority root/tail snapshots. `StageExtensionLeave:1819-1829` tags only proven new SpriteNodes and flushes only if source admission still holds. `StageExtensionCompleted` and its log at `:1836-1842` aggregate eligible calls, **not individual B4/B5/print/6C physical draw receipts**. The excluded 6C is outside these exact E8 parent wrappers; that fact alone does not tell whether the original renderer physically drew it or whether another independent owner processed it.
4. **Four original queue exits are distinct, not one D3DX draw.** Archived REA `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-32` maps queue consumer `0x42D710` to type0/D3DX `0x42A0A0`, type0/UP `0x42C0F0`, type1 animation quad `0x42A3A0`, and type1 mask/composite `0x42A800`; normal caller `0x449050`. `src/hooks_uiscaling.cpp:4226-4295` selects semantic nodes at original RVA `0x2D762` and closes at `0x2DCB4`, keeping unsafe `0x2D734` unhooked. A 6C animation may travel a type1 path, but **which actual branch and eye route it used is unmeasured**.
5. **D3DX Draw registration is not final GPU submission.** `src/hooks_uiscaling.cpp:3479-3580` snapshots native Begin/Flush/End generation and applies deferred owner restoration only for exact homogeneous batches; `:3615-3685` checks live D3DX object before tracked Flush at a direct stage entry/exit; `:3733-3903` separates first queue-node, same-token different queue-node, and queue-end transitions. `:3907-4059` captures the semantic command before native D3DX::Draw because that call may implicitly Flush/reenter, and only re-arms/flushes exact stage or goal ownership under the guarded ledger. Mixed, foreign, queued, lost-device and stale-object cases retain original native fallback, not blanket ScreenHud promotion.
6. **Eligible HUD eye ownership is conditional on physical Draw and restoration.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30TryScreenSpaceFovDraw:5033-5119` requires corroborated semantic scope, stereo resources, depth/stencil, pose and viewport. `:5141-5273` performs left then right physical D3D9 draw with right-eye RT/depth/viewport/WVP setup and restore, recording failure/fallback; `R30GuardScreenSpace:5276-5287` delegates `E_NOTIMPL` to its fallback. `src/vr/d3d9/stereo_renderer_r7.inc::ExecuteStereoDraw:1540-1559` separately handles ordinary D3D9 Draw*/UP fallback/duplication. Therefore a valid five-parent semantic hook does **not** certify 5/5 eye draws, successful GPU HRESULT, or correct optical depth.
7. **No original positive/negative identity is guaranteed at final XR submission.** `stereo_renderer_r7.inc:1693-1741` composes eligible stereo, calls real D3D9 Present, then conditionally publishes Frame.v2 stereo/run/pose metadata; `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` copies accepted source into separate D3D11 L/R swapchain slices; `main_r23.cpp:3562-3589` calls `xrEndFrame` with R24 final-layer accounting.
