## REVIEW_SCOPE — original producer → semantic/queue → D3DX/native GPU Draw → R30 or lower R26 → L/R → restore → Present / OpenXR

1. **Original producer/queue (historical checked-in REA only).** `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-45,74-92` maps scene scheduler `0x00449050`, +TIME `0x00498670`, rank HUD `0x004B9D80`, vehicle marker `0x004BAD20`, and queue consumer `0x0042D710`. Queue type-0 `ID3DXSprite::Draw` may submit at later `Flush/End`; type-1 often calls native `DrawPrimitiveUP`. Thus a queued producer call, text character, bright texture or source WVP upload is not necessarily the same GPU Draw. This document is an old REA-derived source map, **not** new EXE decompilation or new real-device evidence.
2. **Original mod c64 write recording.** `src/vr/game/outrun_renderer.cpp:1822-1986,1990-2159` gates game `SetVertexShaderConstantF` touching c64..c67, increments `LensCentreUploadGeneration` before forwarding, invalidates the previous WVP marker, and only records a returned native upload if the callback has not been superseded. The exact C993 direct-centre and queued ScreenHud partial-WVP accumulators demand same call/pose/shader/queue/draw identities; their independent helper contracts are `src/vr/game/lens_centre_partial_wvp.hpp:34-127`, `src/vr/game/queued_hud_partial_wvp.hpp:10-65`, `src/vr/game/hud_native_source_transaction.hpp:13-68`. This is a **positive existing guard**; do not reimplement it.
3. **Global last raw WVP includes provenance.** `src/vr/game/outrun_renderer.cpp::RecordGameWvpWrite:1662-1726` stores `LastRawGameWvpWrite`, top-level-draw serial, latched pose epoch, tracked shader pointer+serial, semantic scope, queue node/epoch and producer. `GetLastRawGameWvpWrite:2389-2405` returns the matrix + write/draw/shader serials, **not** the saved source scope/node/producer/pose epoch. A separate `GetLastGameWvpSemanticProvenance` API exists. Data capture and consumer proof are separate concerns.
4. **R30 normal original-WVP recovery, then distinct extended escape.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R44GetOwnedRawOverlayWvp:1959-1999` requires tracked shader epoch and at most 12 Draws. On miss, `R30BuildScreenSpaceEyeConstants:4499-4635` for `PerspectiveHud` or `Hud2D` invokes `R30GetExtendedRawWvpForExactHud`; the latter at `:1858-1886` requires the **current** semantic to corroborate HUD, the same tracked shader pointer/serial, and `0 < currentDraw-writeDrawSerial <= 128` (constant `:1808-1812`). It does **not** compare captured WVP producer, old semantic, queue node/epoch, latched pose epoch, nor original per-D3DX physical batch with the current draw. The strict source snapshot remains available in the writer but is not consumed by this extended path. The current ScreenHud tag proves current draw type, **not** necessarily the historical last c64 writer.
5. **Physical execution / eyes.** The outer `R30TryScreenSpaceFovDraw:4886-5110` requires stereo resources, pose and current semantic before building raw+eye constants. If successful it writes L-eye c64, performs native `actualDraw`, switches RT/depth/viewport, writes R-eye c64, performs R-eye native `actualDraw`, and checks restore; otherwise it returns `E_NOTIMPL` to lower R26 path via `R30GuardScreenSpace`. The lower R7 owner separately checks last verified WVP / shader epoch and restores c64 `src/vr/d3d9/stereo_renderer_r7.inc:929-960,1052-1080,1538-1560`. R28 synthetic epoch and R46 trace findings from 01174/01175 do not substitute for this separate **R30 stored raw-WVP identity** audit.
6. **Final frame gate independent.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-822` demands seeded and nonpoisoned stereo, real Present, and separate frame publication; `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:260-319` waits for the pair of eye copies before setting SafeFrameId; `vrhost/src/main_r23.cpp:3562-3610` records actual `xrEndFrame`. Even if the extended gate accepts a WVP and GPU draws succeed, those facts alone cannot certify correct Quest3 HUD alignment or acceptable visual output.
