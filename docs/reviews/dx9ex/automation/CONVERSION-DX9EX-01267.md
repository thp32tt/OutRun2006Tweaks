2. **Queue provenance:** `hooks_uiscaling.cpp` tracks a live `ID3DXSprite` batch and exact ScreenHud +TIME/GOAL source. Normal `FlushDest/EndDest` restore the producer only for a homogeneous, active, matching sprite with verified queue/direct ownership; native Flush/End HRESULT and generation cleanup remain authoritative. `BeforeQueueTransition` isolates same-token different-node +TIME/GOAL boundaries and fails closed on mixed/foreign/unknown queues. R33 `PhysicalDrawCommand` samples current scope, producer, queueNode, and queueEpoch at real GPU submission, not at the earlier CPU `Draw`.
3. **Actual indexed entry and guarded alternatives:** R30 `DrawIndexedPrimitiveDestR30` consumes a draw semantic and tries F11 **external ImGui** first. On its `E_NOTIMPL` only, R62 attempts native fixed-function DIP. R62 requires TRIANGLELIST, game backbuffer, stereo base, corroborated `ProjectedWorldMarker2D` or `ScreenHud`, current *live* null VS, FVF `0x142`, valid viewport, latched stereo pose/eye affine and finite original/eye projection. These shape checks alone do not grant ScreenHud ownership. A stale `CurrentVertexShaderIdentity` only blocks the non-exact result candidate; exact result re-reads live VS. `E_NOTIMPL` is **eligibility rejection**, not failed final draw.
4. **R62 stereo and restoration:** Once accepted, R62 sets per-eye D3DTS_PROJECTION and calls the original `DrawIndexedPrimitiveHook` for left and (if reachable) right through `R30ExecuteXyzrhwStereo`. That helper records the left result, switches to right RT/depth/viewport, attempts the right draw and calls `RestoreRightPassState(..., nullptr, false)` for the right-eye pass. A right draw or RT/depth/viewport restore failure poisons/arms frame fallback, while the helper returns **the left HRESULT**. R62 then *independently* attempts `SetTransform(D3DTS_PROJECTION, originalProjection)`; failure calls `NoteRestoreFailure` and `R30ArmSafeFallback`.
5. **Confirmed static asymmetric return:** The R62 final expression is `return exactResult && !restored && SUCCEEDED(hr) ? E_FAIL : hr;`. For a **successful left draw and failed final projection restore**, exact +TIME/GOAL result HUD surfaces `E_FAIL`, whereas a non-exact ScreenHud or projected rank marker returns the successful original left-draw `hr` **despite the same restore failure notification and safe fallback request**. If original left draw failed, both retain that HRESULT. This is a difference in the caller-observable success/error contract, not evidence that the restore error was ignored by the global frame guard.
6. **Rejected and subsequently handled path:** If R62 returns `E_NOTIMPL` before taking ownership, R30 tries indexed XYZRHW then guarded native/R29 screen-space path. If R62 returns a terminal HRESULT (including `E_FAIL` after the left draw), R30 returns immediately; no second native left draw is implied. The R30 `RESULT_HUD_REJECT: stage=R62_ONLY finalRoute=UNDETERMINED` telemetry is intentionally intermediate and cannot alone diagnose headlocking/mono.
7. **Presentation / host truth:** R9 `PresentDest` requires world stereo, duplicated draw, no right/incomplete failure, stable pose/metadata, resources and real Present success for stereo publication; it can restore/publish mono fallback on incomplete eye state. A ScreenHud pair alone is not world-seeding proof. The x64 host's `xrEndFrame` layer/submitted frameId/sourceKind is the final OpenXR join. No joined real DIP L/R HRESULT, independent projection restore status, frameId, final R9 normalized Present, and Quest3/VDXR headset evidence was captured in this task.
