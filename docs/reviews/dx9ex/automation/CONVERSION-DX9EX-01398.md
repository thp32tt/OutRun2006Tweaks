- FACT: The default VR-Wide source retains native PMT visible/invisible EAX after a successfully scoped stereo-FOV CPU visibility call, but overrides it to visible when scoped projection/pose cannot be trusted. Therefore `fail_open_calls` can represent intentional *safety-driven extra CPU stage-node admission*, yet it neither counts actual physical GPU calls nor proves whether either eye was fully rendered. Conversely, a native PMT reject happens before the R26 world duplicate-draw machinery and cannot be recovered by a right-eye hook. This is a separate optimization/correctness boundary from #01397's per-eye UP cost.
- HYPOTHESIS_ONLY: transitions between valid and missing/invalid pose may vary original object admission, CPU stage-object traversal and opaque overdraw; an underspecified near-field camera/eye offset may also leave edge objects unsubmitted when the original PMT answer stays zero. Neither has been observed at SOURCE_HEAD in headset footage, and other renderer, host and stage-particle costs are plausible.
- CONTRARY/FALSIFICATION: for frames with live complaints, show `scoped` always true and no fail-open delta while per-node PMT IDs and visibility results are stable; or show extra admitted nodes generate no extra Draw/GPU time. To disprove eye-edge clipping, independently trace the original rejected PMT node against both eye frusta/camera transforms and confirm no visible mesh should have survived. If the signature check refused installation or mode=0/2 was selected, the proposed mode-1 path does NOT describe that session. An overall FPS dip alone is not proof.
