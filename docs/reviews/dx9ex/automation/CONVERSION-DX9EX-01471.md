2. **NEW static one-shot semantic identity boundary.** `src/vr/game/render_semantics.hpp:1703-1755` shows `ConsumeSpriteNodeScope` looks up eligible `node`, assigns `producer`, removes its hint and swaps the consumed record out of `SpriteNodeSemanticTags`. `...:1757-1805,1807-1841` creates a new `SpriteQueueNodeEpoch` at each `SelectSpriteQueueNode` and falls back to `ScreenOverlay2D` if no matching tag is still available. `...:1200-1211,1549-1640` and `...:1841-1894` deliberately keep *unvisited* tags over a partial queue exit and retire frame-old tags only at Present/Reset; **they do not restore the tag already consumed during the first pass**. Therefore, **IF the exact same underlying original node is physically selected twice in one game frame, with no intervening eligible new exact registration**, the second selection has a new epoch but can lose the original producer's exact ScreenHud/marker semantic. This is a deterministic conditional consequence of current code, **not proof the game actually repeats a result node**. If all partial/full queue node visits are disjoint this condition never occurs. Pointer address alone must not be used to claim same logical generation.
3. **The physical GPU path will react differently to exact versus fallback ownership.** `src/vr/game/render_semantics.hpp:1295-1432` captures immutable `PhysicalDrawCommand` scope, producer, node and epoch per native draw; screen scopes veto unsafe world-WVP borrowing. `src/vr/d3d9/stereo_renderer_r33.cpp:1700-1818,1818-1900` preserves unproven screen draws as one original or attempts exact R30/HUD and safe fallbacks at true DP/DIP/UP dispatch; type, FVF and actual D3DX Flush/End decide when the physical call occurs. The second node's fallback could produce different *stereo ownership* even if the game's source geometry/texture is identical. Nothing proves the graph was drawn twice, that both draws reached R30/R62, or that the current **R26+HUD packaged binary** compiles the later HEAD implementation.

A pair of raw L/R calls under *one* native draw interception is the expected stereo duplication.
