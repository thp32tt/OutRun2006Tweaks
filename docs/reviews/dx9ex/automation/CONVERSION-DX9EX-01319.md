## REVIEW_SCOPE — distinct from 01318

01318 analyzed R26 scratch/shadow-vertex CPU copying, full-window transforms and possible frame pacing. This independent pass inspects **R26 tracked-occlusion write-free query proxy single-execution**, the original game's conditional world visibility versus its two-eye visual consequence, and why a successful final stereo Present does not by itself certify bilateral query-driven visibility. No actual occlusion producer, GPU query count, disappearing geometry, HMD artifact or speed-up was observed.

Static logical path: original game world/effect draw **or independently verified direct GPU producer** (not presumed to be a 0x42D710 SpriteNode) -> effective semantic / optional source queue epoch -> R30/R62 direct HUD/XYZRHW handling *or* conservative R29/R26 lower chain -> R26 live D3D9 query/write-mask gate -> native DP/DIP/UP/DIP-UP once for a proven write-free query proxy, versus normal R23/R22/R13/R9 path for rejected candidates -> ordinary world L/R draws and state restoration -> R9 Present/active-versus-mono Frame.v2 gate -> host source/layer selection and xrEndFrame.

1. **Producer / semantic / queue identity:** historical original REA maps world/effect and separate +TIME/result native sprite priority queue, but has not identified a specific original occlusion-proxy CALL RVA or its draw fingerprint. `CapturePhysicalDrawCommand` records effective scope, verified producer if any, queue node/epoch only when queued. An active occlusion query is a device/render-state condition and does not authorize relabeling a generic HUD SpriteNode as a proxy. Queue/D3DX ownership must be proven independently if the selected physical draw is queued; otherwise label DIRECT_ORIGIN_UNKNOWN.
2. **R30/R62 physical ownership:** in R26+HUD default, `DrawPrimitiveDestR30`, `DrawIndexedPrimitiveDestR30` and UP counterparts consume semantic, try exact specialized screen-space/XYZRHW paths, then fall back to R30GuardScreenSpace -> R29/lower R26 chain if not claimed. R62 fixed-function D3DXSprite owns certain exact ScreenHud/projected DIP draws; it does not prove ownership of a world occlusion proxy. The R26 gate is therefore relevant only when the real draw actually reaches it, not to every semantic/world candidate.
3. **Precise R26 admission:** `R26TrackedOcclusionNeedsSingleExecution` requires game device, no internal pass, main backbuffer, no auxiliary RT, no forced mono shadow, available query tracking, wanted and seeded stereo, and `ActiveOcclusionQueries>0`. `R26TrackedOcclusionDrawIsWriteFree` independently requires readable `D3DRS_COLORWRITEENABLE==0`, readable `D3DRS_ZWRITEENABLE==FALSE`, and either stencil disabled or a readable zero `D3DRS_STENCILWRITEMASK`. An unavailable getter or any possible color/depth/stencil write rejects the optimization to ordinary R23. This is an explicit conservative GPU-write predicate, **not** a proof of which eye's occlusion volume or subsequent renderer culling decision is represented.
4. **Actual single physical draw / accounting:** `R26GuardTrackedOcclusion` deliberately bypasses the normal R23 -> R22 -> R13 -> R9 eye-replay chain only for the proven write-free proxy. It manually calls `NotifyTopLevelDraw` to retain draw-serial accounting, increments `R26TrackedOcclusionSingleExec` and `OcclusionStereoRejects`, and invokes exactly one original native D3D9 draw via one of four R26 DP/DIP/UP/DIP-UP hooks. If that draw fails it calls `R9Poison(StereoFailureLeftDrawFailed,...)`. On native success the helper neither performs a right-eye proxy draw nor poisons the entire frame. The log sentence 'stereo Present remains eligible' expresses this design, not a measured bilateral visibility result.
5. **Other physical eyes and restoration:** R30/R62 normal eligible draws have distinct L/R targets, depth/viewport changes and restore requirements; the query-only R26 bypass intentionally does **not** duplicate the query proxy or switch right-eye target just to count it. A successful proxy is not a substitute for later real world both-eye submission. Non-write-free active-query draws continue through the existing conservative replay/mono-safety path; treating them as proxies would risk actual one-eye color/depth loss.
6. **Present and XR boundary:** R9 `PresentDestR9` requires `FrameHadWorldStereo && FrameHadDuplicatedDraw && !FrameRightDrawFailed && !FrameStereoIncomplete` plus pose metadata and stereo resources; otherwise it restores mono when available. After successful normalized Present it publishes active Frame.v2; the host chooses source/projection layers, eventually calls `xrEndFrame` and records actual layer/frame IDs. These are frame-level gates. Neither checks whether an earlier *single-view occlusion query result* conservatively covered all geometry that ought to be visible to **both** optical eyes.
