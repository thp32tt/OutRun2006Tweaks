- FACT: comparator has no finite guard. A hypothetical append-ordered pointer trio `A<B<C` with `SortKey(A)=10`, `SortKey(B)=NaN`, `SortKey(C)=0` produces `A<B=true` (pointer tie), `B<C=true` (pointer tie) but `A<C=false` (numeric comparison). This violates strict-weak-order transitivity required by `std::sort` **if such non-finite keys actually occur**. It does not establish that OutRun supplies a NaN, that an OOB/crash happened, or that alpha pixels are wrong.
- SECONDARY_HYPOTHESIS_ONLY: even with all-finite entries, object-space radius with world-matrix scale and one source game camera key can misorder partially overlapping, large or scaled translucent stage surfaces relative to eye-specific depth. This is a known source approximation, not a proven Quest3 glass/water root cause.
- CONTRARY/FALSIFICATION: complete same-SHA draw-buffer traces showing every relevant `CenterZ/radius/SortKey` finite refute the non-finite predicate for those sessions; per-stage `SkipQuickSort=true` means this comparator did not run. If per-eye alpha order and physical output match original scene expectations despite finite far-edge approximation, do not attribute the visual defect to sorting.
