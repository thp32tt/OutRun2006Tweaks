3. **R7 base transaction must be armed first.** `src/vr/d3d9/stereo_renderer_r7.inc::InstallStereoHooks:1767-1830` initializes base vtable callbacks disabled-first, rolls back a partial create/enable failure, and sets up base owner identity; `stereo_renderer.cpp::R9InstallThread:896-921` waits for `StereoInstallReady`, fails closed on `StereoInstallFailed` or timeout, and calls `R9InstallCallbackPolicy` only for a valid installed device. A runtime build with failed R7 or R9 installation may not traverse the R9 detour.
4. **R9 installs the relevant callback explicitly; no compile-time entitlement implies installation.** `src/vr/d3d9/stereo_renderer.cpp::R9InstallCallbackPolicy:856-894` installs `PresentDest` → `PresentDestR9`, Reset/RT/depth/Clear/Draw* and rolls back on any missing hook. Successful transaction sets `R9InstallReady` with an ACTIVE log. `R9InstallThread:896-921` and `VRFinalTestR9Hook::apply:923-945` show asynchronous startup. A log of registration or a CMake option alone cannot prove which callback ran for a specific Present.
5. **R13 is a later optional wrapper, not a substitute fence in this Present.** `src/vr/d3d9/stereo_renderer_r13.cpp::R13StereoInstallThread:774-841` waits for R9 ready, creates Reset/Resolve/Present/Draw* hooks disabled-first, enables them and then publishes `R13OverlayReady`; failures roll back. `PresentDestR13:718-749` delegates via `R13PresentR9Hook.stdcall` in both ready and not-ready branches, then retires semantic queue tags on R26+HUD. There is **no visible R7-style post-Present producer EVENT S_OK test** within this R13 wrapper. `ResolveDirectTransportR13:243-279` instead checks slot reuse/ACK ownership *before* transport copy, not physical GPU completion *before* Frame.v2 publication.
6. **Consumer/event boundaries are intentionally distinct.** `src/vr/d3d9/stereo_renderer_r7.inc::DirectTransportFrameReadyAfterPresent:1428-1454,::PresentDest:1693-1737` performs a 1 ms no-FLUSH producer EVENT gate after native Present on the base route. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-805` performs `ResolveDirectTransport`, an in-flight Frame.v2 marker and native Present, then can publish `StereoSbsActive` without visibly calling that R7 gate; this **known difference was recorded in 01345**. The host `vrhost/src/main_r23.cpp:2959-3015` rejects in-flight or non-direct candidates, but host filtering and subsequent D3D11 ACK cannot by themselves demonstrate that a specific producer EVENT was already complete at publication.
7. **R26+HUD draw/restore and optical endpoint.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30ExecuteXyzrhwStereo:3874-3954` performs left draw, right target/depth/viewport and right draw, calls `RestoreRightPassState`, and poisons failure; it only sets world-stereo metadata for authoritative world evidence. `vrhost/src/main_r23.cpp:3330-3413` publishes a verified fresh projection or intentionally reuses released cached projection, and `:3559-3616` actually calls `xrEndFrame` and differentiates reported submitted layer/frame. The chain is conditional; a fresh Frame.v2 entry is neither a measured GPU completion nor automatic HMD PASS.
8. **Scope exclusion.** `docs/DX9EX_OPTICAL_ROUTE_PROBE_POLICY_20261020.md:1-25,29-54` requires positive physical draw identification and R26+HUD / R84 isolation.
