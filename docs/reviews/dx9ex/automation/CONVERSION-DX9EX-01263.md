Regular queue consumer 0x449050 → 0x42D710 has four evidenced exits: type0 D3DX 0x42A0A0, type0 direct UP 0x42C0F0, type1 quad 0x42A3A0, type1 mask/composite 0x42A800; 36 indirect calls remain unresolved. These do NOT prove a given result glyph or texture is DXT or calls LockRect with a particular RECT.
2. A translated MANAGED texture can enter R14 tracked Shadow with a SYSTEMMEM peer or tracked DirectOnly. Only a successful Shadow CPU LockRect is relevant to this finding. R14 TextureLockRectR14 sanitizes DISCARD/NOOVERWRITE/NO_DIRTY_UPDATE flags before the CPU peer lock. If the original caller passes rect==nullptr, the successful Lock stores lockRectValid[level]=false; if it passes *any non-null RECT*, R14 copies it and sets lockRectValid[level]=true. R14 does not normalize {0,0,Width,Height} to the null/full-level sentinel. The CPU lock HRESULT may reject an illegal compressed rectangle before either path reaches a successful Unlock.
3. At writable TextureUnlockRectR15, after successful CPU Unlock and no external-write overlap, R15UploadLevel obtains the exact source/destination mip surface and attempts UpdateSurface(source, optional stored RECT, destination, optional point). When lockRectValid is true, the destination point is the rect's left/top. For an explicit rectangle spanning the entire mip, UpdateSurface receives a non-null full-mip RECT; for nullptr LockRect it receives null sourceRect and null destinationPoint.
4. **Verified path asymmetry:** if UpdateSurface fails, R15UploadLevel attempts R14CopyWholeLevelByLock only when !lockRectValid[level], not when the copied RECT numerically spans the full mip. Therefore a successful null whole-mip LockRect can attempt direct whole-level fallback, while a successful explicit {0,0,Width,Height} LockRect cannot; R15 increments partial-upload-fail-close and preserves failure for the explicit case. This branch distinction is static and is not proof of a driver failure or missing pixels. It implements a conservative pointer-presence policy even for geometrically full coverage.
5. With a failed R15UploadLevel the R15 Unlock path clears the mip validMask bit, sets retirePending and eventually retires the Shadow after all outstanding Locks drain; it returns the failed HRESULT. With null-RECT fallback, R14CopyWholeLevelByLock first locks SYSTEMMEM source (READONLY), then translated GPU destination (single-level DISCARD then fallback flags 0; multi-level flags 0), copies min(abs(source.Pitch),abs(destination.Pitch)) per row, and checks both Unlock HRESULTs. DXT uses ceil(mipHeight/4), minimum one compressed block row; other formats use mip height. Success depends on actual GPU lockability, row-pitch legitimacy, and HRESULTs, not this source review.
6. DXT1 per-mip logical estimate is ceil(Width/4)*ceil(Height/4)*8, DXT2-5 use *16; this correctly describes logical compressed blocks but is not a driver pitch/alloc guarantee. R14CopyWholeLevelByLock derives row bytes from pitches rather than requiring the calculated logical block row byte count. A destination with a shorter pitch than the minimum expected logical row would allow the copy function to return success after fewer bytes *if* such a lock were erroneously accepted; no such driver behavior is observed. Conversely padding bytes can be included in min(Pitch) and are not evidence of visible texel corruption by themselves.
7. To make any claim about +TIME, GOAL, selector, menu or particles, the resource identity/mip must match a later *actual* physical primitive. PhysicalDrawCommand captures immutable producer, scope, queue node and epoch at DP/DIP/UP; D3DX Begin/Draw is only CPU work until real FlushDest/EndDest establishes a strictly homogeneous owner or fails closed. - VERIFIED_STATIC=R14 sets lockRectValid from *RECT pointer presence*, not whether the requested rectangle geometrically equals the entire mip. R15 Upload uses that bool to suppress whole-mip fallback on failed UpdateSurface. The design may intentionally choose fail-close rather than infer validity from geometry.
