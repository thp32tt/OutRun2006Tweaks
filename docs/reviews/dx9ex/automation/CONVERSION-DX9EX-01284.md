## EVIDENCE — checked-in code / original REA / negative controls

1. **Original producer and GPU exits (previous static REA; not a fresh executable run).** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md` maps `0x449050 -> 0x42D710`; type-0 D3DX `0x42A0A0` can defer physical draw until native Flush/End; type-0 direct UP `0x42C0F0`, type-1 quad `0x42A3A0` and mask `0x42A800` are independent GPU routes. Thirty-six original indirect CALLs remain unresolved. No observed EXE Destroy/Create/OnLost/Reset call sequence, memory allocator address sequence, or post-reset vtable fingerprint is in that REA file. GitHub Issue #6 is a continuous-review inbox, not live proof of object reuse.
2. **Pointer predicates are exact-address, not lifetime-generation predicates.** `src/hooks_uiscaling.cpp::DX9ExD3DXSpriteLifetime::CanFlush/OwnsLifecycle:3194-3214` compares `candidate==tracked==live` and callback `==tracked || ==live`; its compile-time controls near `3280-3330` cover old, new, foreign and null **distinct addresses**. They do not model old and new objects whose allocations reuse the *same* numerical address. This is a confirmed absence in this particular equality guard, **not** a confirmed use-after-free.
3. **Actual owner ledger protects native session transitions, not an independently allocated-object UUID.** `src/vr/game/hud_command_batch.hpp::Ledger:16-59,77-141,144-176,245-273` stores `sprite`, `generation`, `mutationSerial`, queue node/epoch and ownership. Its `sameGeneration` requires matching pointer+Begin generation; successful observed Begin increments generation, and onBeginResult invalidates on unsafe failure. `src/hooks_uiscaling.cpp::BeginDest:3407-3429` only applies that to calls seen on the installed hook. A **normally intercepted new Begin refutes** stale-owner survival for that new session. An ordinary different-address replacement also fails the pointer guard. No object allocation epoch/ref-count identity appears in the inspected guard/ledger snapshot.
4. **Native Flush negative control and conditional ABA sequence.** `src/hooks_uiscaling.cpp::FlushTracked:3543-3562` reads live `0x55B218`, refuses an old pointer when it differs from live, and reads vtable[10] only after exact pointer equality. `::BeforeDirectStageSource/AfterDirectStageSource/BeforeDirectGoalSource/AfterDirectGoalSource:3570-3650` require an active homogeneous batch and `matchesGpuOwner`; `::FlushDest/EndDest:3432-3508` further reject unknown/mixed/queued cases and guard source ownership, native HRESULT and reentrant generation. **Hypothesis only:** old Sprite S (address P) is replaced silently without a hook-observed lifecycle callback or new Begin on the relevant thread; allocator reuses address P for *different* Sprite S'; the old thread-local ledger still says S at P, direct exact +TIME/GOAL homogeneous owner; a later same-address Flush has no independent allocation-epoch proof and might use old semantic provenance for S'. A normal hooked OnLost/OnReset, new Begin, End, failed Draw/Flush, unrelated/mixed queue, or a different live pointer vetoes this case. Native D3DX submission and any crash remain unproven.
5. **Vtable address equivalence is orthogonal.** `src/hooks_uiscaling.cpp::InstallThread:4055-4109` installs six disabled-then-enabled inline hooks from the first live `ID3DXSprite` vtable slots [8..13] (Begin/Draw/Flush/End/Lost/Reset), tears down partial installations and returns on success. Replacement S' with identical implementation function addresses remains covered by the original inline hooks; this is a **negative control** against claiming all replacement objects bypass R64. Different functions after replacement could bypass coverage, but a vtable address difference alone does not prove any callback actually executed. Neither per-allocation identity nor before/after function addresses were captured.
6. **R13 ResetEx does not establish original Sprite lifecycle ordering.** `src/vr/d3d9/stereo_renderer_r13.cpp::ResetDestR13/R13ResetCommonPre:380-463` retires game-device queue frame tags for R26+HUD, resets stereo/depth/ACK/query state before `ResetCompatDevice`, and only ensures stereo resources after success. This inspected function does not itself invoke `ID3DXSprite::OnLostDevice/OnResetDevice` or read old/new `0x55B218` pointer identity. `src/hooks_uiscaling.cpp::LostDeviceDest/ResetDeviceDest:3511-3540` intercepts those callbacks **if called through the installed functions**. Consequently the original EXE order `OnLost -> ResetEx -> OnReset`, object destruction/recreation and same-address aliasing are **unknown**, not implied by ResetDestR13.
7. **Producer/semantic -> physical GPU gate.** `src/hooks_uiscaling.cpp::VRHudQueueSemanticBridge:4154-4184` performs BeforeQueueNode/End before selection/queue teardown; `::DrawDest:3882-3941` captures physical source/queue epoch and native Draw HRESULT but remains CPU registration until native D3DX may Flush/End. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30SafeStereoBase:75-92` checks game device/main backbuffer, seed, pose/depth, recovery, query and MRT; `R62TryFixedFunctionSpriteIndexed:5126-5250` requires exact HUD/projected semantic, TRIANGLELIST, no live VS, FVF 0x142, finite eye/projection state. `DrawIndexedPrimitiveDestR30:5377-5452` routes F11 external ImGui separately, attempts R62 then XYZRHW/R29/native; an R62 `E_NOTIMPL` is **not** the last GPU draw outcome. Original direct UP, animation and mask paths must be separately identified; a CPU sprite pointer equality cannot prove which API actually rendered.
8. **L/R/restore -> Present/OpenXR remains independent.** `src/vr/d3d9/stereo_renderer_r7.inc::ExecuteStereoDraw:1524-1560` guards stereo eligibility, left/native HRESULT, right RT/depth/viewport/WVP, right draw and restoration with mono fail-closed outcomes; `src/vr/d3d9/stereo_renderer_r13.cpp::R13GuardedDraw:592-650` can keep unsafe MRT/query draws single-execution. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:759-823` normalizes native Present, publishes active/fallback and resets frame state. `vrhost/src/main_r23.cpp:3562-3610` executes actual `xrEndFrame` and checks actual submitted frame/layer. No joined `Sprite object allocation identity -> physical DP/DIP/UP fingerprint -> L/R and restore HRESULT -> frameId/pose -> xrEndFrame` evidence was captured. Non-zero cant and source/game/XR extents also remain unmeasured here.
