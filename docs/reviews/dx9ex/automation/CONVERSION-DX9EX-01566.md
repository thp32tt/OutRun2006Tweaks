1. Current `src/vr/game/outrun_renderer.cpp::LatchFramePose:1494-1522` creates `LatchedHeadInverse=InverseRigid(MatrixFromPose(relativeOrientation,relativePosition))`; relative position is derived from a recentered HMD position and scaled to game units. Thus the wider renderer has both common head translation and per-eye translation available.
2. Current `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30BuildScreenSpaceEyeConstants:5191-5234`, **only for admitted physical** `ProjectedScreenEffect2D`, gets matched-sequence head inverse, sets `identityEye=IdentityMatrix()`, then for eye 0/1 separately passes `stockWvp,inverseBaseProjection,headInverse,identityEye,ProjectionFromFov(baseProjection,stereo.eyeFov[eye]),sourceCameraSynced` to `BuildProjectedSunRay`. This path does not read `stereo.eyeOffset[eye]` at all.
3. `src/vr/d3d9/projected_sun_ray.hpp::BuildProjectedSunRay:11-56` replaces headRotation with identity if sourceCameraSynced; in *both* sync-flag states, clears `headRotation.m[3][0..2]` and `eyeRotation.m[3][0..2]` before `stockWvp * inverseBaseProjection * headRotation * eyeRotation * eyeProjection`. Therefore, **holding the stock WVP, head orientation, FOV and other inputs fixed**, changing only the headInverse translation cannot change output, and changing eye offsets cannot change output because identityEye is always supplied. This theorem does *not* claim that an actual game `stockWvp` remains fixed when the game camera translates.
4. Contrast: `R30BuildScreenSpaceEyeConstants:5299-5345` current `WorldBillboard` path builds `MatrixFromQuaternionTranslation(stereo.eyeOrientation[eye],stereo.eyeOffset[eye],Settings::VRWorldScale * Settings::VRStereoDepth)`, then `InverseRigid(eyePose)`; it multiplies full `headInverse * eyeInverse * eyeProjection`. That branch can represent finite head-translation and IPD parallax unlike admitted R85 ProjectedScreenEffect2D. This is a *screen-kind control*, not proof the original C993/CABE native physical draw took either branch.
5. **Read-only isolated numeric counterfactual (not retail-game execution).** Row-vector identity `stockWvp=I`, `inverseBaseProjection=I`, identity orientations, symmetric perspective with `clipW=z` and unit x scale, test source point `[0,0,2,1]`. Choose head translation `0` or `+0.25` and eye inverse translation `-0.04` or `+0.04` in arbitrary consistent game units. R85-style cleared-translation output x_ndc stays `0` in **all four** cases. A finite spatial transform retaining both terms instead yields, respectively, `-0.020, +0.020, +0.105, +0.145`. These numbers are *chosen synthetic values*, not an actual Quest IPD, world scale, measured WVP, HMD bearing, or proof the sun needs finite depth.
6. **Consequence of control:** If FOV/rotation differ by eye, an R85 angular ray can still yield *different L/R normalized positions* despite zero IPD. Such differences alone cannot identify finite stereoscopic parallax. Conversely, with identical FOV/rotations and unchanged stockWvp, there is no R85 L/R positional disparity in the isolated test; treating that as an automatic defect is unsound because the original C993 sun stack uses artificial view planes (z=-1/-0.2 and far distances) to draw a directional optical effect rather than a verified physical finite-depth sphere. The original 40CBC0 reconstruction and each original PMT's material/depth/alpha have **not** been freshly paired here.
