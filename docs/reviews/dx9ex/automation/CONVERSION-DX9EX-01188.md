## REVIEW_SCOPE — stage indirect object producer → admission → physical draw → two-eye restore → Present/OpenXR

1. **Original stage dispatcher is not a named sand emitter.** Checked-in prior original-EXE REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-20,52-63,92-104` maps original frame scheduler `0x00449050` into both indirect scene-object dispatch and sprite queue `0x0042D710`. `docs/automation/OUTRUN_REA_RENDERING_DEVELOPER_HANDOFF_20261018.md:20-39` labels particle direct API/emitter correlation and original world polygon indirect callbacks **unresolved**. `docs/automation/REA_99_RENDER_FUNCTION_VALIDATION_20261019.md:1-15,34-105` lists sampled device-virtual/world geometry functions with *partial* coverage, not an exact sand generator → DDS/shader fingerprint. These are historical static mappings only; no new original binary REA or original indirect vtable resolution was performed here.
2. **Different producer: stage section/object expansion, not a SpriteNode.** `src/hooks_drawdistance.cpp::DrawDistanceIncrease::destination:499-607` is enabled only when `DrawDistanceIncrease > 0` or `DrawDistanceBehind > 0` (`::validate:601-605`). It reads the current stage/track-section collision-node lists, including `0xFFFF` terminal, and for each bounded `ObjectNum` assembles up to 4096 admitted node IDs before calling original `Game::DrawObject_Internal(xmtSetShifted | ObjectNum, 0, CollisionNodeIdxArray, a4, a5, 0)` (`:532-588`). `src/vr/game/draw_distance_node_safety.hpp:8-36` enforces per-buffer capacity, dedup/exclusion order and sentinel reserve. This produces an original stage-object invocation, not a proven physical GPU Draw or an identified sand particle.
3. **Newly isolated dedup domain.** `CollisionNodeSeenEpoch` is incremented **inside the per-object loop** (`src/hooks_drawdistance.cpp:526-546`), and `CollisionNodesToDisplay[nodeId] == CollisionNodeSeenEpoch` applies only within that object while traversing track sections (`:544-576`). Therefore the *same numeric* `nodeId` can be admitted again when `ObjectNum` changes, even within one frame. This is deliberate object-local dedup semantics in the inspected source, **not proof of duplicate render work**: `xmtSetShifted | ObjectNum` changes the original object context and the same node ID can denote different actual work. For a given object, repeated section-node IDs are filtered only after successful `ShouldQueueNode` admission; rejected exclusion/behind-section candidates remain eligible in their original section.
4. **PMT visibility is a separate predicate, not source identity.** `src/vr/game/pmt_node_culling_contract.hpp:8-22` and `src/hooks_graphics.cpp::DisableStageCulling::BeforeVisible/AfterVisible:1767-1850` identify the original `EXE+0x5015` visibility CALL/`+0x501D` EAX gate and temporary wide-FOV *CPU* projection, restored before original result use. Mode 1 can fail open without a valid pose; mode 2 forces EAX=1. Unlike the per-object stage list, PMT gate acceptance is a visibility result, not a unique sand/particle primitive, GPU API or guaranteed `DrawObject_Internal` emission. 01142 separately reviewed the PMT mode-1 fail-open; not reclassified as a new bug here.
5. **Stage model buffer != native sprite priority queue.** `src/hooks_drawdistance.cpp::StableDrawSort::SortDrawBuffer/DrawStoredModel_Execute_dest:385-428` sorts `Game::s_AftDrawBuffer` entries, invokes `DrawStoredModel_Internal`, then clears the buffer count; this is distinct from original `0x0042D710` sprite type-0 D3DX deferred `Begin/Draw/Flush/End` and type-1 native UP work. The `src/vr/game/render_semantics.hpp::ConsumeForDraw:998-1027` queued-scope/one-shot resolution and `src/vr/game/hud_command_batch.hpp:8-42` producer→node→epoch→D3DX batch boundaries must be joined to a real original source *only if that source actually enters a sprite queue*. There is no demonstrated stage `DrawObject_Internal` → SpriteNode queue bridge here. 01158 already covers the different later stage sorting semantic.
6. **Physical R26+HUD drawing remains conditional.** The active baseline's `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawPrimitiveDestR30/DrawIndexedPrimitiveDestR30:5349-5450` and `::DrawPrimitiveUPDestR30:5464-5491` consume eligible semantic ownership and try R30 XYZRHW/R62 (fixed-function sprite DIP where applicable); rejection uses R29/original guarded Draw instead. `::R30ExecuteXyzrhwStereo:3829-3927` submits left then right, restores RT/depth/viewport, records right/restore failure and requires authoritative world/pose corroboration for world-stereo. A repeated section node is **not** evidence of one original DP/DIP/UP, two real eye draws, or a sand particle; shader/texture/API/culling and both eye HRESULTs are unknown.
7. **Present/host do not close the missing sand source link.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-814` checks duplicated draw, world authority, pose and right-eye safety, performs DirectGPU/SBS fallback and only marks active after original D3D9 Present succeeds. `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` renders two XR projection slices with current eye views and cleanup on failure; `::xrEndFrame:3562-3599` joins the actual submitted frame. There is no matching exact-SHA producer node+object → original shader/texture → real L/R → XR frame trace; no measured p95/p99 or Quest3 evidence.
