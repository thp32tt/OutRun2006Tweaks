## 3. NEW_FINDING, impact hypothesis and falsification

**Source-confirmed new boundary:** Reflection normalization measures time between `FaceCount_dest` invocations (`lastCounter`), not directly time between D3D9 Presents or completed OpenXR submissions. The source contains no `PresentEpoch` comparison in that hook. `R9PresentDest` separately has a game Present counter, an independent frame eligibility and transport choice. Thus it is unsound to interpret the reflection hook's learned cadence or 'late' status as a measured XR GPU frame miss without first correlating producer invocations to Present IDs.

**Conditional hypothesis only:** During skipped/refused reflection calls, pause/load, offscreen-only updates, mid-scene reentry, or cadence transition, callback gaps could differ from XR submitted frame periods. The 18-ms/learned-cadence late branch can then cap face work irrespective of the actual main-eye GPU bottleneck. Conversely, a genuine GPU-late Present might not coincide with a face-count callback. This is a candidate explanation for altered cubemap freshness or scene-specific face-work scheduling, **not** a verified Quest3 visual artifact or measured FPS problem. No new evidence shows repeated/omitted callbacks.

**Deterministic arithmetic sanity example (manually modeled from `Advance`, NOT runtime test):** with requested rate 0.5 and normalized healthy period 1/72 s, 72 face callbacks/s give 180 faces (alternating 2,3). If exactly one callback instead occurs every *two* 72-Hz Presents and the long interval is treated as late, 36 callbacks/s produce 54 faces (alternating 1,2). The latter assumes the observed 27.8-ms gap actually enters the late branch; it illustrates sensitivity to callback sampling, **not** evidence that this situation occurs. At a healthy 120-Hz once-per-Present callback, the same formula budgets 180 faces/s.

**Falsification:** In a single exact-SHA run, count `Envmap_FaceCount` hook invocations keyed to actual `PresentEpoch`, log QPC delta and budget result, and correlate `SetRenderTarget` RT0 descriptors, native DIP/DP/UP calls, cubemap face/texture IDs, GPU timestamp, right/left consumer draw, DirectGPU/SBS status, host acknowledged frame ID, and `xrEndFrame`. If a stable gameplay scene has one callback per Present, valid matching deltas, correct left/right cubemap sampling and no correlated timing/visual anomaly, **reject callback-domain mismatch as that scene's cause**. If the callback never occurs, first verify hook installation/settings and do not infer missing reflection from a zero counter alone. If frame spikes occur without hook/face-budget changes, profile actual shader/overdraw/transport separately. A static REA address or alpha/Z/FVF family is never sufficient material identity.
