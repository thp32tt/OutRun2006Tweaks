## EVIDENCE — pinned source, prior REA and whole-path static simulation

1. **Original producers, queue, and physical API remain separate.** Archived read-only original-executable analysis `docs/automation/OUTRUN_VR_REA_RESOURCE_EVIDENCE_20261018.md:40-55` differentiates projected vehicle-rank SpriteNodes, world centre lens `0xD3A5→0xC980→0xC993`, and screen HUD; `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-46` maps original queue `0x42D710` type-0 D3DX/UP and type-1 quad/masked routes. Original D3DX `Draw` is not necessarily the final native Draw until Flush/End. These **archived** mappings do not establish which sky/marker/lens GPU command occurred in a new Quest3 frame; no new x86 trace was obtained.
2. **Stock glow and actual world sky are not interchangeable semantics.** `src/hooks_graphics.cpp:25-37,1008-1014,1255-1267,1332-1353,1391-1410,1487-1495`: stock game mono-backbuffer reducer/blur is suppressed when VR+true stereo are active, while the R30 independent eye chain is expected. `src/vr/game/render_semantics.hpp:14-25,1029-1034,1083-1101` has a `SkyGlow` postprocess scope distinct from `SceneEffect`, `ProjectedWorldMarker2D`, `ProjectedScreenEffect2D` and `ScreenHud`; `SkyGlow` is not the original sky sphere. Do not blindly promote shader sky to a zero-disparity HUD family.
3. **Fixed-function physical sky can be rotation-only.** `src/vr/d3d9/stereo_renderer_r7.inc:760-853,854-922` reads the actual D3D9 VS/FVF, original view/projection and depth-enabled policy. If it classifies perspective depth-off sky as `SkyRotationOnly`, it zeros head/IPD *translation* while retaining per-eye orientation and asymmetric FOV; `SkyGlow`/known screen semantics are vetoed from generic sky promotion. `src/vr/d3d9/stereo_renderer_r7.inc:1495-1559` handles actual left/right D3D9 submissions, failure, tracked target/depth/viewport and WVP restore. These are source gates, not proof that a particular shader-sky draw passed them.
4. **R30 captures an eye-specific *pre-HUD* source only under narrower semantic gates.** `src/vr/game/render_semantics.hpp:1083-1101` defines `IsSkyGlowPreHudBoundary` **only for `ScreenHud` or `ScreenOverlay2D`**, explicitly excluding projected markers, projected screen effects, WorldBillboard, SceneEffect and SkyGlow. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1160-1217,5510-5553,5625-5643` stamps `PresentEpoch` on the first matching native Draw hook even if capture fails, requires true stereo/valid independent eye surfaces, and `StretchRect`-copies L/R to reduced textures. If capture fails after first screen submit, it deliberately avoids retrying an already HUD-filled source.
5. **Present-time effect is separate from 3D sky identity.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1219-1319,1320-1445,1506-1535` checks stereo readiness and GOAL/TIMEUP/warp exclusions; if a screen draw occurred without a clean capture, glow is skipped rather than using a contaminated current scene. Otherwise it does per-eye bright extraction, blur (optionally 2-step), additive full-eye composite and StateBlock/RT/depth/viewport restore before delegating original Present. If no recognized screen draw occurred, it may copy the live eye surfaces at Present, by documented fallback. Optional postprocessing is not a per-object stereo route or HMD pixel proof.
6. **After game Present, a separate host gate still applies.** `src/vr/d3d9/stereo_renderer_r7.inc:1685-1744` sends Present/Frame.v2 metadata subject to composition/transport eligibility; `vrhost/src/main_r23.cpp:1440-1513` chooses DirectGPU or SBS sources and draws D3D11 projection slices 0/1, while `vrhost/src/main_r23.cpp:3559-3593` reaches `xrEndFrame` and last-submission counters. The previous user HMD baseline (`docs/automation/reviews/DX9EX_HMD_REFERENCE_20261020_0CFF83CF.md:3-18`) reports sky/background improvement and outstanding lens-centre double image; it does **not** observe the present hypothetical SkyGlow boundary on this HEAD.
