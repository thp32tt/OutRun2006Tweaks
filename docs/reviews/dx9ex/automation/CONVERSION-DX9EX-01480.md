## EVIDENCE — pinned source facts, not a reproduced HMD failure

1. The archived original x86 REA audit, `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:3-32`, directly verifies six +TIME CALL sites and the four physical SpriteNode branches; 36 indirect calls remain unresolved. This is **prior archival REA**, not new disassembly or GPU evidence.
2. `src/vr/d3d9/stereo_renderer_r7.inc:1680-1741` composes or retains stereo, calls original `PresentHook`, publishes completed Frame.v2 metadata on success, or publishes mono/fallback state on failure (except the deliberately held DirectGPU-only state). Those transactions identify game Present, not the host window's later rectangle.
3. `vrhost/src/main_r23.cpp:1018-1054`: `R23Capture` can rebind the duplication on a monitor switch, checks live client visibility using `GetGameClientOutputRect`, and initializes `CaptureStatus` with already-copied `haveFrame_` and `lastCapturePresentQpc_`. On `DXGI_ERROR_WAIT_TIMEOUT` it **returns that status without a new CopyResource**. Pointer-only unchanged events also deliberately retain existing `source_`/`sourceSrv_`, with `fresh=false` (`:1060-1095`). These are intentional bounded-reuse performance safeguards.
4. `vrhost/src/main_r23.cpp:1120-1204` copies only a successfully acquired DXGI desktop texture to the stored D3D11 `source_`, with validated description/cache and a successful ReleaseFrame, then publishes `lastPresentQpc`. `vrhost/src/main.cpp:2062-2091` rebinding resets `haveFrame_` and capture QPC and uses the newly selected monitor desktop origin; `:2093-2117` reallocates source/SRV on extent or format change. Those are important **existing** protections against stale output dimensions/monitor generations.
5. `vrhost/src/main_r23.cpp:3449-3476`: gameplay recovery may reuse an already captured **fresh** production image, or it calls `R23RefreshTheaterFallbackCapture`. The fallback accepts `fallbackCapture.available` even when `fresh=false` (timeout/pointer-only reuse); it then calls `R23RenderTheater` without a captured client rectangle or per-capture window-geometry generation. The separate `fallbackSourceIsSbs` boolean was addressed in 01479 and is not this finding.
6. `vrhost/src/main_r23.cpp:1838-1878` invokes `c.GetGameUv(whole, false, &capturedTheaterClient)` at **render time**, after `R23Capture`, and passes that UV and the retained SRV to `RenderTo`. The optional SBS half-width and theater physical aspect are calculated from these live coordinates; `:1880-1912` additionally places a partially visible mono fragment from the same rectangle. Here `capturedTheaterClient` is an **output parameter name**, not evidence of a rectangle timestamped at pixel acquisition.
7. `vrhost/src/main.cpp:2120-2148` recalculates client location/visibility via live `GetClientRect/ClientToScreen` relative to the current `outputDesktop_`. `:2150-2181` **again** samples `GetClientRect/ClientToScreen`, clips against `sourceWidth_/sourceHeight_` and creates UV. The comment at `:2164-2165` explicitly prevents a *second geometry read after UV creation*; it does **not** bind that geometry to the earlier DXGI CopyResource epoch. A stable client/output across both operations is safe.
8. `vrhost/src/main_r23.cpp:1257-1319` requires a fresh fully visible captured client plus matched Frame.v2 Present/QPC for the authoritative *classic stereo projection*; `:1440-1465` similarly invokes `GetGameUv` for non-DirectGPU projection (a secondary temporal check target). `:3562-3590` submits one selected layer via actual `xrEndFrame`; XR submission alone cannot validate capture-epoch window coordinates.
