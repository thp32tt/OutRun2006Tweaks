3. **R9 transport is conditional and upstream:** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-822` requires world/duplicate/pose/compose eligibility, chooses either shared per-eye DirectGPU or `ComposeSbs`, makes the raw D3D9 Present call, and only then publishes active Frame.v2 on success; incomplete/failed frames are mono/fallback. 4. **Classic capture has a full-client gate tied to frame timing:** `vrhost/src/main_r23.cpp::R23Capture:1018-1125` reads `GetGameClientOutputRect` into `CaptureStatus.fullGameClientVisible`; `::R23SelectClassicFrameForCapture:1250-1308` rejects nonfresh/unavailable/partly visible captures and selects a complete SBS Frame.v2 history entry with a <=100ms QPC-skew gate. `::R23FrameUnchanged:1237-1250` verifies the selected game frame's metadata/pose/reserved fields. `::main:3120-3250` then commits a classic source copy, or separately validates/stages DirectGPU.
5. **Classic copy preserves pixels, not the measured HWND crop:** `vrhost/src/main.cpp::CommitStereoSource:1398-1435` allocates a source-size D3D11 texture, copies the desktop source and marks the source valid. It does not attach or store a copy of the previously validated HWND/client normalized UV rectangle as an atomic, frame-keyed capture descriptor.
6. **A fresh HWND geometry read occurs on final gameplay projection:** `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1496` calls `c.GetGameUv(whole)` in the classic path, with default `requireFullyVisible=false`. `vrhost/src/main.cpp::GetGameUv:2150-2181` independently reads the *current* Win32 client rect, `ClientToScreen` and `ClipClient`, and rejects only invisible or (when explicitly requested) partially visible source. If window geometry changes between capture selection/copy and projection, the earlier `capture.fullGameClientVisible` boolean does not prove this later normalized `whole` rectangle still describes the selected source's game pixels.
7. **No automatic double crop on an unchanged source:** `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1517` classic uses `{whole.x, whole.y, whole.w/2, whole.h}` for left and `{whole.x+whole.w/2, whole.y, whole.w/2, whole.h}` for right from ONE `whole` in that call. DirectGPU instead uses `{0,0,1,1}` for each independently held eye SRV. `vrhost/src/main.cpp::RenderTo:2183-2270` uploads per-eye UV scale/offset, binds each SRV/RTV and issues one D3D11 triangle draw per eye. No generic HUD containment or game-viewport-to-XR multiplication is performed by this blit function. This is positive evidence *against* claiming a constant two-times crop solely because Quest 3 reports a portrait eye rectangle.
8. **DirectGPU does not share this window-crop ownership:** `vrhost/src/main_r23.cpp::R23ValidateDirectResourceSize:1310-1380` checks per-slot image dimensions/handle/generation/format; `::R23CommitDirectAfterValidation:1407-1423` stages verified held eyes. The host `R23RenderProjection` full-UV branch bypasses `GetGameUv`; therefore a classic-only crop symptom and a DirectGPU-only one have different first suspects. This distinction is NOT a DirectGPU runtime PASS.
9. **XR output contract differs from desktop UV:** `vrhost/src/main.cpp::CreateProjectionSwapchain:1924-1946` resolves allocated physical eye extent from both XR view configs; `vrhost/src/main_r23.cpp:2584-2635` publishes matching startup extent, fails closed on allocation mismatch; `::R23RenderProjection:1464-1517` uses actual projection RTV dimensions, per-eye XrView pose/FOV and `imageRect`. `vrhost/src/main_r23.cpp:3559-3616` reads actual `xrEndFrame` submitted frame/layer separately from candidate selection. None of these source guards records a same-frame game-client-UV snapshot associated with classic capture.
10. **F11/menu is not the same crop:** `vrhost/src/main_r23.cpp::R23RenderWorldLockedMenuProjection:1520-1738` has a separate same-snapshot menu state/crop/optical containment plan; it must not be applied to gameplay stereo. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawIndexedPrimitiveDestR30:5435-5455` deliberately isolates external F11 ImGui. `AGENTS.md:1-10` and `docs/DX9EX_OPTICAL_ROUTE_PROBE_POLICY_20261020.md:9-50` make R26+HUD default and require a physical GPU fingerprint before attributing pixel artifacts.
