## REVIEW_SCOPE — producer -> semantic/queue -> actual D3D9 draw -> R30/R62 -> L/R -> restore -> Present/OpenXR

1. Original EXE UI is a distinct producer: archived REA shows scheduler 0x00449050 -> consumer 0x0042D710, type0 D3DXSprite 0x0042A0A0, direct UP 0x0042C0F0, type1 quad 0x0042A3A0, masked/composite 0x0042A800. D3DX batching can delay physical API ownership; unresolved indirect edges mean original source nodes alone cannot identify the final GPU draw. **F11 is not any original sprite node**: the mod's external ImGui DrawData becomes D3D9 fixed-function XYZ/DIFFUSE/TEX1 DrawIndexedPrimitive.
2. F11 source raster: overlay EndScene determines visible F11 and VR font density, ImGui NewFrame -> Overlay::render_shell -> ImGui::Render -> ImGui_ImplDX9_RenderDrawData. The shell's VR layout owner is `VREnabled && (is_vr_gameplay_presentation() || !is_in_game())`, but the ImGui content rectangle in a front-end 4:3-letterbox state is the original game's centered BuildMenuContentBounds rectangle. In VR gameplay it uses the full ImGui DisplaySize source surface. The same shell therefore enters different **source-space** coordinate contracts across a state boundary.
3. The font-density factor is calculated from Game::screen_resolution and published per-eye XR extents **only if** F11 is visible, VREnabled, and `!VRUnifiedEyeMenuSource`; it is clamped to at most 1.25x and becomes 1x whenever that gate is closed. This is a documented intentional anti-double-scaling guard, not evidence by itself of a defect. The shell's window size separately derives from VR density/font setting and the content rectangle.
4. During eligible gameplay, the external ScreenOverlay2D scope labels ImGui's physical DIP. The R30 admission requires R30SafeStereoBase, FrameHadWorldStereo, FrameHadDuplicatedDraw, external semantic depth, ScreenOverlay2D, shadow and live null VS, XYZ fixed-function, orthographic projection, zero Z and valid scissor/viewport. Only if accepted, R30 uses a **separate fixed F11 scale 0.65** on the finite/head-recentered plane (not gameplay HudScale 0.55 or the HUD1080p source-reference fit); the same original indexed draw executes LEFT -> right RT/depth/viewport + projected scissor -> RIGHT, then RestoreRightPassState and original raster restore. E_NOTIMPL means the R30 F11 stereo override did not occur; native/R62/XYZRHW/R29 fallback still must be discriminated by physical tracing.
5. In front-end TITLE/MENU, the ImGui physical draw is intentionally **not** tagged as gameplay external ScreenOverlay2D. The mod presents the original composed F11/menu/letterbox game backbuffer. Host Desktop Duplication obtains GetGameUv, optionally crops centered 4:3 title/main source UV, uses captured source aspect/optical coverage, renders D3D11 menu texture for L and copies (or independently renders) R, releases LOCAL-fixed projection views and invokes xrEndFrame. This single full-source UV operation cannot independently normalize only the F11 shell after it is composited into the captured pixels. It does not invoke the R30 gameplay 0.65 F11 scale.
6. R7 Present only publishes qualified gameplay stereo Frame.v2/DirectGPU or SBS when world+duplicated+pose+resources pass; otherwise it retains native/mono or conservative fallback. Host menu LOCAL projection is a distinct optical transaction: two OpenXR eye images containing the same source F11 do not prove gameplay F11 two-eye source draws, matched angular size across modes, or a Quest3 fix.
