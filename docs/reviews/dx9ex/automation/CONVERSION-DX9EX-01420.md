## EVIDENCE (GitHub, exact source HEAD)

1. **Original producer and identity bounds.** `src/vr/game/render_semantics.hpp:39-49` stores valid projected view X/Y/Z and `exactOrdinalEyeCant` separately; it is provenance, not draw-owner permission. `src/hooks_textures.cpp:1008-1055` uses proven source snapshot and Calc3D2D projected marker for exact node tagging. `src/hooks_framerate.cpp:191-200,275-284,318-340` snapshots/replays scope, producer and valid projected anchor on actual newly queued nodes. The checked-in `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-39` describes original 0x42D710: D3DX type0 0x42A0A0 (possible deferred submit), direct-UP type0 0x42C0F0, type1 quad 0x42A3A0 and masked type1 0x42A800, and unresolved calls. Proven source tag is not a trace proving a particular native physical Draw/Flush or source/texture identity.
2. **Signed clip-W is intentionally scoped, but outputs only XY.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1545-1591` (`R57ProjectViewPoint`) admits `fabs(clipW)>1e-6` including negative W only when `Settings::VRRankDx11ProducerReference.get() && marker.exactOrdinalEyeCant`. All other projected producers reject nonpositive W; every candidate checks finite X/Y/W and returns only `ndcX=clipX/clipW, ndcY=clipY/clipW`. It does **not** return ndcZ, 1/W, sign history or depth-range validity.
3. **Both physical eyes are guarded for XY, but depth is not in the R57 contract.** `stereo_renderer_r30_r26_safe.cpp:1594-1695` (`R57BuildProjectedMarkerDelta`) requires a valid marker, latched head inverse and matching pose sequence, chooses rank canted/identity formula using the *independent* `VRRankDx11ReferenceEyePose` setting, and calls `R57ProjectViewPoint` on base and each eye, requiring finite XY delta bounded by 2. It publishes baseX/Y and eye deltaX/Y only. It neither requires same clip-W sign across base, L and R nor derives/compares per-eye projected Z or RHW. That does not prove divergence occurs during normal play.
4. **The three R26 GPU consumers shift XY but do not anchor eye Z/RHW.** `stereo_renderer_r30_r26_safe.cpp:3208-3302` (`R30ConfigureXyzrhwWorldEffect`) takes exact projected scope to R57 XY delta. `:3838-3931` (`R30TransformXyzrhwVertices`) edits only vertex p[0]/p[1] for `state.projectedWorldMarker`; original p[2] screen Z and p[3] RHW survive. `:4823-4870` (`R30BuildScreenSpaceEyeConstants`) applies `clipShift._11/_22/_41/_42` on the original shader WVP, not an eye-specific original-car Z/W rewrite. `:5315-5450` (`R62TryFixedFunctionSpriteIndexed`) accepts exact projected owner + VS null + FVF 0x142 on game backbuffer, then similarly post-multiplies *original* D3DX projection by XY-only shift. By contrast, the separate `src/vr/game/projected_rank_stereo.hpp:7-51` R84 helper explicitly carries `ndcZ[2]`/`invW[2]`, rejects outside-0..1 Z and nonpositive reciprocal W; do not assume that R84-only helper is invoked by R26.
5. **GPU/restore/transport are not geometry-depth validators.** `stereo_renderer_r30_r26_safe.cpp:3960-4064` performs actual L/R UP draws and restores RT/depth/viewport, marking pose/world metadata only on eligible success. `:5435-5517` R62 executes two projection-adjusted D3DX draws and restores original projection. `src/vr/d3d9/stereo_renderer_r7.inc:1625-1744` gates stereo frame eligibility, DirectGPU post-Present EVENT or SBS fallback, publishes Frame metadata; `vrhost/src/main_r23.cpp:1440-1515,3500-3589` samples eye GPU inputs and supplies per-eye OpenXR view pose/FOV to xrEndFrame. None of these boundaries establishes that the original rank SpriteNode's depth corresponds to **each eye's exact projected vehicle anchor**. This is a **depth/optical provenance gap**, not proof of a broken Present or host.
6. **Verifier and issue scope.** Latest `tools/verify_vr_projected_marker_anchor.py:549-611` now checks exact ordinal-only signed-W lexical guard and five destructive mutations; this is a stronger **source guard** than old positive-W-only contract, but not a per-eye GPU depth/pixel validation. GitHub Issue #13 is an open runtime regression ledger; #14 tracks source changes. Neither a static guard nor an issue entry supplies this HEAD's physical rank eye Z/RHW, depth-test or HMD captures.
