## REVIEW_SCOPE — original producer -> semantic -> queue -> D3DX/native GPU -> R30/R62 -> L/R -> restore -> Present/OpenXR

1. Original producer: archived exact-EXE static REA has stage/GOAL/rank animation via 0x429530 -> 0x428A10 -> 0x429460 -> 0x429350 -> 0x428BD0 -> 0x42D0C0 -> 0x42DD50 (type1) and clip via 0x42D280 -> 0x42CFE0 (type0); canonical 0x449050 -> 0x42D710 and conditional 0x4C50A0 -> 0x42D710 may consume the priority lists. The type1 masked/composite arm is separately 0x42A800 and has 85 unresolved indirect original calls. Distinguish registered CPU SpriteNode from its final native GPU Draw identity.
2. Semantic registration: an exact producer can call `RegisterSpriteNodeScope(node,scope,token,...)` and place pointer+scope+producer+monotonic serial into the shared 0x230-entry table. Registration does **not** set `SpriteNodeSemanticFrameExpireCutoff`; it starts as zero, and only the first `BeginSpriteQueueRender` / lazy `SelectSpriteQueueNode` starts the queue/frame cutoff.
3. No-consume frame: construct a frame in which a valid exact sprite is registered but the optional/original priority consumer does not select any SpriteNode before a healthy game `Present`. R33's ordinary `PresentDestR33` calls `EndSpriteQueueFrame(false)`, but the latter computes `cutoff=SpriteNodeSemanticFrameExpireCutoff==0` and **returns without retiring the registered tag**. Repeated such Presents do not themselves age or clear it. This is a source-level conditional, not evidence that OutRun actually skips queue consumption for a registered exact node.
4. Later queue: when a later physical queue walk begins, its newly sampled cutoff includes the old tag serial. If the game's finite reusable SpriteNode ring has assigned that same pointer to an untagged foreign node **without an intervening exact re-registration for that pointer**, `ConsumeSpriteNodeScope` matches the old pointer+serial and returns its old ScreenHud/WorldBillboard/ProjectedWorldMarker2D owner instead of generic `ScreenOverlay2D`; `SelectSpriteQueueNode` exposes that scope and old producer for the *new* node. The queue-epoch increment tracks the current selection but is not compared against a per-tag frame identifier.
5. Deferred native draw: type0 original D3DXSprite Begin/Draw/End may submit after the CPU parent exits, whereas type0 direct-UP, type1 animation and type1 masked/composite are distinct GPU arms. `CurrentQueueExactScope` and `CapturePhysicalDrawCommand` can snapshot the misassociated tag at the eventual hooked DP/DIP/DPUP/DIPUP physical boundary. This does **not** prove the old tag actually survives D3DX batching, that the type1 0x42A800 final API is DPUP, or that any eye was drawn.
6. Eye and safety fences: R33 guards game device, non-internal target, StateBlock recording, RT, stereo eligibility and current semantics; its R30/R62 fixed-source path uses further FVF/shader/target/pose/source checks before LEFT and RIGHT. If these fail, screen-source policy generally preserves **one original native draw**, not automatic R29 road-WVP stereo. Only a physically admitted path may switch RIGHT RT/depth/viewport, perform RIGHT GPU Draw and restore game state. A falsely named producer is insufficient by itself to prove an incorrect binocular rendering.
7. Presentation: the R7 Present gate demands world+duplicated+valid metadata/pose and no right/restore/frame-incomplete faults before DirectGPU or SBS publication; the x64 host may reuse an eligible projection or use guarded mono/theater fallback, followed by OpenXR submission. The stale-tag scenario has no same-frame physical GPU receipt, Present output, xrEndFrame trace, or headset observation. Do not infer HMD PASS or a crash.
