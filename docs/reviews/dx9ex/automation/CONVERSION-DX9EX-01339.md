## EVIDENCE — connected GitHub pinned source

1. **Producer is not GPU proof.** `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-20,62-79` maps original scheduler `0x00449050`, +TIME `0x00498670`, SpriteNode consumer `0x0042D710` and native CPU `ID3DXSprite::Draw` with later Flush/End. GOAL/result producer labels and native batch separation in `src/hooks_uiscaling.cpp:3385-3402`. REA is preexisting static mapping, not newly run disassembly.
2. **Uniformity is an explicit ledger invariant.** `src/vr/game/hud_command_batch.hpp::Ledger:99-142,177-217,269-284`: successful native Draw records only a CPU command; differing source, direct/queued bit, node or epoch sets `homogeneous=false`. `matchesGpuOwner` tests queued node+epoch or true direct isolation. `completeNativeDraw` allows a *clean successful* native internal Flush transition, otherwise invalidates provenance; native GPU success is not inferred from Draw registration.
3. **Mixed queued batches are not eagerly drained.** `src/hooks_uiscaling.cpp::BeforeQueueNode:3660-3804` computes source/node transitions but `FlushTracked` is guarded by owner checks; on failed checks it leaves native behavior intact and revokes boundary readiness. `::BeforeQueueEnd:3805-3835` drains only `HudBatch.homogeneous`, matching live node/epoch and exact scope. An unmatched/mixed native buffer may therefore remain for original D3DX End or an internal texture-dependent Flush; source inspection alone does not establish whether that state is reachable during a later GOAL node.
4. **Direct native Flush/End has a fail-closed semantic shield, but queued native submission does NOT use it.** `src/hooks_uiscaling.cpp::FlushDest:3431-3469` and `::EndDest:3472-3507` restore the exact ledger owner only when `HudBatch.matchesGpuOwner(false,nullptr,0)` AND `CanRestoreDeferredResultOwner` allows a homogeneous, live, nonqueued batch. With `restore=false`, `src/vr/game/render_semantics.hpp::CanSuppressUnprovenDirectResultD3DXSubmission:280-337` refuses suppression whenever queue is active; `ScopedUnprovenDirectResultD3DXSubmission:1498-1551` is explicitly direct-only. Thus a *hypothetical mixed queued* native submission is **not** relabeled by the ledger and may still see the current queue's semantic at the outer GPU hook. This does not imply native D3DX actually submitted mixed triangles in that interval.
5. **The R30 result predicate is a separate proof plane.** `src/vr/game/render_semantics.hpp::CapturePhysicalDrawCommand:1420-1431` samples current scope, producer, queue node and epoch. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30IsExactResultHudDraw:3118-3128` tests exact finite result plus for queued commands only *non-null node and nonzero epoch*. It does not test `HudBatch.homogeneous`, `HudBatch.matchesGpuOwner`, sprite identity or the native Draw batch's mutation serial. This is a **source-confirmed non-equivalence of two eligibility predicates**, not confirmation that any inappropriate result primitive reached R62.
6. **Original D3DX texture/batch exit is conditional.** `src/hooks_uiscaling.cpp::DrawDest:3838-3926` attempts an outgoing-owner Flush *before* a foreign Draw only when the prior batch is clean direct+homogeneous; original `Draw_hk` can internally Flush before returning. `HudBatch.completeNativeDraw` admits only a matching-source, successful, same-generation clean mutation; mixed/reentrant ambiguity revokes ledger ownership. `DX9ExD3DXSpriteLifetime::CanRestoreDeferredResultOwner:3219-3239` and `::CanDrainDeferredResultBeforeForeignDraw:3248-3285` have positive/negative static asserts. A queued mixed native Flush lacks the analogous direct semantic suppression; native reentrancy and exact Draw ordering still need runtime proof.
7. **StateBlock and live shader checks prevent overclaiming.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30PrepareXyzrhwState:2538-2565` and `::R62TryFixedFunctionSpriteIndexed:5171-5225` explicitly recognize a potentially stale `CurrentVertexShaderIdentity` hint after D3DX StateBlock; only an exact result may bypass that cache hint, and a *live* `GetVertexShader` still vetoes a real shader. `::R62TryFixedFunctionSpriteIndexed:5239-5391` also requires live FVF `0x142`, pose/viewport/projection and attempts left/right/restore. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:1261-1275,1385-1404` independently restores an R30 SkyGlow `D3DSBT_ALL` StateBlock and explicit RT/DS/viewport; **that is NOT evidence that a specific native D3DXSprite StateBlock restored successfully**. No GPU StateBlock Apply HRESULT tied to the hypothetical GOAL DIP was obtained.
8. **End-to-end frame gate remains distinct.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30ExecuteXyzrhwStereo:3874-3990` attempts L/R and poisons on right/state restore failure; even `leftHr` can be returned after a failed right-eye attempt (previously reviewed in 01337; not a new finding here). `::DrawIndexedPrimitiveDestR30:5422-5507` may reject R62 and try XYZ/RHW or generic/R29. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-822` requires stereo completion/pose/transport and successful raw Present before active Frame.v2 publication. `vrhost/src/main_r23.cpp:3562-3616` joins actual `xrEndFrame` layer/frame. Nothing in this task joins a mixed GOAL physical DIP to an accepted XR frame.
