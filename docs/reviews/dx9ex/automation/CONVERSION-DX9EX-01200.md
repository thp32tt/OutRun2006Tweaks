## REVIEW_SCOPE — original producer -> queue semantic -> deferred D3DX/native draw -> R30/R62 -> eyes/restore -> Present/OpenXR

1. **Original static producers and priority passes.** Checked-in REA at docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-42,62-69 gives scheduler 0x00449050, +TIME 0x00498670, numeric 0x004973C0/0x004974E0, result 0x004979E0, consumer 0x0042D710 and conditional early 0x004C50A0 priority path. Type-0 0x0042A0A0 queues ID3DXSprite::Draw and physical indexed submission can occur at Flush/End; flagged/type-1 0x0042A3A0/0x0042A800 uses DrawPrimitiveUP as a separate negative control. This is previously committed REA mapping, NOT a new original EXE disassembly, live producer trace or captured GPU draw.
2. **First partial pass serial snapshot.** src/vr/game/render_semantics.hpp:1762-1789 and 1789-1837 snapshot the next serialized registration at entry/lazy first node, set a per-walk SpriteQueueSemanticCutoff, and hold the earliest cutoff in SpriteNodeSemanticFrameExpireCutoff. The exact node hook in src/hooks_uiscaling.cpp:4146-4207 calls R64::BeforeQueueNode then SelectSpriteQueueNode at the original 0x2D762 site, avoiding unsafe 0x2D734. The queue-end 0x2DCB4 calls R64::BeforeQueueEnd then EndSpriteQueueRender. At :1839-1863 it deliberately does NOT delete unvisited tags; another priority pass may follow.
3. **Protected old node, parallel newer registration.** src/vr/game/render_semantics.hpp:1576-1645 registers under one mutex. If a matching address already has serial <= SpriteNodeSemanticActiveQueueCutoff, the registration loop SKIPS overwriting that snapshotted entry and may append another tag with the SAME node address but a greater serial. The hint bits are REF-COUNTED at :1150-1191, so removing one duplicate does NOT itself imply an incorrectly cleared hint bit. Nested-exact preservation and bounded-table saturation introduce further fail-closed guards; no runtime pointer recycling is established.
4. **Conditional selection-order counterexample, not a reproduced defect.** In a symbolic sequence: (a) P/serial=10/prod=old is registered before first queue walk; (b) the first walk starts with cutoff=10 but never visits P; (c) while that walk is active, a legitimate source registers a REUSED P/serial=11/prod=new, preserving old serial=10; (d) first walk ends; (e) second same-frame walk starts with cutoff=11 and reaches P. src/vr/game/render_semantics.hpp::PeekSpriteNodeScope:1647-1696 and ::ConsumeSpriteNodeScope:1698-1760 iterate matching array entries in order and take the FIRST one satisfying serial <= current cutoff; with the old record still in the earlier slot, this can return old producer at (e) instead of the new registration. SelectSpriteQueueNode increments a consumer queue epoch (:1800-1837), but that epoch does not distinguish two producer serials when the wrong first match is selected. If the old tag was consumed in (b), or the original node cannot be reused before consumption, this counterexample does not arise. A table deletion can swap a trailing entry, so an actual record order must be logged rather than presumed after arbitrary earlier deletions.
5. **Present frame fencing is real and backend-specific.** src/vr/game/render_semantics.hpp::EndSpriteQueueFrame:1868-1907 retires serial <= the FIRST pass's frame-expire cutoff and intentionally preserves newer registrations; with a live SpriteQueueDepth it defers normal expiration. Under OUTRUN_VR_R26_HUD_COMPARE, src/vr/d3d9/stereo_renderer_r13.cpp::PresentDestR13:716-749 calls that fence AFTER forwarding the lower original Present, even without R13 overlay readiness; ::ResetDestR13:425-440 uses deviceReset=true. In R84/R33, src/vr/d3d9/stereo_renderer_r33.cpp::PresentDestR33:2235-2304 and ::ResetDestR33:2132-2146 provide their own fence. src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-818 performs stereo eligibility and original native Present, but is not itself the owner of the R26+HUD tag-expiration call. The R13/R33 routing is compile-time/installation-conditional; it is not proof that an exact DLL enabled the expected hook.
6. **Deferred native GPU owner does not repair a wrong queue tag.** src/vr/game/hud_command_batch.hpp:74-141,177-282 stores exact native D3DX sprite/Begin generation, homogeneous producer, queue node/selection epoch, mutation/Flush outcome; it cannot independently reconstruct whether the source producer serial 10 versus 11 was chosen for a reused pointer. src/hooks_uiscaling.cpp::VRProjectedD3DXSpriteIsolationR64::BeforeQueueNode/BeforeQueueEnd:3661-3835 flushes old exact homogeneous +TIME/GOAL batches before changing queue owner; Draw/Flush/End at :3407-3508 preserves original native HRESULT/fallback. These are material existing protections, so even the symbolic wrong first-match need not become a wrong GPU draw. Type-1 native DrawPrimitiveUP bypasses deferred ID3DXSprite ledger ownership and must be traced separately.
7. **Physical eyes and terminal host are independent gates.** src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30IsExactResultHudDraw:3073-3083 requires exact physical semantic and queue node/epoch, while ::R62TryFixedFunctionSpriteIndexed:5126-5352 needs actual DIP triangle-list, null VS, FVF 0x142, live viewport/pose and valid original projection. ::DrawIndexedPrimitiveDestR30:5377-5461 tries R62, XYZRHW, then guarded R29/original; ::DrawPrimitiveUPDestR30:5464-5490 is separate. ::R30ExecuteXyzrhwStereo:3829-3945 submits both eyes with RT/depth/viewport restoration and error poisoning; optional R22 replay has its own raster restore. src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-818 can publish valid stereo or mono/fallback, and vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513 plus ::xrEndFrame:3562-3599 composite/submit XR eye images. Neither native Present nor xrEndFrame proves which of two SAME-address producer serials authored a particular glyph.
