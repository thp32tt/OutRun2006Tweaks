## REVIEW_SCOPE — producer -> semantic -> native D3DX queue -> actual draw -> L/R -> restore -> Present/OpenXR

1. Original +TIME animation producer 0x00429530 and numeric 0x004973C0/0x004974E0 (distinct original E8 sites and mode-2 0x00498AC6 negative control) or a normal sprite -> original canonical 0x0042D710 SpriteNode priority consumer -> type-0 non-direct 0x0042A0A0 / ID3DXSprite::Draw. The optional original 0x004C50A0 partial consumer is not a proven complete REA inventory.
2. Queue entry/selection in `render_semantics.hpp` increments a queue-node epoch and takes its exact tag when present; untagged nodes remain generic ScreenOverlay2D. `VRProjectedD3DXSpriteIsolationR64::DrawDest` captures this immutable scope, producer, queued flag, node and epoch *before* original ID3DXSprite::Draw. `HudCommandBatch::Ledger` requires a homogeneous original owner and matching queue pointer + epoch, rather than assuming that the CPU Draw is a physical GPU draw. A native texture transition can Flush internally, so this provenance is guarded by generation/mutation checks.
3. Positive branch: `BeforeQueueNode` drains a proven outgoing batch before replacing the physical queue owner; `BeforeQueueEnd` flushes a still homogeneous, armed +TIME/GOAL batch with matching node and epoch before `EndSpriteQueueRender`. A successful in-queue physical fixed-function DIP (FVF 0x142, live VS null and valid stereo) may be owned by R62; R30's outer Draw* SkyGlow guard has the current queued ScreenHud semantic and can capture the pre-HUD L/R scene. This is *eligibility*, not an observed R62 eye submission.
4. **Different fail-closed branch:** `BeforeQueueEnd` only attempts the explicit Flush if `boundaryReady && QueueRenderActive && matchesGpuOwner(true,currentNode,currentEpoch) && (StageOwner || GoalOwner) && drawCount>0 && homogeneous && scope/producer match`. A mixed/unarmed/mismatched/foreign/failed-boundary batch does not gain the queue-owned pre-End Flush. `EndSpriteQueueRender` then exits the queue and restores `CurrentScope` to the prequeue scope; its node, producer and exact queue scope are cleared. A subsequent original D3DX End/Flush *can* be the first physical submission for the pending commands.
5. Native `FlushDest` and `EndDest` restore the deferred exact screen owner only when `HudBatch.matchesGpuOwner(false,nullptr,0)` and `CanRestoreDeferredResultOwner` pass. A ledger still marked queued cannot pass this direct-owner test once the queue has ended. The normal native End/Flush is nonetheless invoked; its D3D9 Draw*/DIP callbacks consume the current outer semantic, which no longer necessarily denotes ScreenHud/ScreenOverlay2D. Crucially, losing positive provenance is NOT equivalent to native D3DX dropping commands; it deliberately avoids assigning unknown/mixed triangles a speculative HUD eye plane.
6. Conditional optical consequence: in normal active stereo with positive SkyGlow, if a pending screen sprite physically reaches the game backbuffer after queue exit while `EffectiveScope` is not a pre-HUD screen semantic, `R30BeforeScreenDrawForSkyGlow` does not stamp `R30SkyGlowScreenDrawEpoch` and does not snapshot clean scene. At `PresentDestR30`, absent a recognized screen stamp, the optional SkyGlow Present fallback may copy the now-HUD-populated live L/R sources, which could bloom HUD pixels. The same deferred physical DIP may decline R62 and fall back to R29/original; its success or particular eye placement is not proven here. If a *different* earlier screen draw stamped the epoch, the protected skip/capture path changes this result.
7. R30 SkyGlow per-eye reduced source and optional additive composite occur before R7 Present. R7 gates world/duplicated/right-eye/pose/resource transport and may publish DirectGPU/SBS or hold; R23 host independently binds L/R SRVs/UV, pose/FOV and XR imageRects, without certifying that a deferred sprite was excluded from bloom. No exact-SHA GPU frame, clean/dirty reduced texture, native HRESULT sequence, headset halo, frame time, or FPS claim follows from this static branch.
