## REVIEW_SCOPE — producer -> semantic -> queue/direct -> D3DX/native -> R30/R62 -> L/R -> restore -> Present/OpenXR

1. **Original producers, and what this is not.** Archived REA/Ghidra evidence (`docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md`, original EXE SHA-256 `68ceb386829066f8455b9d027320af962584321f3e2e8a79c72841495a6134c3`) maps the canonical 0x0042D710 priority consumer to type-0 D3DX Draw 0x0042A0A0, type-0 direct-UP 0x0042C0F0, type-1 animation 0x0042A3A0 and mask 0x0042A800. +TIME has six individually verified E8 callers, but 0x00498AC6 stage mode-2 is not a blanket finite ScreenHud token. Those queue/animation paths are negative controls here. This review follows **direct nonqueued** GOAL print helpers and stack-proven B9200 D3DX glyphs, whose CPU Draw can be registered before physical native End. Partial original 0x004C50A0 and unresolved indirect CALLs preclude asserting exhaustive game paths.
2. **Direct semantic and Begin preservation.** In `VRProjectedD3DXSpriteIsolationR64::DrawDest` direct B9200 fallback binds `ResultTextB9200` only for GOAL state, no active queue/no current producer and `OriginalB9200GoalStackActive()` proof. Direct GOAL sources are separately bounded by the exact helpers; a source-less or foreign Draw cannot be promoted. `BeginDest` snapshots the ledger and, after native Begin, calls `onBeginResult(self,SUCCEEDED(hr),hr==D3DERR_INVALIDCALL)` only if the game sprite is exact and generation has not changed. `Ledger::onBeginResult` retains an active same-sprite batch on reentrant INVALIDCALL, preserving the former source rather than treating a nested rejected Begin as a new batch. Any other failed Begin invalidates, and an inner successful newer-generation Begin is protected from the stale outer callback.
3. **Pending native ownership.** `DrawDest` captures the physical command's pre-native scope/producer/queue epoch and snapshots `HudBatch`; a successful same-generation Draw becomes a CPU ledger command after native return, while failed or changed-source/reentrant cases revoke unproven ownership. A homogeneous direct batch is distinct from an exact queued node, and B9200 requires `provenDirectB9200`. Direct stage and GOAL pre-source, exit and foreign-Draw drains attempt a narrowly proved `FlushTracked`; failed/ambiguous buffers retain native fallback rather than globally flushing each glyph.
4. **Native Flush vs End asymmetry (confirmed in source).** `FlushDest` and `EndDest` both snapshot {sprite,generation,mutationSerial}, conditionally restore a direct homogeneous B9200/GOAL source across actual physical submission and call the original native D3DX method with its HRESULT unchanged. On Flush return, `Ledger::completeNativeFlush` checks **sameGeneration AND unchanged mutationSerial AND succeeded**, otherwise revoking same-generation uncertain source. On End return, `Ledger::completeNativeEnd` checks **only sameGeneration** then unconditionally `end()` regardless of mutationSerial or End HRESULT. This is an observable **static policy difference**, not proof native D3DX permits a same-generation nested Draw from End.
5. **Narrow hypothetical interleaving.** Let active direct B9200/GOAL generation G carry a homogeneous old Draw A; nested Begin on exact sprite returns INVALIDCALL so G and the old batch remain. Outer `EndDest` snapshots G, serial S and conditionally restores A's exact source. If original D3DX End invokes a callback that successfully records an **inner Draw B in the same G** (serial S+), without a new Begin and before outer End returns, `completeNativeEnd` still sees G and clears the ledger. The code does not distinguish whether B was physically consumed by that End, rejected, or queued to a still-live native session. Future native Flush/End cannot recover B's ledger owner after the reset. Conversely, if nested Begin succeeded and incremented generation, the same-generation check blocks the stale teardown; if callback Draw changes scope/producer, `recordDraw` may already make the ledger mixed, which prevents false positive direct owner restoration.
6. **GPU route and eye effects are unproven.** The outer End's conditional `ScopedExactProducerSemantic` can route physical D3D9 Draw* under the restored direct owner; the R30 outer DrawIndexedPrimitive hook consumes current semantic and tries the pre-HUD SkyGlow boundary, R62 fixed-function SpriteDIP (valid RT/stereo, VS=null, FVF=0x142, triangle list) or guarded R30/R29/original fallback. No successful native End, physical inner Draw, FVF match, actual bilateral rasterization, HUD offset, bloom halo, or frame time was recorded. The R30 L/R RT/depth/viewport restore and R7 Present stereo world/right/pose/resource transport gates, followed by R23 OpenXR SRV/UV/pose/FOV/imageRect projection, cannot reconstruct semantic metadata deliberately cleared before later callbacks. However later transport correctness/incorrectness cannot be inferred merely from an owner reset.
7. **Negative and safety paths.** Native End without an inner Draw should close the session normally. Reentrant **new successful Begin** uses a different generation and must survive old End return (already tested). Same-generation inner Draw during native **Flush** uses mutationSerial protection and is intentionally NOT this finding. Non-INVALIDCALL Begin failure invalidates conservatively; a failed End may justifiably close the ledger for safety even if native D3DX retains commands, because physical ownership is unproven. Mixed/foreign direct HUD, queue-node epoch, lens/rank WorldBillboard, ESC native queue and F11 external ImGui remain independent.
