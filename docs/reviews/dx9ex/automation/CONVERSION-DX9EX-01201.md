## REVIEW_SCOPE — producer → semantic/queue → native D3DX or UP → R30/R62 L/R/restore → Present/OpenXR

1. **Producer / API split (committed original REA, not live GPU evidence).** `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-43,62-69` maps original scheduler `0x00449050`, +TIME `0x00498670`, numeric `0x004973C0/0x004974E0`, GOAL/result `0x004979E0`, conditional partial priority path `0x004C50A0`, normal consumer `0x0042D710`. Type-0 `0x0042A0A0` registers `ID3DXSprite::Draw`, whose actual native GPU submission may occur during *implicit texture-change Flush*, explicit `Flush`, or `End`; type-1/flagged `0x0042A3A0/0x0042A800` uses native `DrawPrimitiveUP` as a negative control. The source REA is historical checked-in disassembly analysis only.
2. **Independent startup boundaries.** `src/hooks_uiscaling.cpp::VRProjectedD3DXSpriteIsolationR64::InstallThread:4039-4094` polls for the game sprite at `0x55B218`, constructs six disabled inline hooks (Begin, Draw, Flush, End, LostDevice, ResetDevice), then attempts enabling all. It logs a positive readiness message only on complete success; on partial failure it rolls the hook handles back and continues polling, eventually logging `exact sprite batch/lifecycle hook set unavailable`. `::apply:4101-4121` merely starts that thread and returns true when `CreateThread` succeeds, **before** confirming any of the six hooks. Separately, `VRHudQueueSemanticBridge::apply:4221-4257` installs the `0x2D762` node and `0x2DCB4` epilogue hooks atomically, without waiting for R64 native D3DX readiness; never touch unsafe `0x2D734`. These are distinct readiness clocks even with `Settings::VREnabled`.
3. **Queue identity is not proof of the physical D3DX interceptor.** `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1837` assigns queue node, exact source and consumer epoch, and `::EndSpriteQueueRender:1839-1863` closes a partial pass without retiring unvisited tags. R64 `src/vr/game/hud_command_batch.hpp::Ledger:12-141,150-282` is only populated by hooked Begin/Draw and cleared by hooked Flush/End. Without verified completed R64 installation *before the particular Begin*, positive queue tags/R50 install logs cannot certify that ledger tracked the texture batch. This is an **observable control-plane gap**, not evidence that the actual DLL missed installation.
4. **Normal installed R64 path has explicit defenses.** `src/hooks_uiscaling.cpp::BeginDest/FlushDest/EndDest:3407-3508` snapshots original native Begin generation, restores a proven homogeneous *direct* +TIME/GOAL owner only during the actual native callback, and preserves original HRESULT/fallback; queued work depends on its current queue context. `::DrawDest:3824-3990` pre-drains a proven direct outgoing owner before a foreign incoming Draw and compares exact `scope/producer/queued/node/epoch` before and after the original D3DX Draw. `hud_command_batch.hpp::completeNativeDraw:82-141` admits an implicit internal Flush only when the same generation has a successful clean Flush mutation and empty new native batch. `::BeforeQueueNode/BeforeQueueEnd:3661-3820` use exact old owner / queue epoch to conditionally Flush +TIME/GOAL before switching consumer node or ending the queue. No unconditional per-glyph Flush is warranted; failed/unknown/mixed batches remain native/fail-closed.
5. **Two conditional symbolic flows; neither is a captured defect.** (A) If the complete six-hook R64 install log precedes the exact sprite Begin, direct `+TIME` Draw A may be physically submitted during internal texture-change Flush when Draw B arrives; the Flush interceptor can restore A's former exact direct semantic, record success, and let Draw B enter the next mutation generation. Later queue-node transitions or final End follow the existing distinct protections. (B) If an R50 queue bridge installed but R64 failed or was still polling while the original Begin/Draw/Flush was executed, queue scope may exist while the *batch ledger* has no matching native Begin/Draw record. The original game native call still executes, but a source-specific **deferred** restoration cannot be credited from a queue tag alone. When GPU submission happens inside the active original queue, ambient queue semantics may independently supply correct ownership; absence of R64 is therefore NOT automatically a missing glyph or stereo defect.
6. **Physical GPU/R30/R62 negative controls.** A true D3DX type-0 fixed-function physical `DrawIndexedPrimitive` is eligible for `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R62TryFixedFunctionSpriteIndexed:5126-5352` only after exact semantic, game backbuffer, triangle-list, live null VS, `FVF 0x142`, valid D3D9 viewport/projection and latched pose. `::R30IsExactResultHudDraw:3073-3083` requires exact physical producer and valid queued node/epoch; `::DrawIndexedPrimitiveDestR30:5377-5461` can reject R62 yet continue via XYZRHW or R29/original. `::R30ExecuteXyzrhwStereo:3829-3945` does L/R physical API calls, RT/depth/viewport restoration and fail-closed frame poisoning; R62 restores original projection. Type-1 native `DrawPrimitiveUP` uses `::DrawPrimitiveUPDestR30:5464-5490`, not R64's D3DX batch ledger. No exact GPU fingerprint or live physical Draw serial was observed here.
7. **Frame/host acceptance independent of installation and draw logs.** For R26+HUD, `src/vr/d3d9/stereo_renderer_r13.cpp::PresentDestR13:716-749` calls queue-frame retirement after forwarding native lower Present even when R13 overlay is not ready; `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-818` gates transport publishing on world stereo, actual duplicated draws, right-eye/restore health, pose and successful original Present, otherwise mono/fallback. `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` renders each direct SRV/SBS half-UV to independent XR eye views; `::xrEndFrame:3562-3599` submits the frame. Neither the queue semantic log, native Draw HRESULT, nor host xrEndFrame alone proves specific glyph geometry or Quest3 binocular optics.
