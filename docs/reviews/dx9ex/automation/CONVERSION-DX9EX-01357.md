## CONDITIONAL PRODUCER -> SEMANTIC -> QUEUE -> GPU -> EYES -> XR TRACE

1. **Original producer and physical fanout.** The previously recorded original-EXE REA mapping associates +TIME numeric/print source RVAs 0x989AD/0x98A10/0x98A89 with the result/stage UI family; GOAL B9200 has independently verified parent callers. Native priority-queue consumer 0x42D710 may dispatch kind-0 D3DXSprite Draw (0x42A0A0), kind-0 direct UP (0x42C0F0), kind-1 animation quad (0x42A3A0), or masked branch (0x42A800). No new REA disassembly or runtime branch identity was acquired here. The following **D3DX-lifetime** analysis applies to kind-0 D3DX / direct numeric-glyph draws, not automatically to the other three paths.
2. **Source tag and queued identity.** Exact stage/GOAL entry/leave and queue hooks put a proven producer/scope/node+epoch on the draw path; `BeforeQueueNode` flushes a proven outgoing node before `SelectSpriteQueueNode`, and `BeforeQueueEnd` drains homogeneous exact queued work before retiring the queue. Direct GOAL B9200 requires the original return-address stack proof; fallback leaves unproven work native. A same token with a different queue node is NOT the same batch owner.
3. **Begin/Draw and implicit texture Flush.** `BeginDest` snapshots current sprite and generation. An exact same-sprite nested `D3DERR_INVALIDCALL` does not clear the prior batch; a different Begin failure may revoke it. `DrawDest` saves `CapturePhysicalDrawCommand` *before* native Draw, conditionally drains a known previous direct owner before a foreign Draw, then compares post-Draw producer/queue epoch and calls `HudBatch.completeNativeDraw`. `Ledger::completeNativeDraw` recognizes a successful internal native Flush only if same sprite/generation, clean zero-draw homogeneous batch and matching `lastSuccessfulFlushMutationSerial`; failed Flush, source drift, foreign/reentrant Begin/Draw and mixed buffer lose exact ownership. Thus registration is not physical GPU submission.
4. **Native Flush/End and loss.** `FlushDest`/`EndDest` only restore a proven homogeneous *direct* producer through a scoped guard around original D3DX physical submission, then validate snapshot mutation/generation. `LostDeviceDest` and `ResetDeviceDest` invoke their respective original ID3DXSprite slots 12/13 and then `InvalidateForDeviceLifecycle` for the tracked or currently live sprite, including when global `0x55B218` has changed. `HudBatch.invalidate` retires pending owner/sprite; `FlushTracked` forbids dereferencing a stale pointer unless candidate=tracked=live sprite. A native End after loss is not proof the old queued triangles reached the GPU.
5. **Independent D3D9 Reset domain.** The stereo device hook `ResetDest` (D3D9 slot 16) calls render-probe reset notification, releases stereo/DirectGPU resources, invalidates tracked D3D states, publishes a disabled frame, performs native Reset/compat ResetEx, then on success primes device states/resources. In the inspected `ResetDest` body there is **no direct HudBatch.invalidate call**; the HUD ledger's revocation contract is in the separate ID3DXSprite lost/reset callbacks, Begin failure and stale-object guards. This is a **callback-order dependency**, NOT proof that the game ever calls Reset without its expected D3DX sprite lifecycle or that stale triangles are actually submitted.
6. **Physical draw / R30/R62 / final output.** Only original D3DX internal native Flush/End (or independent direct-UP family) yields a concrete D3D9 Draw*. `CapturePhysicalDrawCommand` stores scope, producer, selected queue node/epoch at that GPU time. If the physical method/eligibility is the protected R26+HUD `DrawPrimitiveUP` XYZRHW route, R30 may emit the original left draw and guarded right RT/depth/viewport draw, then restore; fixed-function FVF-0x142 DIP may independently follow R62, while unknown or ineligible physical draws retain guarded/native behavior. No D3DX CPU Draw or reset callback proves that either path was actually hit. `PresentDest` admits stereo metadata only with world-stereo/duplicate proof, consistent pose/resources and non-poisoned right/restore state; successful Present and post-Present DirectGPU publication/SBS remain distinct. Host R23's actual `xrEndFrame` layer is yet another necessary condition. No exact-sha Reset→two-eye→published-frame→Quest3/VDXR sequence was observed.
