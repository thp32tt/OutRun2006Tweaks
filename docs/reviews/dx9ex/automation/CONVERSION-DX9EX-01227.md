## Static read-only, original-to-XR path simulation

1. **Original producer and semantic ownership (not assumed equivalent to the final GPU draw).** Checked-in original-EXE REA evidence `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:1-44` pins SHA-256 `68ceb386829066f8455b9d027320af962584321f3e2e8a79c72841495a6134c3`, the six +TIME E8 calls, `0x449050 -> 0x42D710` queue and four diverging paths: type0 D3DX `0x42A0A0`, flagged type0 direct-UP `0x42C0F0`, animation `0x42A3A0`, masked `0x42A800`. The REA has unresolved indirect calls. A producer, semantic tag, D3DX Draw or queue node alone cannot establish whether, when, or how a physical DP/DIP/DPUP/DIPUP reaches R30/R26.
2. **Producer → semantic → queue → physical draw.** `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode/EndSpriteQueueRender/EndSpriteQueueFrame:1789-1909` and `src/hooks_uiscaling.cpp::VRProjectedD3DXSpriteIsolationR64::BeforeQueueNode:3661-3795, VRHudQueueSemanticBridge::QueueNode:4152-4169` separate queue-node/epoch from deferred D3DX native Flush/End. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawIndexedPrimitiveDestR30:5377-5461` routes external F11 first, eligible R62 fixed-function, then guarded R30 XYZRHW/R29/original. R30 L/R and RT/depth/viewport restore are physical-eye contracts, not implications of semantic provenance. Rank/rival, lens/sky, +TIME/result and cockpit must remain independently attributed.
3. **R9 completed Present boundary.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-823` requires an eligible world stereo frame with valid pose, no failed right draw/frame poison and stereo resources; resolves direct transport and publishes an in-flight marker before original Present, and only publishes `StereoSbsActive` after a successful native Present and complete stereo. On failure the mono shadow can be restored; `ResetDestR9:825-841` clears R9 seed/depth identity. The game ring's producer `src/vr/d3d9/stereo_renderer_r7.inc::PublishRenderFrame:1489-1510` exposes frame ID, run generation, DirectGPU slot, transport generation and handles. No current physical-reset frame trace was captured.
4. **Host selector and correct run-scoped cursor reset.** `vrhost/src/main_r23.cpp:2665-2685,2950-3026` holds `lastProcessedStereoFrame`, `directRunEpoch`, `cachedProjectionValid`. On a **PID/run-generation** transition, the first eligible history frame triggers `lastProcessedStereoFrame=0`, invalidation of `matchedStereoValid`, cached projection and verified bundle. `OutRunVrDirectRingLatest::Pick` (`vrhost/src/runtime/direct_ring_latest.hpp:5-68`) chooses the newest current generation's eligible frame by wrap-aware frame order; `R37FrameIdBefore:517-521` is signed-delta wrap-aware. `vrhost/src/runtime/direct_ring_skip_ack.hpp:17-40` permits skip-ACK only when *generation, run generation, PID, and strict older-than selected* prove same producer epoch. These controls argue against generic stale-slot recycling.
5. **Boundaries are deliberately not identical.** `vrhost/src/runtime/r23_verified_bundle.hpp::IsFresh/BelongsToCurrentProducerRun/ReadFresh:101-136` accepts a verified bundle up to `MaxPresentationAgeMs=1000` from publication and compares latest **runGeneration and game PID**, but it does **not compare the latest frame's DirectGPU transport generation** with the cached bundle's transport generation. The policy comment `:18-23` explicitly allows a newer game frame to coexist with an already-owned, about-to-be-submitted texture/pose pair. This is a confirmed static eligibility difference, not proof of incorrect submission. `vrhost/src/main_r23.cpp:3291-3415` keeps `cachedProjectionValid` for same-source XR tick reuse and can hold an already released projection during a gameplay stall. Run change, OpenXR session STOPPING, reference-space transition and presentation transition have distinct invalidation fences (`:2730-2794,2874-2906,2977-2989`), but there is no equivalent direct transport-generation comparison in the **cached projection reuse branch** `:3291-3409`.
6. **Cache reuse must be distinguished from protected producer resources.** `vrhost/src/runtime/direct_hold_frame_reuse.hpp:10-43` requires exact frame ID, slot, transport generation, run generation, PID, both handles **and actual left/right D3D11 resource pointers** before reusing a host-owned hold copy. `vrhost/src/main_r23.cpp::R23StageDirectHold:548-641` submits two CopyResource commands on one immediate context and caches the exact key; `R23CommitDirectAfterValidation:1413-1433` fail-closes invalid source/copy; `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:90-106` resets SafeEye/shared texture caches on device/context change. An old **released projection image** can therefore remain visually reusable without old producer textures being passed as a new-generation hold-copy. This separates a potentially intended freeze image from a stale shared-resource bug.
7. **ACK fencing and actual xrEndFrame.** `vrhost/src/runtime/r32_direct_submit.hpp::SyncAckDeviceOwner:150-174,ObserveAckIdentity:176-197,PollCompletedAcks:210-310` binds the EVENT/ACK to current D3D11 device+context and fences completed ACKs by transport/run/PID; old-generation late completions are discarded, not published into active ACK state. `::CanFastSubmit:427-476` checks `VerifiedBundle::ReadFresh`, complete frame, direct metadata, projection-to-bundle match and generation fault, but **not latest transportGeneration equality**. `::EndFrame:550-610` observes verified identity, polls/arms EVENT and calls actual OpenXR end path; `vrhost/src/main_r23.cpp:3562-3615` separately records actual intercepted xrEndFrame status, submitted frame/layer, and frame-aligned telemetry. Cached visual reuse, fast-submit eligibility, GPU-copy completion ACK and actual Quest3 eye visibility are four separate claims.
8. **Reset/recenter scenario simulation (conditional).** Same PID/runGeneration, transport generation G1 -> G2 after device Reset/reopen; G1 projection already released in OpenXR and last verified bundle published fewer than 1000 ms earlier; newest G2 frame may be ineligible/in-flight/not-yet-committed. The host selector does not produce a new G2 bundle, so cached projection can remain displayed by design; bundle run-only freshness **can** remain true, subject to matching projection and all other R32 gates. ACK arm/completion retains its own epoch/device/context safeguards. Thus, static inspection justifies a *transport transition visibility audit*, **not** the conclusion that the host incorrectly ACKs a G1/G2 producer slot, draws twice, breaks recenter or crashes.
