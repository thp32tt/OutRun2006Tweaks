1. **Original source, semantic and physical submission are different objects.** Archived `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:7-42,88-101` maps the original scheduler `0x00449050`, priority consumer `0x0042D710`, deferred D3DXSprite Begin/Draw/Flush/End and independent native D3D9 DrawPrimitive[Indexed][UP] families. No new x86 CALL/XREF or exact producer texture/RT pair was obtained.
2. **Confirmed sparse-census phase alias (distinct new finding).** `src/vr/d3d9/gpu_water_profiler.hpp:162-204` starts `s.draws=0` per query slot's logical frame and computes `i=s.draws++`; state sampling requires `((i + (frame_*7)) & 15u) == 0`. The *RT and pixel-shader census* at `:206-235` is nested under that state-sample branch and further requires `(i & 63u) == 0`. The latter forces `i % 16 == 0`, so the first condition is satisfiable **only when `7*frame_ % 16 == 0`, equivalently `frame_ % 16 == 0`** (7 and 16 are coprime). Thus in the other 15 out of each 16 logical frame phases the RT/PS census does not execute at all; this follows algebraically from the source, without any runtime measurement. Even in an eligible frame, only logical Draw indices 0,64,128,... can enter the census, provided the slot has valid query state and the two alpha/test getters succeed. The `i & 63u` condition is also true for the shader census, not a separate independent random sample.
3. **A 'smaller than first sampled RT' heuristic is not backbuffer ownership.** `src/vr/d3d9/gpu_water_profiler.hpp:48-59,203-228` seeds `referenceWidth_/referenceHeight_` from the *first successfully inspected RT descriptor*, not a verified D3D9 game backbuffer. It increments `offscreenRtSamples` only when `desc.Width < referenceWidth_ || desc.Height < referenceHeight_`. Equal-sized or larger offscreen surfaces will not be counted as offscreen by that heuristic; if first sampled RT is already offscreen, its dimensions form a misleading reference for subsequent frames. Reset explicitly clears this baseline (`:143-161`). `offscreenRtSamples=0` cannot prove every draw targeted a verified game backbuffer; dimensions cannot prove actual water material identity.
4. **Existing measurements are opt-in and explicitly not water-specific.** `src/vr/d3d9/gpu_water_profiler.hpp:2-18,20-44,65-130` enables sampling only for `OUTRUN_VR_GPU_PROFILE=1`, uses D3D9 timestamp/disjoint/frequency queries and `GetData(...,0)` without FLUSH/busy wait, labels route bins diagnostic rather than original producers, and logs `waterAttribution=UNPROVEN`. `beforeDraw` samples alpha blend/test, ZWRITEENABLE, ZENABLE and stencil in separate independent snapshots (`:193-204`); it does not measure *physical* overdraw, effective per-pixel fragment count, texture identity, scissor occluded area, both-eye fragments, or a confirmed water polygon. A no-ZWRITE sample is not a no-ZTEST sample. Its span from initial frame's top-level Draw through before-Present can include GPU idle gaps; derived GPU p95/p99 must not be renamed XR app-to-photon latency or water GPU cost.
5. **Profiler brackets logical R33 entry rather than the actual per-eye Draw alone.** `src/vr/d3d9/stereo_renderer_r33.cpp:1818-1884,1885-1979,1981-2047,2049-2122` wraps each top-level native DP, DIP, DPUP and DIPUP hook in `GpuWaterProbe::beforeDraw -> R33GuardStereoRasterState(call) -> afterDraw`.
