3. **R13 release is a *two-proof* transaction, not a global consumed-ID heuristic.** `src/vr/d3d9/stereo_renderer_r13.cpp::ResolveDirectTransportR13:222-377` scans four producer slots, requires a previously published slot's dedicated per-slot `completedFrameId[index]` to be at-or-after `slot.frameId`, *then* requires that slot's producer D3D9 EVENT `GetData` return `S_OK` before changing `published=false` and reusing. `S_FALSE` preserves the hold; hard EVENT errors or failed eye StretchRect/Issue quarantine the transport until ResetEx. If all slots remain held, it returns no DirectGPU frame and increments backpressure. 4. **The R13 seqlock snapshot already fences restarted processes.** `src/vr/ipc/direct_ack_r13.hpp:9-36` defines the 48-byte ACK IPC with `hostPid`, `transportGeneration`, per-slot IDs and reserved `(runGeneration,gamePid)`. `stereo_renderer_r13.cpp::R13ReadGpuCompletionSnapshot:147-201` performs bounded stable-sequence reads and checks *host PID*, transport generation, run generation and game PID before importing four IDs. Therefore the simple claim “an old ACK frame ID alone lets the new process recycle a producer texture” is contradicted by these explicit guards.
