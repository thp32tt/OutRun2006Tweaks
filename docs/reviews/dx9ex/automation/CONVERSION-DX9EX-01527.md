## NEW_FINDING — source-proven negative control; NOT a new optical defect

- NEW_FINDING=NEGATIVE_CONTROL_ENDSCENE_CLIENT_FRAME_COMPLETED_NOT_STEREO_RENDER_FRAME_PUBLICATION; NEW_CONFIRMED_RENDER_DEFECT=NONE.
- In the inspected game/client source, a successful `EndSceneDest` marks `ClientFrameCompleted` and calls `PublishClientTelemetry`. That routine increments `ClientHeartbeatIndex` and writes `ClientFlagsIndex`, angle, presentation mode and game-state fields. It does **not** allocate an eye transport frameId, populate an L/R render-frame ring slot or call `PublishRenderFrame`. Therefore multiple scene-end heartbeats within a single game Present are not by themselves evidence of multiple host stereo-frame/eye submissions.
- The independent R7 `PresentDest` obtains `pendingFrameId=NextStereoFrameId()` once per requested game Present, tests completed stereo eligibility, then publishes render-frame metadata in that Present path. The SBS path can publish a **pre-Present fallback/in-flight marker** and later publish a completed stereo frame; these are different states of the Present publication protocol, **not proof of two completed XR projection layers**. The DirectGPU path publishes only after its post-Present readiness criteria. A direct-only hold may deliberately preserve prior good metadata. None of these paths proves an `xrEndFrame` layer count without a host trace.
- The existing aggregate `MultiBeginScenePresents` / `MaxBeginScenesPerPresent` counters are calculated from `GetBeginSceneCallCount()` at Present, conditioned on `GameplayActive()`. Their existence confirms a diagnostic *capability*, not that any actual flare-bearing frame had two scenes. They are neither keyed to C993/CABE object/texture nor matched to a host XR frame.
- Consequence for 01526: if a second BeginScene occurs before one Present, previous-game raw c64 may remain conditionally eligible in the same source lifetime, but an accompanying second `EndScene` does NOT create a second `PublishRenderFrame` just because it writes `ClientFrameCompleted`. Separate actual same-eye raster duplication (A/B/D), wrong C993 ray/pose (C/F) and host layer reuse (E) remain distinct, unverified alternatives.

- SCOPE_LIMIT: This only rejects the *simple* mechanism “two EndScene callbacks alone publish two complete stereo transport frames” in inspected hooked source.
