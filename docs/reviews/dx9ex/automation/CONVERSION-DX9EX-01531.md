Merely being a lens texture or original object 0x570008 does **not** satisfy this predicate.
4. If that projected ownership has lapsed and the actual physical scope is `SceneEffect` or `None`, and no other `semanticOverlay` case admits it, the path instead evaluates `TryPrepareOutRunWvp` (2113-2155). This routine (1562-1628) **does not always inject**: it requires enabled renderer, latched head inverse, a complete c64..c67 source, valid renderer matrices, near-match to `Transpose(WorldView*Projection)`, and finite corrected WVP. Only if all gates hold is `WorldView * HeadInverse * Projection` (or the configured matrix order) uploaded. Its subsequent `RecordGameWvpWrite(uploadedData, originalData)` retains a separately recorded *original raw* c64 even when GPU c64 was head-corrected; a changed device register alone cannot prove raw source loss.
5. At later **physical** R30 classification, `SceneEffect` can become `WorldBillboard`, `PerspectiveHud` or rejection; `ProjectedScreenEffect2D` can copy recovered *raw original* stock WVP to both eyes. These R30 decisions (2232-2392, 5030-5227) are **distinct from the earlier setter branch**. Successful R30 raw recovery and bilateral state restore can supersede the earlier GPU c64; rejection/fallback might leave its path to the lower renderer. Thus “lost projected scope” is **not** sufficient proof of double head transform, nor a specific physical route. Check both decisions for the same original mesh serial.
