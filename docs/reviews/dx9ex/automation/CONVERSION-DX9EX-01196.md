## REVIEW_SCOPE — original producer → queue/physical D3DX → R62/R30 eye stages → native restore/StateBlock/Reset → Present/OpenXR

1. **Static original producer, not optical attribution.** `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-42,62-67` maps original +TIME `0x00498670`, numeric `0x004973C0/0x004974E0`, GOAL/result `0x004979E0` and queue consumer `0x0042D710`. Queue type-0 enqueues `ID3DXSprite::Draw` and later `Flush/End` leads to a physical fixed-function indexed GPU Draw; type-1/flagged paths may issue native `DrawPrimitiveUP` instead. This task reviewed the checked-in REA map, not a new disassembly or live observed glyph. `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1837` and `src/vr/game/hud_command_batch.hpp::Ledger:74-141,177-240` are pre-existing source/queue/batch controls; neither a source token nor D3DX API call alone establishes the final pixel.
2. **Entry and preflight are mutation-free with respect to projection.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R62TryFixedFunctionSpriteIndexed:5126-5198` requires backbuffer triangle-list indexed Draw, HUD/projected source, live null VS, `FVF=0x142`, stereo resource/viewport/pose and a finite original `D3DTS_PROJECTION` obtained by `GetTransform`. `:5200-5273` computes both finite eye projections *before* invoking the physical callback. An early preflight reject returns `E_NOTIMPL` and therefore does not call the R62 eye-specific `SetTransform` nor its own projection-restoration block.
3. **Per-eye projection API stage versus physical Draw stage.** At `::R62TryFixedFunctionSpriteIndexed:5275-5288`, `drawEye` first stores `device->SetTransform(D3DTS_PROJECTION, &eyeProjection[eye])` into `eyeHr[eye]`. On failure it returns generic `E_FAIL` **without calling** `DrawIndexedPrimitiveHook`. On success, it overwrites `eyeHr[eye]` with the actual DIP HRESULT. Thus the recorded field denotes *one of two stages* and the original projection-SetTransform failure HRESULT is not propagated as such to R30. It is not correct to infer `physical DIP attempted` merely from a failed `left` or `right` field in the existing `RESULT_HUD_EYES` record.
4. **R30 helper misidentifies the failing stage, though its frame gate remains protective.** `::R30ExecuteXyzrhwStereo:3829-3850` invokes left callback; a left projection SetTransform failure is classified `StereoFailureLeftDrawFailed` and short-circuits the right pass, although no left DIP was issued. If left succeeds, `:3852-3875` switches RT/depth/viewport for right and calls right callback; a right projection SetTransform failure is classified `StereoFailureRightDrawFailed` at `:3868-3871,3931-3936` with no right DIP issued (state-setup failures before callback retain separate `RightStateFailed`). `RestoreRightPassState` runs after the right callback attempt. If either right API or state restore fails, R30 poisons/arms fallback; `:3944` still returns the left HRESULT. Previous 01193 already documented the attempted-draw counters; **this task isolates error-stage provenance**, not those counters.
5. **Projection restore is a second and separately timed operation.** After R30 returns (including a left early failure), R62 `:5296-5307` makes an independent `SetTransform(originalProjection)` attempt under `InternalPassScope`, then records a boolean `projectionRestored`. A failed restore calls `NoteRestoreFailure` and `R30ArmSafeFallback`. For exact-result draws, `:5324-5346` prints bounded source/viewport/pose plus `left/right` ambiguous stage HRESULTs and the restore boolean; `:5346` converts a successful left `hr` to `E_FAIL` on failed projection restore. It does **not** separately print per-eye SetTransform HRESULT, whether DIP was actually invoked, the restoration HRESULT, or the succeeding unrelated native draw's live projection. An R62 `RESULT_HUD_REJECT` in `::DrawIndexedPrimitiveDestR30:5377-5461` is R62-only: XYZRHW/R29/original may still consume the same physical DIP. Native type-1 `DrawPrimitiveUPDestR30:5464-5488` is a separate route.
6. **Native D3DX StateBlock/Reset is a different owner, not proof of matrix leakage.** `src/vr/d3d9/stereo_renderer_r22.cpp::R22StateBlockApplyDest:143-179` invalidates/re-primes cached raster/shader tracking on successful `IDirect3DStateBlock9::Apply`; `::BeginStateBlockDestR22/EndStateBlockDestR22:244-276` tracks recording events. These are separate source routines from R62's projection restoration. `::ResetDestR22:562-578` closes stereo eligibility and resets cached baseline before device Reset; `src/vr/d3d9/stereo_renderer.cpp::ResetDestR9:825-840` invalidates mono/depth identity and stereo seed and captures a refreshed main depth on successful Reset. This audit did **not** confirm a particular same-frame StateBlock::Apply/Reset interleaving with an exact physical +TIME draw, or prove the R22 path is the active handler in every R26+HUD configuration. A hypothetical stale post-failure projection at the *next* native draw remains unproven; the existing success-path restore is positive mitigation, not a demonstrated leak.
7. **Frame/host acceptance must remain separate.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-825` admits stereo only with seeded world, duplicated draw, no right failure or incomplete frame, matching pose and usable resources, then checks actual original Present; it may output mono fallback. `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513,::xrEndFrame:3562-3599` performs final eye-source composition/XR submission. These are not a correlated proof that a particular result-number DIP reached either eye, and neither the R84 candidate nor a successful API HRESULT is an exact-build Quest3 HMD PASS.
