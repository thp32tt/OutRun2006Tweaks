## EVIDENCE — pinned code observations, not runtime proof

1. Archived REA source architecture: `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:7-32,48-78` documents game producer -> 0x42D710, D3DX Begin 0x429C60 / Draw 0x42A0A0 / End 0x429F60 and the separate non-D3DX direct branches. `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:5-42` gives the original four targets and the limits of 0x4C50A0 REA proof. This was not a fresh Ghidra run.
2. Exact D3DX ledger is keyed to a physical batch, **not merely its most recent CPU Draw**: `src/vr/game/hud_command_batch.hpp:13-42,75-143,179-212,232-283` records original sprite, Begin generation, mutation serial, homogeneous producer, queued flag, node and selection epoch. A native Draw may internally Flush a previous texture batch; recovery of its return only succeeds after an exactly matched successful internal Flush mutation. `matchesGpuOwner(false,nullptr,0)` explicitly returns false when `queued=true`.
3. Real R64 hook integration exists, subject to installation success, not only helper predicates: `src/hooks_uiscaling.cpp:3422-3569,3911-4090,4130-4195` hooks original ID3DXSprite Begin/Draw/Flush/End plus loss/reset slots. The exact global live sprite at original EXE `0x55B218` must match the ledger; partial hook installation fails closed, so a source-code path is not proof it ran in the user's R26 packaged binary.
4. Queue callback ordering is explicit: `src/hooks_uiscaling.cpp:4220-4272` calls `BeforeQueueNode(node)` **before** `SelectSpriteQueueNode(node)`, and `BeforeQueueEnd()` **before** `EndSpriteQueueRender()`. The bridge uses already-established safer 0x2D762 / 0x2DCB4 sites; it does not reinstall the unsafe 0x2D734 or B9200 post-CALL/+5 hooks.
5. **NEW static queued-batch submission window / fail-closed boundary.** `src/hooks_uiscaling.cpp:3807-3907` fences Stage and GOAL owner/queue-node/epoch transitions and accepts a last end-of-queue Flush **only if** `boundaryReady && QueueRenderActive() && matchesGpuOwner(true,currentNode,currentEpoch) && recognized owner && drawCount>0 && homogeneous && identical scope/producer`. The callback then clears `boundaryReady` and exits queue. At a later `EndDest`, `src/hooks_uiscaling.cpp:3549-3576` attempts deferred exact restoration through `matchesGpuOwner(false,nullptr,0)` and `CanRestoreDeferredResultOwner(...,!QueueRenderActive(),...)`; for a *still queued ledger* the former is unconditionally false by `hud_command_batch.hpp:271-277`. **Therefore if a genuine queued exact batch survives that final queue window without an earlier successful physical Flush, a later non-queue native End cannot reacquire the vanished queue-node/epoch exact owner.** Native End still occurs and no original HRESULT is replaced. This is a deterministic *conditional ownership limitation*, NOT evidence that a queued batch actually survived in a reproduced finish screen or that a fallback necessarily draws only one optical copy.
6. There is intentional mitigation before that window: `src/hooks_uiscaling.cpp:3991-4078` and `src/vr/game/render_semantics.hpp:634-738,748-804` rearm `boundaryReady` on the first clean queued Stage/GOAL Draw following Begin; GOAL retains 2+ same-source D3DX Draws and Flushes at the next node or queue tail, while unproven/mixed draws remain native. `src/hooks_uiscaling.cpp:3736-3818` separately drains exact **direct** GOAL/+TIME batches *before the first queue node*. Even direct B9200, excluded from the generic helper `render_semantics.hpp:499-583`, has a dedicated `provenDirectResultText` branch requiring exact stack-proven homogeneous direct owner. Do not incorrectly report B9200 as globally undrained or require an unsafe new hook.
7. `src/vr/d3d9/stereo_renderer_r33.cpp:250-291,1690-1855,1885-2005` captures original physical semantic in real DP/DIP/UP paths, tries eligible fixed-FVF/R30/R62 or exact screen routing, and preserves original screen draw on missing proof rather than using a road WVP. `src/vr/d3d9/stereo_renderer_r7.inc:1519-1559,1678-1744` conditions L/R GPU and Present validity on RT/depth/stencil, pose, second-eye result and state restore; `vrhost/src/main_r23.cpp:1438-1513,3559-3595` independently fills 2 D3D11 image-array eyes and calls xrEndFrame. No part of this logical fence shows actual Quest 3 optical pixels.
