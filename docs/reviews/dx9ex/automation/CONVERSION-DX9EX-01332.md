- **Confirmed:** the failed gameplay projection path may release a swapchain image even when one eye returned false; the subsequent direct-only bootstrap may reuse prior menu projection *view metadata* without verifying that the latest released raster still came from the menu writer. A normal successful stereo render clears that menu cache; STOPPING and reference-space change invalidate it. - **Conditional hypothesis:** when a first-eye gameplay Draw was enqueued but second-eye Map failed, a released partially updated image could become the image sampled for the retained menu layer, leading to a transient mismatched, mono, or black eye instead of the promised last-good menu. OpenXR's returned image selection, GPU completion, final composition and headset appearance must be observed; **not** every failed render, every menu transition or every release causes an optical defect.
