## NEW_FINDING — source-confirmed policy distinction; runtime impact unproven

- NEW_FINDING=B9200_PARENT_PROVEN_BATCH_NOT_ADMITTED_BY_FIRST_QUEUE_DRAIN_POLICY.
- CLASS=SOURCE_CONFIRMED_POLICY_ASYMMETRY; LIVE_CODE_PATH=NOT_PROVEN; ACTUAL_RENDER_DEFECT=NOT_ESTABLISHED; PERFORMANCE_GAIN=NOT_MEASURED.
- FACT: `HudCommandBatch::Ledger::recordDraw` can represent a homogeneous direct `ResultTextB9200` batch with exact original parent evidence, and `CanSuppressUnprovenDirectResultD3DXSubmission` includes direct B9200 when attribution is missing at the physical Flush/End. But `CanDrainDirectResultBeforeFirstQueueNode` intentionally yields false for B9200 regardless of the homogeneous flag (explicit static_assert); its input has no parent-proof bit. The three safeguards are **not equivalent** and cannot be collapsed by token equality or CPU caller stack.
- HYPOTHESIS_ONLY: if a parent-proven direct B9200 glyph is still pending on the same D3DXSprite when the first queued SpriteNode becomes current, and no native Flush/End already fenced its GPU triangles, B9200 may lack the special pre-first-queue isolation applied to +TIME/other GOAL families. The later native path could correctly fail closed to one original draw, or could cause a transient missing/duplicated finite GOAL stereo glyph depending on active hook/ledger ordering. Neither outcome has been observed.
- FALSIFY / CONTRARY: document an unconditional successful native End/Flush between every direct B9200 batch and first queue selection; prove B9200 never shares the relevant native sprite; prove this helper is not invoked in an installed R26+HUD/R84 route; or demonstrate a fresh matched HMD L/R result with the boundary present and no ownership mismatch. Any of these limits/rejects the proposed visual consequence. If an explicit policy deliberately excludes even parent-proven B9200, the guard difference is intentional safety, not a defect. A missing path/hook read must not be turned into a runtime claim.
- This review does NOT propose auto-enabling B9200 pre-drain: inserting an extra native Flush or widening exact owner classes without physical proof risks changing native batching, perf and draw order.
