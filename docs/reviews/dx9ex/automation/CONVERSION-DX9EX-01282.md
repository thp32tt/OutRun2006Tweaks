## EVIDENCE — producer → semantic/queue → D3DX/native GPU API → R30/R62 → L/R/restore → Present/OpenXR

1. **Producer and queue entry are known, actual reset overlap is not.** Checked-in REA `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-32` resolves original central `0x449050 -> 0x42D710`, type-0 D3DX `0x42A0A0` (deferred Draw to Flush/End), type-0 direct UP `0x42C0F0`, animation quad `0x42A3A0`, and mask `0x42A800`; 36 indirect CALLs remain unresolved. `src/hooks_uiscaling.cpp::VRHudQueueSemanticBridge::QueueNode/QueueEnd:4154-4184` attaches the 0x2D762 node and 0x2DCB4 queue-end callbacks. It calls `BeforeQueueNode` **before** `SelectSpriteQueueNode`, and `BeforeQueueEnd` **before** `EndSpriteQueueRender`. This proves callback ordering in checked-in mod source, not that a game Reset can interrupt the original queue.
2. **Queue snapshot and TLS are different state domains.** `src/vr/game/render_semantics.hpp:1196-1219` keeps the published tag serials, active shared queue cutoff and frame-expire cutoff separate from thread-local `SpriteQueueSemanticCutoff`, `SpriteQueueDepth` and `CurrentSpriteQueueNode/SpriteQueueNodeEpoch`. `::SelectSpriteQueueNode:1789-1837` snapshots a new serial cutoff **only when** `SpriteQueueDepth==0`; with an existing queue depth it increments `SpriteQueueNodeEpoch` and calls `ConsumeSpriteNodeScope` without refreshing the cutoff. `::ConsumeSpriteNodeScope:1712-1758` rejects tags whose serial is newer than the active TLS cutoff, conservatively falling back to `ScreenOverlay2D` and a null producer. `::CapturePhysicalDrawCommand:1420-1432` later samples this state for a physical primitive. A node pointer or producer name alone is not a GPU identity.
3. **Device Reset retires semantic tags but does not itself close queue TLS.** The protected R26+HUD compile guard in `src/vr/d3d9/stereo_renderer_r13.cpp::ResetDestR13:425-435` calls `EndSpriteQueueFrame(true)` for the game device **before** the R13 overlay-ready/compat branches and `ResetCompatDevice:436-463`. `src/vr/game/render_semantics.hpp::EndSpriteQueueFrame:1866-1905` on `deviceReset=true` expires all published tags at the sampled next serial, sets the shared active cutoff to zero and frame cutoff to zero. It **does not** set `SpriteQueueDepth=0`, `SpriteQueueSemanticCutoff=0`, `CurrentSpriteQueueNode=nullptr`, or reset the TLS selection epoch. Only `::EndSpriteQueueRender:1839-1863` closes queue depth and clears the TLS cutoff when its depth reaches zero. This is a **confirmed source-static state-boundary distinction**, not a confirmed crash/artifact.
4. **Conditional stale-cutoff trace (hypothesis, not a captured timeline):** (A) a node walk starts with TLS depth 1 and serial cutoff C; (B) ResetEx is invoked on that same thread **before queue epilogue**, and the protected reset path expires tags through new published serial N while leaving TLS depth/cutoff unchanged; (C) a post-reset producer registers node B with serial N+1; (D) if the old queue epilogue has not run, a subsequent `SelectSpriteQueueNode(B)` sees depth nonzero, skips cutoff refresh, and `ConsumeSpriteNodeScope` excludes B (N+1>C); (E) physical draw semantic becomes fallback `ScreenOverlay2D`/null producer rather than the new exact +TIME/GOAL/rank tag. A normal queue exit between B and D, Reset that only occurs outside queue, or thread separation without shared queue TLS refutes this specific sequence. There is **no evidence** of A–E co-occurring in an OutRun frame.
5. **D3DX deferred lifetime is a second, guarded boundary.** `src/hooks_uiscaling.cpp::VRProjectedD3DXSpriteIsolationR64:3350-3376` owns the thread-local `HudCommandBatch::Ledger`; `::DrawDest:3882-3941` captures exact source and queue node/epoch at CPU Draw and native Draw return. `src/vr/game/hud_command_batch.hpp::Ledger:12-59,177-216` distinguishes native batch generation, mutation, queued node and queue epoch. `src/hooks_uiscaling.cpp::BeforeQueueNode:3661-3808` attempts bounded flush of verified outgoing owner; `::BeforeQueueEnd:3810-3832` only flushes homogeneous, matching queued owner; unknown/mixed batches retain native End. `::FlushDest/EndDest:3432-3508` can recover a proven *direct* +TIME/GOAL producer only if the native batch is homogeneous, live-object-identical and **no queue is active**. Therefore a stale queue-depth state would also veto this direct-owner restoration rather than proving unsafe forced stereo.
6. **Existing lifecycle defense is real, but covers its observed callbacks.** `src/hooks_uiscaling.cpp::LostDeviceDest/ResetDeviceDest:3511-3540` invalidates a tracked/live D3DX batch when the old/live sprite's OnLostDevice/OnResetDevice callback occurs. `::FlushTracked:3543-3562` refuses freed/replaced sprite pointer mismatch. `src/vr/game/hud_command_batch.hpp::Ledger::invalidate:262-277` discards pending producer/queue identity. In the **inspected** R13 `ResetDestR13/R13ResetCommonPre:380-463`, there is no direct call to that D3DX ledger invalidation or to `EndSpriteQueueRender`; this does **not** establish that original game always omits D3DX lifecycle callbacks. An OnLostDevice callback, native Flush/End, or regular queue epilogue could retire the pending batch in actual operation. No live sprite/vtable callback trace was supplied.
7. **Physical owner and L/R are gated independently.** For the protected R26+HUD path, `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30SafeStereoBase:75-93` requires actual game device/main backbuffer, stereo desire/seed, valid runtime pose/depth and rejects recovery/MRT/query/forced mono. `::DrawPrimitiveDestR30:5350-5375` and `::DrawIndexedPrimitiveDestR30:5377-5452` test R30 XYZRHW, fixed-function R62 and fall back to R29/native hooks; R62's `E_NOTIMPL` is **not** final GPU route evidence. `src/vr/d3d9/stereo_renderer_r13.cpp::R13GuardedDraw:594-651` further enforces actual target/MRT/occlusion single-execution or mono-shadow fallback. The lower actual Draw* and right-eye path can also decline or fail. Missing exact semantic could lead to a native/nonfinite fallback, not necessarily a doubled HUD. Left/right draw HRESULT, WVP, RT/depth/viewport restore and selected physical API remain unobserved.
8. **Present/OpenXR cannot retroactively establish queue correctness.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:759-823` restores mono if incomplete, invokes native Present, publishes StereoSbsActive or fallback and clears frame seeds. `src/vr/d3d9/stereo_renderer_r13.cpp::PresentDestR13:718-749` subsequently invokes queue-frame retirement on game Present for R26+HUD, but `EndSpriteQueueFrame(false):1871-1874` returns early when queue depth is still nonzero. The host `vrhost/src/main_r23.cpp:3562-3610` confirms actual `xrEndFrame` and submitted frame/layer IDs; it does not attest to CPU queue cutoffs or glyph stereo depth. Historical REA and Issue #6 review-inbox policy are context only; no fresh game log, disassembly run, Quest3/VDXR capture or FPS trace was acquired.

## NEW_FINDING — confirmed static seam, unproven runtime manifestation

- **NEW_FINDING=RESETEX_QUEUE_TAG_RETIREMENT_DOES_NOT_REBASE_ACTIVE_TLS_CUTOFF**
- **CONFIDENCE=CONFIRMED_STATIC_STATE_SEAM; RUNTIME_DEFECT=UNPROVEN; HMD_PASS=NO.**
- **Verified:** In the inspected default R26+HUD R13 Reset path, reset-era *shared tag retirement* is not the same operation as per-thread queue walk teardown. The first future selected node only refreshes the queue serial cutoff when TLS depth is zero. In an in-flight walk that crossed ResetEx, a newer exact tag could be ignored until the genuine queue epilogue. This is separate from 01281's query-object generation counter and from 01279/01280's query draw/mono replay.
- **Conditional visual/performance hypothesis:** If the game actually resets mid-queue and resumes a node selection in that TLS scope without an old queue end, +TIME/GOAL or projected rank may be admitted as generic screen overlay, changing binocular depth or leaving a deferred D3DX batch to a later native End. This is **not an observed defect**. A later physical DP/DIP can instead be rejected by independent frame/pose/depth/recovery gates. Avoid assuming that source tags prove final GPU API, or that an unsuccessful guarded Flush proves GPU duplicate/vanishing draw.
- **REFUTATION:** Exact game-side call sequencing always closes each queue before Reset; the Reset uses another thread and the old queue thread ends without new node admission; a guaranteed post-Reset EndSpriteQueueRender runs before any new registered SpriteNode; D3DX OnLostDevice/OnResetDevice or Begin/End invalidates the pending batch before potential draw; captured post-reset queue serial cutoff is fresh; or captured physical Draw* does not occur on the main target with stereo eligibility.
- **Required evidence before proposing an actual repair:** Exact baseline ZIP/DLL SHA, build flags and original EXE SHA; queue thread ID, queue-entry/node/epilogue original RVAs, `SpriteQueueDepth`, TLS/shared cutoffs, node pointer+tag serial+selection epoch, device Reset/ResetEx HRESULT and order; D3DXSprite pointer, Begin/Draw/Flush/End/OnLost/OnReset callback order, ledger generation/homogeneous/queued fields; native DP/DIP/UP primitive ID with RT/VS/PS/FVF/texture/viewport/depth and draw HRESULT for both eyes, restoration and pose; game Present frame/pose+mono fallback and host actual submitted `xrEndFrame` frame ID/layer. Passive bounded logging only, no risky midhook or unbounded synchronous GPU queries.
