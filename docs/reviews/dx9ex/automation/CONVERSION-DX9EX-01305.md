## REVIEW_SCOPE

New route, distinct from 01303's **fresh classic projection** client-rectangle/UV epoch and 01304's live HDR SDR-white-scale sampling. Here the stereo producer may stall after one successfully released OpenXR pair while the game HWND/output or Desktop Duplication identity changes. Trace: +TIME/result producer -> SpriteNode semantic and queue epoch -> deferred D3DX/native physical Draw -> R30/R62 stereo L/R and restore -> R9 ComposeSbs/Present -> Frame.v2 -> conditional R23Capture/desktop output rebind -> classic source commit -> per-eye D3D11 RenderTo and XR swapchain release -> R42 cached projection -> actual xrEndFrame. Investigate whether the last released projection cache is qualified by the currently bound classic output epoch, and whether the monitor check runs without a *new* producer frame.

4. **Candidate gate limits classic capture:** `vrhost/src/main_r23.cpp:3091-3126` detects `already-processed` when frameId matches `lastProcessedStereoFrame`, and only enters the candidate body when a new complete eligible frame exists. `main_r23.cpp:3134-3162` calls classic `R23Capture(compositor,2)` inside that body, not on each cached stereo XR tick. Also, if R23Capture isn't invoked because no new Frame.v2 exists, it cannot perform that monitor check.
6. **R42's cache is intentionally not a per-frame fresh capture:** `main_r23.cpp:3290-3379` sets `cachedHold=cachedProjectionValid` independently of `grace`, and refreshes a projection on `newStereoCommitted || !cachedProjectionValid`. Otherwise `projection-cached` submits the saved released `cachedProjectionViews`, even after stereo grace expires; it does not compare source HMONITOR, duplication ID, output extent, frame/crop geometry or age before holding. The code explicitly prefers retaining the last good stereo image over black/empty compositor frames during a gameplay stall. This *by itself* is a deliberate UX/performance policy, not a proven defect.

None is a generic classic HWND/DXGI-output rebind invalidator; this observation does NOT imply those protected transitions are defective.

R42 reuse executes neither new full-eye blit nor new per-eye source/crop calculation. `main_r23.cpp:3562-3589` submits the selected layer via `xrEndFrame`. A successful XR API result cannot establish freshness, binocular geometry, correct +TIME visual placement or a Quest3/VDXR HMD PASS.
9. **Issue/runtime evidence limit:** GitHub Issue #6 is an open continuous-review inbox, not a same-SHA output-switch trace. No actual Windows monitor move, DXGI loss log, per-eye pixel capture, original GPU draw trace or Quest3 HMD test was supplied. The conditional output transition is unproven; performance deltas are unmeasured.

- **Static finding:** Classic SBS desktop capture/source validity can be re-bound or invalidated without clearing the separately held released XR projection, and when there is no new eligible Frame.v2, capture and the HMONITOR check may not run at all. This is distinct from late UV recomputation for a newly admitted projection and from cached SDR-white conversion values.
- **Conditional simulation, not an incident report:** game produces a valid classic projection on monitor A; Frame.v2 remains at an already-processed ID; user moves game window to monitor B or duplication resets while XR remains gameplay/LOCAL. No new candidate means no per-tick R23Capture; R42 resubmits the old released A pixels until new producer/transition or an explicit invalidator. If capture is later invoked and binds B but no replacement projection commits, R42 can still retain its old pair. That can present visually stale content **by intentional last-good freeze**; no assertion is made that the real system transitioned in this order or would prefer a different fallback.
- **Falsifiers / contrary conditions:** continuous new eligible stereo frameIds on actual output move, presentation switch to Theater, session STOPPING, LOCAL reference-space change, game PID/host restart, DirectGPU epoch invalidation, or an exact installed binary containing an additional output identity gate; no monitor change without a new source; runtime requirement that last-good stereo remain visible across all capture stalls.
