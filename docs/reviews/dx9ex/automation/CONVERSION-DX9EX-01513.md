3. R7 `ClearDest` duplicates eligible game clears to right RT/depth with saved viewport; successful left clear calls `RecordFullMainDepthClear`. The record is gated on `TargetIsBackBuffer`, tracked depth, and `ClearCoversStereoBackbuffer`, which *explicitly requires a full-sized current viewport* and a full clear rectangle/Count=0; it stores clear depth/stencil value, flags, depth descriptor and `PresentEpoch`.
4. R7 may have `RightDepthSynchronized=false` / `RightStencilSynchronized=false` after allocating a right depth or after a left-only/failed or incomplete draw/clear path. Not every source of unsynchronization is eligible for publication; failed/poisoned paths still fail closed in `PresentDest`. This note isolates the **bootstrap predicate**, not an assertion that an observed frame escaped those guards.
5. `PrepareDuplicatedDraw` calls `TryBootstrapRightDepthFromRecentClear` if a tracked left depth exists and either right sync flag is false. The bootstrap confirms same `PresentEpoch`, left/right/last-full-clear **descriptors** and appropriate previous clear flags, then snapshots `savedViewport` with `GetViewport` — but does NOT call `ViewportCoversStereoBackbuffer` or otherwise prove `savedViewport` covers the surface.
6. The bootstrap sets right RT/depth, applies **that saved viewport**, then issues `ClearHook(device, 0, nullptr, replayFlags, 0, lastZ, lastStencil)`. According to Microsoft Direct3D 9 `IDirect3DDevice9::Clear` and `Viewports and Clipping`, Count=0/pRects=null clears only the *current viewport* and rectangles are clipped by that viewport: it is NOT a whole-surface clear when the current viewport is cropped. Reference: https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3ddevice9-clear and https://learn.microsoft.com/en-us/windows/win32/direct3d9/viewports-and-clipping .
7. On successful right clear **and successful state restore**, the bootstrap sets `RightDepthSynchronized=true` for Z and/or `RightStencilSynchronized=true` for stencil based solely on replay flags. These booleans are whole-depth eligibility gates for subsequent `PrepareDuplicatedDraw`; there is no maintained per-rectangle/viewport coverage, nor a recheck after the replay to confirm full-surface clear.
8. **Bounded conditional state sequence (not observed):** same-Present genuine full left main clear is recorded, right surface remains unsynchronized and has contents outside viewport V that differ from left (e.g. a fresh right allocation whose initialization value differs from a previous left full-clear value, or intervening left-only depth writes). The game narrows viewport to V before eligible draw preparation. Bootstrap passes epoch/descriptor checks, clears only V on right and restores the viewport; marks right sync true despite unchanged mismatching area outside V. Later in the same Present the game expands viewport and runs a real depth-tested/stencil-tested world draw through R7 or eligible R30/R62 physical L/R. With valid independent eye pose/RT/projection/HRESULT and no poisoned/incomplete frame, left/right occlusion **could** differ; successful `PresentDest` and DirectGPU/SBS metadata do not prove depth equality.
9. **Additional freshness risk, kept subordinate to this scope:** right-depth clear replay matches a *historic full-left-clear value*, not necessarily all left writes since that clear. The source does not carry a per-depth-write lineage in `LastMainDepthClearEpoch`; this matters only if a subsequent unsynchronized state remains eligible and a new stereo frame is genuinely accepted. Do not infer that poisoned mono fallbacks become accepted merely because bootstrap was attempted.
10. Controls: full-size viewport at bootstrap makes Count=0 clear full viewport (removes THIS viewport-coverage issue, though content freshness remains a separate question); no same-Present full-clear record / descriptor mismatch / no right depth / no replay flags returns false; depth/stencil testing off reduces visual impact; failed replay/restore returns false; any independently poisoned, right-failed or frame-incomplete R7 path must not publish stereo. An earlier full bilateral clear may already synchronize; a right surface with identical contents outside V would also show no difference.
11. R7 guarded actual `ExecuteStereoDraw` checks LEFT, RIGHT RT/depth/viewport and transform setup/draw/restore, and `PresentDest` requires world+duplicated draws, pose, healthy resources, no right failure/incomplete flag, then commits either DirectGPU after producer-fence confirmation or SBS followed by original Present. R7 source acceptance is not a Quest3 `xrEndFrame` or verified pixel equivalence test.
