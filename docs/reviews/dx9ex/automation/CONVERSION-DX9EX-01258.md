4. Surface coverage matches both hooked method targets (`Surface::LockRect`, `Surface::GetDC`) against the returned surface vtable. If already hooked but either target differs, coverage fails. Initial installation creates disabled hooks and requires both enabling successfully; failure resets both hook objects/target pointers. 5. On coverage success, a surface-only borrow is permitted without retiring the CPU shadow. A successful writable surface `LockRect` (non-READONLY flags), or successful `GetDC`, invokes `R14MarkSurfaceExternalWrite`, obtains its parent texture by `GetContainer(IID_IDirect3DTexture9)`, marks GPU-write/coherency retirement for a registered identity, and releases that temporary parent AddRef. Read-only or failed Lock and failed GetDC do not mark the texture. A successful writable lock is treated conservatively as a potential write **before** a pixel modification or `UnlockRect` is observed; a real modification is not established by that signal alone.
6. On surface-hook coverage failure, `TextureGetSurfaceLevelDestR14` attempts to retire the CPU shadow **before** returning the uninstrumented surface: if shadow is unlocked, `R14RetireShadow` detaches it, releases its CPU peer and leaves the native call's original HRESULT/surface intact. **If the CPU shadow is still locked**, `R14RetireShadow` returns false; the wrapper releases the newly borrowed GPU surface, sets output to nullptr and returns `D3DERR_INVALIDCALL` even though the underlying `GetSurfaceLevel` succeeded. This deliberate fail-closed return-contract change is the independently confirmed conditional source behavior.
7. Where parent `GetContainer` maps a surface write to a registered R14 GPU key, `R14MarkExternalGpuWrite` invalidates `validMask`, sets `retirePending`, and immediately detaches the unlocked shadow. With an outstanding CPU shadow lock, it sets `externalWriteDuringLock` and defers release; the R14/R15 final `UnlockRect` suppresses stale CPU overwrite. Missing/failed `GetContainer` does not by itself prove a write or trigger this mark. DirectOnly entries do not own a CPU shadow. Surface hook lifetime, COM identity and later texture deletion must not be conflated with a particular renderer draw.
