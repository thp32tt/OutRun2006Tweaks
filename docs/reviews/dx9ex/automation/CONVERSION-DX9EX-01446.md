## REVIEW_SCOPE: static full path and state timeline

1. **Producer/REA and queue boundary.** Existing original-executable REA provenance (`docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md` and `docs/automation/OUTRUN_VR_REA_RESOURCE_EVIDENCE_20261018.md`) defines original +TIME/GOAL/priority SpriteNode/D3DX Draw->Flush/End and direct-UP paths; those *are negative controls*, **not** evidence that an external F11 ImGui UI originates from original D3DX/SpriteNode. `src/vr/game/render_semantics.hpp:962-1025` keeps `ScopedExternalOverlaySemantic` / `ExternalOverlaySemanticDepth` separate and has `ConsumeForDraw()` return the current external scope without consuming a pending original-game one-shot token. F11's ScreenOverlay2D path bypasses the original D3DX queue owner and must not inherit +TIME, GOAL, ESC native sprites, rank or lens producer identities.
2. **Physical GPU entry and ownership.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:5555-5582` calls `ConsumeForDraw()` and `R30BeforeScreenDrawForSkyGlow()`, then tries `R30TryExternalImGuiIndexed` *before* R62 fixed-function game SpriteNode/XYZRHW/R29/native fallback for the same physical `DrawIndexedPrimitive`. The ImGui branch's `ActualDraw` is the intercepted original D3D9 `DrawIndexedPrimitiveHook.stdcall`; a CPU semantic or ImGui command is not already proof of a submitted eye pixel.
3. **Exact F11 eligibility, coordinate and projection boundaries.** `R30PrepareExternalImGuiProjection:2876-3068` requires safe stereo base, previous world/duplicated-frame evidence, exact external `ScreenOverlay2D` semantic depth, no VS, XYZ+DIFFUSE+TEX1 FVF, identity world/view, orthographic stock projection, Z disabled, scissor enabled, finite nonzero viewport, valid latched eye poses/sequence. It builds the finite HUD-plane `hudWorldLockValid` route when `R30ConfigureXyzrhwWorldEffect` succeeds; otherwise it builds a *different* FOV-only affine fallback (`2943-2961`). It computes each eye's scissor by transforming the stock command rectangle into the current game viewport (`3018-3067`); this is **not** evidence that the HMD projection extent equals the game backbuffer or that a 2496x2688 XR portrait source was corrected in an actual new capture. `R30PlaneScaleForOwner:2786-2803` selects fixed F11 scale 0.65 separately from gameplay HUD scaling.
4. **Eye submission, restore and telemetry order.** `R30TryExternalImGuiIndexed:3071-3193` sets left projection/scissor; if left setup/draw fails it returns/poisons before reaching the counter. After **successful left draw** it attempts right render-target/depth/viewport/projection-scissor setup and only then invokes `draw()` for the right eye. `rightHr` therefore records the first *state/setup or draw* HRESULT, not an unambiguous `rightDrawHr`. It calls `RestoreRightPassState` and `restoreRaster()`, but then unconditionally sets `FrameHadDuplicatedDraw` and increments `DuplicatedDraws`, `NonWorldDuplicatedDraws`, `R30SafeTwoEyeDraws`, and `R30ExternalImGuiStereoDraws` **before** checking `FAILED(rightHr)` or `!restored` (`3141-3193`). The `VR F11 SOURCE-ASPECT PROBE` log is also emitted **before** those failure checks: it reports `hits`, game size, viewport, dynamic mode, both scissor rectangles and `leftHr/rightHr` (`3161-3181`). The current format-to-argument alignment includes `mode` and both HRESULT fields, correcting the earlier positional misalignment; it does **not** turn `hits` into a per-frame bilateral-success count. The one-time `VR R30 F11 IMGUI SCREEN2D ... uses finite world-locked` message (`3148-3153`) is emitted even if that attempt used `FOV_ONLY_FAILSAFE`; the dynamic `mode` field is the more specific diagnostic. Failures correctly poison/invalidate/arm safe fallback afterwards; `return leftHr` can still return a successful left-eye HRESULT when right failed, independent of the frame poison flag.
5. **R7 transport and host/OpenXR separate success gates.** `src/vr/d3d9/stereo_renderer_r7.inc::PresentDest:1625-1740` requires world stereo, duplicated draw, right-eye/no-incomplete flags, pose/resources, then completes direct GPU or SBS fallback **and** checks actual D3D9 Present before publishing active stereo; direct-only misses can hold the previous good frame. `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` independently selects two SRVs/UV halves, issues both `RenderTo` calls, requires both results, releases the swapchain and assigns each eye OpenXR pose/FOV/imageRect. `R30ExternalImGuiStereoDraws` and the sampled F11 SOURCE-ASPECT line carry **no common frame ID, pose sequence, published stereo state, transport kind, or host XR submission result**, so neither a nonzero `hits` count nor two zero HRESULTs prove the *same* frame reached a Quest 3 display.
6. **Bounded counterexample (source simulation, not observed gameplay).** At T0 an eligible external F11 DIP enters with valid left projection/scissor. At T1 left original D3D9 `draw()` returns `D3D_OK`. At T2 the right `SetRenderTarget`, depth, viewport, projection/scissor, or right draw returns a failure *or* state restore fails. At T3 the F11 `hits` counter increases and the SOURCE-ASPECT probe may print despite the failed right/restore, then the code marks right failure and safe fallback. At T4 R7 refuses newly active stereo or holds/falls back; R23 independently accepts/rejects source. This scenario is **statically possible by control-flow**; no specific HRESULT, render failure or binocular defect has been observed in this task. With telemetry disabled, an R30 eligibility reject, a left-eye failure, a non-sampling counter value, or a different exact tested SHA, the expected log may be absent.
