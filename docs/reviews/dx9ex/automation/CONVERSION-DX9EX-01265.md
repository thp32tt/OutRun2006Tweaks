## Static execution trace (producer to submitted frame)

1. **Original producer / semantic:** Checked-in REA file docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md records original PE SHA256 68ceb386829066f8455b9d027320af962584321f3e2e8a79c72841495a6134c3, six +TIME CALL RVAs 0x9898E, 0x989AD, 0x98A10, 0x98A36, 0x98A89 and 0x98AC6, and a normal sprite consumer 0x449050 -> 0x42D710. Its evidenced physical exits are type0 D3DX at 0x42A0A0, type0 direct UP at 0x42C0F0, type1 quad at 0x42A3A0, and type1 mask at 0x42A800, with 36 indirect calls still unresolved. These are prior static mappings, not a new REA analysis and not a CPU-shadow texture identity match.
2. **Texture creation / resource identity:** ex_device_upgrade.cpp::CreateManagedTextureCompat requests DEFAULT|DYNAMIC first, otherwise a 2D non-dynamic DEFAULT fallback. ex_device_upgrade_r14.cpp::CreateTextureCompatDestR14 routes successful dynamic objects to DirectOnly, not CPU Shadow. For non-dynamic GPU texture, R14CreateCpuShadow first checks GPU level-zero Width/Height/Format and GetLevelCount, then calls CreateTexture with the same dimensions, explicit number of levels, Usage=0, same Format and SYSTEMMEM Pool; registration/byte-budget admission is necessary. This gives a strong *construction-time compatibility expectation*, although it is not a fresh per-mip descriptor equality comparison in the copy helper.
3. **Lock/dirty boundary:** TextureLockRectR14 sanitizes unsupported flags for the CPU peer, uses the original level and RECT, records readOnlyMask/dirtyMask and pointer-present lockRectValid. Only a successful writable lock, a coherent CPU Unlock, and no external GPU write overlap are eligible for R15UploadLevel. A failed UpdateSurface with lockRectValid=false may enter R14CopyWholeLevelByLock; explicit full RECT is not eligible for that R15 fallback. The 01263/01264 eligibility and DISCARD-attempt behavior are inputs, not new findings here.
4. **Signed-Pitch arithmetic:** R14CopyWholeLevelByLock reads **CPU** GetLevelDesc(level), separately locks CPU READONLY and GPU writable, and computes sourcePitch/destinationPitch as size_t absolute magnitudes. Negative signed LONG Pitch is promoted to int64 before negation; the signed minimum does not overflow in that magnitude calculation. For each row, the address is pBits + ptrdiff_t(row)*the **original signed Pitch**, not + row*abs(Pitch), while memcpy length is min(abs(source Pitch),abs(destination Pitch)). Therefore the code is not intrinsically doing unsigned forward traversal for a negative-pitch surface. Correctness still requires the D3D lock's pBits/Pitch contract to describe the first logical row and a sufficiently sized locked region; native driver values were not observed.
5. **Mip geometry and compressed rows:** R14BlockCompressed(DXT1..DXT5) selects max(1,(CPU desc.Height+3)/4) block rows; others select CPU desc.Height rows. The helper does not independently call GPU GetLevelDesc(level), compare Width/Height/Format or require min(Pitch) >= ceil(width/4)*{8|16} for DXT. Nor does it validate expected bytes per pixel for ordinary formats before memcpy. But CPU texture was created with GPU level-zero format and explicit GPU level count, so a mismatched per-mip descriptor cannot be presumed from this absence alone. Driver-specific Pitch padding and signed row ordering are separate from visible texture corruption; mere unequal pitches do not prove lost pixels.
6. **Failure / restore boundary:** Invalid null pBits or zero rowBytes causes E_FAIL; failing destination Lock leaves the CPU source to be unlocked; successful Locks are followed by both GPU and CPU Unlock checks and failure propagation. In R15, an upload failure clears the mip valid bit, marks retirePending and eventually detaches the Shadow after outstanding locks drain. These guards prevent a failed native HRESULT from being silently counted as successful upload, but do not by themselves prove all bytes of a successful copy cover the logical row.
7. **Queue / GPU / eye / final submission:** The texture would have to be sampled by an actual physical DP/DIP/UP. PhysicalDrawCommand captures producer/scope/node/queueEpoch at that physical boundary; hooks_uiscaling.cpp::FlushDest/EndDest only restores exact homogeneous D3DX owner during native submission and leaves unknown/foreign/mixed batches untagged. R30 indexed path tries F11 external ImGui, R62 fixed-function, XYZRHW then guarded R29/native; R62 E_NOTIMPL is not final draw failure. R7 has actual Draw*, RT/depth and Present hooks; any stereo L/R acceptance additionally needs valid pose/eye extents, original-vs-duplicated primitive HRESULT and StateBlock/RT0..N/depth/viewport/WVP restore. stereo_renderer.cpp::PresentDest can publish stereo only on its eligibility and successful normalized real Present; otherwise the normal mono fallback is relevant. x64 vrhost/main_r23.cpp joins actual frameId/sourceKind at xrEndFrame, rather than a merely produced CPU glyph. No bounded texture->actual draw->both eyes->restoration->Present->submitted OpenXR frame join exists for this review.
