## 2. NEW_FINDING — proved control flow vs conditional screen symptom

**Proved from GitHub source:** R30's enabled SkyGlow compositor writes eyes sequentially and can fail after only the first eye's additive composite. On `false`, the postprocess itself increments a failure counter but does not poison the stereo frame, and its caller discards the return value before delegating to R29/R26/R9 Present. The R9 eligibility predicate does not include a SkyGlow error flag.

**Conditional visual risk, NOT observed:** Under a second-eye `StretchRect`, `GetSurfaceLevel`, GPU postprocess draw, or bind failure **after a completed left-eye additive composite**, the left image can carry extra bloom while the right does not. A partial restore failure could also leak D3D state before Present. Because the stage still delegates, normal `StereoSbsActive` metadata may coexist with asymmetric postprocess pixels if no other error is detected. Such circumstances could look like one-eye lens/sky glow, vergence discomfort, intermittent halos or a device-loss transition; they are **not proven current symptoms**. A failure before any composite generally leaves both eyes without a completed SkyGlow pass; `SkyGlowFactor<=0`, `SkyGlow` bypass states, or an earlier no-clean-HUD capture skip defeats the partial-left scenario.
