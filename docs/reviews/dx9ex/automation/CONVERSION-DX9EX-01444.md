1. **Original physical producer bounds.** Archived REA/Ghidra note `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:3-46` ties executable SHA-256 `68ceb386829066f8455b9d027320af962584321f3e2e8a79c72841495a6134c3` to +TIME E8 caller sites, priority consumer 0x0042D710, type-0 deferred ID3DXSprite::Draw 0x0042A0A0, distinct type-0 direct-UP 0x0042C0F0, type-1 animation 0x0042A3A0 and mask 0x0042A800. A partial 0x004C50A0 consumer and unresolved indirect CALLs prevent exhaustive physical-draw claims. This task does not re-run REA/disassembly. Direct numeric +TIME and GOAL / original B9200 parent-proven glyphs can register a *CPU* D3DX Draw outside the SpriteNode queue and be physically submitted by later native Flush/End. Generic unknown and queued batches are negative controls.
2. **Exact provenance and entry-time object check.** `src/hooks_uiscaling.cpp:3196-3242` defines `CanFlush(candidate,tracked,live)` as **three nonnull equal pointers** and `CanRestoreDeferredResultOwner` as active, nonqueued, homogeneous, nonempty, exact-live, finite result HUD (or pause-arrow) owner, with B9200 stack proof required. `HudCommandBatch::Ledger` stores the exact `sprite`, generation, mutation serial and draw-source homogeneity (`src/vr/game/hud_command_batch.hpp:12-65,177-217,269-284`). `DrawDest:3837-3943` captures source/queue identity before native Draw and rejects failed or changed-source reentrant ledger updates. No assumption is made that successful CPU Draw equals a physical GPU Draw.
3. **Known safe lifetime boundaries.** `FlushTracked:3545-3563` re-reads the live game object at `0x55B218` immediately before any vtable dereference; mismatch invalidates the tracked old owner and avoids calling a potentially freed vtable. `LostDeviceDest/ResetDeviceDest:3513-3543` take `OwnsLifecycle(callback,tracked,live)` **before** original callback, then invalidate the old owner even if that original callback replaced the global pointer. `BeginDest:3409-3431` accepts a successful new exact-game sprite Begin or invalidates an old tracked sprite callback after the global object changed. These guards materially bound the risky sequence and must not be bypassed.
4. **Distinct native End interval.** `EndDest:3475-3510` samples `HudBatch.snapshot()`, tests `CanFlush(self,HudBatch.sprite,*0x55B218)` while computing `restore`, then constructs `ScopedExactProducerSemantic` for the proven direct result owner **before** calling original `End_hk.stdcall`. There is no second read of `0x55B218` *inside this outer End scope* before the original End returns. `ScopedExactProducerSemantic:1440-1490` snapshots/restores thread-local `CurrentScope`, queue-exact scope, direct producer and pending draw (when opted in), but does not bind its lifetime to the live D3DX sprite pointer. This is a **confirmed entry-time identity / temporally scoped producer-label property**, not a demonstrated stale-pointer dereference. `EndDest` does not dereference the old sprite's vtable itself after original End returns.
5. **Conditional substitution/reentrancy thought experiment.** At T0, exact original sprite A owns a homogeneous direct +TIME/GOAL batch, with global live pointer A, and End entry authorizes temporary semantic owner A. At T1, *only if* original End or its nested callback changes the game global from A→B/null while still executing (unobserved), outer RAII keeps A's semantic until End returns. At T2, if a distinct B/foreign callback physically submits a Draw* on the **same thread** without installing its own exact semantic / explicit queue or F11 override before outer RAII unwinds, that physical Draw can sample the surrounding A source. A successful nested Begin for B increments ledger generation (preventing the outer `completeNativeEnd` from clearing the newer ledger), but this generation guard **does not itself revalidate the temporarily active TLS semantic at the physical GPU Draw**. Nested exact source RAII, queued exact scope, external F11 overlay, lens-centre override or deferred Draw after old End returns can all negate the risk. It is not known whether native D3DX allows the proposed callback ordering or whether B has a physical draw during the interval.
6. **Physical GPU routing, eyes and restore.** Only if T2 reaches the game backbuffer with the wrong inherited semantic would `render_semantics.hpp::ConsumeForDraw:998-1027` and `stereo_renderer_r30_r26_safe.cpp::DrawIndexedPrimitiveDestR30:5555-5590` classify a physical Draw under A. `R30BeforeScreenDrawForSkyGlow:1200-1215` may then stamp an incorrect first pre-HUD screen boundary; `R62TryFixedFunctionSpriteIndexed:5304-5358` still requires game backbuffer, stereo resources, exact HUD/projected scope, VS=null, FVF=0x142, valid latched eye pose/viewport. R30 dual-eye draw performs independent target/depth/viewport state transitions and returns through restore/fallback, not an unconditional bilateral pass. R7 `PresentDest:1625-1704` independently vets world stereo, right-eye failure, pose, resource readiness, directGPU/SBS/hold and original Present. Host R23 `R23RenderProjection:1440-1513` independently consumes L/R SRVs/UVs, renders both eyes and builds OpenXR pose/FOV/imageRect. None of these downstream checks independently reconstructs the historical per-D3DX sprite identity; conversely no wrong-eye output follows merely from an End entry pointer check.
7. **Protected negative path.** If no A→B switch occurs, if End submits only A's own pending commands, if an inner B draw has its own exact scope or exact queue, or if original End is non-reentrant, the entry-time A restore is consistent. A pointer swap detected by a later `FlushTracked`, `OnLostDevice`, `OnResetDevice` or old-object `BeginDest` is already conservatively invalidated. Old-object `End` completing while global B exists is *not alone* proof of a wrong HUD pixel or stale native dereference. Do not blend this with 01443's same-generation inner Draw mutation-serial gap.
