## EVIDENCE — pinned source and original draw-family boundary

1. **Producer/semantic/queue/physical API boundary:** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md` identifies original queue consumer 0x42D710 and four distinct sprite draw exits: type-0 D3DX 0x42A0A0 (actual batch Flush/End can occur later), type-0 direct primitive UP 0x42C0F0, type-1 animation 0x42A3A0, type-1 mask 0x42A800. 36 unresolved CALLs prevent claiming exhaustive draw XREF. `src/vr/game/render_semantics.hpp::CapturePhysicalDrawCommand` (around 1420-1432) captures queue-active/provenance/epoch rather than proving the GPU command. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30SafeStereoBase` (75-94) excludes auxiliary RT, stereo-incomplete, active occlusion query, depth/recovery/pose not ready; `R30TryXyzrhwPrimitiveUP` (3947-3989) transforms L/R and submits two native DrawPrimitiveUP calls. This bounds the R26+HUD path, not every original sprite form.
2. **Compile owner:** `AGENTS.md` newest 2026-10-20 user override and `CMakeLists.txt` (97-108, 230-244 as cited in 01286) make fresh no-option R26+HUD default, separately opt-in R84. Actual user-run DLL hash/CMake cache were not obtained: no assertion that the installed game uses a specific owner.
3. **Game L/R -> restore -> Present/packet:** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9` (664-823) assigns a pending frameId for stereo requested, checks world draw/duplicated draw/pose/meta/right-eye integrity, resolves DirectGPU ring or composes SBS when allowed, and restores mono before Present on incomplete stereo. It publishes an in-flight fallback descriptor before invoking physical D3D9 Present, normalizes the result, and publishes the active completed metadata only if compose and Present succeeded. Then it clears stereo frame flags and advances PresentEpoch. Successful Present and active metadata **are producer-side events**, not physical XR layer acceptance.
4. **Host ring candidate and ACK:** `vrhost/src/main_r23.cpp` (2940-3150) direct-only R41 reads four-slot frame history, filters in-flight/stale IDs, selects current-generation newest eligible, immediately ACKs only older skipped unsampled ring slots, and preserves selected-slot GPU-completion ACK for R32 EVENT. It refuses classic `Read(before)` in direct-only mode. For classic SBS, (3150-3280) Desktop Duplication must be visible and must match stable Frame.v2 history/QPC skew (100 ms window); pose history is joined and `R23FrameUnchanged` rechecked before D3D11 commit. Direct branch does not establish successful headset presentation solely through slot selection.
5. **GPU copy is not ACK and projected image is not XR-submitted yet:** `vrhost/src/main_r23.cpp` (3200-3355) explicitly declines global consumed ACK after `R23CommitDirectAfterValidation` / classic commit because D3D11 work was only queued. R32 later waits for its event before per-slot GPU-completion ACK. `R23RenderProjection` succeeds -> `cachedProjectionValid=true`, `OutRunVrR23VerifiedBundle::Publish`, `lastProcessedStereoFrame=pendingBundleFrame.frameId`, and `candidateRejectReason="displayed-fresh"` (around 3290-3348) **before** `xrEndFrame` is called. If no new projection is ready, previously released cached projection can be resubmitted rather than a forced theater layer (3355-3410). These are intended producer/host stages, not itself an optical fault.
6. **New telemetry authority split:** `vrhost/src/main_r23.cpp` (3562-3695) calls `xrEndFrame`, then obtains `actualFinalLayerKind`, `LastSubmittedFrameId`, `LastSubmittedKind`, `LastSubmittedLayer` from the actual interception. It logs requested/actual separately, and pacing samples are guarded by `actualSubmittedLayer && actualSubmittedFrameId && verifiedBundle.frameId==actualSubmittedFrameId`. **However `cadence.NoteFrame(frameFreshProjection, frameCachedProjection, layerReady, candidateCadenceRequestId)` still consumes pre-interception booleans, and `sample.cached = !frameFreshProjection` classifies freshness by the host's attempted projection state rather than comparing `actualFinalLayerKind`/source kind to the submitted bundle.** The `"displayed-fresh"` reason is also assigned pre-xrEndFrame. The mismatch between flag provenance and actual-submission identity is confirmed source ordering; a real contradictory submission has not been observed.
7. **Performance guardrails:** The pacing CSV includes xrTick/runGeneration/frameId/cached, gameRenderMs, gamePresentMs, presentToConsumeMs, hostCapture/Copy/Render, xrWaitMs, xrEndMs; fresh-only capture fields are populated only when candidateGameFrameId==actualSubmittedFrameId. Cached XR ticks can validly re-submit old frame IDs, so neither the number of successful game Presents nor row count proves unique headset game frames or 72 Hz. There is no observed Quest3/VDXR GPU capture, actual final-kind mismatch, framepacing CSV, percentiles, sand-scene workload, or timer result for this TASK.
