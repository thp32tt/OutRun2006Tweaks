## REVIEW_SCOPE — source-to-eye-to-XR pipeline and distinct lifecycle boundary

Original +TIME source `0x00498670`, GOAL/result glyph helpers `0x004973C0/0x004974E0`, source-proven B9200 stack and result progress producer -> original `0x00449050` scheduling -> `0x0042D710` canonical SpriteNode consume (possible partial `0x004C50A0`) -> selected node/producer/queue epoch -> original type-0 `0x0042A0A0` D3DXSprite Begin/Draw with deferred texture-batch Flush/End, versus separate type-0 direct UP `0x0042C0F0`, type-1 animation `0x0042A3A0`, type-1 mask `0x0042A800` -> hooked R64 native Begin/Draw/Flush/End and Lost/Reset boundary -> TLS `HudCommandBatch` sprite identity, generation and provenance -> **actual** D3D9 physical DP/DIP/DPUP/DIPUP under R33 source rules, then R30/R62 finite HUD or original-preserved admission -> R7 left/right RT, depth/stencil, viewport/WVP restoration -> original D3D9 Present and stereo pose/frame metadata -> R23 DirectGPU or SBS input and distinct D3D11 projection image array layers 0/1 -> R24 actual `xrEndFrame`.

Narrowed question: while native `OnLostDevice(G)` or `OnResetDevice(G)` has entered with a **pre-call** owned exact sprite G, what happens if a same-thread callback, before the native lifecycle call returns, successfully registers a **new** Begin generation (for G or replacement exact game sprite H)? A source-level possibility is not evidence of such a callback in OutRun. An expected native End internal Flush, a failed nested Begin, an original duplicate producer and the two intentional eye draws are separate events.

## EVIDENCE — pinned repository facts, with bounded inferences

1. Original GPU-path evidence: `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:5-42` lists REA-verified original type-0 D3DX and three other SpriteNode physical routes; `0x42D710` still has unresolved outgoing calls, so its inventory does not prove lifecycle callback ordering. No REA or runtime disassembly was rerun for this task.
2. `src/hooks_uiscaling.cpp:3479-3502` `BeginDest`: pre-native `HudBatch.snapshot()`; after native `Begin_hk.stdcall(self,flags)`, only `IsExactSprite(self)` may call `HudBatch.onBeginResult`, guarded by `HudBatch.generation == beforeBegin.generation`. A successful nested **new Begin** increments generation, and the outer Begin therefore does not overwrite it. If the global game sprite has changed, a returned Begin on the **old tracked** pointer takes the explicit invalidation path instead.
3. `src/vr/game/hud_command_batch.hpp:33-97,144-175,242-267`: the ledger snapshot carries `sprite,generation,mutationSerial`; `begin(exactSprite,true)` sets a new owner/active session and increments generation (except saturation at UINT64_MAX). `onBeginResult` retains an active *same exact* pointer on `D3DERR_INVALIDCALL`, otherwise invalidates. `invalidate()` ends the batch, clears owner/queue provenance and then sets `sprite=nullptr`. Neither physical pending GPU commands nor their completion can be inferred from this bookkeeping.
4. **Distinct static mismatch:** `src/hooks_uiscaling.cpp:3583-3613` `LostDeviceDest/ResetDeviceDest` records only the boolean `ownsBatch = OwnsLifecycle(self, HudBatch.sprite, *0x55B218)` **before** invoking native `LostDevice_hk/ResetDevice_hk.stdcall(self)`. `InvalidateForDeviceLifecycle(ownsBatch)` **after** the native call invokes `HudBatch.invalidate()` unconditionally on that saved true boolean. It does **not** snapshot/recheck the generation, callback self against any reentrant new ledger sprite, or subsequent live game sprite. This differs from the explicit Begin and `completeNativeEnd/Flush` generation protection in `src/vr/game/hud_command_batch.hpp:43-97`.
5. `src/hooks_uiscaling.cpp:3266-3286,3404-3419,3615-3634`: `OwnsLifecycle(self, tracked,live)` accepts a callback on an old tracked instance after game-global replacement; `CanFlush` requires candidate==tracked==live before dereferencing vtable. This is **intended** device-loss safety, not a bug by itself. `InstallThread` at `:4127-4179` hooks slots 8..13 of the original game sprite method implementations as one all-or-none set; a replacement object's callbacks are intercepted only if it reaches a hooked implementation.
6. **Concrete conditional state proof, not an observed frame:** at lifecycle entry `HudBatch.sprite=G, active=true, generation=N`, callback `self=G`, so `ownsBatch=true`. While original `ResetDevice(G)` is executing, suppose a same-thread successful hooked `Begin(H)` occurs with live `*0x55B218=H` and native Begin returns success. `BeginDest(H)` can publish `sprite=H, generation=N+1, active=true`. The outer `ResetDeviceDest(G)` then returns and calls `InvalidateForDeviceLifecycle(true)`, clearing **H's new ledger**. The same possibility exists for a newly begun G generation, subject to actual native D3DX constraints. No corresponding reentrancy is established by GitHub source. Normal Reset with *no* new Begin correctly invalidates old G; a blind change to preserve any post-call owner could retain stale data across loss.
7. Negative control for prior requested Begin failure audit: `src/hooks_uiscaling.cpp:3479-3502` and `src/vr/game/hud_command_batch.hpp:158-175` retain an active identical G ledger after `Begin(G)` returns `D3DERR_INVALIDCALL`, **whether or not** the source establishes that a nested Begin really occurred. The HRESULT/active/pointer triple is a *policy proxy* for "native old batch survived," not positive evidence of a specific D3DX failure cause. If Reset/Lost invalidation has run on this thread, active becomes false, so the preservation predicate does not automatically survive that callback. A generic INVALIDCALL (bad flags/state) need not prove device loss; do not classify every preservation as wrong.
8. Downstream separation: `src/vr/d3d9/stereo_renderer_r33.cpp:1645-1755` conservatively chooses original physical GPU draw when exact finite HUD/eye proof fails; `src/vr/d3d9/stereo_renderer_r7.inc:1518-1559` handles left/right per-eye physical execution and restores RT/depth/stencil/viewport/WVP, while `:1680-1744` checks Present success and published frame metadata. `vrhost/src/main_r23.cpp:1438-1513` draws image-array eye layers 0 and 1, and `:3559-3599` runs actual `xrEndFrame`. A ledger cleared by Reset, a Begin HRESULT or a successful Present does **not** prove duplicated final graph, eye pixels, Quest HMD PASS, or a corrected +TIME/GOAL sprite.
