2. **Four original consumer branches must remain separate.** Verified REA source `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md` maps scheduler -> normal queue `0x0042D710` (conditional early `0x004C50A0`) to (a) type-0 `node[3]==0`, no `0x100`: `0x0042A0A0` -> ID3DXSprite::Draw -> possible later physical DIP at texture Flush/End; (b) type-0 + `node[0x11]&0x100`: `0x0042C0F0` -> direct primitive UP; (c) type-1 `node[0x18]&0x40000 == 0`: `0x0042A3A0` -> animated native primitive; (d) type-1 mask/composite with `0x40000`: `0x0042A800` -> independent native drawing, including still-unresolved indirect calls. Original queue has 36 unresolved indirect calls and mask function has 85; **no per-element final D3D9 API or GPU serial was observed during this task**. Do not collapse all four into a single D3DX Draw or one +TIME animation Draw.
3. **Ownership from producer to queued node is guarded, not absolute.** `src/hooks_textures.cpp:1090-1111` tags an appended SpriteNode only after bounded proof of old/current priority root and tail; `src/vr/game/sprite_queue_tail_proof.hpp:9-62` rejects detached, recycled, nonterminal or cyclic tails. `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1820` separates selected node/epoch and specifically forbids a historically crash-prone canonical queue prologue midhook at original RVA `0x2D734`. An exact source/E8 return thus does not prove which physical native draw later consumed a particular node; use live node+epoch and physical draw signature.
4. **Deferred type-0 D3DX control path differs from UP.** For type-0 D3DX, `src/hooks_uiscaling.cpp::VRProjectedD3DXSpriteIsolationR64:3407-3508,3661-3819,3824-3990` snapshots Begin/Draw and waits for a homogeneous proven native Flush/End; direct numeric +TIME and direct proven GOAL B9200 are separated from queued siblings and each node transition. `src/vr/game/hud_command_batch.hpp::Ledger:82-141,184-284` requires identity, successful native Flush and queue-node/epoch homogeneity, and invalidates failed native batches. The original sprite may internally Flush on texture change. These protect *attribution of the D3DX batch*; they cannot be assumed to cover flagged type-0 UP, type-1 native animation or masked composite draws.
5. **Actual native UP enters a different R30 gate.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawPrimitiveUPDestR30:5464-5490` consumes the live physical semantic, tries `R30TryXyzrhwPrimitiveUP:3947-3990`, then falls back through `R30GuardScreenSpace` / R29/native when `E_NOTIMPL`. Indexed UP takes its own `::DrawIndexedPrimitiveUPDestR30:5493-5525` / `R30TryXyzrhwIndexedPrimitiveUP:3992-4060` route with index-window limits. By contrast, `::R62TryFixedFunctionSpriteIndexed:5126-5210` is a non-UP `DrawIndexedPrimitive` fixed-function FVF `0x142` candidate; `::DrawIndexedPrimitiveDestR30:5377-5461` explicitly logs `R62_ONLY finalRoute=UNDETERMINED` on rejection and still permits XYZRHW/other fallback. Therefore a sampled `RESULT_HUD_EYES` R62 entry/rejection is **not an all-branch census** of +TIME animation and masked physical draws. This is a source-path distinction, not proof that the UP path is currently missing or broken in the headset.
6. **Bilateral and host fences are later independent gates.** An admitted UP XYZRHW draw invokes `R30ExecuteXyzrhwStereo:3829-3945`: left GPU draw, right RT/depth/viewport transition, right draw, then RT/depth/viewport restore. Right or restore failure poisons the frame even though the routine returns the left HRESULT and increments a duplication counter. Rejected UP may follow R29/native, so neither an attempted R30 branch nor the returned HRESULT establishes L/R pixel equality. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:693-811` requires verified world stereo + duplicated draw + frame pose and absence of right/incomplete frame faults, stages R13 DirectGPU/Classic SBS where eligible, and publishes complete stereo only after successful native Present. `vrhost/src/main_r23.cpp:3200-3366` then selects a verified frame, stages DirectGPU or Classic source, draws both XR eye projections and may reuse a cached projection; `:3562-3695` distinguishes candidate projection from actual `xrEndFrame` layer submission. Neither scheduler, UP native-HRESULT nor `StereoSbsActive` alone proves current-frame Quest3 +TIME/GOAL glyphs or optical appearance.
