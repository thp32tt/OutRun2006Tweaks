There is **no source-proven base-sky/cloud/light producer→shader/DIP fingerprint** in the material read for this task. A specific base-sky draw is NOT asserted to be queued or to use D3DX, nor to be `RotationOnly`.
2. **Material alpha producer is different from stereo bloom:** `src/hooks_graphics.cpp:918-946,990-1051,1115-1129` describes the stock mono HDR combiner exposure in framebuffer alpha, material-specific alpha/reference and an exposure-seeded game clear. `RestoreSkyGlow::SkyGlowAllowed:930-935` is FALSE when `VREnabled && VRStereo`. `ClearBuffer_dest:1359-1388` then immediately calls the original clear **without** the mono exposure alpha seed; if stock sky glow is allowed it temporarily substitutes game clear alpha and restores the original `BackColor`. `RestoreSkyGlow::apply:1400-1435` still configures the independent original shader/alpha patches; disabling mono clear seed does NOT prove the game eye surfaces all have alpha=1, 0, or any fixed exposure.
3. **Semantic/queue → actual physical draw:** `src/vr/game/render_semantics.hpp:1028-1102` distinguishes `SkyGlow`, `SceneEffect`, `WorldBillboard` from `ScreenHud` and `ScreenOverlay2D`. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:5342-5517` consumes physical Draw*/UP semantics, tries R62 only for its fixed-function sprite DIP fingerprint and routes shader world/other draws through R30/R29/R26 with fallback. Sky shader/c64 identity must be checked at the actual D3D9 Draw, not copied from a prior road or sun Draw; `stereo_renderer_r26.cpp:435-510` requires verified WVP, projection/pose and shader epoch for an exceptional world rebind, while `stereo_renderer_r30_r26_safe.cpp:2290-2345` separately guards C993 identity. A generic `SceneEffect`, texture family or alpha cannot grant sky optical ownership.
4. **Different R26 L/R postprocess mask (confirmed):** `stereo_renderer_r30_r26_safe.cpp:1014-1055` creates a `BrightPs` that samples `c=tex2D(Scene,uv)` and computes `peak=max(c.rgb)`, `bright=saturate((peak-0.58)*2.75)`, `worldMask=max(0.15,saturate((1-c.a)*2))`, `m=bright*worldMask`. Therefore R26 stereo glow's brightness selection **reads both RGB and alpha**, whereas the stock mono extraction treats alpha as HDR exposure relative to a per-stage baseline. For pixels whose RGB is above the threshold, `c.a=1` implies mask floor 0.15, while `c.a=0` implies mask 1; exact output still depends on RGB, sampled alpha, blending, resources and frame state. This is a proven algorithmic difference, not evidence that the user's base sky/clouds rendered incorrectly.
5. **Capture/per-eye submission and restore:** `R30CaptureSkyGlowSceneBeforeHud:1156-1191` copies BackBuffer and RightEyeSurface into separate reduced targets subject to world-stereo/right-eye gates. `R30ApplyStereoSkyGlow:1213-1428` applies an eye-local RGB/alpha bright pass, horizontal/optional vertical blur and additive composite, with RT/depth/viewport and StateBlock restoration; `PresentDestR30:1491-1507` runs before lower Present inside `InternalPassScope`. This is a screen-space effect *after* original world/sky physical Draw, not a sky geometry re-projection. R62 HUD kind-0/other original UI still has independent ownership and cannot be deduced from additive glow.
6. **Postprocess status not admitted by final stereo gate (additional static finding):** `R30ApplyStereoSkyGlow:1407-1428` returns `false` after a failed per-eye postprocess/restore and increments `R30SkyGlowFailures`; its log explicitly says the frame continues. `PresentDestR30:1491-1507` **does not inspect the returned bool**. Hence that return value is not itself an R9 poison/fallback trigger. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-805` still checks world stereo, duplicated draw, pose, right-eye/frame-incomplete and resources before physical D3D9 Present; it does not check `R30SkyGlowFailures`. An error might occur before either composite, after partial eye work, or during restore; this audit has no proof that an actual partial-eye or dirty-state frame occurred. Distinguish optional glow continuity from world-stereo correctness before proposing a policy change.
7. **OpenXR is a separate success boundary:** `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp::CopySharedFrameToSafeEyesR32:253-322` copies an L/R pair to inactive SafeEyes, only swaps on fence/publish success, and preserves old pair on timeout. `vrhost/src/main_r23.cpp:3562-3609` records actual `xrEndFrame` layer/source frame, not just candidate D3D9 draw or D3D9 Present. Neither a `R30SkyGlowFrames` increment nor the failure warning establishes a Quest3/VDXR outcome or nonzero-eye-cant optical correctness.
