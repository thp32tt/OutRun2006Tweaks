## REVIEW_SCOPE — original producer through eventual XR submission, with transport epoch/cache selected as new review boundary

1. **Producer and GPU draw are not XR frames.** Checked-in original REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-43,62-69` maps game loop `0x00417B20`, frame scheduler `0x00449050`, +TIME `0x00498670`, GOAL `0x004979E0`, normal queue consumer `0x0042D710` and conditional priority consumer `0x004C50A0`. Type-0 D3DXSprite::Draw may become a physical GPU DIP only at texture-change Flush/End; type-1 `0x0042A3A0/0x0042A800` uses native DrawPrimitiveUP. This source-checked provenance gives no live +TIME/GOAL draw ID and no runtime frame-stall trace.
2. **R26+HUD eye dispatch and restore boundary.** `cmake.toml:84-90,117-129,212-228` makes R26+HUD the fresh-cache default; independently compiled R84 requires explicit opt-in. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30ExecuteXyzrhwStereo:3829-3945` switches left/right target, viewport and depth/stencil, then restores, with right-eye/restore failure poisoning. `::R62TryFixedFunctionSpriteIndexed:5126-5352` gates result HUD physical DIP by live fixed-function shader/FVF=0x142 and pose/semantic/source evidence; R62 rejection alone is not proof of final eye loss. Thus hypothetical later cached-projection behavior cannot be credited to successful +TIME/GOAL physical draw without one native submission joined to the same pending game-frame ID.
3. **Game-side frame admission/Present.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-822` requires completed world stereo, duplicated eye work, pose/metadata and absence of right/restore failure. It marks a pending transport frame in flight, forwards actual D3D9 Present and only publishes active stereo on a complete successful frame; otherwise it retains conservative mono/fallback. `src/vr/d3d9/stereo_renderer_r13.cpp::PresentDestR13:718-749` retires sprite queue tags *after* lower Present. No +TIME/result semantic alone proves host-visible image.
4. **Direct ring ownership and immutable host hold.** `src/vr/d3d9/stereo_renderer_r13.cpp::ResolveDirectTransportR13:222-385` scans actual slots, refuses overwriting a published slot until a dedicated per-slot host GPU-completion ACK and also requires producer EVENT GetData S_OK. In copy-issue errors it quarantines the ring until ResetEx. `vrhost/src/main_r23.cpp::R23StageDirectHold:550-655` stages left/right D3D11 CopyResource once per strict frame/slot/generation/run/PID/handle/resource key (`vrhost/src/runtime/direct_hold_frame_reuse.hpp:9-41`); an unchanged projection tick is not a fresh game draw nor another pair of host source copies. `vrhost/src/main_r23.cpp:2940-3090` chooses newest complete DirectGPU frame and may ACK older never-sampled frames immediately via `direct_ring_skip_ack.hpp`; ACK of a never-sampled older frame does not mean it was shown.
5. **NEW bounded static timing boundary — main loop can retain stereo while final authority expires.** `vrhost/src/main_r23.cpp:3292-3409` chooses `cachedHold=cachedProjectionValid`, refreshes projection only after new committed source (or first projection), and otherwise resubmits cached released projection in gameplay; an upstream stall does **not** by itself time it out. The `R23VerifiedBundle::Publish` belongs to a successful newly rendered projection, not a repeated XR tick (`main_r23.cpp:3310-3359`). Independently `vrhost/src/runtime/r23_verified_bundle.hpp:16-20,107-139` defines `MaxPresentationAgeMs=1000` and `ReadFresh` requires still-valid run and age. After a sufficiently long producer gap, cachedProjectionValid can remain true at the main loop while `ReadFresh` returns false at the final owner. This is a **static difference in authority/lifetime**, not evidence of real headset stutter.
6. **EndFrame may legitimately replace that incoming cached stereo projection.** `vrhost/src/runtime/r32_direct_submit.hpp::CanFastSubmit:426-473` rejects `BundleNotFresh` before direct fast submission; `::EndFrame:550-613` then routes to R26/R24. `vrhost/src/runtime/r24_black_screen_guard.hpp::EndFrame:577-705` also needs `ReadFresh` (or its bounded display-only grace) to accept exact DirectGPU/Classic stereo; beyond this it chooses fresh classic or `SubmitVisibleFallback`. `::BuildCachedVisibleQuad/SubmitVisibleFallback:416-575` can submit a **view-space QUAD**, older matching-run SafeEye flat/theater recovery, emergency visible quad or no layer depending on independent caches. Therefore `main_r23.cpp` setting `finalLayerKind=projection-cached` does NOT guarantee `xrEndFrame` actually receives that same stereo projection after bundle TTL expiry. The view-space fallback is a safety policy, not automatically a bug. `vrhost/src/runtime/r26_recenter_hardening.hpp::EndFrame:565-618` also intentionally keeps pending recenter when R24 visible fallback occurs.
7. **Final submission and rate accounting.** `vrhost/src/main_r23.cpp:3562-3695` reads the actual intercepted `xrEndFrame` result (`actualFinalLayerKind`, `actualSubmittedFrameId`, `actualSubmittedLayer`) and emits 5s pipeline/pacing telemetry only with matching bundle identity. `pacing.csv` cached XR ticks are not unique new-game FPS; after expiry the bundle ReadFresh join can fail even if `xrEndFrame` submitted a visible fallback layer. Only a same-run frame/pose/slot/ACK ↔ final layer ↔ headset-eye association can distinguish intentional freeze, degraded quad and missing true stereo.
