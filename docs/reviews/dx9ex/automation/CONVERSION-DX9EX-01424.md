## EVIDENCE (pinned GitHub source, static only)

1. **External rails use explicitly screen-space XYZRHW, allocated outside their scope.** `src/overlay/hooks_overlay.cpp:29-37` defines `CUSTOMFVF=(D3DFVF_XYZRHW | D3DFVF_DIFFUSE)`. `CreateLetterboxVertex:40-108` allocates one `D3DPOOL_DEFAULT` eight-vertex buffer with `CreateVertexBuffer(sizeof(vertices),0,CUSTOMFVF,...)`, then Lock/copy/Unlock. `D3DInit:119-139` may construct it; `D3DEndScene:145-157` explicitly **recreates** it after a valid aspect/source/device change, outside the per-draw external semantic scope. Geometry is 8 x 20 bytes (160 source vertex bytes) before driver/shadow allocation overhead; no measured cost follows from this count.
2. **Actual external scope begins only around physical rail draw.** `src/overlay/hooks_overlay.cpp:291-317` (scoped `ScopedExternalOverlaySemantic(ScreenOverlay2D)`) covers precisely two native `DrawPrimitive(D3DPT_TRIANGLESTRIP,0,2)` and `(...,4,2)`, after Create/Lock have already occurred. `:318-363` restores viewport/device state and source input. This scope is not a D3DXSprite `Begin/Draw/Flush/End` and is not a game queue node. R30 must not infer menu bars from original REA sprite families.
3. **Conditional early-RHW shadow gate sees rail creation as non-external.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:790-825` calls the real CreateVertexBuffer and sets `gameOwner=(ExternalOverlaySemanticDepth==0)`. If the R30 creation hook is already attached, creation succeeds, VR is enabled, and the FVF matches XYZRHW, `R30EnsureVertexShadow` registers this **plugin-generated** rail buffer and sets `createdWithXyzrhwFvf` plus `R30EarlyRhwRegistered`. No independent `IsOriginalGameGeometry` or rail-specific provenance appears in this gate. These conditions are source-confirmed; their occurrence and cost for a particular game session are not recorded. `:635-670` may then record Lock bytes while external depth remains zero; `:670-701` finalizes the tracked content at Unlock and invalidates it on failure. `:713-735` removes the registry entry on final Release. If hook installation occurs only after initial D3DInit, the later D3DEndScene resize/recreation remains the discriminating scenario.
4. **Scoped draw preserves pending original one-shot token.** `src/vr/game/render_semantics.hpp:876-881,959-1007` preserves nesting depth and prior `CurrentScope`; `ConsumeForDraw` returns the external scope **without consuming `NextDrawScope`** when depth is nonzero. Tagged original queue nodes win their own exact authority outside that scope; `CurrentQueueExactScope` and `NextDrawScope` are not overwritten by the overlay RAII. Therefore this review does **not** claim observed F11/letterbox token theft or queue corruption. A real nested-game-draw scenario is still unobserved.
5. **Distinct physical draw APIs / stereo routes.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:5528-5554` invokes `ConsumeForDraw` for rail `DrawPrimitive`, attempts `R30TryXyzrhwPrimitiveVB`, otherwise uses guarded R29/native fallback; a successful finite HUD coefficient build, per-eye draws and correct restore must not be assumed from an external scope alone. `:5558-5612` uses a **different** `DrawIndexedPrimitive` path, which tries `R30TryExternalImGuiIndexed` ahead of R62; `:2873-2921,3069-3193` checks fixed-function F11 FVF/projection/scissor and conditionally submits/restores L/R DIPs. `src/overlay/hooks_overlay.cpp:496-514` wraps **only gameplay-active ImGui_ImplDX9_RenderDrawData** in its own external semantic RAII. F11 and letterbox are not merged into one batch or renderer path; any ImGui font/device creation before that scope is not an ImGui draw.
6. **Resource provenance and scene restore matter more than raw allocation count.** `stereo_renderer_r30_r26_safe.cpp:3290-3440` recognizes an exact `ScreenOverlay2D` semantic as non-world for XYZRHW and constructs a bounded head-recentered/FOV eye projection only if necessary pose, projection and source/shadow conditions hold. Early VB shadow **may be required** to read opaque rail vertex data for binocular re-submission. Thus treating registration as unconditional waste or suppressing it globally risks removing the bars in one/both HMD eyes. The actual GPU owner and per-eye result require same-SHA instrumented resource/Draw identity; no FPS or pixel quality benefit is established.
7. **REA and frame-end negative controls.** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-43` maps original SpriteNode type-0 D3DX/UP and type-1 animation/masked branches with unresolved indirect edges. None owns externally constructed `CUSTOMVERTEX` rails or ImGui. `src/vr/d3d9/stereo_renderer_r7.inc:1625-1740` requires world/duplicate/right-eye/pose/resource eligibility, original D3D9 Present and post-Present DirectGPU EVENT completion or SBS fallback. `vrhost/src/main_r23.cpp:1440-1515,3550-3570` performs independent L/R D3D11 projection and `xrEndFrame`. These global frame gates are not a per-rail GPU capture or Quest3 acceptance. GitHub Issue #13 is a regression ledger, not this exact-session trace.
