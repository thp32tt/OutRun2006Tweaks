4. **R23 host copies and exact frame-reuse boundary.** `vrhost/src/main.cpp::PrepareDirectStereoSource:1342-1377` opens shared game L/R textures on `c.device_` and skips the older private snapshot fence for the R23 primary path. `vrhost/src/main_r23.cpp::R23DirectHoldState:448-477` holds two texture/SRV COM owners, pixel descriptors and copied `FrameKey`; `::R23StageDirectHold:548-641` creates hold textures only on missing resources/size/mips/array/format mismatch, then copies both eyes using `c.context_->CopyResource` unless same immutable producer key is reusable. `vrhost/src/runtime/direct_hold_frame_reuse.hpp:9-39` compares frame/slot/transport/run/PID/numerical handles and two source resource pointer values, **not a D3D11 destination device or immediate-context identity**. Thus *if* a new device/context were substituted while descriptors and frame identity stayed unchanged, no independent hold-owner epoch check is present in the reviewed recreate/reuse predicate. This is a conditional static hardening boundary, not evidence that such a transition currently occurs.
5. **Effective host lifecycle is substantially narrower.** In production `vrhost/src/main_r23.cpp:2544-2551` calls `CreateD3D11Device(req)` **once** and binds the resulting device to the XR session; `:2619-2632` builds and initializes one `StereoCompositor(session,d3d.device,d3d.context,...)`. In the inspected main loop `:2690-2752`, READY begins the existing session and STOPPING ends it and invokes `R23RetireSessionDirectGpu`. `::R23RetireSessionDirectGpu:1403-1410` invalidates slot descriptors and calls `R23ReleaseDirectHoldResources`; `::R23ReleaseDirectHoldResources:524-540` releases the two texture/SRV pairs and clears their copied-frame key. An XR EXITING/LOSS_PENDING or live-game-PID switch requests host shutdown rather than creating a replacement D3D11 device in that frame loop. `:3724-3749` calls compositor shutdown and destroys session/instance; `R23DirectHoldState::~R23DirectHoldState:463-475` releases any residual COM owners at process-static destruction. **No executable R23 same-process D3D11 device recreation without XR STOPPING was traced in the audited entry path.** This is a bounded source fact, not a theorem about future versions or undocumented runtime intervention.
6. **R32 has stronger future-rebind guards but cannot stand in for R23.** `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp::R32SyncDirectDeviceOwner:91-107` explicitly rebinds SafeEye/shared-slot caches on `Device+Context`; `::R32EnsureInactiveEyes:211-250` compares a device owner. `vrhost/src/runtime/r32_direct_submit.hpp::SyncAckDeviceOwner:151-172;::EndFrame:552-612` similarly retires EVENT/ACK caches after a new device/context and may use a verified asynchronous submit. These R32 protections do **not** automatically release a distinct `R23DirectHold` pair. Conversely, current R23's single-device lifecycle makes this difference unproven as a present runtime defect.
7. **Projection and final image ownership remain distinct.** `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` samples host-owned hold L/R, renders independent image array slices, cleans stale bindings on eye-1 failure and fills the current stereo pose/FOV; `:3562-3595` calls `xrEndFrame` and joins the actual final submission. No image capture, device-rebind injection, resource-owner query, headset optical test, frame pacing sample or measured time was performed.
