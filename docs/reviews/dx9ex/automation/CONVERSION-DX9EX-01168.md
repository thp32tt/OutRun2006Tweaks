4. **Left/right and state restore contract.** `R62TryFixedFunctionSpriteIndexed:5260-5337` calls `R30ExecuteXyzrhwStereo:3820-3934`, temporarily applies each-eye projection, then separately attempts stock projection restoration. The shared helper calls original left Draw first. After left success, it switches right RT/depth/viewport, calls right Draw if those operations succeed, and attempts `RestoreRightPassState` for original RT/depth/viewport. **Confirmed source asymmetry:** it increments `DuplicatedDraws` and `R30SafeTwoEyeDraws` after the right-eye attempt, *before* testing `rightHr` or `restoreOk`, and returns `leftHr` even when the right-eye draw/state or right-eye restore failed (`3850-3934`). On right failure it marks `FrameRightDrawFailed`, records R9 failure and arms fail-closed incomplete status; on restore failure it records restore failure and arms incomplete status. `R30ArmSafeFallback:67-73` sets `FrameStereoIncomplete=true` and can request mono shadow. Successful per-draw HRESULT or incremented two-eye attempt counter therefore **does not prove a fully successful binocular physical draw**.
5. **Exact result and other negative cases.** The R62 exact-result wrapper additionally returns `E_FAIL` if projection restore itself fails despite an otherwise-successful helper HRESULT (`R62TryFixedFunctionSpriteIndexed:5280-5337`); it **does not** change the helper's general `return leftHr` convention for right-eye failure. The F11-only `R30TryExternalImGuiIndexed:2940-3060` has a separately scoped projection/scissor restore and similar left-result/fail-closed right handling; F11 is **not** an original +TIME HUD Draw. Left-eye failure returns the failing HRESULT immediately. `E_NOTIMPL` before owning a draw permits R29 fallback; a handled draw whose right eye subsequently fails is not evidence that the dispatcher replays it through R29.
6. **Frame-level R9 decision.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-822` requires `FrameHadWorldStereo && FrameHadDuplicatedDraw && !FrameRightDrawFailed && !FrameStereoIncomplete` plus seeded stereo, valid pose metadata and resources before stereo composition/direct publication. An incomplete frame can attempt `R9RestoreMonoBeforePresent:383-399` *only if* mono backup was seeded without a gap; this restore can itself fail. Following the original Present, `StereoSbsActive` is published only if composed stereo, successful physical Present and not incomplete. Otherwise it publishes mono/disabled fallback state and clears per-frame eligibility after decision. Thus the confirmed static mismatch between per-Draw HRESULT and binocular completion has a **separate fail-closed frame gate**, and is not proof of leaked bad right-eye pixels into a delivered stereo frame.
7. **Transport and real XR boundary.** `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:267-319` copies both shared eyes to inactive resources, waits on the copy fence and swaps the safe pair before setting `SafeFrameId`. Fence timeout preserves the prior safe pair. `vrhost/src/main_r23.cpp:3562-3610` observes final `xrEndFrame` submission identity. Neither a R62 `hits` log, the returned original DIP HRESULT, incremented `R30SafeTwoEyeDraws`, `Present` success alone nor host SafeFrameId proves that this exact +TIME/result/F11/source-matched draw rendered and was submitted correctly for both eyes.
