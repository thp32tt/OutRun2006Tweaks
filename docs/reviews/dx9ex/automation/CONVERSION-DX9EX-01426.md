## EVIDENCE (pinned GitHub source; verified facts and unverified runtime assumptions separated)

1. **F11 density decision occurs at EndScene.** `src/overlay/hooks_overlay.cpp:365-375,378-490`: the first visible F11 edge is selected before ImGui frame setup; VR gameplay can derive a density from a valid published L/R eye extent pair and source aspect, apply stepped hysteresis, and clamp the gameplay F11 multiplier to `[1.0,1.25]` (`:466-480`). If `Overlay::VrFontMultiplier` changes it sets `Overlay::FontsDirty=true`; an invalid extent while an F11 action is live can retain the prior multiplier, whereas closing/desktop resets toward 1x. A different computed or unchanged multiplier is a valid counterexample to any claimed forced rebuild.
2. **Full atlas regeneration precedes that frame's native ImGui draw, but is not itself an external stereo DIP.** `src/overlay/hooks_overlay.cpp:481-509`: on dirty, `Overlay::rebuild_fonts()` then `ImGui_ImplDX9_InvalidateDeviceObjects()`, then `ImGui_ImplDX9_NewFrame()`, `ImGui::Render()`, and eventually `ImGui_ImplDX9_RenderDrawData()`. `src/overlay/overlay.cpp:375-461` shows `rebuild_fonts` first clears `FontsDirty`, computes a 13px * GlobalFontScale * VrFontMultiplier font size, clears `io.Fonts`, reconstructs the atlas from cached system TTF bytes (fallback available), and may update ImGui 1.92 style FontSizeBase. This is renderer-thread atlas/texture lifecycle work; a measured upload/allocation stall is **not** established by source inspection.
3. **Temporary device-object recreation is a separate, earlier owner.** `src/overlay/hooks_overlay.cpp:512-534,548-573`: `D3DTemporariesRelease` invalidates DX9 ImGui device objects when `overlayInited`; `D3DTemporariesCreate` eagerly calls `ImGui_ImplDX9_CreateDeviceObjects()` when `overlayInited`, independently of `FontsDirty`, visibility, `vrGameplay`, or the eventual eye-extent decision at `D3DEndScene`. The original game midhooks are declared at offsets `0x17970` and `0x17A20`. **Conditional double-lifecycle window:** if those callbacks run before a first subsequent EndScene that changes font density, the freshly requested backend device objects can immediately be invalidated/rebuilt by the dirty-font branch. The exact device callback order, native backend allocation count and cost are not demonstrated in this review.
4. **Font preferences provide a second independent dirty source.** `src/overlay/overlay.cpp:889-911,1041-1052` changes `GlobalFontScale` from the F11 slider and marks `FontsDirty` when the pending edit is finalized. `src/overlay/overlay.cpp:47-64,103-139,309-312` makes the VR shell own full-source rect/layout and applies a local `SetWindowFontScale` fit rather than directly altering game HUD geometry; a changed F11 text layout or glyph sharpness is not sufficient to infer a game-SpriteNode regression.
5. **External draw scope begins after font resource decisions.** `src/overlay/hooks_overlay.cpp:493-509` wraps only gameplay-active `ImGui_ImplDX9_RenderDrawData` in `ScopedExternalOverlaySemantic(ScreenOverlay2D)`. `src/vr/game/render_semantics.hpp:959-1027` gives that external scope precedence and does not consume an original-game `NextDrawScope`. Neither `rebuild_fonts`, `InvalidateDeviceObjects`, `NewFrame` nor `CreateDeviceObjects` is enclosed by that specific external semantic RAII; no evidence shows their texture uploads are falsely processed as physical F11 DIP or that a game queue token is stolen. Scope ownership for a texture API must not be inferred from a later draw scope.
6. **Physical F11 DIP is exclusive and gated.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:5558-5625` consumes a draw semantic at the physical indexed-DIP hook, attempts `R30TryExternalImGuiIndexed` ahead of original R62 fixed-function sprite/R29 fallback. `:2873-2935` requires exact external ScreenOverlay2D, current device/stereo evidence, null VS, XYZ + DIFFUSE + TEX1 FVF, suitable orthographic projection, disabled Z and scissor/viewport. `:3069-3193` sets first-eye projection/scissor, draws L, switches RT/depth/viewport and draws R, restores projection/scissor/RT/depth and marks failures for fallback. Successful per-eye ImGui glyph placement and native backend resource creation **cannot** be inferred from an atlas dirty transition alone.
7. **Original queue and Present/XR are distinct.** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-43` records original `0x42D710` type-0 D3DX/direct UP and type-1 animation/masked physical branches, including unresolved indirect calls; those do not own external ImGui atlas generation. `src/vr/d3d9/stereo_renderer_r33.cpp:2133-2167,2240-2303` guards Reset/lost-device and retires queue-node semantic tags at Present; the tag fence is not an ImGui font GPU-object fence. `src/vr/d3d9/stereo_renderer_r7.inc:1625-1744` requires complete world-stereo/pose/eye/restore state and post-Present DirectGPU event readiness (or SBS/hold), not F11 font density correctness. `vrhost/src/main_r23.cpp:1440-1484,3550-3570` separately renders L/R D3D11 projection and calls `xrEndFrame`. These establish routing but no exact-SHA headset PASS.
8. **History and Issue are context, not this execution.** `docs/automation/reviews/DX9EX_R26_QUEST3_FIELD_3RUN_SUN_HUD_F11_20261021.md` describes previous 3440x1440/2496x2688 Quest 3 captures with an oversized F11 UI and an implemented 1.25x multiplier cap, explicitly pending optical verification; those are different runtime identities, not proof of a reset-font double upload now. - **Fact:** the temp resource create callback requests ImGui DX9 device objects without querying `FontsDirty` or current VR F11 density; later EndScene has independent authority to clear the ImGui font atlas and invalidate those objects on a changed density. The static callback order *permits* a short-lived font-object generation if a changed density follows eager create. This is not evidence that two successful GPU texture allocations, a frame stall, or an F11 glyph defect happened in any session.
- **Falsification:** (a) on a matching game-binary/source-SHA trace, no temp Create callback precedes an EndScene with dirty density; (b) the font multiplier remains constant across the observed interval, and no preference-driven dirty is pending; (c) backend instrumentation proves no font GPU object is created by the eager call, or any requested object survives without regeneration; (d) measured p95/p99 draw/copy/wait cost remains invariant with a matched reset/transition control. The existence of a `FontsDirty` branch alone cannot prove any performance regression.
- **Confounders:** window/source resize, Reset/device-loss, missing/partial XR eye extent, native game/VR mode transition, D3D9Ex `ResetEx` versus classic Reset, OS TTF cache, ImGui version, F11 slider edits, and letterbox resource recreation may change the timeline independently.
