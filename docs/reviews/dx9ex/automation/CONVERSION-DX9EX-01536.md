## NEW_FINDING — sampled R30 PHYSICAL EYES is not necessarily two executed Draws

NEW_FINDING=STATIC_VERIFIED_R30_RIGHT_PRE_DRAW_FAILURE_CAN_EMIT_PHYSICAL_EYES_RECEIPT; R30_EYES_LOG_IS_POST_RIGHT_TRANSACTION_BUT_NOT_GUARANTEED_RIGHT_DRAW_EXECUTED.

Source-grounded distinct branch:

1. src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30TryScreenSpaceFovDraw:5683-5702 executes LEFT actualDraw, and on FAILED(leftHr) returns before the sampled EYES receipt. Therefore an EYES row (if sampled and scope-admitted) implies the LEFT actualDraw returned SUCCEEDED; it does NOT prove which original flare object produced that primitive.
2. At :5704-5738, RIGHT first calls SetRenderTargetHook, SetDepthStencilSurfaceHook, SetViewport and SetWvpOneRegisterAtATime conditionally. The **only** RIGHT actualDraw call at :5734-5738 is inside if (SUCCEEDED(rightHr)). If RIGHT RT/depth/viewport/WVP setup fails, rightHr is failed and **RIGHT actualDraw has NOT run**. RestoreRightPassState is nevertheless attempted at :5739-5741.
3. At :5744-5769, the sampled "VR LENS R30 PHYSICAL EYES" row is emitted for lensPhysicalCandidate after that block **without** a guard asserting that the RIGHT actualDraw was invoked. A RIGHT setup failure can thus still produce the EYES row (if its separate lensEyeSamples counter is in the sampled window). The constant field eyeRT=LEFT_RIGHT_TRANSACTION is a transaction label, NOT live per-eye GetRenderTarget readback. wvpEqual compares the two candidate eyeConstants arrays, NOT proof both arrays reached the GPU after possible RIGHT WVP setup failure.
4. At :5772-5791, pairComplete requires SUCCEEDED(rightHr) && restoreOk, in the already LEFT-success path. The R30SafeTwoEyeDraws and related duplicated-draw counters increment only when that requirement passes. These counters count an expected one LEFT/one RIGHT stereo pair, **not** an extra same-eye lens emitter.
5. At :5854-5865 a failed RIGHT HRESULT poisons the frame and arms fallback for later recovery; ::R30TryScreenSpaceFovDraw returns leftHr (the previously successful LEFT HRESULT). In ::R30GuardScreenSpace:5869-5900 the lower R26/R23 callback is invoked **only on E_NOTIMPL**. A RIGHT setup failure after successful LEFT does not itself prove a second lower draw/replay on that same call; it is an incomplete/poisoned pair path. EYES rightHr=E_FAIL alone cannot distinguish a failed WVP setup from a RIGHT actualDraw returning E_FAIL because the log omits the failing stage.
6. The marker was already present at the current source pin in 01535; 01535 characterized it as a post-attempt eye receipt but did not test the *conditional RIGHT actualDraw invocation*. This is a new **diagnostic negative control**, not a newly introduced game rendering regression. Baseline R26+HUD is an immutable HMD comparison; absent current diagnostic receipt on the old baseline cannot imply that its pixels were correct or different.
