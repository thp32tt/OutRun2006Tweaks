3. **Different lifecycle invalidation stages are statically observable.** `src/hooks_uiscaling.cpp::VRProjectedD3DXSpriteIsolationR64::LostDeviceDest/ResetDeviceDest:3510-3547` determines whether the callback is for tracked/current sprite, **calls the original D3DX lifecycle method first**, then calls `InvalidateForDeviceLifecycle` to revoke the thread-local `HudBatch` even if the game global sprite has changed. That is a callback-local **post-return** provenance invalidation, not an atomic global D3D9 device Reset epoch. Conversely `src/vr/d3d9/stereo_renderer_r22.cpp::ResetDestR22:562-578` invokes `R22FailClosedEligibility` and `R22ResetBaselineTracking` **before** its original D3D9 Reset trampoline, then re-primes shadow state only on successful Reset. `src/vr/d3d9/stereo_renderer.cpp::ResetDestR9:825-840` also drops stereo/mono/depth identity before its Reset callback and only recaptures fresh main depth on success. These guards have different invocation ownership; the audited routines do **not** share a recorded per-device Reset generation with R64's per-sprite native Begin/Draw generation. No actual interleaving is asserted.
4. **StateBlock/viewport/scissor ownership is a separate layer.** `src/vr/d3d9/stereo_renderer_r22.cpp::R22StateBlockApplyDest:143-179` invalidates/re-primes tracked raster and shader state after successful native `StateBlock::Apply`, marking internal raster touched where applicable. `::BeginStateBlockDestR22/EndStateBlockDestR22:244-276` track recording boundaries. `::R22ReplayScope:341-395` snapshots the **game** viewport/scissor/scissor-test at an outer replay entry, then restores a viewport via the unhooked trampoline and reapplies the prior scissor/scissor-test after internal stereo replay if touched; failed capture/restoration fail closed. `::DrawIndexedPrimitiveDestR22/DrawPrimitiveUPDestR22:639-714` use separate outer replay scopes only when installed, on a game device and stereo callbacks eligible. A hypothetical native D3DX StateBlock Apply during Flush is not enough to prove a stale scissor: the intended invalidation and outer restoration are present. Installation timing/R26+HUD actual hook activation require runtime proof, not assumption.
5. **GPU split: D3DX DIP versus native UP.** At `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R62TryFixedFunctionSpriteIndexed:5126-5352`, the exact fixed-function DIP route requires backbuffer triangle-list, live null VS, FVF `0x142`, finite game viewport and original projection; on admission R30 runs left/right eye callbacks, switches right RT/depth/viewport, restores tracked right-pass state, and R62 separately restores original projection (`::R30ExecuteXyzrhwStereo:3829-3945`). R62 rejection returns to original/R29 paths in `::DrawIndexedPrimitiveDestR30:5377-5461`; **rejected R62 does not mean dropped native draw**. Type-1 native `DrawPrimitiveUP` never passes through `HudBatch.completeNativeDraw`; it goes via `::DrawPrimitiveUPDestR30:5464-5490`, optional XYZRHW two-eye `::R30TryXyzrhwPrimitiveUP:3947-3990`, then original/R29 fallback if not admitted. R22 scissor replay surrounds eligible outer physical Draw APIs; it must not be inferred merely from an R64 producer token.
6. **Viewport bases and final host, distinct epochs.** The R22 snapshot above is an original D3D9 game-pixel viewport/scissor, and the R62 preflight similarly reads a live D3D9 viewport; neither is the OpenXR image extent. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-825` admits stereo only with world + duplicated draw, valid pose/transport, no right/restore failure and successful original Present; otherwise mono/fallback is possible. `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` copies independent left/right direct SRVs or SBS UV halves to **XR projection swapchain** width/height per eye; `::xrEndFrame:3562-3599` submits an XR layer. A draw HRESULT, D3DX successful Flush, R22 cache update or XR layer submission alone does not certify a particular +TIME glyph's successful two-eye raster coverage.
