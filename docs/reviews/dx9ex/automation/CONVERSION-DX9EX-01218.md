3. **Indexed-UP declared-window and rebase correctness gates.** `src/vr/d3d9/r30_indexed_up_bounds.hpp:1-35` bounds primitive index count, declared `[minVertexIndex,minVertexIndex+numVertices)` to 262144 vertices and maps indices through `LocalIndex`. In R26 owner `::R30TryXyzrhwIndexedPrimitiveUP:3992-4126`, index data must be nonnull, INDEX16/INDEX32, <=524288 elements and stride >=16. The code validates all raw indices before entering eye GPU submission; `scratch.used.assign(numVertices,0)` then marks only referenced local indices (4033-4052). When `minVertexIndex!=0`, the whole `indexCount*indexBytes` `scratch.indexSource` is resized then **fully overwritten** by one `memcpy` per index at offsets 0,2/4,... (4070-4110); the validated range means rebased INDEX16 values do not wrap. Both L/R pass the same rebased pointer with min=0 (4111-4125). For min=0 the original index pointer is reused, avoiding a copy. This proves a guarded **static byte-initialization/rebase invariant**, not actual live allocation size or original DrawSerial.
4. **New independent CPU-work attribution.** After the sparse mask is built, `R30TransformXyzrhwVertices:3427-3473` allocates/fully overwrites **the entire declared vertex window** into a per-eye scratch buffer via `memcpy(bytes)`, where `bytes=numVertices*stride<=4 MiB`; then `3469-3793` traverses `numVertices`, skipping unreferenced entries only for expensive reprojection/affine writes. `R30TransformXyzrhwStereo:3795-3826` performs L and R, and may repeat **both** passes for coherent affine fallback after an asymmetric full-reproject result. `scratch.used.assign(numVertices,0)` also clears the entire declared window every admissible indexed-UP draw. Therefore a *sparse referenced index set within a large declared window* still incurs 2× full-window copies and full-window scans; potentially more work when fallback runs. This is a **confirmed static cost boundary**, not a measured bottleneck, a visual defect or a license to compact the D3D9 vertex window without verifying primitive topology.
5. **VB/IB shadows are a separate original-memory evidence channel.** The VB/IB hook path has `R30BufferShadow::bytes` as **uninitialized** lazy storage with sorted valid intervals and a 64 MiB registry budget (`stereo_renderer_r30_r26_safe.cpp:325-379`; `r30_shadow_bytes.hpp:1-41`; `r30_shadow_ranges.hpp:1-73`). Observed write `Lock/Unlock` copies bytes and marks exactly written intervals (506-565); a DISCARD write invalidates prior intervals (523-527); Release with refcount zero removes object/budget (678-693,727-743). `R30CopyVertexShadow/R30CopyIndexShadow:567-631` reject unobserved ranges *before reading* and then overwrite `scratch.source/indexSource` completely. `R30TryXyzrhwIndexedPrimitiveVB:4233-4496` validates actual IB/VB descriptors, physical index + baseVertexIndex, and full observed ranges before converting to bilateral UP; original stream/index restores follow both eye calls. `ResetDestR30:1511-1521` disarms subsequent capture, but is **not by itself evidence that all old shadow objects were destroyed**; surviving resources and actual Release/Reset chronology require proof. Do not infer GPU shadow safety solely from Reset returning success.
6. **Physical bilateral/restore → transport/OpenXR is conditional.** `R30ExecuteXyzrhwStereo:3829-3945` submits actual left UP, then right RT/depth/viewport UP and restores right-pass state.
