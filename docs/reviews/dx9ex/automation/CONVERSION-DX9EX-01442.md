1. **Original producer/dispatch.** The archived REA/Ghidra evidence for original executable SHA-256 `68ceb386829066f8455b9d027320af962584321f3e2e8a79c72841495a6134c3` records +TIME's six E8 sites, canonical 0x0042D710 queue node walk, and type-0 D3DX 0x0042A0A0 → ID3DXSprite::Draw; type-0 direct-UP 0x0042C0F0, type-1 animation 0x0042A3A0 and mask 0x0042A800 are negative controls for the present *D3DX deferred batch* hypothesis. Original 0x004C50A0 partial queue consumption and unresolved indirect calls remain non-exhaustive. Stage 6C mode-2 at 0x00498AC6 must not be reclassified as +TIME finite ScreenHud.
2. **Queued semantic / epoch.** `SelectSpriteQueueNode` publishes the incoming queue node, consumes the exact tag when valid, advances `SpriteQueueNodeEpoch`, sets its queue producer, and defaults unknown nodes to ScreenOverlay2D. `EffectiveScope` and `ConsumeForDraw` favor the currently selected exact queue scope; they do **not** carry a historical per-triangle owner to the physical D3D9 hook. `CapturePhysicalDrawCommand` snapshots scope, queued flag, queue node and epoch at `DrawDest`.
3. **Proven boundary (normal path).** `VRProjectedD3DXSpriteIsolationR64::BeforeQueueNode` runs before selecting B, and attempts `FlushTracked` on A if a stage/GOAL token or same-producer distinct-node transition requires isolation. It checks live sprite pointer, `matchesGpuOwner` with A's node+epoch, owner policy and homogeneity. When these checks and native Flush succeed, A is physically submitted under A's semantic and ledger reset precedes B; the hypothetical gap does **not** apply.
4. **Conditional gap (different from 01441).** An outgoing native D3DX buffer may remain after boundary protection is *not eligible* or `FlushTracked` fails (mixed/foreign/uncertain provenance or live owner mismatch; the code deliberately fails closed). The queue then selects B and keeps `QueueRenderActive=true`. `DrawDest` performs an eager pre-Draw drain only if `HudBatch.matchesGpuOwner(false,nullptr,0)`, so a still-queued A buffer does not pass this direct-only guard. B's original `ID3DXSprite::Draw` may provoke an implicit earlier-texture submission inside D3DX *before* B's command is registered in the CPU ledger. Whether any particular D3DX runtime executes this physical path, and whether its internal Flush traverses the hooked public `FlushDest`, is **not established** by current repo evidence.
5. **If the internal submission reaches native FlushDest.** `FlushDest` restores deferred exact result ownership only via `matchesGpuOwner(false,nullptr,0)`; queued A rejects that direct-only proof. It calls native Flush under the currently active B queue context. `HudBatch::completeNativeFlush` can then reset a successful unchanged ledger and stamp `lastSuccessfulFlushMutationSerial`; the returning B `DrawDest` may re-admit B as the first post-Flush command via `completeNativeDraw`'s clean-internal-Flush exception. This protects the new CPU command ledger against ordinary same-generation reentry; it does not itself prove the *already submitted* physical triangles were tagged with their outgoing A node. A reentrant Begin, failed native Flush, source mismatch, or changed mutation serial revokes this exception. If D3DX bypasses hooked FlushDest, this exact mutation-serial path is not asserted.
6. **Physical GPU routing and optical consequence — hypothesis only.** If pending A triangles actually submit under B's current exact scope via D3D9 DIP/Draw*, R30's outer `ConsumeForDraw` and `R30BeforeScreenDrawForSkyGlow` can observe B rather than A. B ScreenHud/ScreenOverlay2D may authorize pre-HUD SkyGlow stamping on an A spatial draw; B WorldBillboard/ProjectedWorldMarker2D may fail to stamp an A genuine screen draw. The R62 fixed-function sprite branch independently requires valid stereo/BackBuffer, triangle-list DIP, HUD/projected semantic, live VS=null and FVF=0x142. It may accept or decline; R30/R29/original fallback remains available. Therefore neither a wrong eye placement nor a real bloom defect follows merely from the queue scope mismatch.
7. **L/R and restore/publish.** R30-owned Draw uses left/right device surface/depth/viewport swaps and restore; SkyGlow uses independent pre-HUD captured L/R reduced textures and optional composite. R7 Present gates stereo world/duplicate/right failure/pose/resources and decides direct transport, SBS or hold. R23 host consumes per-eye SRV/UV, stereo pose/FOV and XR projection rectangles. These later stages do not reconstruct an outgoing per-D3DX-triangle queue epoch. Their success or HMD pixel identity on SOURCE_HEAD was not observed.
