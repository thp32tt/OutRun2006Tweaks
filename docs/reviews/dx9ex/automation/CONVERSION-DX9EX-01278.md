## REVIEW_SCOPE

Follow 01277's next-review proposal **without repeating its stale full-clear/bootstrap generation finding**. Producer identity/queue tag is not GPU stencil-state provenance; no new REA, disassembly, binary patch or live sprite draw trace was made.
2. **Occlusion-query producer and actual device state.** `src/vr/d3d9/stereo_renderer_r7.inc::QueryIssueDest:1616` invokes the native D3D9 Issue first, then adjusts `ActiveOcclusionQueries` only on successful `D3DQUERYTYPE_OCCLUSION` Begin/End on the game device. `::CreateQueryDest:1617` installs Issue tracking or marks tracking unavailable. The *tracking-unavailable* route is a different fail-closed case and must not be confused with a successfully tracked, currently active query.
3. **Physical draw routing is split.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30SafeStereoBase:75-93` rejects an active query, so its XYZRHW/screen-space admission and `::R62TryFixedFunctionSpriteIndexed:5126-5149` do not establish a right-eye copy while active. `::DrawPrimitiveDestR30:5349-5375`, `::DrawIndexedPrimitiveDestR30:5377-5462`, and UP hooks `:5464-5529` distinguish physical API from semantic queue. `src/vr/d3d9/stereo_renderer_r29.cpp::R29StableStereoBase:426-453` similarly rejects active query and `::R29GuardStableDraw:536-560` routes rejected stable draws into legacy R13/R9 handling. A particular draw's complete fallback call stack still needs runtime capture.
4. **R9 mono-shadow and depth-history are different from right sync.** `src/vr/d3d9/stereo_renderer.cpp::R9ReplayMonoDraw:338-362` returns success without replaying a query-active draw onto mono shadow (`R9OcclusionBackupSkips` increases). `::R9ExecuteDraw:567-649` nevertheless increments `R9MainDepthContentSerial` whenever the original left/main draw *may* write depth or stencil, before its lower legacy physical call; it does not update `RightDepthSynchronized` or `RightStencilSynchronized` in that block. The serial is combined depth/stencil telemetry, not proof a pixel actually changed.
5. **NEW static bypass, distinct from 01277.** In `src/vr/d3d9/stereo_renderer_r7.inc::ExecuteStereoDraw:1542-1549`, `occlusionActive` is true for an active or untracked query. When `PrepareDuplicatedDraw` fails, the only normal pre-draw synchronization invalidation is conditional on `!occlusionActive`; then the native `drawCall()` executes once. `::PrepareDuplicatedDraw:1521` rejects an active query *without* the tracking-unavailable poison; the comment explicitly describes single-eye query execution without invalidating the stereo Present. In contrast, `::ExecuteStereoDraw:1550-1554` invalidates after viewport/left/right failure hazards, and `::InvalidateRightDepthStencilIfLeftMayWrite:1129-1134` conservatively clears flags on potential writes. Thus a successfully tracked query-active, main-target, write-capable, native draw is **not routed through that available right-sync invalidation** by this branch. This is a source-level control-flow observation, not a reproduced stencil mismatch.
6. **Same-frame return to two-eye work.** After successful query END decrements the count at `::QueryIssueDest:1616`, `src/vr/d3d9/stereo_renderer_r29.cpp::R29StableStereoBase:426-453` can again admit ordinary work if other health gates pass. `::R29GuardStableDraw:541-560` only tries its right-depth/stencil bootstrap when a sync flag is *already false*, and `src/vr/d3d9/stereo_renderer_r33.cpp::R33PrepareRightDepthStereo:491-515` similarly reads sync booleans and attempts bootstrap only if needed. If a query-only left write left both bits true, these guards cannot detect buffer-content divergence from the booleans alone. R33 cached write flags `:460-489` and left/right failure invalidation `:703-726,799-813` do not retroactively tag an unowned, successfully executed query-only draw; which dispatcher owns a later specific draw remains uncaptured.
7. **L/R, restore and output remain independently gated.** Regular stereo `src/vr/d3d9/stereo_renderer_r7.inc::ExecuteStereoDraw:1552-1554`, R30 XYZRHW `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30ExecuteXyzrhwStereo:3829-3944`, and R33 fast `src/vr/d3d9/stereo_renderer_r33.cpp:685-815` perform physically separate left/right draws and restore with error poisoning; the *occlusion-active* shortcut does not perform a paired right draw for that primitive. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-823` requires verified world stereo/duplicated draw, no failure flags, pose, transport and native Present before advertising active stereo. `vrhost/src/main_r23.cpp:3555-3617` observes real `xrEndFrame` submitted frame/layer; a successful query and a passing Present health gate do not prove equal per-eye stencil contents or fresh HMD pixels.

## NEW_FINDING — verified fact versus conditional risk

- **Verified:** R7's exact `!occlusionActive` condition excludes active queries from the generic `InvalidateRightDepthStencilIfLeftMayWrite` call, while R9 separately skips query-only mono replay and may advance the main depth/stencil-content serial. Existing successful-query-path bookkeeping does not on its own show the right-eye attachment matches a left attachment potentially written by this native draw. This review concerns **the decision not to invalidate on the first query-only draw**, not 01277's later clear replay freshness.
- **HYPOTHESIS_ONLY / minimal conditional sequence:** (A) paired full depth/stencil clear and right synchronized; (B) successful tracked D3D9 occlusion query Begin; (C) main-target primitive executed once with write-enabled stencil/depth state, actually modifying the left attachment; (D) successful End with no intervening paired clear or conservative invalidation; (E) next eligible stencil-testing right-eye draw sees `RightStencilSynchronized=true` and executes on stale right contents; (F) the frame still passes Present and actual fresh OpenXR submission gates. Steps C/D/E/F were **not** observed together, and the default query-only primitive may be depth/stencil-write-disabled or otherwise invisible.
- **REFUTATION:** Query-only draws always disable stencil writes/depth writes or cannot touch the tracked main attachment; the game uses only offscreen query passes; the relevant writes are paired, later fully cleared in both eyes before stencil testing, or poisoned before eligible stereo work; another actual codepath invalidates flags across query transitions; depth/stencil buffers match at the later gate; the host only submits mono/cached content. Any of these defeats a claimed in-game bug.
