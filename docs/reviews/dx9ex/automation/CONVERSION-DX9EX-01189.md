2. **Sphere 4:3 correction is finite-only and source-resolution-relative.** `ScreenEdgeCullFix::destination:1624-1646` first invokes original `CalcBall3D2D`, then *only when enabled* reads `Game::screen_resolution->x/y`. `src/game_addrs.hpp:102,404` maps that pointer to original game EXE RVA `+0x340C8C`. `src/vr/game/stage_edge_cull_projection.hpp::CorrectBallProjection:16-37` rejects non-finite/non-positive width/height or overflow, then independently calculates `x'=(x/(w/h))*(4/3)`, `y'=(y*(w/h))/(4/3)`. Its `valid` check **does not verify source-frame ID, viewport generation, actual active D3D9 viewport or XR eye extent**; this helper has no such parameters. On invalid source it leaves both original sphere components and original return untouched, which is a positive protection against partial edits.
3. **The two resolutions are deliberately different domains.** `src/vr/settings.cpp:49-64` documents `VRUnifiedEyeMenuSource=false`, configurable original-game/menu source and independently allocated XR eye extent; `VRFollowGameResolution=true` and `VRAutoRenderResolution=true` do not alone prove which source was actually selected in an installed binary. `vrhost/tests/stage_edge_cull_smoke.cpp:12-55` statically checks 4:3 identity; 1920x1080, 3440x1440 and 2496x2688 historical correction arithmetic; invalid zero/NaN/INF/overflow rejection; and recovery. It **does not** test a *finite, plausible, but stale or different-epoch* original source compared with actual draw viewport. A configured 3440x1440 source is not a bug merely because the XR eyes use different extents.
4. **PMT wide-FOV test does not consult sphere resolution.** `src/hooks_graphics.cpp::GetWideFov:1717-1755` reads *latched* per-eye OpenXR `eyeFov` plus adjustable 0–15 degree margin and takes symmetric enclosing tangents. `::BeforeVisible:1767-1805` substitutes `min(original._11,1/tanH)` and `min(original._22,1/tanV)` in a writable CPU projection only while the original `render_node_visible_404b00` call executes; `::AfterVisible:1807-1849` restores the projection BEFORE original result use. Default `Settings::VRStageCullingMode=1` and margin 8 degrees are defined at `src/vr/settings.cpp:133-143`. When pose/projection is unusable the mode-1 gate fails open; mode-2 explicitly accepts all nodes. This is distinct from the sphere projection and was already reviewed as a single-path fail-open in #01142; **this run examines cross-predicate source-epoch attribution**, not that old fact.
5. **Semantic/queue and D3DX do not repair a CPU-culling omission.** Only an admitted original stage producer may later enter an indirect DP/DIP draw or sprite queue; no unconditional bridge from sphere/PMT accept to `SpriteNode` is established. `src/vr/game/render_semantics.hpp::ConsumeForDraw:998-1027` consumes a proven queued semantic or safe fallback at a physical draw; `src/vr/game/hud_command_batch.hpp:8-70` retains producer/node/epoch and native D3DX Begin/Draw/Flush/End identity to avoid deferred cross-source misattribution. The separate stage model DrawObject path in #01188 must not be charged as a D3DX sprite draw without proof. A CPU-cull rejection can produce zero physical commands and therefore cannot be corrected by blindly modifying R30/R62 stereo draw count or HUD routing.
6. **R26 real viewport and both eyes are a third trust domain.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30PrepareXyzrhwState:2493-2549` reads the **live** D3D9 viewport and a pose-sequenced stereo frame and rejects null/invalid viewport, real VS and incompatible FVF. `::DrawPrimitiveDestR30/DrawIndexedPrimitiveDestR30/DrawPrimitiveUPDestR30:5349-5491` requires physical eligibility and can fall back via R29/original; `::R30ExecuteXyzrhwStereo:3829-3945` performs left draw, right RT/depth/viewport and draw, then restores and poisons the frame on right/restore error. `Game::screen_resolution` is not cross-validated against that live D3D9 viewport within these sampled functions. This fact alone does NOT imply the game set incorrect dimensions, that the actual draw is XYZRHW, or that the CPU-cull path runs on every world object.
7. **Transport/host does not prove what was culled.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:676-815` demands seeded/corroborated stereo, duplicate draw, valid pose, no incomplete right eye and a successful original Present; it can select DirectGPU shared-eye or SBS fallback with mono restore. `vrhost/src/main_r23.cpp::R23RenderProjection:1440-1513` renders independent OpenXR array-slice eyes using current pose/FOV and source image extents; `::xrEndFrame:3557-3599` is the final submitted-layer boundary.
