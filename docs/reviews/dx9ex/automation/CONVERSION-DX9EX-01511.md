3. R30/R62 handles right RT/depth/viewport/projection and original-state restoration before returning toward R7. Shared R7 `PresentDest` requires `FrameHadWorldStereo && FrameHadDuplicatedDraw && !FrameRightDrawFailed && !FrameStereoIncomplete && valid pose/resources`; successful L/R producer submission is a **precondition**, not evidence that final SBS pixels were correctly composed.
4. If DirectGPU `ResolveDirectTransport` succeeds, R7 bypasses `ComposeSbs` entirely. With no DirectGPU and `VRDirectGpuOnly` disabled (or HMD-less debug enabled), R7 calls `ComposeSbs` and may use Desktop Duplication SBS fallback. Thus this finding has NO direct-transport reachability absent fallback.
5. `ComposeSbs` checks both `StretchRect` copies and `CreateStateBlock(D3DSBT_ALL)`; it fetches RT/depth/viewport, requires valid RT and viewport, then checks switching to `BackBuffer`, null depth and `BeginScene`. Its internal pass scope suppresses normal game draw-hook bookkeeping.
6. **NEW boundary:** once `BeginScene` succeeds, calls to `SetVertexShader(nullptr)`, `SetPixelShader(nullptr)`, `SetFVF(XYZRHW|TEX1)`, eleven render-state setters, stage0/1 texture-state setters and sampler filter/address/sRGB setters are issued as **unchecked return values**. `stateOk` tests only full viewport SetViewport plus black Clear; `DrawTextureHalf` tests its own SetTexture and DrawPrimitiveUP.
7. `success = leftOk && rightOk && SUCCEEDED(EndScene)`; afterward `StateBlock::Apply`, original RT/depth/viewport restores ARE checked and failed restore poisons frame. There is no accumulated `stateSetupOk` covering the earlier setters. Consequently the source-level return predicate does not represent the HRESULT of every state used to produce the SBS halves.
8. Bounded CONDITIONAL fixture (NOT run on device): begin/RT/depth/viewport/Clear succeed, e.g. one `SetSamplerState(D3DSAMP_ADDRESSU,CLAMP)` or `SetRenderState(D3DRS_SRGBWRITEENABLE,FALSE)` returns failure while earlier GPU state persists; both SetTexture+DrawPrimitiveUP calls, EndScene, StateBlock Apply, RT/depth/viewport restores and game Present succeed. The current boolean graph accepts `ComposeSbs=true` because the failed setup setter has no dataflow to `success`. Whether a D3D9/DXVK driver permits that exact HRESULT combination, and whether output is wrong, are unproven.
9. For such a hypothetically accepted frame, `PresentDest` increments `StereoComposeSuccess`, sets `composedStereo=true`, then publishes `StereoSbsActive` and valid pose/frame metadata after successful original Present; neither publication checks compositor-state HRESULTs that were discarded. That metadata does not validate actual L/R decoded color, alpha, sRGB, filtering, or lack of bleed at half-frame boundary. Actual x64 host `xrEndFrame` and Quest3/VDXR pixel result remain untested.
10. Negative controls: all setup calls S_OK -> no finding; SetViewport/Clear fail -> `stateOk=false`, no draws/return false; left/right SetTexture or Draw fail -> false; EndScene fail -> false; StateBlock::Apply/RT/depth/viewport restore fail -> `restoreOk=false`, poisoned; Present fail -> mono failure route. DirectGPU success or direct-only hold -> SBS setup never reached. A state setter failure followed by guaranteed Draw failure would also block the asserted publication sequence.
