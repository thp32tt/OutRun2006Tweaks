A +TIME/GOAL D3DX Begin/Draw is CPU-side submission only; `FlushDest`/`EndDest` temporarily restore exact ownership only for matching homogeneous proven batches. Mixed/foreign/live-queue batches remain fail-closed. Do not add any B9200 post-CALL/+5 interception.
3. On game `CreateTexture(D3DPOOL_MANAGED)` the R13 translation can produce a DEFAULT|DYNAMIC direct-lockable GPU texture. R14 then records `DirectOnly` or, for the non-dynamic path, creates a separate `D3DPOOL_SYSTEMMEM` CPU peer. Its registry key is **the original GPU pointer**, not the separately created CPU peer. `CreateTextureCompatDestR14` exits immediately for non-MANAGED pools, so the nested `device->CreateTexture(..., D3DPOOL_SYSTEMMEM)` does not itself enter R14 tracking. Failed registration releases any temporary CPU peer and unaccepted GPU pointer.
4. Registered R14 entries store `gpu` as identity only, `cpu` as owned CPU shadow when present and `device` with its own AddRef. The destructor raises thread-local `R14InternalReleaseDepth`, releases the CPU peer and device, then lowers depth. Every Release through the shared texture implementation may enter `TextureReleaseDestR14`, but `R14Erase(texture)` is called only when the original Release returns zero **and depth is zero**. A normal CPU peer final Release is either suppressed by depth during entry destruction or, where released on the retirement/failure path outside that guard, is not a registry GPU key. This is a source-level identity argument, not proof about unusual COM aggregation/reentrancy.
5. `R14RetireShadow`, successful/failed `LockRect` retirement and R14/R15 `UnlockRect` can release a detached CPU peer outside destructor depth. The peer is still distinct from the GPU registry key. Conversely, `device->Release()` inside the destructor is **not itself a texture Release**; a hypothetical wrapper/driver reentrant final Release of another **registered GPU** during that call would be suppressed by the non-identity-scoped depth guard, but that causal path is **not demonstrated**. A separate thread's Release has its own depth, and a normal final GPU Release outside the guard erases its map entry.
6. R13/R9/R7 eye routing remains separately gated; prove L/R callbacks, state restores for RT0..N/depth/stencil/viewport/StateBlock, and non-zero eye cant before attributing an optical symptom to this guard.
7. R9 Present requires frame eligibility and actual stereo world/right-eye draw/pose, can choose SBS/direct transport or restore mono fallback, then calls native Present.
