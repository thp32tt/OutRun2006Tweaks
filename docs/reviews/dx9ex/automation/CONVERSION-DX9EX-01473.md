1. Original source-path inventory: `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:7-42,62-68`; `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:5-42`. Original type-0 D3DX `Begin/Draw/End` can defer GPU work; type-1 masked and direct-UP calls are distinct. This archived REA is not a newly run disassembler.
2. Hook is installed on the **method implementation pointers** obtained from the game sprite vtable, `src/hooks_uiscaling.cpp:4127-4179` (`vtable[8..13]` -> one `BeginDest`/`DrawDest`/`FlushDest`/`EndDest`/`LostDeviceDest`/`ResetDeviceDest` hook each; partial install torn down). A second D3DXSprite of matching implementation could enter that same inline detour. Whether one exists and uses it in actual R26+HUD game frames is UNKNOWN.
3. **NEW confirmed static callback mismatch:** `src/hooks_uiscaling.cpp:3504-3543` captures `HudBatch.snapshot()`; native `Flush_hk.stdcall(self)` is run; then `HudBatch.completeNativeFlush(submission, SUCCEEDED(hr))` is called **without any final requirement `self == submission.sprite`**. `restore` eligibility checks `CanFlush(self, HudBatch.sprite, live)`, but that check only gates `ScopedExactProducerSemantic`; it does not gate ledger completion. Thus a foreign callback with unchanged tracked ledger generation/serial can call `onFlushSuccess()` on G's batch even though native `Flush(F)` did not flush G.
4. **The End half is symmetrical:** `src/hooks_uiscaling.cpp:3545-3580` computes identity-gated `restore` for semantic ownership, invokes the real `End(self)`, then calls `HudBatch.completeNativeEnd(submission)` without callback-self identity check. `src/vr/game/hud_command_batch.hpp:43-97,219-266` shows `completeNativeFlush` checks ledger sprite/generation/serial and success, while `completeNativeEnd` checks sprite/generation but not `self` or mutation serial. An intercepted foreign End in the same unaltered generation can end G's ledger; a failed foreign Flush can call `onFlushFailure()` and invalidate it.
5. This is **not** true of every hook: `src/hooks_uiscaling.cpp:3479-3502` checks `IsExactSprite(self)` for Begin; `:3992-4013` calls `completeNativeDraw` only when `self == submission.sprite`; `:3597-3613` uses `OwnsLifecycle(self,tracked,live)` for Lost/Reset; `:3615-3634` uses `CanFlush(candidate,tracked,live)` for explicit `FlushTracked`. `src/hooks_uiscaling.cpp:3266-3286,3404-3419` defines pointer policy and static asserts. The mismatch is limited to the *post-native bookkeeping* of direct FlushDest/EndDest.
6. **Concrete source-level hypothetical state sequence:** G has `active=true, sprite=G, drawCount>0, homogeneous=true, boundaryReady=true`, current `generation=N`, serial `S`. A different sprite F with same detoured method calls `FlushDest(F)`; `restore=false` because `CanFlush(F,G,G)=false`. With no intervening ledger mutation and successful `Flush(F)`, `completeNativeFlush(snapshot(G,N,S),true)` sees unchanged G/N/S and executes `forget()`, clears `boundaryReady`, stamps a successful flush mutation: **the ledger now reports no G Draw despite only F having been flushed**. On `EndDest(F)`, the same-generation ledger can be ended. G's native buffer is not shown deleted or submitted by this code: the missed association affects later exact stereo semantic admission, not proof of a new physical duplicate. If F's method does not share a detoured implementation, this sequence cannot occur.
7. Downstream proof boundary: `src/hooks_uiscaling.cpp:3882-3904,4226-4255` requires ledger owner/node/epoch at outgoing queue end; an emptied ledger will not qualify. `src/vr/d3d9/stereo_renderer_r33.cpp:1690-1755` retains conservative original physical draw when HUD screen proof fails. `src/vr/d3d9/stereo_renderer_r7.inc:1694-1744` gates Present metadata, and `vrhost/src/main_r23.cpp:3562-3599` makes real XR `xrEndFrame` separately. None proves a final-result HMD symptom or runtime frame-level stereo correctness.
