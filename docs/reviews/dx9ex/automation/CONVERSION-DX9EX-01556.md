## NEW_FINDING — an acknowledged native lens Draw is not equivalent to a complete L/R pair

NEW_FINDING=STATIC_COUNTEREXAMPLE: A lens-eligible R30 physical Draw may return successful LEFT HRESULT to its caller while RIGHT Draw or restore has failed; current pair counters are correctly gated by RIGHT success+restore, but the R30 caller return alone and existence of an R30 PHYSICAL EYES event are not stereo-pair proof. This is a **receipt/completion semantics distinction**, not an observed one-eye defect, duplicate original emitter, head-lock cause or regression created after baseline.

1. The source chain is original C993 central projected 0x570002/006/00F/010 or original CABE outer 0x570008 -> `src/hooks_graphics.cpp::DrawObjectAlphaCentre:943-1069` / `DrawObjectAlphaProjected:787-903` -> qualifying inline or deferred opaque native DP/DIP/DPUP/DIPUP -> `R30GuardScreenSpace` -> `R30TryScreenSpaceFovDraw` -> host `R23RenderProjection`. The original 405360 descriptor/4052C0 flush-to-PMT link is **not** available here; conditional R30 analysis applies only to a correctly identified physical flare draw, not every SceneEffect log.
2. Current `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30TryScreenSpaceFovDraw:6251-6279`: after admission, the first `actualDraw()` returns `leftHr`; if FAILED it exits immediately after poison/restore attempt. No matching RIGHT draw or `VR LENS R30 PHYSICAL EYES` can be inferred from that early failure.
3. In the success branch (:6320-6347), RIGHT requires successful target/depth/viewport/WVP setup and then `actualDraw()`; any stage can fail, and `RestoreRightPassState` is evaluated separately. The gated `VR LENS R30 PHYSICAL EYES` event (:6399-6477) is logged **before** `pairComplete` is computed, includes `leftHr/rightHr/restore`, and is sampled (first 32 and powers of two); it is neither a complete per-draw census nor successful colour-write receipt.
4. Only `pairComplete = SUCCEEDED(rightHr) && restoreOk` increments `R30SafeTwoEyeDraws`/`R30ScreenSpaceFovDraws` in the current head (:6494-6510). On failed RIGHT, :6573-6580 marks `FrameRightDrawFailed`, poisons frame and arms safe fallback; on failed restore, :6581-6585 separately arms safe fallback. Nevertheless the routine returns **`leftHr`** at :6586. If LEFT was S_OK, this return is S_OK even when RIGHT failed; this is not a completed pair.
5. `R30GuardScreenSpace:6590-6630` invokes lower R29 only when `R30TryScreenSpaceFovDraw == E_NOTIMPL`. Successful LEFT / failed RIGHT therefore **does not execute a second lower R29 draw for the same call**, although a later safe-fallback path may be armed. Do not misread absence of `VR TRACE LENS LOWER FALLBACK FULL` as evidence of correct RIGHT pixels or host presentation.
6. Protected R26+HUD `stereo_renderer_r30_r26_safe.cpp:4890-4962` already returned `leftHr` and armed fallback on RIGHT failure, so the LEFT-return contract itself is **inherited, not a new regression**. Importantly, that baseline incremented `R30SafeTwoEyeDraws` and `R30ScreenSpaceFovDraws` *before* checking RIGHT failure; current counters instead require `pairComplete`. This is a concrete baseline-vs-focus diagnostic difference. The older counter was not reliable proof of right-eye completion; the new counter is a narrower native-pair status, still not pixel or XR proof.
7. Host `vrhost/src/main_r23.cpp::R23RenderProjection:1838-1924` separately obtains game source and renders L/R to XR array slices 0/1. Its independent `firstEyeOk && secondEyeOk` and image/pose submission do not carry the original C993/CABE native HRESULT, original 4052C0 PMT, or per-flare colour delta. A native R30 pair counter, host eye pair, and physical same-eye flare duplication are three different statements.
8. `VR R69 FLARE FIX` is gated by `pairComplete` but logged once for the projected family, not once per original lens material or HMD frame. A past positive line cannot override a later failed native RIGHT, missing source-to-PMT join, stale eye source, or the user's unreproduced optical report.
