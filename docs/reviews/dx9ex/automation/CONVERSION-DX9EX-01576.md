1. In original *reconstructed* `r4dius/outrun2-decomp@e1e1c592...`, `src/platform/pc_render_queue.cpp::render_object_override_4056d0` lines 288-305 obtains the object colour-record count `n`, records `n` pre-mutation undo entries, and **then calls** `render_object_405360(c,id,1,...)`. The `1` selects the **opaque** queue in `Descriptor::alpha_queue` and `walk_404d10` (lines 28-33,171-179). Thus, when `n=0` but the object has a drawable/visible PMT node and queue capacity, an opaque entry can be enqueued without any corresponding colour-undo entry. This is a **constructible control-flow counterexample**, not evidence that 0x570008's actual resource has `n=0`.
2. The reverse implication also fails: an undo entry may be recorded even when a subsequent object walk is culled, contains no submitted mesh, or reaches a different non-drawing path. `src/platform/pc_render_queue.cpp:288-305` mutates/records colour entries before `render_object_405360`, whose validity, bounds, visibility and queue capacity checks occur subsequently (`:171-179,219-246`). Therefore `patchCount>0` is not proof that an eye draw or the *second* visible halo occurred.
3. `src/hooks_graphics.cpp::TraceLensOpaqueFlush:703-795` presently reads `0x464F14` into `prePatchCount`, hashes the capped 128 undo pairs at `0x4995A0` through `HashOpaquePatchLedger:684-700`, and logs three raw `queueWords` at `0x464EF8/0x464EFC/0x464F00`, before/after the original `4052C0` call. Those three word meanings have **not** been authenticated as queue-entry count/generation/PMT identity in this review. There is no separately typed, verified `opaque.count` read or per-PMT enqueue/drain record in `VR TRACE LENS OPAQUE FLUSH FULL`; its `patchCountBefore/After`, `patchHash` and `flushFlagAfter` must not be silently substituted for queue entry count or actual left/right RGB.
4. `src/platform/pc_render_flush.cpp::render_queue_flush_4052c0:970-980` reconstructs `order(rc.opaque.count)`, calls `405890` with **only `rc.opaque`**, clears `rc.opaque.undo`, resets **`rc.opaque.count` and `matrix_count`**, and switches `immediate_8999b0=1`. `rc.alpha` is **not** cleared here. Consequently the last review's normal D79B barrier is correctly limited to an **opaque descriptor already queued before D79B**, not an indiscriminate assertion that all model/alpha/sprite queues and all possible visual components have been drained. Conversely, it is NOT evidence that original 570008 itself uses the alpha queue: the reconstructed `4056D0 -> 405360(...,1)` is an opaque path.
5. The original sun sequence `src/platform/race_course_passes.cpp::sun_flare_40cbc0:695-715` explicitly sets immediate=0, queues eleven ring children including the **first** 0x570008 (:702-713), invokes 4052C0 (:714), and then invokes the **second** 0x570008 with a distinct scale/alpha coefficient (:715). The first opaque queue is consumed/cleared on the normal reconstructed path before the second. Two intended source 570008 contributions or two left/right draws are **not by themselves** an extra same-eye ghost; texture/alpha/pixel evidence is still missing.
6. New separation: even a **D79B PRE patchCount=0 / POST patchCount=0**, a changed/unchanged undo hash, and `flushFlagAfter=1` cannot establish either that the target first 570008 PMT was absent, or that the target second flare was submitted twice. Use real opaque queue entry count and individual descriptor/PMT generation, or a verified original memory map connecting raw words to these fields, followed by physical eye draw and accepted R19/R24 eye image.
7. Existing R30 `R30CaptureVisualRouteTrace` (`stereo_renderer_r30_r26_safe.cpp:4214-4233`) assigns `family=LENS` for *any* active opaque-flush serial/scope, and `R30TryScreenSpaceFovDraw:6241-6248,6852-6915` posts admitted lens-scope physical result attempts/HRESULT but explicitly prints `opaquePmtIdentity=UNVERIFIED`. The lower `R30GuardScreenSpace:7160-7289` wraps `r29Draw()` and emits lower HRESULT/texture0/RT0, but likewise has no exact original descriptor/PMT or eye RGB delta. R7 `ExecuteStereoDraw:1708+` has independent stereo results, not original PMT material identity. Existing receipts can bracket candidate routing without certifying which of the ~5–6 visual flare lobes is doubled.
8. Nothing in this review re-runs original EXE bytes or captures the user's headset. Reconstructed queue semantics and GitHub pinned mod C++ support a **diagnostic false-inference boundary** only; neither a production code regression, emitter duplication, R19 source-B/pose-A defect, nor HMD visual repair is established.
