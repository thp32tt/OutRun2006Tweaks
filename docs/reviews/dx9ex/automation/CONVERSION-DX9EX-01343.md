REA/source do not provide today's actual Draw HRESULT or screenshot.
3. **Producer-side ring stays owned until host ACK *and* D3D9 EVENT completion.** `src/vr/d3d9/stereo_renderer_r32.cpp::R32ResolveDirectTransport:505-634` scans free slots (instead of blocking solely on modulo preference): a published frame needs per-slot GPU ACK before reuse, then `R30SupportPollDirectTransportSlotProducer` must not return S_FALSE/failed. Copy/fence errors quarantine direct transport; successful staging is not a free-slot acknowledgment. Under backpressure it records blocked-ring counters and falls back rather than overwriting unconsumed eyes.
4. **Host latest-frame-wins does not ACK a sampled source early.** `vrhost/src/main_r23.cpp:2944-3076` chooses the latest eligible DirectGPU frame from Frame.v2 history, with PID/run generation filtering. `vrhost/src/runtime/direct_ring_skip_ack.hpp::CanAcknowledge:15-42` permits an immediate `PublishCompletedFrame` only for strictly older **unsampled** frames with matching transport generation, run generation, PID and monotonic displayed-frame bound. A selected DirectGPU source is not ACKed there.
5. **DirectHold copies are host-owned; exact reuse is narrower than frameId.** `vrhost/src/main_r23.cpp::R23StageDirectHold:550-640` validates live source pair/slot, allocates the host-owned L/R textures, and enqueues `CopyResource` to them. The no-copy retry check `vrhost/src/runtime/direct_hold_frame_reuse.hpp::CanReuse:26-43` matches frameId, slot, transport/run generations, PID, handles **and opened source pointer identities**. Subsequent projection draws sample the host-owned SRVs, not a freed producer ring slot (`main_r23.cpp::R23RenderProjection:1440-1517`). The actual D3D11 queued-work completion is not proven merely by CPU-side `CopyResource`.
6. **Selected-frame GPU ACK is deferred until host consumption EVENT completion.** `vrhost/src/main_r23.cpp:3240-3274` explicitly avoids the legacy immediate global consumed ACK; `vrhost/src/runtime/r32_direct_submit.hpp::ArmConsumptionFence:317-399` inserts a `D3D11_QUERY_EVENT` on the same immediate context after the sampled projection commands. `::PollCompletedAcks:211-311` uses nonflushing `GetData`, retries a failed ACK publication, rejects errors and discards superseded generation/run/PID completion. `::EndFrame:550-612` synchronizes device/context owners before polling and routes fast submission through an exact verified bundle. It does **not** use xrEndFrame return alone as producer-consumption proof.
7. **Cache reuse doesn't imply fresh producer sampling.** `main_r23.cpp:3294-3413` saves only an actually rendered/released projection as R42 cached view, then resubmits that XR projection image on unchanged XR ticks; it does not re-run the shared-eye copy or projection blit. `r32_direct_submit.hpp:349-376` allows an already-armed EVENT for the **identical** submitted frame/generation/run/PID; only different pending frames on the same slot trigger poll/deferred Flush/slot-busy fallback. Thus R42 held XR image pixels and producer ring slot ownership are separate concepts.
8. **Device and session epoch guards exist, with one bounded conditional question.** `vrhost/src/runtime/r32_direct_submit.hpp::SyncAckDeviceOwner:153-174` drops pending queries on D3D11 device OR immediate-context change. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp::R32SyncDirectDeviceOwner:80-106` also resets SafeEye/shared-slot/CopyFence on either change. `main_r23.cpp::R23RetireSessionDirectGpu:1394-1410` releases hold copies on XR STOPPING (`:2718-2748`). However `R23StageDirectHold:567-603` decides whether to reallocate held textures by texture dimensions/format and null references, not an explicit held D3D11 device pointer. Host construction `main_r23.cpp:2626-2630` creates compositor for the run with initial device/context; source review did not demonstrate a reachable **same-process, same-session compositor device rebind** that would make the held copy stale. This is only a **conditional diagnostic gap**, NOT a confirmed defect.
9. **Final submitted frame identity remains independently observable.** `main_r23.cpp:3559-3616` calls actual `xrEndFrame`, captures intercepted final layer/frame/source and only joins a fresh verified bundle to matching frame IDs for pacing. A source-verified ACK invariant is distinct from pixel-perfect two-eye output and p95/p99 GPU latency; no Quest3/VDXR artifact or runtime fault was observed during this task.
10. **Fallback staging also has a different completion fence.** `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp::CopySharedFrameToSafeEyesR32:253-318` copies into inactive SafeEye, waits on its own copy fence, publishes ACK only on success, then swaps active eyes. Timeout preserves old active SafeEye and does not assert the new frame was displayed.
