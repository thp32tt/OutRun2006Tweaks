## REVIEW_SCOPE

Different boundary from #01380's Reset/recovery **lifetime reliability**: check the *intra-draw generation contract* when a queued GOAL percent/result or direct StageExtension +TIME GPU primitive follows D3DX Sprite Begin/Draw/Flush/End or an original UP path, and StateBlock::Apply occurs **between producer/semantic queue selection and the actual physical draw, or between native left and right**. Audit what the R30 exact physical GOAL source stamp protects, what the R22/R31 StateBlock generation protects, and whether either is proof of identical two-eye raster state. Do not assert that such interleaving happened on Quest 3.

## EVIDENCE — pinned source and checked-in REA, not new device observations

1. **Original four physical branches and deferred batch**. `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:5-51` supports scheduler `0x449050 -> 0x42D710`, type-0 D3DX `0x42A0A0` (Draw registration can be physically deferred to Flush/End), flagged type-0 direct UP `0x42C0F0`, type-1 animation UP `0x42A3A0`, masked type-1 UP `0x42A800`. `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:35-76` distinguishes original D3DX virtual Begin/Draw/Flush/End from actual device Draw* and original +TIME/GOAL helpers. Source-backed REA, not fresh x86 bytes/GPU capture.
2. **Semantic producer is not an Apply generation**. `src/vr/game/render_semantics.hpp::ConsumeForDraw:998-1032` preserves exact queue scope over one-shot unrelated game semantics. `::CapturePhysicalDrawCommand:1420-1432` emits scope/producer/node/queue epoch, not StateBlock generations. `::BeginSpriteQueueRender/SelectSpriteQueueNode:1760-1837` pins frame serial cutoff and increments node epoch per selection; `::EndSpriteQueueRender/EndSpriteQueueFrame:1840-1904` retains still-unvisited partial-queue tags until the explicit frame fence. These are deliberately independent of GPU raster-state ownership.
3. **GOAL stamp is exact-source, not raster-state, evidence**. `src/vr/game/goal_progress_physical_source.hpp::Source/IsValid/SameAfterNativeLeft:10-120` records exact producer, queued node/epoch, pose, top-level draw serial, VS identity/epoch, and *original game* WVP provenance only for shader-backed draws; it has no `ApplyGeneration` or `RecordingGeneration` member. `src/vr/d3d9/stereo_renderer_r30.cpp::R30CaptureStagePhysicalSource/R30CaptureGoalPhysicalSource:6030-6130` derives independent +TIME and GOAL source stamps at physical GPU admission and refuses captured foreign original VS c64 for shader-backed results. A fixed-function FVF draw correctly does not borrow the preceding road shader's c64.
4. **Apply event is separate from exact source**. `src/vr/d3d9/stereo_renderer_r22.cpp::R22StateBlockApplyDest:156-183` calls original Apply, invalidates R22 tracked raster/render state and resynchronizes shader identity upon successful game Apply, then notifies `StateBlockEvents` with the returned HRESULT. `src/vr/state/state_block_events.hpp::NotifyApply:48-55` fans out the callback; `src/vr/d3d9/stereo_renderer_r31.cpp::R31OnStateBlockApply/R31MarkStateBlockCachesDirty:545-590` increments ApplyGeneration, dirties eye/world/effect/raster caches and requests lazy resync. This consumer increments on observed Apply notification even when HRESULT fails; generation delta alone is **not proof of successful state replacement**. Alternate/unintercepted Apply coverage is handled by the independent fail-closed reliability gate, as #01380 audited.
5. **Cache snapshots have their *own* generation fence**. `src/vr/state/state_block_tracker.hpp::Reliable/NoteApply/ApplyGeneration:14-100` defines the separate trust and monotonic Apply/Recording generations. `src/vr/d3d9/stereo_renderer_r29.cpp::R29EffectCacheCurrent:125-149` disallows cache reuse during recording, unreliable coverage, generation mismatch or Present/draw epoch mismatch. `::R29SyncEffectState:313-367` takes live alpha/Z/cull/stencil getter samples and compares Apply and Recording generations **before vs after its own six getters**, discarding potentially torn policies. `src/vr/state/state_block_recovery.hpp::FlushPendingResync:42-82` supplies lazy shader/raster resync. These protect the effect-state snapshot, but do not make the GOAL source stamp a post-left proof of all raster state.
6. **Actual physical stereo transaction has explicit source and completion checks, but not an explicit stamp-field equality test of StateBlock Apply generation**. `src/vr/d3d9/stereo_renderer_r30.cpp::R30ExecuteXyzrhwStereo:6158-6469` captures exact GOAL before native left, again after left, and immediately before right after RT/depth/viewport setup. `GoalPhysical::SameAfterNativeLeft` compares the fields listed above; `R30Execute...` separately snapshots tracked RT/depth, uses a null-depth shortcut only if `StateBlockTracker::Reliable()`, restores right pass, and publishes only if both GPU HRESULTs and restore succeed. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R62TryFixedFunctionSpriteIndexed:5171-5380` requires live VS-null/FVF 0x142, applies/restores separate original projection; `::DrawIndexedPrimitiveDestR30:5425-5512` can continue after R62 E_NOTIMPL through XYZRHW/R29 fallback. **No claim** that an unobserved Apply could silently produce bad pixels: internal passes, intercepted caches, actual D3D state and fallback are separate guards.
7. **Present is a transport fence, not source-Apply equivalence proof**. `src/vr/d3d9/stereo_renderer_r7.inc::PresentDest:1625-1745` requires completed frame, real Present and, for DirectGPU, bounded post-Present completion before publication; `vrhost/src/main.cpp:2700-2719` checks frame/pose/transport and can render bounded last-safe OpenXR projection. Successful OpenXR frames by themselves cannot attribute a specific GOAL glyph to an exact StateBlock Apply generation. Issue #6 is background review inbox, not a new runtime log.
