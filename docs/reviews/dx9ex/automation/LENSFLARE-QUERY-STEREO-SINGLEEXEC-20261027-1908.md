## NEW_FINDING — a tracked, write-free 570010 query cannot itself be doubled by the inspected R26/R30/R7 stereo path

1. The reconstructed original `r4dius/outrun2-decomp@e1e1c592b802a6f3f7020a676abd3ba1be479e62/src/platform/race_course_passes.cpp::sun_flare_40cbc0:649-675` records 0x570010, calls `occlusion_411420`, and **then separately** calls visible `draw_40c980(0x570010,1)` and 0x57000F. `occlusion_draw_4114e0:500-513` issues `D3DISSUE_BEGIN` and `D3DISSUE_END` around `pmt_object_draw_4116f0`. `occlusion_411420:517-531` temporarily sets render states 7/14/15/168 = ZENABLE=1, ZWRITEENABLE=0, ALPHATESTENABLE=0, COLORWRITEENABLE=0. It does **not** force stencil off; that is a separate live-state requirement.
2. Current mod `src/vr/d3d9/stereo_renderer_r7.inc::QueryIssueDest:1693` intercepts successful game-device `D3DQUERYTYPE_OCCLUSION` BEGIN/END and updates `ActiveOcclusionQueries`. `CreateQueryDest:1694` arms the Issue hook and marks `OcclusionQueryTrackingUnavailable` if it cannot arm. Therefore `active>0` is a conditional observed query lifetime, **not** something to infer merely from source ID 0x570010.
3. `src/vr/d3d9/stereo_renderer_r26.cpp::R26TrackedOcclusionNeedsSingleExecution:337-352` requires game main target, active tracked query, stereo seeded/wanted, no aux target, no forced mono, tracking available. `R26TrackedOcclusionDrawIsWriteFree:354-385` additionally requires tracked `COLORWRITEENABLE==0`, `ZWRITEENABLE==FALSE`, and either stencil disabled or `STENCILWRITEMASK==0`. If all pass, `R26GuardTrackedOcclusion:388-428` calls `NotifyTopLevelDraw` and **one** `actualDraw()`, bypassing R23/R22/R13/R9 replay; failure poisons, but does not create a second draw. It wraps all four D3D9 DrawPrimitive/DrawIndexedPrimitive and UP variants at :777-843. If any write-free gate fails it delegates to the normal R23 path, **not** a proven one-execution R26 bypass.
4. Independent downstream protection: `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30SafeStereoBase:77-121` rejects `ACTIVE_OCCLUSION_QUERY` and `OCCLUSION_TRACKING_UNAVAILABLE`; `src/vr/d3d9/stereo_renderer_r7.inc::PrepareDuplicatedDraw:1587-1589` rejects tracked active query (or fails closed when tracking unavailable) before per-eye duplicated draw; `::ExecuteStereoDraw:1610-1620` executes the original call once on that rejection. `src/vr/d3d9/stereo_renderer.cpp::R9ReplayMonoDraw:339-367` also skips mono backup replay while active and treats unknown/nonzero colour mask as a poisoned gap. This is source-negative evidence **against** query geometry being automatically replayed once in each eye and inflating its occlusion samples in the normal tracked, write-free path.
5. The protection is **not** new: baseline R26+HUD `0cff83cf...` and current `vr-d3d9ex-focus` have the **same exact blob** for `stereo_renderer_r26.cpp`: `4e486a14c0f180928732419868f5449b6d8759cf`. Baseline `stereo_renderer_r7.inc` also contains `QueryIssueDest` and active-query reject (its line numbers differ). This review cannot call the guard a newly fixed lens regression or assert its success at runtime.
6. The original query is relevant to **later visible alpha**, not directly a colour layer. `sun_flare_40cbc0:631-645` uses the previous sample count when `query_get_data` is pending (return 1), otherwise updates `samples_89f684`; computes `ratio=samples/visibility_73e2ac`, clamps the displayed visibility at 0.22, and updates calibration under the high-ratio branch. `:657-659` 0x570002 alpha is `intensity*visible`; `:682-684` 0x570006 alpha is `intensity*bright*visible`; `:698-715` first CABE 0x570008 uses `intensity*(0.65*bright*visible)` and second uses `intensity*(ring*visible)`. Meanwhile `:672-673` visible 0x570010/00F use `intensity*1.0` at the source-call level (not proof of final visible pixels: z/occlusion/material can still reject them). Thus delayed or unusual sample ratios can change the **relative appearance** of the original sun stack without a second source call, native replay, or host projection layer. This is an independent alpha/timing control; it does not establish observed bad query samples.
7. The conditional failure edge is explicit: `ActiveOcclusionQueries` might not be active if no successful BEGIN, or stencil writes may be enabled, or R26 not installed/eligible, or the original reconstruction may differ from executed EXE. Such cases must be classified by actual query begin/end, stencil, render states, R26 guard decision and native GPU receipts, not by the original source's intent. No Quest3/VDXR/driver validation exists for this HEAD.
