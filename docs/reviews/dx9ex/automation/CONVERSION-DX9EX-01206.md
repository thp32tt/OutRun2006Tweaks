## REVIEW_SCOPE — original producer → semantic/queue → D3DX/native draw → R30/R62 → L/R restore → game Present → host SBS → OpenXR

1. **Original GPU provenance is upstream and distinct.** Checked-in `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-51,62-69` traces original scheduler `0x00449050`, normal queue `0x0042D710`, conditional priority `0x004C50A0`, +TIME `0x00498670`, GOAL `0x004979E0`, type-0 `0x0042A0A0` D3DX Sprite::Draw deferred physical Draw via Flush/End and type-1 `0x0042A3A0/0x0042A800` native DrawPrimitiveUP. Source semantic/queued owner/epoch and a physical GPU DIP/UP are not interchangeable. This task has no new exact-call disassembly or observed GPU draw ID.
2. **Protected R26+HUD left/right and state restore.** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30ExecuteXyzrhwStereo:3829-3945` performs guarded left draw, right RT/depth/viewport setup/draw, `RestoreRightPassState`, poison/fallback on failed right/restore; the separate fixed-function R62 owner `::R62TryFixedFunctionSpriteIndexed:5126-5352` (already scoped in 01202) requires live shader/FVF/viewport/pose/queue proof before a possible indexed sprite two-eye route. It must not be assumed to own every result glyph. `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:693-805` requires world-stereo, duplicated draw, valid pose, no right/restore failure and successful native Present before Frame.v2 `StereoSbsActive` publication, otherwise mono/fallback. `stereo_renderer_r13.cpp::PresentDestR13:718-749` retires R26 semantic tags only after lower Present. **All these producer/eye guards can succeed independently of a later HOST crop epoch.**
3. **Capture rectangle sampled before output acquisition.** In `vrhost/src/main_r23.cpp::R23Capture:1018-1205`, `status.fullGameClientVisible=c.GetGameClientOutputRect(gameRect)` is evaluated before `AcquireNextFrame`, source `GetDesc`/`EnsureSource`, `CopyResource` and `ReleaseFrame`; the local `gameRect` is not published as a capture identity or passed to projection. Capture status keeps that earlier boolean; a same-monitor resize/move between these steps does not itself attach an epoch to the boolean. `vrhost/src/main.cpp::GetGameClientOutputRect:2120-2148` uses mutable `hwnd_` client-to-screen coordinates, `outputDesktop_`, and current `sourceWidth_/Height_`, and rejects partial off-output rectangles.
4. **SBS admission checks frame/pose, not crop provenance.** `main_r23.cpp::R23SelectClassicFrameForCapture:1257-1320` requires `capture.fullGameClientVisible`, fresh Desktop Duplication output QPC, stable completed Frame.v2 history and flags. `::R23FrameUnchanged:1237-1254` checks frame fields including backbuffer dimensions but **not the Desktop Duplication captured client rectangle, HWND position or output-desc epoch**. `::main gameplay:3092-3289` only advances after selected pose history and stable metadata; `R23CommitClassicAfterValidation:1429-1438` then calls `StereoCompositor::CommitStereoSource` with no physical client rectangle parameter.
5. **Image copied as full output; UV separately sampled later.** `main.cpp::CommitStereoSource:1399-1434` copies `source_` to `stereoSource_` (size/format-reallocated as needed), not a cropped immutable client texture. Then `main_r23.cpp::R23RenderProjection:1440-1513` calls `c.GetGameUv(whole)` again **without** `requireFullyVisible=true` for Classic, halves that newly read UV width to form left/right source rects, and draws both D3D11 eye targets with `c.RenderTo`. `main.cpp::GetGameUv:2150-2181` again reads mutable client-to-screen position/output extent, invokes `OutRunVrMenuCapture::ClipClient` and allows a partially visible rectangle by default. `vrhost/src/runtime/menu_capture_snapshot.hpp::ClipClient:9-29` explicitly clips partial rectangles and reports `visible=true, fullyVisible=false` for a nonempty partial case. The non-R23 older `main.cpp::RenderProjection:1438-1453` instead passes `GetGameUv(whole,true)`: **do not confuse that other function with the active R23 call**.
6. **Final pixels and layer remain independent.** `main.cpp::RenderTo:2183-2255` uploads per-eye UV constants and calls `ID3D11DeviceContext::Draw(3,0)` into projection eye array views, then clears bindings; `main_r23.cpp::R23RenderProjection:1480-1513` requires both host blit calls to return true and fills XR per-eye image array indexes, pose/FOV from matched history. After success `main_r23.cpp:3315-3366` publishes the verified bundle and cursor. Actual `xrEndFrame` R32/R24 owner and `main_r23.cpp:3562-3635` final submitted kind/frame may still differ from requested `projection-fresh`. None of these gates proves the copied desktop pixels match the later UV rectangle, nor do they prove headset-visible incorrect pixels.
