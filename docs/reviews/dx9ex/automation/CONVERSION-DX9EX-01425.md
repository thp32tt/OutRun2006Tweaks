## EVIDENCE (pinned source / original REA / historical evidence)

1. **Producer arming exists in source, but its active registration is NOT demonstrated.** `src/hooks_uiscaling.cpp:2620-2625` defines `TimeRecord_AdjustPositionAndHud`, which adjusts a UI X value and calls `GameSemantic::ArmNextDraw(RenderScope::ScreenHud)`. Full-file source inspection finds this function name at its declaration only, with no direct registration/use of that callback elsewhere in the same translation unit. Among inspected renderer and graphics source files, the separate `ArmNextDraw` implementation in `render_semantics.hpp` is not itself proof of an installed callsite. Accordingly **do not assert that this arming path currently executes**; a built-symbol/installed-hook trace or another verified caller would be needed. It is a plausible latent contract, not an observed active TIME RECORD regression.
2. **Thread-local pending token has no frame field.** `src/vr/game/render_semantics.hpp:871-881` declares `thread_local RenderScope NextDrawScope = None`, independent of `SpriteQueueNodeEpoch`, tag serials and `SpriteNodeSemanticFrameExpireCutoff`. `:993-1027` sets the single token via `ArmNextDraw`. `ConsumeForDraw` prioritizes an external overlay (without consuming pending token), the exact centre lens and a tagged exact queue node, then takes and clears `NextDrawScope` on the first eligible draw; it does not check a frame stamp or source token. This establishes a **source-level lifetime difference**, not a measured incorrect scope.
3. **Queue tags have an explicit frame fence, direct one-shot does not.** `render_semantics.hpp:1760-1816` captures a serial cutoff for the first partial/full queue traversal; `:1839-1864` exits the queue without clearing remaining tagged nodes, deliberately allowing another priority pass. `:1871-1905` implements `EndSpriteQueueFrame(deviceReset)` and retires old `SpriteNodeSemanticTags` via serial cutoff (Reset using current serial) while touching no `NextDrawScope`. The function may early-return for active queue depth or zero cutoff; neither branch retires a pending direct token. `src/vr/d3d9/stereo_renderer_r33.cpp:2128-2151,2235-2255,2275-2300` calls the queue-tag fence on Reset, device lost and after the game Present respectively. The comparison/no-R33 fallback in `stereo_renderer_r13.cpp:425-437,705-750` also invokes the tag fence. This is **not evidence that an actual pending direct token survived** any such frame.
4. **Scoped safety is local, not a frame-epoch lease.** `render_semantics.hpp:959-1007` makes external F11 and native letterbox draws preserve a pending original one-shot; `:1437-1490` allows opted-in exact direct producer scope to temporarily isolate and then restore a prior token; `:1508-1538` likewise snapshots/restores it around an unproven direct D3DX Flush/End. None of these is equivalent to frame-ending invalidation. Crucial counterexample: while an original pending token is armed, **a later same-frame eligible physical original draw consumes it normally**, and a tagged queue or external overlay by itself cannot prove a leak.
5. **Physical GPU dispatch has a token consumption opportunity, not automatic binocular proof.** `stereo_renderer_r30_r26_safe.cpp:5527-5554,5555-5641,5643-5699` selects `ConsumeForDraw` at native DP, DIP, DPUP, DIPUP when the game device and non-internal stereo pass are active; an R30 XYZRHW/F11/R62 admitted path may attempt eye submissions, otherwise R29/native fallback is guarded. `stereo_renderer_r33.cpp:247-266` consumes at the upstream raster guard and routes via R33 (including possible single-draw guard fallthrough). A stale token **could alter classification of a later unrelated draw if such a token actually exists**, but no current-source evidence proves the next draw, its FVF/VS/shadow/queue owner, its GPU HRESULT, or a wrong-eye pixel. Never equate a `ScreenHud` label with successful finite-HUD stereo.
6. **Presentation is independent of token provenance.** `stereo_renderer_r7.inc:1625-1744` requires duplicated/world eye evidence, pose, right-eye/restore status and resources, submits the original D3D9 Present and checks DirectGPU EVENT completion only afterwards, otherwise SBS/hold as configured. It resets frame GPU flags and increments PresentEpoch, but does not explicitly reset this `GameSemantic::NextDrawScope`. `src/vr/game/outrun_renderer.cpp:2262-2293` invalidates WVP/cadence/culling on Present/Reset, not this token. `vrhost/src/main_r23.cpp:1440-1510,3550-3570` binds distinct L/R D3D11 projection outputs and calls `xrEndFrame`; no host frame success proves original per-draw semantic attribution.
7. **Original and headset evidence limitations.** `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-43` confirms original `0x42D710` type-0 D3DX/UP and type-1 animation/masked branches, with unresolved indirect calls, not an actual `NextDrawScope` frame leak. `docs/automation/reviews/DX9EX_R26_QUEST3_FIELD_3RUN_SUN_HUD_F11_20261021.md` documents previous +TIME split/head-locked and F11 optics on a **different runtime SHA/session**; it cannot attribute those pixels to this specific lifetime hypothesis. GitHub Issue #6 describes an evidence/review inbox; it is not a current GPU capture. Exact source and original disassembly evidence were read from GitHub; no new disassembly or full game log was generated.

## NEW_FINDING

- **Confirmed:** `EndSpriteQueueFrame` is a node-tag serial retirement mechanism. It never clears or stamps `NextDrawScope`; `ConsumeForDraw` has no per-frame expiration. The sole arming function observed in `hooks_uiscaling.cpp` lacks a proven live registration. These are code facts that may be independently audited.
- **Conditional hypothesis ONLY:** if an actual producer arms a token, no eligible original physical draw consumes it before Present/Reset, and rendering resumes on the same thread, a later draw may use a stale ScreenHud scope. Whether this happens in the current binary and whether it changes any L/R pixel, FPS, or HUD is **UNPROVEN**.
- **Falsification / counterevidence:** (a) search of compiled symbols/callback registrations plus same-SHA log shows no executable `ArmNextDraw` caller; (b) sampled next eligible physical draw consumes the token before the frame boundary; (c) frame transition independently sets it to `None` through a currently uninspected route. A queue cleanup count alone does not prove (a), (b), or (c). An identical-color frame or R7 `StereoSbsActive` alone is also insufficient to prove correctness.
