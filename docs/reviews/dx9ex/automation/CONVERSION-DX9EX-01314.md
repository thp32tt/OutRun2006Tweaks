- FACT: queue-end can skip a tracked Flush when boundaryReady is false, the queue/node epoch/scope is no longer an exact match, no homogeneous pending batch exists or actual Flush fails. After EndSpriteQueueRender clears queue TLS, the ledger intentionally cannot restore a queued batch as *direct* HUD in a subsequent native Flush/End. CPU-side successful Draw, queue-end reached, and native End HRESULT alone **cannot certify two final-eye GPU submissions**.
- CONDITIONAL HYPOTHESIS: If an eligible prior queued D3DX batch physically submits only AFTER the semantic epilogue, the original (node=N,epoch=E) stereo owner may be unavailable and native fallback may execute. **Do not assert this ordering occurs:** original 0x42D710 can perform End/Flush before the epilogue; the proper boundary Flush, when eligible, preserves the outgoing owner. Even a late native fallback can render correctly. No Quest3/headlocked/missing glyph repro has been seen here.
- COUNTEREVIDENCE: tracked exact boundary flush drains old batch with still-live node/epoch; onFlushSuccess clears pending draws, internal texture Flush is handled via mutationSerial. If all physical D3DX calls end before 0x2DCB4 in observed frame, or HMD L/R image is correct, the proposed late-owner defect is refuted.
- FALSIFICATION: exact build trace with original queue partial/full entry/exit and native Begin/Draw/Flush/End order; 0x2D762 node/epoch/producer/serial/cutoff, sprite pointer, ledger generation/mutation/drawCount/homogeneous/boundaryReady, original HRESULT, per-eye physical D3D9 draw/FVF/VS/PS, R30/R62/native selected route, L/R RT/depth/viewport/projection restored, R9 poison/mono fallback and normalized Present/active Frame.v2, host selected source+both image slices and xrEndFrame; compare matched Quest3/VDXR pixels and 72/90Hz p95/p99 before claiming any actual bug or optimization.
