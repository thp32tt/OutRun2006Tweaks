## REVIEW_SCOPE — producer -> semantic -> queue -> GPU -> eyes -> restore -> XR (static)

1. Original +TIME producer 0x00498670, GOAL/result/6th-rank/ESC and menu SpriteNode producers -> scheduler 0x00449050 -> queued consumer 0x0042D710. Archived original REA documents four alternatives: type-0 D3DX 0x0042A0A0 (may Flush on Begin/End), type-0 UP 0x0042C0F0, type-1 quad 0x0042A3A0 and type-1 mask/composite 0x0042A800. The exact native GPU API for the last branch and its mask state are NOT resolved by this task.
2. The game's exact scope/producer, queue node+epoch and D3DX batch ledger in src/hooks_uiscaling.cpp can feed physical original D3D9 DP/DIP/DPUP/DIPUP; the actual R33 route may choose R30/R62 finite two-eye or original-preserved fallback depending on live FVF/VS, render target and semantic proof. A queued logical graph is not automatically one physical Draw or a HUD layer.
3. Under eligible R30/R62 XYZRHW or exact FVF142, the renderer has a pre-LEFT state.viewport used for optical pixel/clip transforms and for later RIGHT SetViewport and restore. Native LEFT draw executes once; R30 captures POST-LEFT tracked render target/depth, installs RIGHT RT/depth/viewport, conditionally checks +TIME/GOAL/projected-rank identities, physically draws RIGHT, restores RT/depth/viewport and (for FVF142) original projection. Failed right draw/restore poisons completion; never replay native LEFT.
4. R7 then handles original game D3D9 Present and valid DirectGPU/SBS Frame.v2 publication, and x64 host R23 consumes the successful stereo path as separate D3D11 eye images to OpenXR/R24 xrEndFrame. MENU theater is independently captured mono and rendered as a LOCAL-fixed projection, so menu-screen size reports cannot by themselves prove this R30 gameplay viewport scenario.

## NEW_FINDING — static state-lifetime mismatch, physical consequence untested

- NEW_FINDING=R30_EYE_PAIR_RESTORES_PRELEFT_VIEWPORT_WITHOUT_POSTLEFT_VIEWPORT_GENERATION_CHECK.
- STATIC_CONFIRMED=R30 snapshots viewport before physical LEFT, samples RT/depth after physical LEFT, yet provides the original PRE-LEFT viewport to RIGHT and restore. The post-LEFT source checks identify queue/pose/WVP/shader/FVF but do not compare the current logical viewport to that saved pre-LEFT value. This is a narrowly observable static lifetime asymmetry.
- CONDITIONAL_SCENARIO=An original game callback / hooked native draw path **synchronously and legally** changes viewport from V0 to V1 during physical LEFT (e.g., an exceptional StateBlock Apply or explicit SetViewport) without violating source stamp checks. RIGHT draws and restores V0 with all HRESULTs successful, even though the game's state immediately following the original LEFT may expect V1. The next original native sprite/particle could be clipped/scaled differently; whether that happens, whether V1 is actually intended to persist, and whether OpenXR receives any bad pixels are ALL unverified. Normal non-reentrant native draw with V0==V1 is a correct negative control.
