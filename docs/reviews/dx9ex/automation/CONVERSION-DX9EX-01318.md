## REVIEW_SCOPE — new, independent of 01317's R84 GPU ring fault

Review the **default R26+HUD R30 CPU-scratch lifetime** during eligible XYZRHW UP, shadowed non-indexed VB and indexed VB/UP draws. Focus on allocation/growth versus full-window copy/transform, fail-closed lease/reentry, conditional reprojection retries and CPU frame cost, then follow semantic/queue -> native GPU API -> R30/R62 L/R -> state restore -> R9 Present/Frame.v2 -> x64 OpenXR. 01317 already inspected R84-only first-eye SetStreamSource/bind failures; do not reuse that finding.

1. **Producer -> semantic -> queue/D3DX/native owner (bounded inference):** The existing original-game REA identifies HUD +TIME/6th/6 SpriteNodes and D3DX deferred batches separately from dense-world/sand *candidate* effect draws. A physical sand DrawPrimitive/VB producer has NOT been established here; no original sand CALL RVA, material identity or D3DX ownership is invented. Queued sprite producer/epoch is selected through original priority rendering, `render_semantics.hpp::CapturePhysicalDrawCommand` records effective semantic and queue node/epoch; `ConsumeForDraw` occurs at R30's UP entrypoints. UP or shadow VB follows the actual original D3D9 draw form, not a semantic claim. An explicit fingerprint must first join native producer/queue (or direct producer), exact `RenderScope`, FVF, VS/PS, texture/alpha/Z, and physical API.
2. **Default R26+HUD scratch scope:** `stereo_renderer_r30_r26_safe.cpp` includes `stereo_renderer_r26.cpp` and defines thread-local `R30ScratchBuffers` with source/indexSource/left/right reusable byte capacities, indexed masks/vectors and a `busy` flag. `R30ScratchLease` grants one active lease per thread; re-entry returns no lease and its caller returns E_NOTIMPL to conservative original/R29 guard. This is an intentional fail-closed prevention of scratch aliasing, not an observed reentrant race. `WriteOnlyByteScratch::resize` retains capacity on non-growth and grows to max(requested, capacity*1.5), destructively (without old-byte copy); callers must overwrite the whole logical window. **Capacity retention avoids repeated allocation, but does not avoid mandatory per-draw data copies.**
3. **Physical draw / copies / eye vertices:** Eligible direct UP -> `R30TryXyzrhwPrimitiveUP` obtains lease, makes complete left and right byte clones with `R30TransformXyzrhwVertices` and supplies separate pointers to `DrawPrimitiveUPHook`. Shadow VB adds `R30CopyVertexShadow` under the shadow entry's mutex: validated CPU shadow -> `scratch.source` memcpy, then separate source -> L and source -> R full-window memcpy, followed by per-eye XYZRHW transform, physical `DrawPrimitiveUP` calls. Thus for an admitted nonindexed shadow VB payload of N bytes, the source visibly performs **at least 3N bytes of CPU copies before driver UP consumption**, in addition to per-vertex math and any driver-side copy. This is an approximate structural byte count, NOT profiler-measured traffic, frame time, memory bandwidth, allocation frequency or a claim the game issued sand VB draws.
4. **Indexed variants / bilateral retry:** Indexed UP initializes a per-vertex `used` mask, visits all indices to mark referenced vertices and rebases nonzero first-index windows once; indexed VB copies validated IB and VB CPU shadow bytes, builds physical index remapping, zeroes `used` across the declared physical vertex window and builds two full vertex-window eye buffers before `DrawIndexedPrimitiveUP`. `R30TransformXyzrhwVertices` copies the **complete** window even when `usedMask` selects only sparse vertices, preserving unreferenced attributes. If a full world reprojection is rejected, it recopies the original bytes for an affine fallback; a left/right full-reprojection-policy disagreement can re-run both eyes with `allowFullReprojection=false`. This is source-confirmed **conditional extra CPU copy/compute**; neither its frequency nor benefit of changing it has been observed.
5. **Both-eye GPU and restore:** `R30ExecuteXyzrhwStereo` calls the original UP hook for left, switches RT/depth/viewport for right, invokes right UP and restores; its failed right/restore paths poison/incomplete the stereo frame. Shadow VB restores original stream 0 after the two-eye UP path; indexed VB also restores IB. R30/R62 route ownership, including native FixedFn and D3DX Flush/End, must still be observed at the actual terminal API per draw; a producer/queue match or R30 scratch hit alone never proves R62 or L/R pixels. A mismatch or no-lease eligibility follows R30 guard/original owner rather than claiming a safe stereo draw.
6. **Present/OpenXR and pacing separation:** `stereo_renderer.cpp::PresentDestR9` gates frame activation on verified world/duplicated/pose and no failed/incomplete eye, otherwise restores mono and publishes conservative Frame.v2 status through Present. `main_r23.cpp` chooses projection/layer and measures `xrEndFrame` independently. Increasing dense-scene CPU time cannot be attributed to scratch clones, a GPU Draw, Present, copy, or XR wait without same-SHA timestamps/counters across these independent boundaries. A successful Present or xrEndFrame call is not binocular headset proof.
