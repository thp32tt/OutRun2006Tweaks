## EVIDENCE — pinned code and static producer-to-physical-eye simulation

1. **Original reflection producer is a count hook, not a proven per-face GPU receipt.** `src/hooks_graphics.cpp:1545-1586` patches resolution arguments used in Envmap_Init and D3D_CreateTemporaries. `:1588-1667` describes original Envmap_RenderToCubeMap, a 6-face cubemap, and injects a midhook at EXE RVA `0x1447E` to replace the *face count* in EAX. The hook does not itself sample a reflection render-target pixel or tag a physical D3D9 draw. `src/vr/game/render_semantics.hpp:14-32` defines `ReflectionCube`, but the enum alone cannot prove that an EXE face pass carries an exact producer, sprite queue node, shader or semantic at the eventual native draw. The archived original routing `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:7-29,84-93` maps scene scheduler and D3DX type-0 deferred Begin/Draw/Flush/End versus native UP; it expressly does not classify every indirect water/reflection caller. **No new original EXE/Ghidra per-face trace is presented.**
2. **The normalization knob and frame budget are source-visible.** `src/hooks_graphics.cpp:71-75` defaults `ReflectionResolution=1024` (original documented 128) and `ReflectionUpdateRate=0.5`. `src/vr/settings.cpp:142-143` defaults `NormalizeReflectionRate=true`. `src/hooks_graphics.cpp:1609-1647` samples QPC *between face-count hook invocations*, applies `AdaptiveFrameCadence::Observe`, calculates `frameScale60`, then invokes `ReflectionFrameBudget::Advance`. This is observed **game hook cadence**, not an actual predicted XR display interval, GPU timestamp, frame-ready acknowledgment or compositor wait duration.
3. **Confirmed late-frame residual workload, not proven slowdown.** `src/vr/game/reflection_frame_budget.hpp:17-117` learns plausible healthy 60/72/80/90/120 Hz intervals, marks over-20%-plus-0.5-ms cadence misses after four samples (also the original 18-ms limit), and allows a stable nominal slower mode to re-lock after 24 candidate observations. `:127-162` uses `scaled = lateFrame ? 0.5 : clamp(elapsed60,0,1)`, `requested=previous+6*rate*scaled`, a late face cap of **2** (healthy cap **3**), and nonnegative retained debt limited to 1 when normalized. At the *default* rate 0.5 and a learned 120-Hz cadence, a healthy ~8.33-ms interval also has scaled ~0.5, so both a healthy and a flagged late frame add **1.5 requested faces** before integer truncation and carry. Thus the late flag does **not** automatically reduce face work below the healthy 120-Hz default cadence and never means `faces=0`. A ~12-ms late game interval may still produce 1–2 reflection faces. This is a mathematical property of the present source, not proof of an actual game/driver bottleneck or of a bug.
4. **Offscreen and final-eye work must be distinguished.** `src/vr/d3d9/stereo_renderer_r7.inc:390-399,1521-1559` distinguishes tracked game backbuffer from offscreen RT; `ExecuteStereoDraw` explicitly forwards a verified offscreen world Draw as one original execution, while an eligible backbuffer Draw runs separate native L/R with eye RT/depth, viewport, WVP and state restore. `src/vr/d3d9/stereo_renderer_r29.cpp:427-452` requires `TargetIsBackBuffer`, seeded resources, non-aux target, synchronized depth and no active occlusion query. An offscreen cubemap face is **not** automatically duplicated per eye merely because it describes world content. The actual EXE face RT and sampling consumer must still be identified; suppressing a mono face Draw based solely on the enum would be unsafe.
5. **Two-sided transparency is not identical to the cubemap schedule.** `src/vr/d3d9/vr_pass_policy.hpp:153-175` conservatively sends depth-test-disabled effects to zero disparity; `src/vr/d3d9/stereo_renderer_r29.cpp:51-110,125-248` snapshots blend, cull, depth and stencil states under StateBlock generation fences and checks front/back stencil write operations if enabled. `src/vr/d3d9/stereo_renderer_r33.cpp:292-310,630-668` separately evaluates depth/stencil writes and rejects fragile alpha/depth configurations from the cached-WVP fast path, leaving the R29/R30 conservative route. `D3DCULL_NONE`, alpha blend and zwrite flags are *effect predicates*, not proof of a water surface/reflector, not proof of two distinct geometry passes and not an original producer identity. Changing them indiscriminately could corrupt world glass, water, HUD and stencil.
6. **End-to-end GPU/XR boundary remains unobserved.** For an actual reflection-influenced game backbuffer Draw, required evidence is original producer and texture/RT/depth face, direct native draw versus queue/D3DX flush owner, R29/R33/R30 semantic/state gate and any L/R physical draw/restore, followed by `src/vr/d3d9/stereo_renderer_r7.inc:1685-1744` Present/Frame.v2 eligibility. `vrhost/src/main_r23.cpp:1440-1513` consumes DirectGPU eye textures or SBS halves and renders independent D3D11 projection slices; `:3559-3593` records actual `xrEndFrame` submission. QPC intervals in `FaceCount_dest` alone cannot attribute p95/p99 GPU time or show that reflected surfaces appeared identically in both optical eyes.
7. **Prior evidence is context only.** The older R26+HUD HMD reference and user-reported dense beach/water/smoke slowdown do not constitute a matched 01466 game scene, exact DLL or fresh GPU frame. No new Quest3/VDXR observation, shader disassembly, XREF or hardware GPU capture establishes which reflection face was rendered, when the face was sampled, or how much it cost.
