## EVIDENCE — authenticated GitHub source + original REA + immediate predecessor + issue

1. **Original draw origin is separate from the physical GPU sink.** docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:5-45,62-98 maps game frame 0x00417B20 -> scheduler 0x00449050 -> priority queue consumer 0x0042D710. +TIME 0x00498670, fixed rank 0x004B9D80 and world car rank 0x004BAD20 are distinct producers. Queue type 0 enters ID3DXSprite Draw and only submits at a later native Flush/End; type 1 or flagged sprites can reach DrawPrimitiveUP directly, while physical D3D9 COM indices 81-84 distinguish DP/DIP/DPUP/DIPUP. This is checked-in REA/disassembly reconstruction, NOT a new original-EXE runtime trace.
2. **Queue epoch and native deferred ownership.** src/vr/game/render_semantics.hpp:1760-1836 snapshots a node-tag publication cutoff and advances SpriteQueueNodeEpoch on selected nodes, defaulting unproved nodes to ScreenOverlay2D. src/hooks_uiscaling.cpp:3417-3493 preserves only safe homogeneous direct +TIME/GOAL D3DX native Flush/End ownership, shielding unproved or reentrant batches. A CPU producer/sprite tag cannot establish which actual GPU API, route, RT or viewport is in use at the subsequent draw.
3. **R33 original and right extent leases are independent.** src/vr/d3d9/stereo_renderer_r33.cpp:100-160 contains R33TargetResetViewportMatches and R33SavedTargetResetViewportMatches. Each tests its own surface identity and GetDesc dimensions; the original lease additionally rejects zero saved dimensions, both require X/Y=0 and depth range 0..1, and unknown/GetDesc-failed cases force normal viewport setting. These tests compare the **saved game D3D9 viewport to each D3D9 RT0 extent**, not to the headset OpenXR projection extent or the user's monitor resolution.
4. **R33 R84-only physical L/R and restore gates.** src/vr/d3d9/stereo_renderer_r33.cpp:629-814 (R33TryFastWorld) and :1370-1515 (R33TryHud) capture the saved viewport before left/right operation, set the original WVP for LEFT and call actualDraw. After left succeeds, they decide independently whether a right SetViewport can be omitted and whether restoring the original viewport can be omitted; they then bind right RT/depth, set right WVP, perform the actual right draw when permitted, and call R32ReviewRestoreRightPassState. A failed right bind/draw or original-state restoration prevents completed-stereo publication and triggers current-frame fail-close/recovery. R33TryHud additionally fences reentrant +TIME/GOAL, car-rank, shadow and lens sources before the right physical draw, so the original semantic cannot be assumed preserved merely by the extent check.
5. **R32 restore forces a live viewport setter on failed RT0 recovery.** src/vr/d3d9/stereo_renderer_r32.cpp:370-402 (R32RestoreRightPassState) restores original RT0, depth and WVP and checks ((!restoredRt || !skipSavedViewportRestore) && FAILED(device->SetViewport(&savedViewport))). Therefore an RT0 restoration failure does not silently consume the saved-viewport skip flag; caller still vetoes on restore failure. This is a syntactic fallback guarantee, not proof that a failed original RT0 could be repaired by SetViewport.
6. **Reset invalidates both extent leases.** src/vr/d3d9/stereo_renderer_r33.cpp:2130-2177 (ResetDestR33) clears R33RightViewport and R33SavedViewport after R32 reset lifecycle, including unsuccessful Reset. The two borrowed surface identities cannot be reused across that reset via these caches. This review found no evidence that the two optional viewport setters alone determine final game source dimensions or XR eye sizes.
7. **Physical path choice and protected default.** src/vr/d3d9/stereo_renderer_r33.cpp:1559-1768 shows R33 may choose exact HUD, fast world, R29 or original unchanged route based on source, StateBlock and effect eligibility. src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:74-92,4878-5100,5320-5510 describes the *independent default R26+HUD* admission and R30/R62/native physical paths. AGENTS.md:1-9 (newest 2026-10-20 override) makes R26+HUD default and R84_TEST nondefault; no R33-only optimization demonstrates an active package fix.
8. **Present != headset acceptance.** src/vr/d3d9/stereo_renderer.cpp:690-821 requires world stereo, two-eye draw, right/pose completeness and a successful DirectGPU/SBS/Present path; vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:253-320 only advances SafeFrameId after a completed inactive-eye CopyResource fence; vrhost/src/main_r23.cpp:3562-3609 distinguishes candidate output from actual intercepted xrEndFrame source/layer/result. No matching R33 skip-on/off physical draw IDs, SafeFrameIds or actual headset images were supplied.

## Conditional original-producer -> eyes -> restore -> Present/OpenXR simulation (STATIC, NOT OBSERVED)

- **S0 / main game and eye extents exactly match:** producer -> queued semantic and node epoch OR direct source -> physical D3DX End/Flush/DP/DIP/UP -> R33 may admit only if R84_TEST and its state/pose/effect gates pass -> game saved viewport is (0,0,fullW,fullH,MinZ=0,MaxZ=1); saved original RT desc matches and StateBlockTracker::Reliable is true; rightEye desc also matches -> after successful LEFT Draw and right SetRT0, R33 omits redundant right SetViewport; following RIGHT actualDraw it may request skip of the original viewport setter, but R32 still requires successful RT0 restoration and restores depth/c64 -> complete bilateral frame gate -> successful R9 Present/transport -> fence-complete new R32 SafeEyes -> actual accepted xrEndFrame. *Not proof all branches were exercised.*
- **S1 / original RT full, right-eye target different extent:** the original viewport restoration may qualify for omission if tracking reliable, but the **RIGHT** target comparison fails and right SetViewport is explicitly executed. Different right-eye storage size does not itself mean the game source follows desktop resolution; verify source/backbuffer logical extent and OpenXR eye extent independently. If the right setter fails, no right physical Draw is certified; R32 attempts original state restoration, R33 blocks stereo completion.
- **S2 / inset viewport or custom Z range:** R33 rejects one/both elision predicates, sends actual right SetViewport and/or original restore viewport regardless of surface size. This preserves a deliberately cropped render while avoiding a full-screen-only inference. If matching viewport dimensions are observed but raster/scissor or eye pixels differ, investigate separate R22/R23 tracking, c64/pose and final host presentation rather than blaming a successful extent comparison.
- **S3 / left succeeds, right or original RT restore fails:** R33 records right failure or !restoreOk; src/vr/d3d9/stereo_renderer_r32.cpp R32RestoreRightPassState attempts SetViewport on unsuccessful original RT restore even when prior skip was requested; R33's CanPublishStereoDraw requires both eyes plus restore. R9 can choose mono fallback or fail-closed; do not convert a successful left HRESULT into a stereo/HMD PASS.
- **S4 / StateBlock reliability lost or Reset:** original restore-skip is disallowed on unreliable tracker, and Reset clears both borrowed extent leases. R33 may delegate to conservative lower route; under the current protected R26+HUD package the R33 branch is not a default route to begin with. A raw R84-only optimization must not be promoted into the R26+HUD default without matched HMD and measured CPU/GPU evidence.
