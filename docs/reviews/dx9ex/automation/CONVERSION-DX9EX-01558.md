## NEW_FINDING — static diagnostic interpretation, not an observed optical defect

NEW_FINDING=STATIC_CONDITIONAL_FAILURE_LOG_WITH_RASTER_UNCAPTURED; `VR LENS R30 TRANSACTION` can be printed solely due to the independent failureSample counter while `rasterSample=0`. Its three `VR LENS R30 EYE RASTER` lines then contain `captured=0`, `qpc=0`, zero-initialized viewport/scissor/RT/depth and `E_PENDING` getter HRESULT sentinels. Such a line **does not prove** either an absent real D3D render target or a physical right-eye Draw failure. This does **not** establish the user's doubled/head-locked lens-flare root cause.

1. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:5550-5560` defines the read-only `R30LensRasterTrace` with `captured=false`, getter HRESULTs `E_PENDING`, and numeric fields initialized to zero. The `Capture` method alone queries real viewport/scissor/scissor-test/RT0/depth and records QPC; `Log` prints either actual captured fields **or** unobserved sentinel fields, with an explicit `captured` flag.
2. `R30LensTransactionTrace::Begin:5578-5600` computes normal `sample` using first 32, power-of-two totals and first 8 samples after a stable Reset-epoch transition. `Emit:5602-5641` *independently* counts `!pairComplete` failures, printing first 16 and power-of-two failures even when `sample==false`; it always calls three raster `Log` methods after the transaction line if emitted. It reports `rasterSample=sample` explicitly.
3. `R30TryScreenSpaceFovDraw:6359-6361,6380-6400,6410-6429,6502-6518` calls `left.Capture`, `right.Capture` and `post.Capture` **only if** `lensTransaction.sample`. It calls `Emit` on early left WVP/Draw failures and at the end of the RIGHT transaction; none of these Emit paths retroactively calls Capture. Hence failure-only logging without raster captures is a reachable source branch when the normal sample gate is off.
4. In the RIGHT path (:6473-6518) `rightStage` records RT, depth, viewport, WVP or draw step, and `rightDrawAttempted` is set immediately before `actualDraw()`. If `SetRenderTarget` or subsequent setup fails, `rightDrawHr` remains `E_PENDING` and `rightResultHr` records that setup HRESULT. **This is not an attempted failed RIGHT Draw**. If RIGHT `actualDraw` returns failure, both `rightDrawAttempted=1` and `rightDrawHr=FAILED` are present. Distinguish setup failure, physical Draw failure and restore failure; do not infer them from `stage` alone.
5. `R30TryScreenSpaceFovDraw:6664-6759` keeps the existing `pairComplete` gate and returns `leftHr` after a failed RIGHT; the new transaction `pairComplete` at :5605-5607 is stricter about *attempt flags* plus restore. The legacy `PHYSICAL EYES` event at :6571-6641 remains independently sampled and prints `rightHr`, but does not distinguish RIGHT setup from Draw without the new transaction. Neither is verified GPU colour-pixel, same-eye PMT multiplicity, R23 final source-eye image, or OpenXR actual layer proof.
6. The new transaction trace is additionally restricted to `lensPhysicalCandidate` (effective `ProjectedScreenEffect2D` or `SceneEffect` at :6090-6110, and `Begin` at :6359-6361), **after** many R30 admission/E_NOTIMPL exits (:6270-6350). A missing transaction event cannot refute original C993/CABE producer or lower R26/R23/opaque queue Draw. The same source's `sourceCallSerial` can be zero on deferred candidate; do not treat a queue window as exact original PMT/texture identity.
