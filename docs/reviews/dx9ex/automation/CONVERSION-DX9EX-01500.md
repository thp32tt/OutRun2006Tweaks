## REVIEW_SCOPE — original producer -> semantic/queue -> D3DX/native DP/DIP/UP -> R33/R30/R62 -> L/R -> restore -> Present/OpenXR

1. Archived original REA: +TIME's six original E8 calls near 0x9898E..0x98AC6 include sprani and numeric children; scheduler 0x449050 -> 0x42D710 consumes four original sprite categories: type0 D3DX 0x42A0A0 (possibly deferred Flush/End), type0 direct UP 0x42C0F0, type1 animation 0x42A3A0, type1 masked 0x42A800. **This is historical binary evidence**, not a live observation that every +TIME call reaches fixed-function FVF142.
2. Semantic admission is physical, not broad alpha: render_semantics `CanReprojectFiniteResultHudPlane` admits only ScreenHud plus StageExtensionTime, GoalTime020, GoalTime150, ResultProgress, OutRunStagePrintf or ResultTextB9200. A deferred D3DX draw must carry correctly captured producer/queueNode/queueEpoch; unknown SpriteNode cannot inherit a prior +TIME batch. Projected rank and 6th/6 have separate non-result admission. No new B9200 return-site hook is permitted.
3. R33's resynced game raster guard tries R30 fixed-function original sprite on DP/DPUP/DIPUP and R30 fixed-function projected rank on DIP before generic XYZRHW/R29. R30 requires game main backbuffer, triangle list, corroborated ScreenHud/projected marker, **live null vertex shader and exact FVF 0x142**, valid viewport/pose/eye resources and finite original projection. Additional DP/DPUP/DIPUP entry is restricted to exact StageExtensionTime producer; DIP has existing R62 owner boundaries.
4. R62 snapshots the physical draw command and original projection. It constructs a projected-marker clip-shift or finite ScreenHud eye matrix. For each eye, a private `SetTransform(D3DTS_PROJECTION, eyeProjection[eye])` precedes the original native raw draw. R30ExecuteXyzrhwStereo checks StageExtension/GOAL/rank physical source across LEFT/right setters, switches right RT/depth/viewport, submits RIGHT, and restores right RT/depth/viewport. Only successful bilateral draws and this inner restore record a stable pair.
5. **Distinct outer restore**: after R30Execute returns, *outside* its eye/RT restore transaction, R62 independently calls `SetTransform(D3DTS_PROJECTION, &originalProjection)` under InternalPassScope. If this setter fails, R62 calls `NoteRestoreFailure("R62 D3DXSprite fixed-function projection restore")` and `R30ArmSafeFallback()`. The first sets FrameRightDrawFailed, FrameStereoIncomplete and RestoreFailures; the second maintains frame-incomplete / guarded mono safety.
6. **Conditional HRESULT split**: after telemetry (including RESULT_HUD_EYES/STAGE_HR only for exactResult with enabled VRTelemetry), the return expression is `exactResult && !restored && SUCCEEDED(hr) ? E_FAIL : hr`. Thus, with dual native eye Draw success and inner right RT/depth/viewport restore success but *only outer original projection restore failure*, an exact StageExtensionTime/GOAL command returns E_FAIL, whereas an otherwise admitted projected ordinal or non-result FVF142 ScreenHud command returns successful `hr`. The latter is logical API success with a poisoned same-frame stereo state and a possibly dirty original game projection.
7. R33/R30's non-E_NOTIMPL fixed-sprite result is terminal: no second native original draw is replayed. R7 Present requires both FrameRightDrawFailed=false and FrameStereoIncomplete=false plus world stereo, pose/resource and duplicated-draw guards. The forced outer restore fault therefore vetoes *fresh* stereo publication irrespective of the caller-facing S_OK on the non-result path; x64 host can retain an earlier safe layer or use bounded recovery theater, not a proved fresh correct OpenXR eye image.
8. Negative controls: if outer projection restore succeeds, ordinary pair success returns raw LEFT HRESULT for both producer classes. If R30 rejects before a physical LEFT draw, E_NOTIMPL is a distinct fallback case. If RIGHT raw Draw fails or right RT restore fails, R30 has its own RIGHT failure/restore path; do not misattribute that to the outer R62 projection setter. A shader-backed GOAL or FVF144 final graph is NOT this fixed-function transaction.
