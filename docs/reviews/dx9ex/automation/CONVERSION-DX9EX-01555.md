## NEW_FINDING — a pending draw semantic is shielded by projected C993 but not by CABE's outer wrapper

NEW_FINDING=SOURCE_STATIC_CONDITIONAL_COUNTEREXAMPLE_CABE_PROJECTED_WRAPPER_SCOPE_IS_NOT_SUFFICIENT_TO_FORCE_PROJECTED_NATIVE_DRAW_IF_NEXTDRAWSCOPE_IS_PREARMED; C993_PROJECTED_SCOPE_EXPLICITLY_SHIELDS_AND_RESTORES_THAT_PENDING_TOKEN. This identifies an **eligibility/diagnostic asymmetry only**, not proof that any real flare had a pending token, was drawn twice, or is head-locked.

1. `src/vr/game/render_semantics.hpp:925-935,1054-1084` defines thread-local `NextDrawScope` and `ConsumeForDraw()`: with no exact centre GPU owner, no exact queued override, and a pending non-None token, the next native Draw **returns and clears that pending scope**, rather than inheriting the current projected wrapper scope. A source wrapper's `CurrentScope=ProjectedScreenEffect2D` therefore need not equal the physical Draw's selected semantic.
2. `src/hooks_graphics.cpp::DrawObjectAlphaProjected:787-903` sets only `ScopedRenderSemantic(ProjectedScreenEffect2D)` around `DrawObjectAlpha_Internal` at :889-902. It creates an inline lens-call receipt but **does not instantiate** `ScopedExactProducerSemantic(..., isolatePendingDraw=true)` and does not clear or restore an earlier `NextDrawScope`. That applies to a possible immediate CABE `0x570008` physical Draw; the first 570008 can instead remain deferred to the original 4052C0 opaque flush and must be treated separately.
3. `src/hooks_graphics.cpp::DrawObjectAlphaCentre:943-1069` constructs `ScopedExactProducerSemantic(ProjectedScreenEffect2D,nullptr,true,ProducerToken::None)` only when `projectedSun=true`, then invokes the original object renderer. `render_semantics.hpp:1497-1546` saves the pending scope and temporarily sets `NextDrawScope=None` for this direct source (only while `SpriteQueueDepth=0`), restoring the old token on destruction. This gives an inline projected C993 source a different protection from CABE; it is not the already-scored ray-branch token guard.
4. Native `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:7369-7420,7420-7514,7515-7567,7569-7629` calls `ConsumeForDraw()` at the start of each eligible DP/DIP/DPUP/DIPUP hook, then wraps the selected value in `ScopedRenderSemantic` before any R30 screen-kind classification. `R30ClassifyScreenSpacePass:2320-2340` grants `ProjectedScreenEffect2D` only from effective projected semantics; `R30TryScreenSpaceFovDraw:6120-6150` requires that scope for projected admission.
