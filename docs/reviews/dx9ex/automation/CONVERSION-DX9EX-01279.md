## EVIDENCE — producer -> semantic -> queue -> physical GPU API -> R30/R62/R29/R9/R7 -> L/R/restore -> Present/OpenXR

1. **Original producer is not identified as a query.** The checked-in prior REA `docs/research/REA_ORIGINAL_SPRITE_GPU_FOUR_PATHS_20261018.md:19-47` resolves original `0x449050 -> 0x42D710` and type-0 D3DX `0x42A0A0`, direct UP `0x42C0F0`, type-1 quad `0x42A3A0` and mask `0x42A800`; 36 indirect CALLs remained unresolved. None proves that an original sprite path executes with an occlusion query active. `src/vr/game/render_semantics.hpp::SelectSpriteQueueNode:1789-1835` increments queue epoch and conservatively applies generic ScreenOverlay2D unless exact evidence exists. Semantic/producer token/queue epoch cannot substitute for physical query state, RT identity or final GPU API. D3DX Begin/End can defer the physical draw beyond source ownership.
2. **Query tracking has a separate unavailable flag.** `src/vr/d3d9/stereo_renderer_r7.inc::CreateQueryDest:1617` installs `QueryIssueDest` on an occlusion-query vtable; successful hook arms `OcclusionQueryTrackingUnavailable=false`, failed hook sets it true and logs fail-closed stereo duplication. `::QueryIssueDest:1616` increments/decrements `ActiveOcclusionQueries` only from successful hooked Issue Begin/End on the game device. Thus after an Issue hook installation failure, `ActiveOcclusionQueries==0` does **not** prove absence of a hardware-active query. No per-query runtime Begin/End evidence exists for this SOURCE_HEAD.
3. **Main/auxiliary target and safe-route rejection.** `src/vr/d3d9/stereo_renderer_r7.inc::ExecuteStereoDraw:1524-1555` leaves offscreen-target work native and tests `occlusionActive=(ActiveOcclusionQueries>0 || OcclusionQueryTrackingUnavailable)` for its nonduplicated branch. `::PrepareDuplicatedDraw:1520-1522` poisons stereo when tracking is unavailable. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30SafeStereoBase:75-93` and `src/vr/d3d9/stereo_renderer_r29.cpp::R29StableStereoBase:426-453` each reject both the unavailable flag **and** positive active count. Physical DP/DIP/DPUP/DIPUP hook separation is visible in `stereo_renderer_r30_r26_safe.cpp:5349-5529`. R62's fixed-function indexed DIP admission is separate (`::R62TryFixedFunctionSpriteIndexed:5126-5193`) and cannot be assigned as the query owner from semantic tags.
4. **R9 mono backup checks a narrower predicate.** `src/vr/d3d9/stereo_renderer.cpp::R9ReplayMonoDraw:338-362` skips replay (incrementing `R9OcclusionBackupSkips`) only when `ActiveOcclusionQueries>0`; unlike the R7/R29/R30 gates, this function never inspects `OcclusionQueryTrackingUnavailable`. If its count remains zero during an untracked-but-actually-active hardware query, it proceeds to `R9BindMonoTarget` and executes `actualDraw()` against the mono shadow before restoring the game target. This is a **confirmed static guard asymmetry**, not proof such a live query exists in OutRun's sampled frames.
5. **The replay can occur before frame poison or native draw.** `src/vr/d3d9/stereo_renderer.cpp::R9ExecuteDraw:567-649` first requires game device, non-internal pass, StereoWanted, main backbuffer, seeded frame, mirrorable depth and mono resources. It calls `R9ReplayMonoDraw` **before** testing `FrameStereoIncomplete`, then notes conservative main depth/stencil-write serial and dispatches either the physical `actualDraw()` or lower legacy callback. Consequently a preexisting R29/R7 fail-closed poison does not, by itself, stop an already-seeded R9 mono replay. `R9ClearDest:495-563` seeds `R9StereoSeeded/R9MonoSeeded` on successful paired full-main color clear while frame remains complete; precise position of failed hook relative to this clear is not observed.
6. **Actual physical query effect is conditional.** `R9BindMonoTarget:296-334` switches to `R9MonoSurface`/mono depth, and `R9RestoreGameTarget:328-335` restores RT/depth/viewport. The `actualDraw` lambda in `R9DrawPrimitiveDest/R9DrawIndexedPrimitiveDest` and their UP variants (`stereo_renderer.cpp:633-689`) ultimately invokes the underlying physical D3D9 Draw* hook, **not** merely a queue tag. If a query is hardware-active at that instant, an extra Draw* can affect the query's sample accumulation independently of whether it changes visible pixels. No hardware occlusion results, actual query begin/end, physical primitive identity or post-draw target restore HRESULT have been observed here.
7. **Depth/mono and frame output are not query-correctness checks.** `R9ReplayMonoDraw:355-362` increments `R9MonoDepthContentSerial` on possible mono writes; `R9ExecuteDraw:604-618` advances `R9MainDepthContentSerial` for possible main writes. `R9PresentDestR9:692-823` gates eligible stereo on seeded, paired world/draw, pose, no failure, transport, compose and native Present; it does not prove an occlusion query was not affected by replay. `vrhost/src/main_r23.cpp:3555-3617` checks actual `xrEndFrame` submitted frame/layer, not correctness of game-side query sample count. Right-eye safety and eventual host submission remain separate from the mono replay query side effect.
