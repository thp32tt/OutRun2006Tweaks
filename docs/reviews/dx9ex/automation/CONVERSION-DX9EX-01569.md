2. **R19 then splits the selected rectangle exactly in half.** `RenderProjectionOverride:1027-1143` takes `whole=GetGameUv()`, computes `eyeUv[0]=(whole.x,whole.y,whole.w/2,whole.h)` and `eyeUv[1]=(whole.x+whole.w/2,whole.y,whole.w/2,whole.h)`, calls `RenderTo` once for each separate XR array slice, and submits one replaced two-view projection when successful. This is an **input-crop origin/scale** issue, distinct from 01568's sub-texel bilinear mixing across the correctly selected split.
3. **Read-only deterministic numeric counterexample** (illustrative source coordinates; not observed HMD pixels). Thus left-eye output samples 77 source pixels from the **right** client-eye subrectangle near the split, and right-eye output additionally samples desktop pixels beyond the actual client right edge. This effect can extend far beyond the 01568 one-texel bilinear footprint.
4. **Independent position and threshold controls:** With the **same** 1766x994 client centered at x=77..1843, both midlines are x=960; whole-desktop mode still includes margins and alters apparent scale, but the internal eye split is not displaced.
