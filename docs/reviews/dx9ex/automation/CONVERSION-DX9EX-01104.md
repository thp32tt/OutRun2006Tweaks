## Confirmed facts versus conditional hypothesis / disproof

- **CONFIRMED STATIC:** non-atomic/non-TLS R23 Draw serial is sampled from TLS R28 previous-serial and per-thread CPU/QPC baselines; R27 aggregate telemetry variables are global while its activation edge flag is TLS. This establishes a **metric attribution contract gap if more than one game render/Present thread participates**, not a demonstrated race or a known Quest3 issue.
- **H1 (UNPROVEN — multiple actual game threads):** if eligible Draws from thread B arrive between two Present-end samples of thread A, the A TLS draw delta includes B's global serial increments. If another thread toggles telemetry, shared R27 rollup may reset or combine intervals across owners. **Falsifiers:** all intercepted game-device DP/DIP/UP and Present always occur on one verified OS thread for the full run; thread changes never overlap; additional serialization/ownership gating elsewhere applies to all relevant calls; or the logged draw metric is intentionally defined as global across multiple producing threads.
- **H2 (UNPROVEN — actual data race):** concurrent unsynchronized R23 increments/reads from different threads could be a C++ data race, but no concurrent invocation was observed, and the game D3D9 device/thread creation flags and driver serialization were not established here. **Disproof:** single-thread game-device use or demonstrated synchronization encompassing every R23 writer and R28/R27 reader. Do not assert a live race from a plain variable alone.
- **H3 (UNPROVEN — user-visible optics):** apparent 72Hz source slow windows or R28 `drawPeak` might diverge from actual host fresh-frame cadence, but this metric path alone cannot create a second sun, wrong F11 shell or headlocked +TIME. **Disproof/segmentation:** actual physical GPU L/R, Restore and source/host matched frame ID expose unchanged screen defect even while single-thread metrics are stable. R28 source-frame p95/p99 is not HMD FPS.
