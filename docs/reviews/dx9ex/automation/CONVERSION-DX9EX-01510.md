Neither archived evidence nor an E8 CPU call proves physical eye API submission.
2. **Entry ordering.** At `ResultProgressEnter`, outer `ResultProgressDepth++` saves `SourceAdmission{VR,GOAL,!QueueRenderActive(),CurrentQueueNodeEpoch()}`, then `ResultProgressEntrySerial`, then *all* priority old roots/tails. Only **after** this snapshot, if `mayBeginDirect()`, `FlushD3DXBeforeDirectGoalSource()` submits a proven outgoing homogeneous old-owner batch; then `mayPublish()` checks VR, GOAL, queue inactive, unchanged queue-node epoch before activating direct `ScopedExactProducerSemantic(ScreenHud,ResultProgress)`.
3. **What pre-drain can do.** `BeforeDirectGoalSource` calls `FlushTracked` only for active, matching live ID3DXSprite with pending homogeneous draws and suitable owner. The original native `Flush` may invoke COM/hook callbacks; reentry into a *producer that appends a SpriteNode* is a conditional hypothesis, NOT demonstrated. If this appends an untagged foreign P after old tail A with stable priority root and no `SelectSpriteQueueNode`, the queue-node epoch stays E0. A new exact foreign tag would independently protect ownership; this finding specifically requires an **untagged** P.
4. **Post-drain original E8.** Suppose pre-drain returns with VR=true, GOAL, queueDepth=0, epoch E0; `ResultProgressAdmittedAfterDrain=true`, and original 0x2D200 then adds legitimate progress Q after P. `ResultProgressLeave` sees unchanged VR/GOAL/epoch and `admitted=true`; it calls `TagAppendedNodes` with *the pre-drain saved A and root*, not a post-drain A->P checkpoint. Stable-root reachability proves A->P->Q is linked but does not prove P was appended by original progress E8.
5. **Semantic publication distinction.** `TagAppendedNodes` walks each verified appended node through terminal tail; `RegisterSpriteNodeScope` can attach `ScreenHud/ResultProgress` to untagged P as well as Q. `preserveNewerExactSince=entrySerial` protects a newer **different explicitly tagged producer**, not P with no tag. `CurrentQueueNodeEpoch` is incremented by `SelectSpriteQueueNode`, not by merely appending an untagged node. Thus the current post-drain admission rejects queue selection, but does not itself distinguish a pre-source append without selection.
6. **Negative/positive contrasts.** If native pre-drain cannot append P, this scenario does not occur. If P was already present before the entry snapshot, it is excluded by A. If the pre-drain selects *any* node, epoch E1!=E0 rejects admission (desired). If P has a newer different exact tag, `PreserveNestedExactSpriteOwner` keeps it. If root identity is replaced/detached, stable-root proof rejects. In contrast, `ResultProgressFullParent` deliberately snapshots serial, roots and tails **after** its pre-drain admission (not before), so this exact time window is specific to the inner E8.
7. **Physical consumer.** When P later reaches original queue selection, `ConsumeSpriteNodeScope` may return the mistaken finite HUD tag instead of generic `ScreenOverlay2D` if serial cutoffs, identity and lifetime checks pass. The actual original type-specific D3D9 draw may be deferred D3DX Flush/End, direct-UP, quad, or masked path. `CapturePhysicalDrawCommand` uses current node/epoch. R26-safe R62 requires exact finite owner *plus* valid device/backbuffer, TRIANGLELIST, actual VS=null, FVF=0x142, pose/eye projection/viewport/RT resources; so an erroneous tag changes **eligibility**, not proof of stereo output.
8. **L/R -> restore -> Present/OpenXR.** If all R62 gates pass, guarded LEFT and RIGHT physical raw draws and projection/RT/depth/viewport restoration still each have independent HRESULT/failure routes.
