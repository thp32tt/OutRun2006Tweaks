4. **R69 semantic first gate:** `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp:2170-2320` computes exact `semanticProjectedScreen`; at approximately 2283-2288 it returns `ProjectedScreenEffect2D` immediately **before** the generic `GetRendererBaseProjection` / projection-signature classification. The exact CABE mode is intentionally independent of generic SceneEffect projection type at this classifier boundary.
5. **R69 physical shader WVP entrance:** `stereo_renderer_r30_r26_safe.cpp:4613-4788` requires a tracked nonzero vertex shader and exact owned original game c64 (`R44GetOwnedRawOverlayWvp` or `R30GetExtendedRawWvpForExactSceneEffect`), guards finite `stockWvp`, then unconditionally calls `R30BuildEyeAffine(stereo,eyeScale,eyeOffset)` around 4768-4770 and unconditionally obtains a *finite and invertible* `GetRendererBaseProjection` around 4779-4786. `R30BuildEyeAffine` (`:2468-2504`) rejects nonfinite/too-small FOV widths, scale outside [0.5,1.5] and offset magnitude >0.5. These are valid conservative gates for generalized stereo HUD reconstruction.
6. **Source-confirmed difference:** only **after** the above preflight, `stereo_renderer_r30_r26_safe.cpp:4788-4808` sees `ProjectedScreenEffect2D`, transposes the original stock WVP, copies **identical** constants to L/R and returns `true`. This path reads **neither** the just-computed `inverseBaseProjection` nor the `eyeScale/eyeOffset` (other than upstream diagnostic logging using eyeOffset) to construct the CABE eye WVP. Inability to invert base projection, or failure of a finite but outside-range FOV affine, therefore vetoes a transformation that does not otherwise need that derived math. Original c64 finite/owner proof, valid pose, resources and two-eye restore remain necessary independently.
7. **Per-eye draw/restoration and failure behavior:** `stereo_renderer_r30_r26_safe.cpp:5050-5121` requires exact `ProjectedScreenEffect2D` scope, resources, depth/stencil synchronization and latched pose. Any build failure increments only aggregate `R30ScreenSpaceBuildFailures` and returns `E_NOTIMPL`. `:5123-5285` on success submits left native Draw with original c64 replaced, switches right RT/depth/viewport, submits right, calls `RestoreRightPassState` for RT/depth/viewport/original WVP, and poisons/arms fallback on right or restore failure. `:5275-5296` `R30GuardScreenSpace` delegates `E_NOTIMPL` to previous R29/original native draw. `:5300-5324` R62 fixed-function indexed FVF142 instead admits HUD/projected-*world-marker*, **not** the new CABE `ProjectedScreenEffect2D` scope. A fallback return does not prove bilateral CABE optical correctness.
8. **Postdraw to headset:** `src/vr/d3d9/stereo_renderer_r7.inc:1494-1520,1625-1740` composes two-eye SBS or probes D3D9Ex shared-eye DirectGPU before/after original Present, never publishes an incomplete active stereo frame, and restores game D3D9 state around SBS. `vrhost/src/main_r23.cpp:1257-1319,1439-1510,3132-3249,3555-3575` correlates admissible game frame/capture with QPC/pose, renders distinct OpenXR projection eye textures from either shared handles or desktop SBS UV, and submits layers. None of these downstream gates certifies that an **individual** CABE source draw ever passed R69's zero-disparity constants gate. #01414's PresentRect/client-seam question is independent.
