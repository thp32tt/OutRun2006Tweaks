## REVIEW_SCOPE — original producer → semantic/queue → physical D3D9 API → R30/R62/R26 L/R → Reset/restore/Present → R41/R32 → xrEndFrame

1. **Producer and GPU draw identity are distinct.** Existing checked-in historical REA `docs/automation/OUTRUN_REA_RENDERING_ARCHITECTURE_20261018.md:31-69` maps original game `0x00449050` render scheduler, sprite pipeline `0x00429530→0x00428A10→0x00429460→0x00429350→0x00428BD0` queue, `0x0042A3A0` native GPU, and D3DX Begin/Draw/Flush/End (which can defer native Draw). The historical map is NOT a new disassembly or evidence that any specific sun/HUD/result primitive physically submitted on this run. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::DrawPrimitiveDestR30/DrawIndexedPrimitiveDestR30:5349-5410` consumes semantic scope and chooses bounded XYZRHW/R62/native or delegated path. `::R30ExecuteXyzrhwStereo:3829-3907` attempts left physical Draw, then right-eye RT/depth/viewport + Draw, then restore. Only corroborated pose, draw HRESULT and successful state restore can qualify complete stereo; no Quest3 frames observed.
2. **R9 Reset enters the base Reset lifecycle.** `src/vr/d3d9/stereo_renderer.cpp::ResetDestR9:825-838` clears R9 mono/depth identity and seeds, marks depth reacquisition, invokes the pre-existing `ResetDest` hook, then conditionally re-captures depth on success. This is conditional upon `R9InstallCallbackPolicy:849-887` having successfully installed; do not assume that the user's installed DLL ran R9. The underlying `src/vr/d3d9/stereo_renderer_r7.inc::ResetDest:1739-1741` resets render tracking, calls `ReleaseStereoResources`, clears pose/stereo frame state, publishes StereoDisabled/Frame.v2 fallback, invokes D3D9 Reset or the R13 ResetEx compat path, and re-primes resources on success. Release precedes the final Reset HRESULT.
3. **Old game-side DirectGPU slots are explicitly retired.** `src/vr/d3d9/stereo_renderer_r7.inc::RetireDirectTransportFramePublications:1176-1212` takes ring/slot seqlocks and clears current-run DirectGPU frame IDs, flags, handles, width/height, format, generation and slot indexes; `::ReleaseStereoResources:1215-1225` retires slots and releases fences/shared textures/eye RTs. The runGeneration remains the **game run identity**, initialized by `EnsureRenderFrameState:625-686`, not a new run on every device Reset. A subsequent `EnsureDirectTransportResources:1353-1357` recreates all four slot pairs and increments `DirectTransportGeneration` on successful allocation. This is a producer-resource generation rollover within the same PID/run; it does not by itself call a host-side compositor invalidation.
4. **R41 consumes only new active frames and treats run vs transport separately.** `vrhost/src/main_r23.cpp:2940-3017` reads completed history in direct-only mode, observes **PID+runGeneration** in `directRunEpoch.Observe`, resets `lastProcessedStereoFrame`, match and `cachedProjectionValid` only when that *game run* changes, and uses `OutRunVrDirectRingLatest::Pick` to select newest eligible `RenderFrameDirectGenerationIndex` with strictly newer frame ID. There is no *producer transport generation change* invalidation branch for `cachedProjectionValid` in the inspected R41 block. This is not a claim that a new generation is accepted without validation: candidate identity and direct frame/pose/flags are checked again at `vrhost/src/main_r23.cpp:3110-3250`.
5. **R32 caches never blindly join an old pair to a new frame.** `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp::R32SyncDirectDeviceOwner:91-107` invalidates R32 caches/SafeEyes when the *host D3D11 device/context binding* changes; a game-only D3D9Ex Reset does not necessarily change those pointers. `::R32OpenSharedSlot:111-207` keys each shared pair on slot+producer DirectTransportGeneration+runGeneration+PID+both handles+extent/format+host device, reopens and validates both eye descriptors when the identity changes. `::CopySharedFrameToSafeEyesR32:253-315` writes into inactive SafeEyes, waits for an EVENT, acknowledges completion, then swaps + updates SafeFrameId/generations; `::EnsureSafeFrameR32:323-335` checks the exact frame before an early SafeEye cache hit. Thus the static path guards **future fresh frame ownership**, not whether a previous released XR projection remains on screen between game Reset and new good frames.
6. **XR retained projection can bridge a same-run Reset.** `vrhost/src/main_r23.cpp:2719-2750,2777-2793` explicitly invalidates `cachedProjectionValid` on XR STOPPING/reference-space changes; `:2870-2890` clears it on presentation-mode changes; and `:2970-2990` clears it on a PID/runGeneration change. But `:3300-3390` renders only when a new validated stereo frame committed (or there is no cached projection) and otherwise resubmits the last released `cachedProjectionViews` if cached. In unchanged Gameplay/host XR-session/PID/run, a producer Reset may retire all shared slots without changing `cachedProjectionValid`, so `xrEndFrame` at `:3557-3580` can receive a **cached pre-Reset projection** while no post-Reset live stereo frame exists. Direct-only mode at `:3425-3450` avoids SBS fallback when no layer. This describes a conditional stale-image *lifetime*, not proof of corruption, stale D3D11 shared-handle use or a headset defect.
