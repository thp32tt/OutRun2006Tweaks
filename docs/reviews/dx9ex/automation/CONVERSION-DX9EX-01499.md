2. In gameplay with visible F11, the overlay scopes ImGui_ImplDX9_RenderDrawData under external ScreenOverlay2D semantics. R30's DIP destination checks live null VS, source FVF, orthographic projection, external semantic depth, scissor and existing world/duplicate/pose/RT state. R30's external F11 function precedes R62 fixed-sprite, XYZRHW and R29 fallbacks; an E_NOTIMPL rejection permits the subsequent route, not an automatic stereo pass.
3. With admission proven, source desktop-client orthographic positions are transformed to a full BackBufferDesc eye viewport, then two eye projection/scissor rectangles are prepared (finite plane or FOV fail-safe). R30 sets LEFT viewport/projection/scissor; if this fails, restore is attempted and E_NOTIMPL is returned only when recovery succeeds, before any physical F11 draw.
4. On successful LEFT raw DIP, R30 switches RIGHT RT and optional RIGHT depth, then attempts RIGHT viewport/projection/scissor and RIGHT raw DIP. A RIGHT RT/depth or setEye failure skips RIGHT DIP; a RIGHT DIP failure means the API was invoked but reported failed. RestoreRightPassState and restoreRaster are then attempted, regardless of RIGHT success.
5. **Conditional failure split**: after the restore attempt, R30 unconditionally sets FrameHadDuplicatedDraw and increments DuplicatedDraws, NonWorldDuplicatedDraws, R30SafeTwoEyeDraws and R30ExternalImGuiStereoDraws, and can log the F11 source-aspect probe with rightHr=failed. Only *after* increment/logging does it set FrameRightDrawFailed, poison RightStateFailed or RightDrawFailed, and arm safe fallback; it returns *leftHr* (S_OK in this scenario). R30's immediate caller treats any non-E_NOTIMPL as handled. Thus apparent two-eye counters and logical DIP success do not imply a successful physical RIGHT draw.
6. With a failed RIGHT route, R7's Present eligibility explicitly requires !FrameRightDrawFailed && !FrameStereoIncomplete; R9Poison also enforces incomplete-frame safety. A failed F11 draw does **not** by itself prove contaminated SBS/DirectGPU publication. The x64 host may retain the previous safe projection or use guarded mono/theater recovery before xrEndFrame; no new OpenXR/XR eye pixels were captured for this case.
7. Negative controls: (a) rejected F11 setup with successful restore returns E_NOTIMPL and must not increment those post-LEFT counters; (b) both LEFT and RIGHT successful, restores successful, can increment a valid pair; (c) a LEFT draw failure returns leftHr and poisons immediately *before* post-two-eye increments; (d) an unrelated original EXE sprite draw is not an external ImGui candidate.
