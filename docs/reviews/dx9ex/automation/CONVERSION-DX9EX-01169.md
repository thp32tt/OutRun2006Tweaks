3. **F11 FOV mapping algorithm.** `src/vr/d3d9/f11_screen_2d.hpp::Build:26-76` validates each eye tangent span and then sets `commonLeft/commonRight/commonDown/commonUp` to arithmetic **means** of the corresponding two eye edges (`37-40`), not to the binocular **intersection**. 4. **New bounded static counterexample (geometry only, not observed pixels).** The existing portable `TestAsymmetricEyes:88-98` passes eye L tangent X interval `[-1.1,+0.9]` and eye R `[-0.9,+1.1]`. `Build` therefore chooses common interval `[-1,+1]`. Its +1 right edge is **outside left-eye right limit +0.9** and its -1 left edge is **outside right-eye left limit -0.9**. For that example `scaleX=1`, `offsetX(L)=+0.1`, `offsetX(R)=-0.1`, so a stock NDC +1 source edge goes to left-eye +1.1 NDC, and a stock -1 source edge goes to right-eye -1.1 NDC. Each lies beyond the visible [-1,+1] clip interval. This proves *possible edge clipping for full-extent content under a valid input*, NOT that Quest3 has those FOVs or that F11 actually draws content at the edge. Existing static asserts only test offset sign/equal/invalid FOV; they do not assert both-eye full source-rect visibility. As an independent contrast, the host **menu** helper `vrhost/src/runtime/menu_content_aspect.hpp:103-157` intentionally intersects both eye FOV tangent rectangles to prevent one-eye crop. It does not imply the menu helper is invoked by F11.
5. **Scissor / left+right / restore.** `R30PrepareExternalImGuiProjection:2888-2935` projects the four corners of the current ImGui command scissor using the eye projection and clamps both per-eye rectangles to the *current D3D9 viewport*. `R30TryExternalImGuiIndexed:2940-3060` sets projection+scissor for left native indexed draw, switches to right RT/depth/viewport and right projection+scissor for another physical indexed draw, then restores original RT/depth/viewport and projection/scissor. Any right-eye/restore failure poisons the frame and arms safe fallback; F11 attempt counters are not binocular-pass proof (previous task 01168). **Viewport clamp cannot recover triangles already outside the eye's clip volume**. Current `VR F11 SOURCE-ASPECT PROBE` logs backbuffer/viewport/scissors and draw HRESULTs (`3024-3046`), but not the per-eye FOV edges, Build common edges, projected full-extent clipping percentages or actual headset pixels.
6. **Present/host boundary.** `src/vr/d3d9/stereo_renderer.cpp::PresentDestR9:692-822` requires world-stereo, duplicated draw, no right failure/incompleteness, valid pose/resources and successful original Present before stereo-active publication; otherwise mono/disabled fallback. `vrhost/src/runtime/d3d9ex_direct_passthrough_r32.hpp:267-319` waits for both eye-copy completion before publishing SafeFrameId, and `vrhost/src/main_r23.cpp:3562-3610` differentiates actual `xrEndFrame` submission. Successful draw/scissor API calls or a SafeFrameId do not prove those F11 edge pixels survive lens compositor clipping, nonzero eye cant, source/viewport/XR extent and both-eye viewing.
