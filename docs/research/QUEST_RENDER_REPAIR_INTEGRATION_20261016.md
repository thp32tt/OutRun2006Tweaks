Target: `thp32tt/OutRun2006Tweaks` `vr-d3d9ex-focus`, exact material SHA in git history. No Quest hand tracking; steering wheel and FFB unchanged. Existing R84 R33→R29 path, DX11/DXVK isolation and R26_SAFE rollback preserved.

## Newly verified defects and repairs
1. **Driver seat and HUD projection poison after settings/Reset.** `src/hooks_graphics.cpp::CalcCameraMatrix_dest` passed `Settings::VRNearPlane` directly into desktop/VR camera `perspective_znear_BC`. Even `std::clamp` is unable to sanitize NaN: NaN propagates into D3D projection and can blank seat, cockpit, lens and HUD. `DriverSeatCamera::SafeNearPlane` supplies finite positive bounds, preserves normal input (0.05–0.15 seat; 0.03–0.50 positional), rejects NaN/Inf/zero, defaults to 0.10 and immediately recovers on next valid frame. This is live code, not just a C++ test.
2. **GPU cubemap work after explicit disabling.** Quest GLES `GlD3D9Device::flush` batches expensive commands, but Windows R84 already uses a bounded 60 Hz `ReflectionFrameBudget`. When `ReflectionUpdateRate` was changed to 0 with outstanding fractional/queued faces, the old algorithm could continue emitting faces. `ReflectionFrameBudget::Advance` now cancels pending debt and emits no GPU faces when rate zero. Default/rate-positive 60 Hz and late-frame caps unchanged.
3. **Failed D3DX GPU Flush retains stale command tags.** R84's `HudCommandBatch::Ledger::onFlushFailure` revoked active status but left stale `drawCount/scope/producer` in memory. A failed Flush does not prove physical GPU submission. Now retire the entire pending batch identity transactionally, retaining the native HRESULT and existing exact provenance checks. Existing HUD screen-space policy remains unchanged.
