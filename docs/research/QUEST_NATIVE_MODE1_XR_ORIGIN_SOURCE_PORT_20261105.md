# OutRun Quest original mode1 camera and XrRig source port (2026-11-05 KST)

## Scope / validated evidence

- **User intent:** preserve the APK's actual seated eye origin and full left/right OpenXR orientation/position, not reproduce it with manually tuned F11 offsets.
- **Quest ELF:** authorized user's `apk/_static_out/liboutrun_quest_core.so`, previously verified SHA256 `fa0f9db9b744515a9a1439741bc9806ad007470b621b88d22a0b8bcbced6120b6`. Used bounded read-only original ARM64 disassembly from `apk/_analysis_focus/quest_20261103_pad_snapshot_run2.asm`, `quest_20261103_android_main_for_seat.asm`, and the new bounded `quest_20261105_xrrig_locate_exact.py`. Original APK/ELF/retail EXE are NEVER committed.
- **Two distinct native matrices:** `race_camera_eye_look_485590` gets guest profile `0x5B2F68[index]` record `+4C/+50/+54`; `run_game::$_2` at ARM64 `0x2E17F4..0x2E1808` adds **(Y+0.319999993, Z+0.550000012)** to *that captured input* under the original gameplay qualification. Former PC branch injected unadjusted profile, then used a guess `SeatBack=+0.35/SeatDown=-0.25`, which is not the original source operation. This update injects the exact source pre-camera pair once, then calls the original PC mode1 swing/snap/blend/ground clamp. E.g. selector0 is `(-.353,.947,.160)`, selector15 `(-.353,.947,.100)`, no modulo-15 collapse.
- **Do not conflate VR controller pivot with headset:** the separate ARM64 `0x2E1B00..0x2E1D18` after `VirtualWheel::update` uses `+0.04` and another +/-0.32/0.55 when composing hand/controller matrices. This path is not a direct headset-view offset; importing the .04 into OpenXR eye pose would cause a new headset error.
- **True headset recenter and eyes:** original `XrRig::locate` ARM64 `0x2D69C8..0x2D6C08`: `xrLocateSpace` orientation/position validity checked; yaw extracted by `atan2(2*(qx*qz+qy*qw),1-2*(qx*qx+qy*qy))`, center quaternion `(0,sin(yaw/2),0,cos(yaw/2))`; `xrLocateViews` must return exactly two valid views. At `0x2D6B98`, inverse yaw-origin XrPose then `compose` individually with two eye poses at `0x2D6BB4/0x2D6BDC`. The resulting left/right full rigid views are precisely `inverse(compose(inverse(origin),eyeWorldPose))`.
- **Port:** portable `src/vr/game/quest_cockpit_v2_apk_xr_pose.hpp` computes yaw origin, inverse-origin composition, head-local eye composition, full two-eye relative poses with finite/unit guards. `outrun_renderer.cpp` gates this on live mode1 / gameplay / valid host pose / default physical IPD and rotation scale, latches BOTH native eye inverses and publishes identical mode1 source poses in Frame.v2; `stereo_renderer_r7.inc` uses those values for fixed-world and programmable-world draws, compensating original c64's already-applied head inverse for shaders so the transform is applied once. Outside mode1, preexisting R26 HUD/sky/menus and OpenXR behavior is unchanged.
- **F11:** `QuestCockpitV2ApkNativeCamera=true` is the dedicated test default and uses native guest camera values, ignoring even previously saved manual seat-back/down/right settings. Setting it false re-enables manual cockpit comparison offsets. No original asset or stable release modifications.
- **Tests:** `tools/tests/quest_cockpit_v2_seat_smoke.cpp` covers source camera constants for selectors0/15, identity recenter, yaw-only center, IPD left/right translation and NaN/invalid input refusal. Windows source build/CI is the separate compile gate; **HMD visual parity is not proven by synthetic tests**.

## Limits

This source port implements the independently inspected 32-bit guest camera input and 64-bit Quest XR rigid-transform order. It is **not** a claim that the PC game and Quest APK have bit-identical runtime: original Quest's guest selector and override-enable byte, PC runtime car ID, the headset compositor's reference-space origin, frame interpolation, and HMD scale/IPD require synchronized hardware comparison. Reference source in host `xrLocateSpace(viewSpace,localSpace)` and `xrLocateViews` is already available, so no fabricated head-pose values or hard-coded fixed eye rotation were added.

**Runtime validation:** Quest 3 HMD=UNTESTED for this source SHA. Future HMD test should compare selector0 and selector15 while stopped, rotate yaw ±45°, lean left/right, view up/down, and check that no double inverse is present before evaluating car body shake/sky.
