## Material source port
- New `src/vr/game/quest_cockpit_v2_occupant.hpp`: original `W * C` order with 16-float finite/affine and overflow checks; original event-362 work pointer equality; gating for valid original player + native game-frame + stereo pose + mode1. Standalone 1,000 noncommuting affine matrix tests, left-versus-right order witness, rejected/unmodified output test.
- Actual game hook `src/hooks_graphics.cpp::QuestCockpitV2PlayerCandidateProbe::RobotDisplay`: resolves live original guest PC event-362 work pointer `0x79F010` (module RVA `0x39F010`), compares to the actual original `EvWorkRobot*`. It will *never* classify robot via the two identical PC character arrays `0x6549B0` and `0x6549C8`, guessed zero workID or global char type. Reads exact player B0,F0, and `robot->d3dmatrix10` (original work+0x10). If finite, composes `W*C` and lends the staged model matrix to the synchronous original `0x514E60` call through an exception-safe RAII with byte-for-byte work-matrix restoration. Reentrant same-thread model scopes are explicitly rejected to avoid compounding the correction. Never changes game physics, HMD view, FFB, other NPC, driver/heroine mapping, HUD, menu or global culling.
- Guard is experimental and conservative: V2 option, native camera1 and playable mode, exact event362 original work token, currently active original game-render frame, valid **current** stereo pose, and no SceneEffect. When any is missing it calls the original robot renderer unmodified and emits a small bounded probe only when telemetry enabled.
- Shipped normal `QuestCockpitV2Enabled=false` and `QuestCockpitV2OccupantCorrection=false`. Dedicated `RUN-QUEST-COCKPIT-V2.cmd` uses the experimental option only for that process. Driver hide stays false; the original is *visible* under near-seat forced-LOD rules.

## Limitations: NOT full Quest visual parity yet
- The original Quest sets car `matrix_F0` to identity **around its vehicle-render owner**. This Windows implementation does not yet modify the original F0 at all and intentionally preserves the car simulation. F0 renderer-local shadow/alias solution and exact original car draw scope remain pending.
- Both native callback/BeginScene/Present and XR pose may be correlated in trace, but exact **same game-frame/eye-frame pairing is unproven** by HMD runtime. Merely observing an active original PC native render hook and latched XR pose is not a full causal proof. The gate thus remains experimental.
- The second Quest native event 363 (one of two allowed occupant TLS work tokens), forced-visible LOD0 view/service byte +0x35, player glass queue-descriptor flag and original near-dashboard culling remain unimplemented. These must not be applied globally.
- There is no PC/Quest automated pixel-by-pixel render comparison; Quest3 HMD, motion/jitter, player/passenger geometry, native F0 usage and performance **RUNTIME_VALIDATION=UNTESTED**.
