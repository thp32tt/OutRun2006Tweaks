# 한글화 공통 글자별 크기·번역 길이 검수 정책

## 2026-10-11 QA 수렴·실게임 시험 분리 정책 (최신 사용자 결정)

**모든 생산/검수 레인 공통 적용:** [KOREAN_LOCALIZATION_QA_THROUGHPUT_POLICY.md](KOREAN_LOCALIZATION_QA_THROUGHPUT_POLICY.md)를 최신 QA 판정의 정본으로 먼저 읽는다. 기존 문서에서 **경미한 원본 서체/효과 차이, 완벽하지 않은 금속 광택, 미세한 각도·자간 차이, 과거 미관만의 HOLD**를 자동 재작업으로 표시하던 지시는 이 정책으로 대체한다. C2는 저장 DDS에서 실제 읽히는 글자·보호 픽셀·CLEAN·RAW/FLIP-Y를 독립 확인하고, 구체적 시각 결함이 없으면 `COSMETIC_VARIANCE_ACCEPTED`와 정적 QA PASS를 검토한다. 없는 결함을 추측하거나 같은 SHA를 반복 재생산하지 않는다.

**하드 게이트 유지:** 오자/가짜 자소/잘림/가독성 불량/원문 효과 bbox 1px 침범/다른 UI 충돌/영어 잔상/플레이트 손상/저장 DDS 압축 훼손/사용자 실게임 FAIL은 계속 차단한다. `TEST_ONLY_ELIGIBLE` 및 `C3_LIGHT_REVIEW_TEST_ONLY`는 격리 시험용 판단이며 `C2_PASS`, `C3_STRICT_PASS`, `qa_evidence_gate.py` 승인·배포, 실게임 PASS를 자동 생성하지 않는다. 고위험 P0/P1 및 공유 HUD는 C3 엄격검수를 유지하고, 사용자가 실제 게임에서 확인하기 전 `RUNTIME_VALIDATION=UNTESTED` 및 OPEN을 유지한다. 기존 A/B/C1/C2 역할·작업 소유권·일정은 불변.


## 2026-10-11 전 레인 글자별 크기 검수 규칙 (최신 사용자 지시)

**적용 대상:** A/B/C1 제작·자체 QA, C2 독립 최종 QA, C3 엄격 QA, CLEAN 이후 렌더·저장 DDS 시각검수, PRE_INGAME 및 재작업 판정 전부. 원문과 번역의 언어/글자 수가 다르다는 이유로 한글 문장 전체 가로세로 비율·폭 점유율·영문 픽셀 면적/실루엣 일치율이 다르게 나온다는 것은 **반려 사유가 아니다**. 이 지시가 과거의 "undersized/underfill/원문 길이·폭에 비례/가능한 크게" 문구보다 우선한다. 자세한 단일 정본은 `docs/KOREAN_LOCALIZATION_GLYPH_SCALE_POLICY.md`.

**판정:** 원문 개별 텍스트/줄의 정확한 글자+효과 bbox를 넘는 한글 픽셀은 1px도 허용하지 않는다. 그 안에서는 한글이 원문보다 더 좁거나 작아도 허용하고, 원문 총 문장 길이나 글자 개수/캔버스 비율을 맞추기 위해 확대하거나 가로 늘이지 않는다. 비교 대상은 실제 한글 **글자 하나하나**의 네이티브 높이/획 굵기/받침·내부 공간/윤곽·효과·가독성과 UI 계열의 대표 원문 글자 크기·위계이다. 영문과 한글 글자 수가 달라 1:1 대응시킬 수 없으므로 'n번째 영문 글자 = n번째 한글 글자' 강제 매칭도 금지한다. 번역이 더 짧은 **그 사실 자체는 PASS** 처리한다.

**반려 가능 조건:** 원문 bbox 초과, 겹침·보호 아트 변경·잘림, 한글 오탈자/획 손상/실제 읽히지 않음, 명백한 서체·기울기·효과 오류는 각각 구체적 원인과 실제 픽셀 증거가 있을 때만 FAIL. 기존 `UNDERFILL`/`SOURCE_WIDTH_RATIO`/`WIDTH_RATIO`/`WHOLE_SENTENCE_ASPECT`만 근거인 REWORK는 현행 글자별 시각검수에서 **크기 조건 PASS로 재분류**하고 나머지 QA 통과를 확인한 뒤 정상 C2/C3 경로로 진행한다. 미검수 자료를 근거 없이 전체 승인으로 바꾸거나 사용자 실게임 OPEN을 닫지 않는다. `RUNTIME_VALIDATION=UNTESTED` 유지.


## 모든 레인의 동일한 검사 순서

1. 정확한 현재 Git SHA·SOURCE/번역 정본과 **개별 레이블·줄**의 원본 glyph/effect bbox를 확정한다. 서로 다른 언어의 *문장 전체* 가로/세로·글자 개수·문자 폭 평균·문장 채움률은 측정값으로 보관할 수 있지만 실패 임곗값으로 사용하지 않는다.
2. 글자별 한글 자소/음절의 native 실제 높이, 획 굵기, 면적 대비 내부 공간, 받침/조합 상태, 경계 AA, 효과 두께와 명료성을 살핀다. 원문 UI의 비슷한 기능/계열에 속하는 **대표 개별 글자**와 획·가독성·강조 수준을 비교한다. 원문과 1:1로 문자 개수나 문자 인덱스를 맞추지 않는다. 한글이 작아도 충분히 읽히면 PASS.
3. 원래 원문이 여러 줄이면 줄별 바운딩 박스와 원본 줄 관계를 각각 검증한다. 번역 글자 수 감소로 줄이 짧아지는 것은 정상. 원본 줄의 의미상 강조 레벨과 기준선/의도된 정렬만 유지하며, 빈 공간을 채우기 위한 강제 폭 늘리기·늘어진 글리프를 금지한다.
4. 결과 DDS **실저장 바이트**를 RAW/FLIP-Y, native/75%/50%, 미프 레벨에서 확인한다. 명시적 오탈자·획 손상·실제 가독성 불량이 확인되면 구체적인 *개별 글자/증거 좌표*로 반려한다. 단순히 영문보다 문구가 짧다거나 alpha 면적·폭·높이 비율이 다르다는 이유만으로 반려하지 않는다.
5. source glyph/effect bbox를 가로·세로 어느 방향으로든 1px 이상 초과하면 FAIL. 원문 잔상, 보호 픽셀 변경, 다른 UI 간섭, 반대 기울기, 명백히 잘못된 스타일도 별도 FAIL. 기계적 bbox PASS만으로 다른 검사를 생략하지 않는다.
6. 기존 `underfill`/문장 폭 비율 단독 반려는 최신 원본과 후보를 재확인해 크기 항목 `PASS_TRANSLATION_LENGTH_VARIANCE`로 처리한다. 기존 독립 C/C3 재판정과 아직 실제 게임 미검증 상태를 명확히 분리한다. **새 DDS 생성 없이 정책이 바뀌었다는 이유로 동일 SHA를 신규 생산물/신규 점수로 계산하지 않는다.**

## PASS/FAIL 사례 (정책 예시, 실제 자산 검증 결과 아님)

- 영문 10자 -> 한글 4자, 전체 폭이 45%: 글자가 각각 읽히고 원래 bbox 안이면 **문장 크기 조건 PASS** (폭 45% 자체는 무관)
- 영문 전체 폭과 1:1로 맞추기 위해 한글 4자를 가로 2배 늘림: **강제 늘리기 금지**, 실제 자소 왜곡은 실패
- 한글 각 글자가 원본 기준보다 다소 작지만 네이티브·50%에서 읽힘: **크기 조건 PASS**
- 한글 효과가 원본 bbox 오른쪽으로 1px 벗어남: **FAIL_OVERFLOW**
- 한글 1글자 받침이 뭉쳐 읽을 수 없음: **FAIL_GLYPH_LEGIBILITY**, 해당 글자와 native 이미지 증거 필요
- 길이 차이만으로 이전 QA가 REWORK인 후보: **크기 조건 PASS 재검토**. 다른 실패나 필수 C2/C3/실게임 미검증은 별도

## 상태·검수 로그

`text_length_difference_ignored=true`, `whole_sentence_width_ratio=diagnostic_only`, `per_glyph_size_and_readability=PASS|FAIL|HOLD`, `source_bbox_containment=PASS|FAIL`를 가능한 경우 기존 QA 관찰에 기록한다. 값이 없다고 가짜 PASS를 생성하지 않는다. 구조화 기록이 어렵다면 기존 `style/readability/glyph_integrity/placement` 관찰의 실제 문장으로 기록하되, 영문/한글 길이 차이 때문에 재작업을 발급해서는 안 된다.

이 지시는 이미지 생성/B/C1뿐 아니라 A와 C2·C3·QA/CPU 워커, controller 안내에도 동일하게 적용한다. 품질 안전장치나 사용자 최종 실게임 판정의 완화가 아니다.
