# OutRun 2006 한국어 그래픽 QA 수렴/생산량 정책 — 2026-10-11

**정책 ID:** KOR-QA-CONVERGENCE-20261011
**적용:** A/B/C1 제작, C2 독립 최종 정적 QA, C3 엄격 QA, PSD/CLEAN, PRE_INGAME 및 사용자 테스트.
**우선순위:** 이 문서는 이후의 사용자 명시 지시가 없는 한 기존 문서의 동일 항목에 있는 원본 서체 *미세 차이만을 이유로 한 자동 반려*, 무제한 동일 원인 HOLD 반복, 영어/한글 문장 폭 비교에 따른 재생산 권고보다 우선한다. 파일 무결성/보호 영역/기존 실제 게임 불량/독립 승인 조건은 **완화하지 않는다**. 기존 회귀 기록과 모든 SHA는 보존한다.

## 1. 제작 결과를 세 등급으로 분리

- `STATIC_QA_PASS`: 저장된 정확한 DDS 바이트에 대해 SOURCE/CLEAN/FINAL/RAW/FLIP-Y, 원문 글자 영역, 다른 UI/보호 아트, 정확한 한글, 가독성, 압축 후 변화가 검증되며 명백한 시각 결함이 없다. 영문과 미세하게 다른 획 두께·명암·금속 광택·광원·자간·서체 형태 자체는 반려하지 않고 `COSMETIC_VARIANCE_ACCEPTED`로 기록한다. C2의 **독립적 실제 픽셀 관찰**은 계속 필요하며, 제작자는 자신을 승인하지 못한다. C3/사용자 실제 게임은 별도의 단계로 유지한다.
- `TEST_ONLY_ELIGIBLE`: 정확한 파일/출처/영역 SHA와 기계적 보호 검사는 PASS했지만, 스타일에 대한 경미한 주관적 차이나 필수 독립 최종 문서가 미완료다. 별도의 격리된 `USER_REVIEW_NOT_APPROVED` **시험 후보**로 분류할 수 있다. 이는 C2 PASS/C3 PASS, `role_C/APPROVALS` 또는 배포 승인으로 바꾸는 상태가 **아니다**. 기존 `qa_evidence_gate.py` 승인/일반 export 로직을 우회하지 않는다. 현재 패키저가 이 등급을 지원하지 않으면 자동 삽입하지 않고 manifest에 명시해 별도 사용자 승인된 격리 시험 작업을 기다린다.
- `REWORK_REQUIRED` 또는 `HOLD_EVIDENCE`: 실제 검출된 불량은 REWORK, 증거가 없어 안전 판단이 불가하면 HOLD다. 증거 부족을 '시각 FAIL'로 가장하지 않는다. 같은 SHA에 대해 이전 HOLD 결과를 반복 생산/검수 완료·추가 점수로 계산하지 않는다.

`STATIC_QA_PASS`는 어디까지나 **정적 독립 QA**이다. 정식 출시는 기존 C3와 필요한 `qa_evidence_gate.py` 승인 및 사용자 실제 게임 성공이 모두 필요하다. **런타임 실측이 없으면 항상 `RUNTIME_VALIDATION=UNTESTED`.**

## 2. 일치 기준 완화 — 반드시 PASS 가능

다음만으로 FAIL/REWORK/HOLD 하지 않는다.

1. 자연스러운 한글 음절 수 차이, 영어 문구 대비 좁은 폭·높이·채움률·문장 종횡비; 실제 글자와 받침이 100/75/50%에서 읽히고 원문 개별 레이블 효과 bbox를 벗어나지 않으면 크기 항목 PASS.
2. 동일한 UI 계열임이 분명하고 글자가 읽히는 상황의 **경미한** 색감·명암·획 두께·테두리·쉐도우·금속 반사·라운딩·서체 느낌·좌우 여백 차이. C2는 실제 native 이미지에서 구체적인 문제 지점을 특정할 수 없으면 `COSMETIC_VARIANCE_ACCEPTED`로 기록한다. 임의 유사도 수치/전체 문구 폭 임계값을 만들지 않는다.
3. 읽는 방향의 기울기와 정렬 관계가 맞고 겹침·잘림이 없을 때의 **미세한** 각도·원근 차이. 전체 서체 형태의 완전 동일성을 요구하지 않는다.
4. 과거 C2/C3 보고서가 `UNDERFILL`, `SOURCE_WIDTH_RATIO`, `ITALIC_MORPHOLOGY`, `METALLIC_FIDELITY`, `BLIND_CALIBRATION_MISSING` 등 **객관적 위해 픽셀 없이 미관 또는 누락 양식만** 근거로 REWORK/HOLD였다면 **정확히 동일한 현재 SHA**를 우선 재판정한다. 재판정은 새 DDS 생산으로 계산하지 않는다. 과거 REWORK가 실제 사용자 게임 불량과 연결되어 있다면 해당 OPEN은 그대로다.

단, **눈에 띄게 전혀 다른 UI 계열/폰트, 뒤집힌 기울기, 가독성 약화, 서로 다른 줄의 강조 위계 붕괴, 심각한 효과 색 오염**은 근거를 특정한 시각 FAIL일 수 있다. 평가자는 '원문과 100% 똑같지 않다' 대신 화면 좌표·보이는 결함·오독/방해 경로를 적는다.

## 3. 무조건 지켜야 할 HARD FAIL/승인 차단

- 한글 오자·누락·반복 자소·가짜 획·깨진 받침·읽을 수 없는 글자; Ferrari 모델명/음악 제목/보호 로고 임의 변경.
- 원문 개별 글자+효과 bbox 1px 초과, 글자/보호 그래픽·스테이지/랭크/HUD 충돌, 잘림·중복 렌더.
- 원문 영어 글자나 그림자 잔상, 눈에 보이는 CLEAN 플레이트 이음매/네모 패치, 알파/그라데이션 손실, 원본 보호 화상 픽셀 훼손.
- DDS 헤더/포맷/미프, RAW/FLIP-Y, 실제 저장/재디코드 불일치, 수정 블록 밖 변경, 시각적 압축 손상, 이전 크래시 원인 미검증.
- 실제 게임에서 이미 관찰한 P0/P1 결함을 **더 새로운 해당 DDS/런타임 빌드의 사용자 실게임 재테스트 없이** CLOSED/PASS로 변경, 근거 없이 게임 통과 주장.

위 결함을 미관 차이라고 분류해서는 안 된다. 기계적 0픽셀 수치만으로 보이는 결함을 덮을 수 없다.

## 4. C2/C3 검수 시간 제한과 위험 기반 작업 분류

1. C2는 새 SHA 및 P0/P1을 우선한다. 현재 저장 DDS의 **최소한의 정확한 SOURCE/CLEAN/FINAL 비교(원본 해상도, 실제 사용 크기, RAW/FLIP-Y, 보호 픽셀, 한글 정확성)**에 집중한다. 기존 확인된 파일·증거 SHA는 재사용하며, 동일 SHA를 무조건 전부 다시 촬영·렌더링하지 않는다. 새 후보가 바뀐 셀만 신규 검사하고 **이전부터 불량인 공유 아틀라스 셀은 여전히 미해결**이라고 명시한다.
2. `HOLD_EVIDENCE`는 **구체적으로 부족한 바이트/셀/검사 1회에 필요한 증거**를 한 묶음으로 지정한다. 이미 검증된 범위를 반복 HOLD하지 않는다. 근거가 새로 제출되지 않은 동일 SHA 단순 재확인은 0 성과.
3. 저위험 후보(단일 레이블, 넉넉한 원문 bbox 여백, 보호 아트 영향0, 이미 검증된 CLEAN, 압축 뒤 영향0, 실제 게임 불량과 무관)의 C3는 **시험 단계에서** 재차 상세 비교 파일을 재생산하지 않고 기록된 C2 원본 픽셀과 함께 간소화 점검으로 처리할 수 있다. 표기는 `C3_LIGHT_REVIEW_TEST_ONLY`; `C3_STRICT_PASS`가 **아니다**. 정식 승인 문턱을 통과하려면 현재 필수 C3 증거를 충족해야 하며 도구 스키마를 가짜 PASS로 채우지 않는다.
4. P0/P1 실제 게임 결함, 공유 HUD/동적 텍스트, HIGH_RISK_EDGE_TOUCH, 압축 보호 변경 가능성, 불명확한 게임 소비자 매핑은 고위험: 기존 C3 엄격 조건 유지.
5. 한 계열에서 CLEAN·기본 UI 스타일이 입증된 대표 샘플을 계속 재사용한다. 동일 원인의 스타일 리워크 2회 이후엔 같은 시도를 반복하지 않고 해당 항목은 격리/보류한 채 다른 READY 작업을 실제 생산한다.

## 5. 소량 인게임 시험과 출시 경계

- `TEST_ONLY_ELIGIBLE`은 승인된 빌드 대상 파일이라고 주장하지 않는다. **별도 사용자 확인을 받은** 격리 패치 시험(원본 자동 백업·복구, SHA manifest, 영향 화면 경로, 위험 안내)에만 검토한다. 기존 `USER_REVIEW_NOT_APPROVED` 패키지 필터 및 사용자 실제 불량 제외 조건을 **허위 상태 수정으로 우회하지 않는다**. 특히 이미 FAIL한 정확한 SHA는 포함하지 않는다.
- 고쳐진 새 SHA의 실제 게임 P0/P1 결함은 테스트 후보로 명시할 수 있지만, 실게임 성공 전 결함은 OPEN이다. 일반 공개 베타·정식 배포는 반드시 기존 승인과 실제 게임 테스트를 충족해야 한다.
- 관리자는 1회 작업에서 `new_saved_dds`, `producer_pass`, `C2_static_pass`, `C3_strict_pass`, `test_only_eligible`, `user_ingame_pass`, `official_promoted`를 구분해 보고한다. 실제 새 DDS가 없으면 0개. 모델 생성 PNG와 합성 시험 픽셀을 DDS 생산으로 계산하지 않는다.
