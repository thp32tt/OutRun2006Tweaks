## Sharpened c64 temporal ownership failure chain (source-possible, NOT runtime-proven)
1. Before `SelectSpriteQueueNode` establishes the exact node semantic, `src/vr/game/outrun_renderer.cpp::SetVertexShaderConstantFDest` can treat a c64 upload as a perspective-world candidate; `TryPrepareOutRunWvp` may upload head-corrected constants.
2. `src/vr/d3d9/stereo_renderer_r30_r26_safe.cpp::R30ClassifyScreenSpacePass` accepts exact `semanticHud` but on a perspective path immediately returns `None` if `CurrentDrawMatchesVerifiedWorld` or `R28CanRebindVerifiedWorld` holds. This hands ownership to lower renderer even though the queue's exact HUD semantic is known at draw.
3. Alternatively when the classifier proceeds to `PerspectiveHud`, `R30BuildScreenSpaceEyeConstants` first asks `R44GetOwnedRawOverlayWvp` for a pre-injection original. The raw owner accepts only a matching shader epoch and a draw age of **1 through 12** (`R44OverlayWvpDrawWindow=12`). A longer batch, differing shader epoch or new-node reuse can make that lookup fail. The function then reads `device->GetVertexShaderConstantF` live; that live register may already contain the head-corrected WVP, and HUD plane correction would then operate on corrected input a second time.
4. This distinguishes two testable error paths: **(A)** exact HUD suppressed by verified-world precedence; **(B)** raw-original ownership missed and active c64 used as though it were raw. Both require matching source pose, draw serial, shader epoch and queue-node semantic to establish occurrence. Never infer from static counts alone that either currently happens in Quest 3.
5. Recommended one-time telemetry: for each exact `ScreenHud/PerspectiveHud` draw count (A) verified-world exclusion; (B) raw-owner age miss and live-c64 fallback; (C) original-vs-injected matrix relation, correlated to queue-node identity/producer and current frame pose. Preserve conditional fail-closed world and never apply a broad HUD override to unknown draws.

This is not a confirmed effect of current game execution; whether the heart producer always synchronously draws and the exact next draw identity require canonical EXE and runtime evidence.
