### P1-B: R30 lazy shadow capture becomes **process-global** and lacks a total VB/IB memory budget
- **Confidence: exact control-flow, conditional pressure/performance impact.**
- `R30BufferShadowCaptureArmed` initially false (~197), flips true after first eligible XYZRHW VB or IB Draw (~3082/3191). `R30VertexBufferLockDest` and index equivalent (~449/494) copy **all subsequently intercepted write-lock byte ranges**, and `R30CreateVertexBufferDest/IndexBufferDest` (~582–614) installs hooks on generic game-created buffers, not only identified HUD FVF.
- Each buffer is accepted up to `R30MaxShadowBytes=16 MiB` (~153); `R30VertexShadows` and `R30IndexShadows` unordered maps (~190–192) have **no global byte cap** in this file. `R30FinishObservedLock` (~344–380) copies written ranges to separate CPU vectors. Thus after the first HUD buffer draw the claim that 'ordinary world buffers no longer pay per-Lock shadow memcpy cost' is not strictly true, and 32-bit address pressure / Lock/Unlock CPU cost can grow with number of buffers. This is **different from** the already-known first-draw shadow miss in the prior review.
- Contrast: `src/vr/d3d9/ex_device_upgrade_r14.cpp` independently caps texture CPU shadows at **384 MiB** (~73–75) and `src/hooks_textures.cpp` bounds VR DDS cache at **64 MiB**. These caps do not bound R30 VB/IB registry.
- Verify total live shadow bytes/high watermarks, per-source FVF classification, writes per Present, and 95th/99th percentile frame time. If proven, scope capture to identified XYZRHW candidates with a total budget or a bounded donor shadow; preserve dynamic DISCARD/NOOVERWRITE integrity.

## P0-A elaboration: ImGui active clip/scissor and vertex-buffer overhead

- The pinned DX9 ImGui code `ImGui_ImplDX9_RenderDrawData` (~193–260) allocates a **D3DUSAGE_DYNAMIC | D3DUSAGE_WRITEONLY** VB and IB, then locks both with `D3DLOCK_DISCARD` on every nonempty render; its `DrawIndexedPrimitive` (~298) applies a scissor rectangle per ImDrawCmd (~291). It subsequently restores fixed-function matrices and a D3DSBT_ALL state block (~306–311).
- The active R30 process-wide lazy buffer observer intercepts corresponding VB/IB Lock/Unlock once armed, even though R30 cannot execute the ImGui FVF XYZ path. This couples optional F11 on-screen drawing to **unnecessary CPU-shadow memcpy** and memory accounting. Prove actual cost with lock-byte and frame-time telemetry before claiming a measured FPS regression.
- Any F11 stereo implementation must transform/clip its scissor rects per eye or instead draw the complete ImGui UI into a dedicated texture and composite into a correctly located finite/recentered HUD surface. Simply changing the FVF eligibility condition and replaying the stock viewport/scissor can truncate the right eye. Preserve `SetTexture`, alpha blend, texture atlas lifetime, `D3DTS_WORLD/VIEW/PROJECTION`, full state block, R22 state tracker and R23 depth/target restoration. Prevent overlay from stealing a queued game sprite token.
- The current P0 verifier `tools/verify_vr_visual_composition_p0.py` checks the F11 RAII semantic wrapper but not pinned upstream ImGui FVF/XYZ/orthographic shape or actual R30 raster ownership. This explains how an exact-SHA Inspector PASS can coexist with this unhandled path.

- The framerate hook ordering proves only `SumoUISpriteReplay::update` before `Interp::AfterTicks`, and that `Calc3D2D_dest` stores global rank/rival sample buffers without an epoch.
