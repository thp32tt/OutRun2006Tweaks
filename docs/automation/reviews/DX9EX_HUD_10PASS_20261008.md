## Evidence and open findings

**F1 — rank 1st–3rd one-node assumption (SOURCE_ASSUMPTION_UNVERIFIED):**
`RankMarker_sprani` compares old/new `tail_4` at each priority and tags only the current tail, unlike the rival path's `TagAppendedNodes` linked-list sweep. Historical comments say each 1st–3rd marker producer draws one sprite. Before changing the semantics, prove from the original `sprani_play_ae_auth_alpha` implementation whether it can enqueue >1 node on any priority; add a targeted synthetic duplicate-node negative test if so. Do not label it a confirmed bug yet.

**F2 — generic ScreenOverlay2D policy divergence (POLICY_MAPPING_TO_VERIFY):**
The neutral `render_semantics.hpp` documents untagged queue content as FOV-only, whereas `R30ConfigureXyzrhwWorldEffect` in the R26+HUD source treats `semanticHud || semanticOverlay2D` with a finite HUD plane. The authoritative game-build flags are `-DOUTRUN_VR_SAFE_DRAW_COMPARE=OFF -DOUTRUN_VR_R26_HUD_COMPARE=ON` (see DX9Ex Active and `Build-OutRunPCFast.ps1`). The separate R33 full-chain compile is not the same runtime configuration. Reconcile exact policy and documentation after considering the past head-lock regressions; never blindly revert intended placement.

**F3 — missing menu/car-selection DDS pixel and actual-load proof (STATIC_GAP):**
The P0 gate verifies known replacement resource paths, transient DDS D3DX buffer lifetime, and source tokens/byte contracts; it does not establish every intended replacement DDS is valid, loaded, transparent and correctly matched to its menu/car-selection origin. Build an asset-replacement manifest/decoder regression test and load-to-resource proof before another HMD trial.
