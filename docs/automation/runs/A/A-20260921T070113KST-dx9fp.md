# Role A handoff — final-dispatch fingerprint coverage

Reviewed immutable integration base `e5e35f483cf7f8d36f99a87807ba6cb9d4b7eccd` without changing runtime behavior.

## Result

The queued `DX9EX-FINGERPRINT-001` work is justified, but the current helper cannot identify the unresolved white HUD/rank/score/menu/effect draws reliably:

- The active CI explicitly builds `ACTIVE_FULL_R34`; `R34` wraps `R33`, and `R33Dispatch` owns successful fast-world and HUD routes.
- `R46TraceShaderFingerprint` is called only below that boundary in `R27GuardWorldEffect`. Any draw handled by `R33TryHud` or `R33TryFastWorld` returns before reaching it.
- Fixed-function draws are accepted as a valid `(VS=0, PS=0)` pair and `RememberPair` deduplicates only by VS/PS bytecode hash. Distinct white rank, score, 6th/6 and YES/NO draws can therefore collapse into one record.
- The emitted record lacks draw API/topology/count, FVF/declaration, projection class, relevant render states, route outcome, resource generation and bounded capture identity.
- With the environment flag enabled, the lower fallback calls `GetVertexShader`, `GetPixelShader` and takes a mutex before pair deduplication on every visited draw. That is unsuitable as an always-on diagnostic in a path already observed near 1,800–2,000 draws per Present.
- The shader bytecode cache uses a COM address as its lookup key and is not reset-generation-aware. A destroyed shader address reused after Reset can inherit a stale cached hash even though final pair deduplication itself correctly uses bytecode hashes.

## Five-lens evidence

1. **Architecture/control flow:** final classification lives in `R33Dispatch`; fingerprint capture lives only in the lower `R27GuardWorldEffect` fallback.
2. **Ownership/lifetime/reset:** the bounded hash cache is process-static and keyed only by COM pointer, with no Reset/device generation.
3. **Stereo/visual correctness:** shader pair alone cannot distinguish fixed-function HUD/effect classes or record whether R33 chose HUD, fast world or fallback.
4. **Hot path/frame pacing:** enabled diagnostics perform per-draw COM state queries and a global mutex before deduplication.
5. **Adversarial/testability:** the selector/profile/capture scripts do not expose `OUTRUN_VR_SHADER_FINGERPRINT`; Ctrl+F9 host telemetry does not contain game-side draw identities, so the expected evening evidence cannot currently be produced by the normal package.

Contrary evidence checked: the current helper correctly hashes bytecode rather than using COM addresses for final pair identity; capture is opt-in; GPL attribution/source files exist in the repository; R31/R33 already provide coarse route counters. None closes the exact-draw coverage gap.

## Proposed bounded implementation contract

Instrument the final `R33Dispatch` decision boundary, not only R27. Record a bounded per-capture signature containing draw API/topology/count, VS/PS bytecode hashes, FVF or declaration signature, projection class, relevant alpha/Z/cull state, render-target/depth/reset generations, selected route and handled/result state. Cache shader hashes at shader state changes or with generation-aware invalidation; do not query/hash under a global mutex for every draw. Flush only the existing Ctrl+F9 window and cap both unique signatures and samples. A deterministic LEVEL0 verifier should prove fixed-function draws remain distinct and simulated pointer reuse after Reset cannot return an old hash. Runtime association of captured signatures with visible objects remains LEVEL1.

## Independent compliance finding

`DX9EX-COMPLIANCE-001`: the active DX9Ex package contains a DLL compiled with `shader_fingerprint_gpl.hpp`, while `.github/workflows/vr-dx9ex-active.yml` emits neither the declared separate compliance ZIP nor `COPYING.GPL3`, `THIRD_PARTY_GPL_NOTICES.txt`, the adapted corresponding source, or a same-SHA compliance manifest. The generic build has license aggregation, but it is not the producer of the active DX9Ex artifact. This contradicts `PKG-002`'s “separate compliance ZIP” claim and the repository notice saying the adapted source is copied into test packages. Proposed LEVEL0 fix: produce and validate a companion compliance artifact from the same source SHA; keep the runtime tester ZIP lean.

Upstream provenance remains `bo3b/3Dmigoto` (`util.h` and `DirectX9/Direct3DDevice9Functions.h`), GPL-3.0; the existing source header, notice ledger and GPL text should be preserved.
